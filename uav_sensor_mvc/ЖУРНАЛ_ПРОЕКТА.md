## 1. Идея и назначение

БПЛА летит из точки **A** в точку **B** с ограниченным **запасом хода** `L_max`.
Точный маршрут заранее неизвестен — это случайная кривая из некоторого
распределения. Нужно расставить `N` датчиков радиусом `R` так, чтобы на типичном
маршруте обеспечить: (1) **кратность** — не менее `k` обнаружений; (2)
**равномерность** — засечки по всей длине пути, а не на одном участке.

Расположение определяется **в динамике**: на каждой итерации приходит новый
случайный маршрут, расположение пересчитывается по всей накопленной выборке и
стабилизируется с ростом выборки.

## 2. Математическая модель (компактно)

- **Эллипс достижимости** `E = { P : |PA|+|PB| ≤ L_max }`, полуоси
  `a = L_max/2`, `c = |AB|/2`, `b = √(a²−c²)`. Любой путь длиной ≤ `L_max`
  целиком внутри эллипса.
- **Дуги (этап 1)** заданы **углом отклонения** `θ` (касательно-хордовый угол в A):
  длина `L(θ)=c·θ/sinθ`, предел `θ_max` из `L(θ)=L_max`.
- **Петли (этап 2)** — синусоида с закреплёнными концами; предельная амплитуда
  по длине (аналог `θ_max`).
- **Манёвр / ломаная (БПЛА самолётного типа)** — боковое отклонение от хорды
  `y(t)=Σⱼ aⱼ·sin(jπt)` (нули на концах); амплитуда каждой гармоники ограничена
  **радиусом разворота**: `aⱼ ≤ 0,9·D/(rmin_frac·(jπ)²)`, где `D=|S0B|`,
  `rmin=rmin_frac·D` (сейчас `rmin_frac=0,11`). Длина ≤ `L_max` (масштаб
  отклонения уменьшается, пока не уложится). «Манёвр» — гладкая кривая (цепочка
  дуг), «ломаная» — те же отклонения по вершинам, соединённым отрезками.
- **Зона старта (вкладка 2)** — старт не из точки, а из **эллипса** вокруг A
  (полуось вдоль A→B = глубина/2, поперёк = ширина/2); каждый маршрут идёт из
  случайной точки зоны в цель B. Кандидаты датчиков — точки `P`, достижимые из
  зоны: `dist(P, зона) + |PB| ≤ L_max`.
- **Обнаружение** — однократный вход в зону датчика; кратность `n(S,γ)` = число
  различных засёкших датчиков.
- **Полезность** на маршруте: `φ(S,γ) = α₁·min(n,k)/k + α₂·m/L_seg`, где `m` —
  число покрытых сегментов из `L_seg`.
- **Критерий** — матожидание `F(S)=𝔼[φ] → max` при `|S|≤N`, заменяемое
  эмпирическим средним по выборке (**SAA**) `F_t(S)=(1/t)Σφ(S,γᵢ)`.
- `F_t` монотонна и субмодулярна ⇒ **жадный алгоритм** даёт гарантию
  `(1−1/e)≈0,632` от оптимума.

## 3. Реализация (MVC)

```
config.py            параметры, режимы, профили, тема
main.py              точка входа matplotlib: gui / selftest / render
main_qt.py           точка входа Qt (2 вкладки)
model/   геометрия, траектории+коридор, обнаружение, оптимизация, SimulationModel,
         area_start (зона старта → цель)
view/        matplotlib: сцена, слои, виджеты, блиттинг (логики нет)
controller/  события, анимация, связь model↔view (общая логика)
view_qt/        Qt: SimulationView + AreaStartView (вкладка 2)
controller_qt/  Qt: QtSimulationController + AreaStartController
```
Две версии интерфейса на общем `model/` и общей логике контроллера:
- **matplotlib** (`main.py`) — базовая, зависит только от `numpy`+`matplotlib`;
- **Qt** (`main_qt.py`, PyQt5+pyqtgraph) — 2 вкладки, плавная анимация, зум/пан.

Model автономен и тестируется без графики (`--mode selftest`).

## 4. Что сделано (по возможностям)

- Ядро: геометрия, генераторы маршрутов, метрики, **жадная субмодулярная**
  оптимизация (инкрементальный SAA); воспроизведена эталонная таблица требований.
- Два режима просмотра: итеративный (анимация накопления) и пакетный (итог сразу).
- Три режима оптимизации (распределение / пересечение / сбалансированный).
- **Редактируемые параметры в интерфейсе** (Enter — перезапуск, откат при ошибке).
- **Дуги по углу** с настраиваемым шагом веера; предельные дуги — пунктир.
- **Все N датчиков** задействуются всегда (вторичный критерий распределения).
- **Профили разброса**: обычный / смешанный / сложный.
- **Случайность**: `seed=None` — каждый прогон другой; `--seed` для повторяемости.
- **Коридор движения**: кандидаты датчиков только в зоне маршрутов; **масштаб
  карты по зоне маршрутов**, при «веере» — по полному коридору.
- **Слои (3 чекбокса)**: тепловая карта (+легенда), 10 вероятных маршрутов,
  веер по шагу угла. Комбинируются; путь полёта виден всегда.
- **Производительность**: плавная анимация через блиттинг.
- Гео-режим (широта/долгота → км), тёмная тема, авто-масштаб, сравнение режимов.
- **Qt-версия (PyQt5 + pyqtgraph)** — `main_qt.py`: аппаратно ускоренная анимация,
  зум/панорамирование мышью, ручной зум сохраняется во время прогона; те же слои
  и легенды (цветовая шкала плотности + легенда типов маршрутов).
- **Вкладка 2 «зона старта → цель»** — старт из ЗОНЫ (эллипс глубина×ширина),
  цель B кликом-направлением (длина |AB| из поля), постановка точек кликами,
  кнопка «Создать маршрут» (повторное нажатие сбрасывает старый маршрут);
  оптимизация учитывает разброс стартов и вероятностные линии.
- **Три модели движения** в обеих вкладках: **дуга / ломаная / манёвр**
  (в вкладке 1 также «петли»). Манёвр — гладкие дуги с ограничением радиуса
  разворота; ломаная — угловые отрезки; обе случайны и разные каждую итерацию.
- **Авто-настройка плагинов Qt** в `main_qt.py` (фикс ошибки Windows
  «platform plugin windows»).

## 5. Отвергнуто / не применять (с причинами)

- **PSO (рой частиц)** — на этом этапе не применяется (так задано постановкой).
- **Игровая постановка с противником** (double oracle, fictitious play,
  Stackelberg, путь наименьшей экспозиции) — отвергнута: маршруты случайны и НЕ
  подстраиваются под датчики, рационального противника нет ⇒ только вероятностная
  постановка (SAA), не минимакс.
- **Осреднение координат датчиков** — недопустимо: среднее двух хороших
  расположений может быть плохим. Усредняется **критерий**, не координаты.
- **Рост N с выборкой** («после 10→1, 50→2») — неверная модель: `N` фиксировано
  (заданный ресурс); с выборкой уточняется оценка, расположение стабилизируется.
- **Растягивание карты (неравный масштаб X/Y)** — отклонено: искажает зоны
  датчиков (круги→овалы) и расстояния. Оставлен равный масштаб + зум на зону.

## 6. Найденные ошибки и их разбор

| Симптом | Причина | Решение |
|---|---|---|
| Появлялись не все N датчиков | ранний останов жадного при насыщении на малой выборке | вторичный критерий распределения по плотности, всегда N |
| «Сложные» петли шли по прямой | амплитуда задавалась через `b`, длина > `L_max` → 300 отбраковок → откат в прямую | предельная амплитуда по длине (`max_serpentine_amplitude`) |
| Большие дуги «схлопывались» (θ>90°, стрела>c/2) | `make_arc` через стрелу прогиба строил минорную дугу | прямая параметризация центральным углом (верно для любого θ) |
| Тепловая карта не видна на тёмном фоне | палитра magma + низкая alpha | палитра turbo + гамма-подъём слабых + легенда |
| «Тофу» вместо значка паузы | глиф ⏸ (U+23F8) отсутствует в DejaVu Sans | подписи кнопок без юникод-значков |
| Детерминизм (каждый прогон одинаков) | фиксированный `seed` при reset | `seed=None` → системная энтропия |
| `ResizeEvent ... inaxes` в терминале | внешний баг matplotlib на **Python 3.14** | рекомендован Python 3.12; блит переинициализируется на ресайзе |
| Qt: пропали легенды к цветам | не были перенесены при переходе на pyqtgraph | `ColorBarItem` (плотность) + `LegendItem` (типы маршрутов) |
| Вкладка 2: точка B рисуется не там | `_sync_geometry` брал `model.p.A/B` (дефолт), а не кликнутые `model.A/B` | синхронизация по реальному маршруту модели |
| Манёвр «едет прямо» | генератор через «наведение на цель» схлопывался в прямую | боковое отклонение суммой гармоник с ограничением радиуса разворота |
| Windows: «Could not find Qt platform plugin windows» | пустой/перебитый путь к плагинам PyQt5 | `main_qt.py` сам выставляет `QT_QPA_PLATFORM_PLUGIN_PATH` |

## 8. История сессии (кратко)

1. **Старт.** Входные материалы: сводка постановки, требования, `uav_core.py`,
   `uav_demo.py`. Задача — мат. модель + приложение в MVC.
2. **Итерация 1.** Построены ядро и MVC, 2 режима просмотра, 3 режима
   оптимизации; воспроизведена эталонная таблица (distribution 75 / crossing 79 /
   balanced 80 %).
3. **Итерация 2.** Редактируемые параметры + перезапуск; авто-масштаб карты;
   дуги по углу с шагом веера; все N датчиков; тёмная тема; вероятные пути в обоих
   режимах; предельные дуги пунктиром; гео-режим. Разъяснён вопрос усреднения.
4. **Итерация 3.** Случайность (seed=None); профили разброса; масштаб по
   коридору; кандидаты только в коридоре; блиттинг; чекбоксы слоёв; примеры убраны.
5. **Итерация 4 (по фото).** 3 чекбокса (теплокарта/10 маршрутов/веер); видимость
   теплокарты + легенда; фикс «сложных» петель; убран значок паузы; ресайз-блит;
   компактнее UI; **зум на зону маршрутов**; **фикс геометрии больших дуг (θ>90°)**.
6. **Документация.** Этот журнал + Word с теорией и математикой; расширена
   методичка (общая теория оптимизации, раскрытие методов, раздел «обозначения и
   синтаксис формул»).
7. **Переход на Qt.** Параллельная версия на **PyQt5 + pyqtgraph** (`main_qt.py`,
   `view_qt/`, `controller_qt/`): плавная анимация, зум/панорамирование мышью,
   сохранение ручного зума во время прогона. Логика контроллера вынесена в общую
   (фабрика таймера + `process_pending`), `model/` переиспользован без изменений;
   matplotlib-версия сохранена как отправная точка.
8. **Qt: легенды + вкладка 2 + манёвр.** Вернул в Qt цветовую шкалу плотности и
   легенду слоёв. Добавил **вкладку 2 «зона старта → цель»** (`QTabWidget`):
   старт из ЗОНЫ (эллипс глубина×ширина вокруг A), цель B кликом-направлением,
   длина |AB| из поля; постановка точек кликами; оптимизация с учётом разброса
   стартов и вероятностных линий. Две модели движения: «дуги из старта» и
   **«ломаная (манёвр)»** — БПЛА самолётного типа со случайными поворотами при
   **ограничении радиуса разворота** (профиль «сложный» — максимально извилистый),
   длина ≤ L_max, идеальные условия. Новые `model/area_start.py`,
   `view_qt/area_view.py`, `controller_qt/area_controller.py` переиспользуют
   отрисовку, анимацию и жадную оптимизацию.
9. **Манёвр везде.** Манёвренная модель вынесена в общее ядро `maneuver_path`
   (`trajectories.py`) и добавлена 3-й моделью «ДВИЖЕНИЕ» в базовую модель —
   доступна во вкладке 1 Qt и в matplotlib-версии (старт из точки A, коридор —
   эллипс достижимости). Поправлена раскладка matplotlib-панели под 3 пункта.
10. **Манёвр-переработка + фиксы вкладки 2.** Манёвр через «наведение на цель»
    схлопывался в прямую — заменён на боковое отклонение суммой гармоник с
    ограничением радиуса разворота: «манёвр» = гладкая кривая (цепочка дуг),
    «ломаная» = угловые отрезки; обе рандомны и РАЗНЫ каждую итерацию (случайное
    число «волн» ±1, амплитуды, знаки). Вкладка 2 получила 3 режима (дуга/ломаная/
    манёвр). Исправлены баги вкладки 2: точка B рисовалась по `model.p` вместо
    кликнутых `model.A/B` (фикс `_sync_geometry`); повторное «Создать маршрут»
    теперь сбрасывает старый маршрут (программно и графически).
