## 1. Идея и назначение

БПЛА летит из точки **A** в точку **B** с ограниченным **запасом хода** `L_max`.
Точный маршрут заранее неизвестен — это случайная кривая из некоторого
распределения. Нужно расставить `N` датчиков радиусом `R` так, чтобы на типичном
маршруте обеспечить: (1) **кратность** — не менее `k` обнаружений; (2)
**равномерность** — засечки по всей длине пути, а не на одном участке.

Расположение определяется **в динамике**: на каждой итерации приходит новый
случайный маршрут, расположение пересчитывается по всей накопленной выборке и
стабилизируется с ростом выборки.

---

## 2. Математическая модель (компактно)

- **Эллипс достижимости** `E = { P : |PA|+|PB| ≤ L_max }`, полуоси
  `a = L_max/2`, `c = |AB|/2`, `b = √(a²−c²)`. Любой путь длиной ≤ `L_max`
  целиком внутри эллипса.
- **Дуги (этап 1)** заданы **углом отклонения** `θ` (касательно-хордовый угол в A):
  длина `L(θ)=c·θ/sinθ`, предел `θ_max` из `L(θ)=L_max`.
- **Петли (этап 2)** — синусоида с закреплёнными концами; предельная амплитуда
  по длине (аналог `θ_max`).
- **Обнаружение** — однократный вход в зону датчика; кратность `n(S,γ)` = число
  различных засёкших датчиков.
- **Полезность** на маршруте: `φ(S,γ) = α₁·min(n,k)/k + α₂·m/L_seg`, где `m` —
  число покрытых сегментов из `L_seg`.
- **Критерий** — матожидание `F(S)=𝔼[φ] → max` при `|S|≤N`, заменяемое
  эмпирическим средним по выборке (**SAA**) `F_t(S)=(1/t)Σφ(S,γᵢ)`.
- `F_t` монотонна и субмодулярна ⇒ **жадный алгоритм** даёт гарантию
  `(1−1/e)≈0,632` от оптимума.

## 3. Реализация (MVC)

```
config.py            параметры, режимы, профили, тема
main.py              точка входа: gui / selftest / render
model/   геометрия, траектории+коридор, обнаружение, оптимизация, SimulationModel
view/    matplotlib: сцена, слои, виджеты, блиттинг (логики нет)
controller/  события, анимация, связь model↔view
```
Зависимости: только `numpy` + `matplotlib`. Model автономен (`--mode selftest`).

---

## 4. Что сделано (по возможностям)

- Ядро: геометрия, генераторы маршрутов, метрики, **жадная субмодулярная**
  оптимизация (инкрементальный SAA); воспроизведена эталонная таблица требований.
- Два режима просмотра: итеративный (анимация накопления) и пакетный (итог сразу).
- Три режима оптимизации (распределение / пересечение / сбалансированный).
- **Редактируемые параметры в интерфейсе** (Enter — перезапуск, откат при ошибке).
- **Дуги по углу** с настраиваемым шагом веера; предельные дуги — пунктир.
- **Все N датчиков** задействуются всегда (вторичный критерий распределения).
- **Профили разброса**: обычный / смешанный / сложный.
- **Случайность**: `seed=None` — каждый прогон другой; `--seed` для повторяемости.
- **Коридор движения**: кандидаты датчиков только в зоне маршрутов; **масштаб
  карты по зоне маршрутов**, при «веере» — по полному коридору.
- **Слои (3 чекбокса)**: тепловая карта (+легенда), 10 вероятных маршрутов,
  веер по шагу угла. Комбинируются; путь полёта виден всегда.
- **Производительность**: плавная анимация через блиттинг.
- Гео-режим (широта/долгота → км), тёмная тема, авто-масштаб, сравнение режимов.

## 5. Отвергнуто / не применять (с причинами)

- **PSO (рой частиц)** — на этом этапе не применяется (так задано постановкой).
- **Игровая постановка с противником** (double oracle, fictitious play,
  Stackelberg, путь наименьшей экспозиции) — отвергнута: маршруты случайны и НЕ
  подстраиваются под датчики, рационального противника нет ⇒ только вероятностная
  постановка (SAA), не минимакс.
- **Осреднение координат датчиков** — недопустимо: среднее двух хороших
  расположений может быть плохим. Усредняется **критерий**, не координаты.
- **Рост N с выборкой** («после 10→1, 50→2») — неверная модель: `N` фиксировано
  (заданный ресурс); с выборкой уточняется оценка, расположение стабилизируется.
- **Растягивание карты (неравный масштаб X/Y)** — отклонено: искажает зоны
  датчиков (круги→овалы) и расстояния. Оставлен равный масштаб + зум на зону.

## 6. Найденные ошибки и их разбор

| Симптом | Причина | Решение |
|---|---|---|
| Появлялись не все N датчиков | ранний останов жадного при насыщении на малой выборке | вторичный критерий распределения по плотности, всегда N |
| «Сложные» петли шли по прямой | амплитуда задавалась через `b`, длина > `L_max` → 300 отбраковок → откат в прямую | предельная амплитуда по длине (`max_serpentine_amplitude`) |
| Большие дуги «схлопывались» (θ>90°, стрела>c/2) | `make_arc` через стрелу прогиба строил минорную дугу | прямая параметризация центральным углом (верно для любого θ) |
| Тепловая карта не видна на тёмном фоне | палитра magma + низкая alpha | палитра turbo + гамма-подъём слабых + легенда |
| «Тофу» вместо значка паузы | глиф ⏸ (U+23F8) отсутствует в DejaVu Sans | подписи кнопок без юникод-значков |
| Детерминизм (каждый прогон одинаков) | фиксированный `seed` при reset | `seed=None` → системная энтропия |
| `ResizeEvent ... inaxes` в терминале | внешний баг matplotlib на **Python 3.14** | рекомендован Python 3.12; блит переинициализируется на ресайзе |

## 7. Открытые вопросы / на будущее

- **Тонкий длинный коридор** (`L_max` чуть больше `|AB|`): при равном масштабе
  остаются вертикальные поля — геометрическое ограничение (без искажения не убрать).
- **Переход на PyQt + pyqtgraph** (или web): плавность, удобный зум/пан, гибкая
  компоновка; matplotlib для этого менее удобен.
- **Этап 2**: усложнить генератор петель (коррелированное случайное блуждание).
- **Производительность**: при огромном коридоре + мелкой сетке много кандидатов —
  возможен ленивый жадный (CELF), пересчёт с шагом.
