# Методичка 2: реальная карта (вкладка 2)

Дополнение к основной `МЕТОДИЧКА.md`. Описывает подсистему географической карты:
гео-привязку, тайлы, кэш, слои, оффлайн-схему, логику кликов A→B и интеграцию в
MVC. Реализация — `view_qt/geomap.py` (математика/тайлы/кэш) и `view_qt/area_view.py`
(отрисовка подложки), управление — `controller_qt/area_controller.py`.

---

## 1. Подход и почему так

Карта нужна только на **вкладке 2** («зона старта → цель»), где маршрут ставится
кликами по местности. Рассматривались (см. аналитический отчёт по вариантам):
* собственный виджет на `QGraphicsScene` с тайлами z/x/y (макс. контроль);
* `pyqtlet2`/Leaflet в `QWebEngineView` (тяжёлый Chromium, асинхронный мост);
* `QtLocation` (QML, капризная конфигурация).

Выбран **компромисс без переписывания**: подложка-карта встроена **фоновым слоём
в существующий `pyqtgraph`-вид** (тот же приём, что у отчётного «способа A», но без
отдельного виджета). Все наложения (эллипс, маршруты, датчики, клики) и анимация
остаются в той же системе координат и НЕ переписываются — риск «сломать рабочее»
минимален, а реактивность (клик → пересчёт → отрисовка) сохраняется.

Координаты модели — локальные **километры** (физика: L_max, R, R_min — в км).
Карта лишь подкладывается под них; перевод км↔широта/долгота — равнопромежуточный
вокруг центра Курска (для области ~150 км погрешность мала).

## 2. Гео-привязка (км ↔ широта/долгота)

Начало локального км-фрейма привязано к **Курску** `KURSK = (lon0=36.1936,
lat0=51.7306)`: км (0,0) = центр Курска.

```
x_км = (lon − lon0)·111.320·cos(lat0)        lon = lon0 + x_км / (111.320·cos(lat0))
y_км = (lat − lat0)·110.574                   lat = lat0 + y_км / 110.574
```

* `111.320·cos(lat0)` — км на градус долготы на широте Курска (≈68.8 км/°);
* `110.574` — км на градус широты;
* функции `lonlat_to_km` / `km_to_lonlat` (`geomap.py`).

## 3. Тайлы: slippy map (Web Mercator, EPSG:3857)

Растровые карты раздаются квадратами 256×256 по схеме `{z}/{x}/{y}`. Перевод
координат ↔ номер тайла (`deg2num` / `num2deg`):

```
n = 2^z
xt = (lon + 180)/360 · n
yt = (1 − asinh(tan(lat))/π)/2 · n            (asinh(tan φ) = ln(tan φ + sec φ))

lon = xt/n·360 − 180
lat = atan(sinh(π·(1 − 2·yt/n)))
```

* `z` — уровень зума (детализация удваивается с каждым уровнем; тайлов вчетверо больше);
* целая часть `xt, yt` — номер тайла; дробная — позиция внутри тайла.

**XYZ vs TMS.** Онлайн-источники (OSM/Esri) используют XYZ (ось Y растёт на юг).
Часть экспортов SAS.Planet — **TMS** (ось Y инвертирована): `y_TMS = 2^z−1−y_XYZ`.
Переключается per-слой переменной `UAV_TMS_LAYERS=ИмяСлоя1,ИмяСлоя2` (применяет
TMS только к перечисленным локальным слоям, не трогая онлайн-источники, которые
всегда XYZ), либо глобально `UAV_TILE_TMS=1`.

**Свои (локальные) слои без скачивания.** Любая папка `<кэш>/<имя>/{z}/{x}/{y}.<ext>`,
не совпадающая с именем штатного слоя, подхватывается автоматически
(`discover_local_layers`) и появляется в списке «Карта» как «<имя> (локальный
кэш)» — сеть для такого слоя не запрашивается, только чтение с диска. Расширение
файла не обязано совпадать с реальным форматом — при чтении перебираются
`.png/.jpg/.jpeg/.webp`, а формат определяется по содержимому (`find_cached_tile`).
Подробный разбор конкретного стороннего кэша — в `МЕТОДИЧКА_КАРТА_ВОПРОСЫ.md`
(локальный справочный файл, не входит в архив) и диагностике
`tools/inspect_tile_cache.py`.

## 4. Слои карты

| Ключ | Подпись | Источник | Формат |
|---|---|---|---|
| `scheme` | схема (оффлайн) | рисуется в коде (без сети) | вектор |
| `osm` | OSM (улицы) | tile.openstreetmap.org | PNG |
| `topo` | топо | opentopomap.org | PNG |
| `satellite` | спутник | ArcGIS World Imagery (`{z}/{y}/{x}`) | JPEG |
| `dark` | тёмная | CartoDB dark_all | PNG |

Слой выбирается выпадающим списком «Карта» (`LAYER_LABELS`). По умолчанию —
`scheme` (оффлайн, работает всегда). Декодирование тайлов — Pillow (PNG **и**
JPEG для спутника), запасной путь — matplotlib (PNG).

## 5. Кэш и оффлайн-режим

**Гибрид cache-first → сеть.** `fetch_tile_bytes` сначала ищет тайл в дисковом
кэше; если нет и разрешён интернет — скачивает (валидный User-Agent) и **сохраняет
в кэш**. После этого тайл доступен оффлайн.

**Где кэш.** `geomap.cache_root()`:
1. переменная окружения `UAV_TILE_CACHE` (если задана);
2. иначе `<проект>/tile_cache/`.
Раскладка: `<cache>/<layer>/{z}/{x}/{y}.png`. Свою папку SAS можно положить как
`<cache>/satellite/{z}/{x}/{y}.*` (учтите XYZ/TMS).

**Ограничение объёма — 10 уровней зума.** `ZOOM_MIN..ZOOM_MAX` (по умолчанию
6..15 = 10 уровней; env `UAV_ZOOM_MIN/MAX`). Самый детальный уровень = `ZOOM_MAX`.
Это держит кэш в разумных пределах: для области масштаба Курской при z≈6..15 —
единицы ГБ (ваши ~4 ГБ соответствуют примерно этому диапазону). Высокие зумы
(z17–19) на большой площади дают десятки–сотни ГБ — поэтому и ограничиваемся.

**Предзагрузка (оффлайн).** Скрипт `tools/download_tiles.py` один раз (с
интернетом) скачивает регион+слой в кэш:
```
python tools/download_tiles.py --layer osm
python tools/download_tiles.py --layer satellite --zmax 15 --zmin 9
```
После этого приложение работает без интернета.

**Правовое (важно для боевого применения).** OSM Tile Usage Policy **запрещает**
массовую выкачку и оффлайн-использование своих серверов; Google запрещает экспорт/
кэш тайлов и относит управление БПЛА к «High Risk». Для серьёзного оффлайна —
поднимайте свой тайл-сервер из данных Geofabrik или используйте источники с явно
разрешённым оффлайном/собственные ортофото. Esri World Imagery — в рамках условий
Esri. В коде слои даны как технический механизм; ответственность за источник — на
пользователе.

## 6. Сборка подложки под текущее окно

`build_raster_basemap(kx0,kx1,ky0,ky1, layer, …)`:
1. км-окно → широты/долготы (через привязку Курска);
2. выбор зума `_pick_zoom` (≈6 тайлов по ширине, в пределах 10 уровней);
3. диапазон тайлов; ограничение `max_tiles` (если больше — зум на ступень ниже);
4. чтение каждого тайла (кэш/сеть), склейка в единое изображение;
5. геокрая сетки тайлов → км-экстент; изображение переворачивается так, чтобы
   строка 0 = юг (для оси Y вверх). Возврат `(rgba, (ex0,ex1,ey0,ey1))` или `None`.

В виде растр кладётся `pg.ImageItem` (z=−20, uint8 RGBA) и позиционируется
`setRect` по км-экстенту. Если `None` (оффлайн, кэш пуст) — показывается схема.

## 7. Оффлайн-схема (всегда работает)

Слой `scheme` рисуется кодом без сети и файлов (`area_view._draw_scheme`):
* **сетка** широт/долгот (`graticule_km`, шаг 0.5°) — линии с координатами;
* **города** Курской области (`KURSK_CITIES` → `city_points_km`): Курск (0,0),
  Железногорск, Курчатов, Льгов, Щигры, Обоянь, Рыльск, Суджа, Фатеж, Дмитриев,
  Горшечное, Тим — точки и подписи (координаты приблизительные, для ориентира);
* **рамка области** (`OBLAST_BBOX` → `oblast_outline_km`) — приблизительный охват.

Это гарантирует географический ориентир даже без интернета и без скачанных тайлов.

## 8. Логика построения маршрута кликами

1. «Создать маршрут» → режим постановки;
2. **1-й клик — точка A** (центр зоны старта; эллипс строится по полям «глубина/
   ширина зоны»);
3. **2-й клик — точка B** (цель). **Расстояние |AB| считается автоматически** как
   евклидово в км между кликами (`on_route_ready`); поле «|AB|» обновляется, при
   необходимости поднимается `L_max` (> |AB|).
4. По |AB| и зоне строится область достижимости (огибающая, см. осн. методичку),
   маршруты БПЛА используют это же расстояние.

Карта центрируется на Курске; зум/панорама — мышью (подложка догружается под новое
окно с дебаунсом).

## 10. Интеграция в MVC и отказоустойчивость

* Модель/физика — в км, без изменений; карта — только слой представления.
* `area_view`: `basemap` (растр) + `graticule/oblast/cities` (схема), обновление
  `_refresh_basemap` по `sigRangeChanged` (дебаунс 280 мс) и при показе/смене слоя.
* Любая ошибка карты (нет сети, битый тайл) → откат на схему; приложение
  продолжает работать как раньше. Вкладка 1 не затронута.
