# Структура проекта: классы, методы и функции

Документ описывает структуру кода и **основные методы и функции** в архитектуре
**MVC** (Model–View–Controller). Каждый элемент дан в форме «`сигнатура` —
назначение». Теория и обоснования — в `МЕТОДИЧКА.md`, обзор и история — в
`ЖУРНАЛ_ПРОЕКТА.md`.

Две версии интерфейса на **общем** `model/` и **общей** логике контроллера:
- **matplotlib** (`main.py`) — базовая; зависит только от `numpy`+`matplotlib`;
- **Qt** (`main_qt.py`, PyQt5+pyqtgraph) — 2 вкладки, плавная анимация, зум/пан.

Qt-слой переопределяет лишь таймер анимации и слой отрисовки, реализуя тот же
контракт методов View; общая логика расширена двумя точками (`_make_timer`,
`process_pending`, `get_param_specs`), не влияющими на поведение matplotlib.

## Дерево

```
uav_sensor_mvc/
├── config.py            параметры (Params), режимы, профили, метки, тема
├── main.py              точка входа matplotlib: gui / selftest / render
├── main_qt.py           точка входа Qt: 2 вкладки (+ авто-путь к плагинам Qt)
├── model/               MODEL — вычислительное ядро (без графики)
│   ├── geometry.py          эллипс достижимости, гео-проекция
│   ├── trajectories.py      генераторы маршрутов (дуга/петли/манёвр/ломаная),
│   │                        коридор, вероятные слои
│   ├── detection.py         модель обнаружения и эталонные метрики
│   ├── optimization.py      сетка кандидатов, структура покрытия, жадный выбор
│   ├── simulation.py        SimulationModel — маршрут A→B (вкладка 1)
│   └── area_start.py        AreaStartModel — зона старта → цель (вкладка 2)
├── view/                VIEW (matplotlib) — сцена, слои, виджеты, блиттинг
│   └── view.py
├── view_qt/             VIEW (PyQt5 + pyqtgraph)
│   ├── view_qt.py           SimulationView — карта A→B (вкладка 1)
│   └── area_view.py         AreaStartView — зона старта → цель (вкладка 2)
├── controller/          CONTROLLER — события и анимация (общая логика)
│   └── controller.py
├── controller_qt/       CONTROLLER (Qt) — QTimer поверх общей логики
│   ├── controller_qt.py     QtSimulationController
│   └── area_controller.py   AreaStartController (поток создания маршрута)
└── docs/                Теория_и_математика.docx + генератор
```

Поток данных: `Controller` обрабатывает события виджетов `View`, вызывает методы
`Model` (расчёт) и передаёт результат обратно во `View` (отрисовка). `Model` от
средств отображения не зависит и тестируется автономно (`main.py --mode selftest`).

## config.py — конфигурация

- `Params` (dataclass) — входные параметры модели; поля: `ab_distance`, `L_max`,
  `N`, `R`, `k`, `L_seg`, `angle_step_deg`, `corridor_depth`, `corridor_width`
  (зона старта, вкладка 2), `mode`, `traj_model`, `motion_profile`, `T`,
  `grid_step`, `sigma_frac`, `n_points`, `seed`, гео-поля (`geo`, `A_geo`, `B_geo`).
  - `A` / `B` (свойства) — координаты точек (A в начале координат, B на оси X);
  - `validate()` — проверка допустимости (например, `L_max > |AB|`); бросает
    `ValueError`.
- `MODES` — веса режимов оптимизации `(α₁, α₂)`; `MODE_LABELS` — их подписи.
- `TRAJ_LABELS` — движения вкладки 1 (`arc` / `serpentine` / `maneuver`).
- `AREA_TRAJ_LABELS` — движения вкладки 2 (`area_arc` / `polyline` / `maneuver`).
- `MOTION_PROFILES`, `MOTION_LABELS` — профили разброса (`normal`/`mixed`/`complex`).
- `SPREAD_EPS` — вес вторичного критерия распределения.
- `THEME` — цветовая палитра тёмной темы.

## main.py — точка входа

- `build_params(args) -> Params` — собрать `Params` из аргументов CLI (включая
  гео-перевод); вызывает `validate()`.
- `run_gui(params, speed)` — собрать `Model`/`View`/`Controller` и запустить окно.
- `run_selftest(params)` — автономный прогон ядра без графики (печать динамики
  SAA, итогового расположения и сравнения режимов).
- `run_render(params, out_dir, speed, n_iter)` — headless-рендер демонстрации
  (PNG по режимам + GIF) через Agg.
- `main()` — разбор аргументов и выбор режима запуска.

## main_qt.py — точка входа Qt

- `_ensure_qt_plugin_path()` — выставить путь к плагинам PyQt5 (фикс Windows
  «platform plugin windows»).
- `main()` — разбор аргументов, сборка двух вкладок в `QTabWidget`:
  вкладка 1 (`SimulationModel`+`SimulationView`+`QtSimulationController`) и
  вкладка 2 (`AreaStartModel`+`AreaStartView`+`AreaStartController`).

## model/geometry.py — геометрия достижимости

- `ellipse_geometry(A, B, L_max) -> dict` — параметры эллипса достижимости
  (центр, полуоси `a, b`, фокальное `c`, угол).
- `point_in_ellipse(P, A, B, L_max) -> bool` — проверка одной точки.
- `points_in_ellipse(P, A, B, L_max) -> ndarray[bool]` — векторизованная проверка
  массива точек `(M, 2)`.
- `auto_axes_limits(geom, margin=0.10)` — границы осей под эллипс (равный масштаб).
- `geo_to_local_km(A_geo, B_geo)` — перевод широты/долготы в локальные километры.

## model/trajectories.py — маршруты, коридор, вероятные слои

**Дуги по углу (этап 1):**
- `make_arc(A, B, sagitta, n_points=140)` — дуга по стреле прогиба.
- `make_arc_by_angle(A, B, theta_deg, n_points=140)` — дуга по углу отклонения θ
  (прямая параметризация центральным углом; корректна для любого θ).
- `arc_length_from_angle(c_len, theta_rad)` — длина дуги по углу.
- `max_deflection_angle(A, B, L_max)` — предельный угол `θ_max` (бинарный поиск).
- `sample_arc_trajectory(A, B, L_max, rng, …, profile)` — случайная дуга по
  профилю разброса.
- `arc_fan(A, B, L_max, angle_step_deg, …)` — веер дуг по шагу угла (предельные
  помечены).
- `polyline_length(traj)` — длина ломаной.

**Коридор движения:**
- `corridor_outline(A, B, L_max, traj_model, …)` — границы коридора (верх, низ);
  для `arc` — предельные дуги, `serpentine` — огибающая, `maneuver` — половины
  эллипса достижимости.
- `corridor_polygon(…)` — замкнутый контур коридора.
- `corridor_filter(pts, A, B, L_max, traj_model, …)` — маска точек внутри коридора.
- `corridor_bbox(…)` — габариты коридора `(x0, x1, y0, y1)`.
- `ellipse_b(A, B, L_max)` — малая полуось; `_reach_ellipse_halves(…)` — половины
  эллипса достижимости (коридор манёвра).

**Петли (этап 2):**
- `make_serpentine(A, B, amplitude, n_lobes, phase, …)` — синусоида с концами A,B.
- `max_serpentine_amplitude(ab_distance, L_max, n_lobes, …)` — предельная
  амплитуда по запасу хода.
- `sample_serpentine_trajectory(A, B, L_max, rng, …, profile)` — случайная петля.

**Манёвр и ломаная (БПЛА самолётного типа):**
- `_maneuver_lateral(D, rng, profile, rmin_frac)` — случайное боковое отклонение
  `Σ aⱼ·sin(jπt)`; амплитуды ограничены радиусом разворота; число «волн» ±1
  (неопределённость каждую итерацию).
- `maneuver_path(S0, B, L_max, rng, profile, n_points, rmin_frac=0.11)` — **гладкая**
  кривая (цепочка дуг) S0→B, длина ≤ L_max.
- `polyline_path(…)` — **ломаная** S0→B (прямые отрезки через вершины).
- `_fit_to_budget(…)`, `_resample_polyline(…)` — укладка в L_max и пересэмплинг.
- `sample_maneuver_trajectory(…)` / `sample_polyline_trajectory(…)` — сэмплеры A→B.

**Вероятные слои (квантили профиля / семплы, данные не требуются):**
- `frequent_arcs(…)` / `frequent_serpentines(…)` — n вероятных дуг / петель.
- `frequent_maneuvers(…, kind="maneuver"|"polyline")` — n манёвров / ломаных.
- `arc_fan(…)` / `serpentine_fan(…)` / `maneuver_fan(…, kind=…)` — вееры.
- `signed_max_lateral(traj, A, B)` — знаковое макс. боковое отклонение.
- `SAMPLERS` — реестр генераторов `{"arc", "serpentine", "maneuver", "polyline"}`
  (единая сигнатура, взаимозаменяемы).

## model/detection.py — обнаружение и метрики (эталонные)

- `n_detections(traj, sensors, R) -> int` — кратность (число различных засёкших
  датчиков).
- `continuous_coverage(traj, sensors, R) -> float` — доля длины пути под
  наблюдением `[0..1]`.
- `segment_coverage(traj, sensors, R, L_segments) -> float` — доля покрытых
  сегментов `m/L_seg` (равномерность).
- `utility(traj, sensors, R, k, L_segments, weights) -> float` — полезность
  `φ(S, γ)` на одном маршруте.
- `avg_utility(trajectories, sensors, R, k, L_segments, weights)` — эмпирическое
  среднее `F_t(S)` по выборке.

## model/optimization.py — дискретизация и жадная оптимизация

- `candidate_grid(A, B, L_max, step, corridor=True, traj_model="arc")` — сетка
  кандидатных позиций, ограниченная коридором движения.
- `CoverageCache` — **структура покрытия** (инкрементальная, по выборке):
  - `__init__(candidates, R, L_seg, k)`;
  - `add_trajectory(traj)` — добавить маршрут (засечки `hit`, маски сегментов
    `segmask`, доли покрытия `covfrac`);
  - `greedy(N, weights) -> ndarray` — жадный субмодулярный выбор **всех N**
    позиций (основной критерий φ + вторичный критерий распределения,
    лексикографически);
  - `n_traj` (свойство) — размер накопленной выборки.
- `greedy_placement(trajectories, candidates, N, R, k, L_segments, weights)` —
  размещение по списку маршрутов (строит `CoverageCache` внутри).
- `_popcount(a)` — векторизованный подсчёт бит для масок сегментов.

## model/simulation.py — главный класс модели (вкладка 1: маршрут A→B)

`SimulationModel(params: Params)` — держит состояние (параметры, ГСЧ, выборку,
структуру покрытия, расположение) и весь расчёт. Старт из точки A; движение —
`arc` / `serpentine` / `maneuver` (через `SAMPLERS[p.traj_model]`).

**Сброс и настройка:**
- `reset(seed=None)` — новая выборка и производные структуры (кэш геометрии);
- `set_mode(mode)` / `set_traj_model(traj_model)` / `set_profile(profile)` —
  переключатели;
- `weights` (свойство) — веса текущего режима.

**Геометрия отображения (кэш):**
- `corridor_bbox()` / `corridor_outline()` — габариты и границы коридора;
- `view_bbox()` — габариты зоны типичных маршрутов (зум карты).

**Динамика (инкрементальный SAA):**
- `sample_trajectory()` — породить случайный маршрут;
- `recompute_placement()` — пересчитать расположение (`cache.greedy`);
- `add_and_replace(traj, feature)` — добавить маршрут и пересчитать;
- `step()` — одна итерация (`sample` + `add_and_replace`);
- `run_batch(T=None, mode=None)` — полный расчёт по всей выборке.

**Слои и показатели:**
- `frequent_paths(n=10)` — вероятные маршруты по модели движения
  (дуги / петли / манёвры);
- `fan_paths()` — веер возможных маршрутов (дуги по шагу угла / петли по шагу
  амплитуды / семплы манёвра);
- `density_field(nbins=160)` — поле плотности для тепловой карты;
- `evaluate(sensors=None, trajectories=None) -> dict` — итоговые показатели
  (ср. пересечений, покрытие, вне зоны, доля ≥ k, число датчиков);
- `compare_modes() -> dict` — показатели трёх режимов на единой выборке;
- `live_metrics(partial_traj)` — онлайн-показатели по части пути (для HUD).

## model/area_start.py — модель вкладки 2 (зона старта → цель)

`AreaStartModel(params)` — старт из ЗОНЫ (эллипс вокруг A), цель B; зеркалит
контракт `SimulationModel` (`reset/step/run_batch/recompute_placement/evaluate/
frequent_paths/fan_paths/density_field/corridor_*/view_bbox/live_metrics/compare_modes`),
переиспользуя `CoverageCache` и `detection`.
- `set_route(A, B)` — зафиксировать кликнутый маршрут и сбросить выборку;
- `set_movement(movement)` — `area_arc` / `polyline` / `maneuver`;
- `start_zone()` — контур зоны старта; `_reachable_mask(P)` / `_build_candidates()`
  — кандидаты, достижимые из зоны (`dist(P,зона)+|PB| ≤ L_max`);
- генераторы: `sample_area_arc(…)` (дуга из старта), `sample_polyline(…)`,
  `sample_maneuver(…)` (через общее ядро `maneuver_path`/`polyline_path`);
- `sample_start_point(…)`, `start_zone_outline(…)`, `reach_ellipse_outline(…)`.

## view/view.py — визуализация (matplotlib)

- `PARAM_SPECS` — список редактируемых параметров `(имя, подпись, тип)`.

**Помощники отрисовки сцены (чистые функции):**
- `fit_axes(ax, bbox, margin=1.14)` — подгонка масштаба под коридор (равные оси).
- `draw_static(ax, A, B, outline, bbox)` — контур коридора, точки A/B, оси.
- `draw_density(ax, H, extent)` — тепловая карта плотности (гамма-подъём, turbo).
- `draw_probable(ax, paths, show_labels=True)` — линии маршрутов (вес → цвет/
  толщина; предельные — пунктир).
- `draw_sensors(ax, sensors, R)` — датчики (зоны радиуса R, центры, номера).

**`SimulationView`** — окно и контракт для контроллера:
- `__init__(A, B, outline, bbox, params, speed, speed_max)` — построение сцены,
  панели (поля, переключатели, чекбоксы, слайдер, кнопки, показатели).
- Контракт (вызывается контроллером): `set_callbacks(**cbs)`,
  `update_geometry(A, B, outline, bbox)`, `draw_clear(…)`,
  `draw_static_frame(sensors, R, freq, fan, density, toggles, title)`,
  `setup_flight(…)`, `update_flight(j, hud)`, `set_metrics(lines)`,
  `flash_title(text, color)`, `set_running_label(running)`, `get_toggles()`,
  `get_param_values()`, `set_param_values(params)`, `get_param_specs()`,
  `process_pending()`, `show()`.
- Анимация — через **блиттинг**: `setup_flight` рисует фон раз на итерацию,
  `update_flight` обновляет только БПЛА, пройденный путь и HUD.

## controller/controller.py — управление

`SimulationController(model, view)` — связывает модель и представление, ведёт
анимацию (таймер) и панель показателей.

**Обработчики событий:**
- `on_apply()` — считать поля, проверить, перезапустить расчёт (откат при ошибке);
- `on_mode(key)` / `on_traj(key)` / `on_profile(key)` — переключатели;
- `on_speed(val)` — скорость анимации;
- `on_toggle()` — переключение слоёв (3 чекбокса);
- `on_start_pause()` / `on_step()` / `on_reset()` / `on_batch()` — режимы просмотра.

**Анимация и вспомогательное:**
- `_make_timer()` — фабрика таймера анимации (**переопределяется** в Qt-контроллере
  под `QTimer`; базово — таймер холста matplotlib);
- `_tick()` — кадр анимации итеративного режима (через таймер);
- `_restart(title)` / `_pause()` — перезапуск и остановка;
- `_sync_geometry()` / `_current_bbox()` — синхронизация геометрии и масштаба
  (при «веере» — полный коридор, иначе зум на зону маршрутов);
- `_redraw_idle_or_last(title)` — перерисовка простоя/последнего кадра;
- `_layers(t)` / `_toggles()` — сбор слоёв по чекбоксам;
- `_update_metrics_idle()` / `_update_metrics_full(extra_compare)` — панель
  показателей;
- `_hud_text(j)` / `_iter_title(j)` — подписи кадра;
- `run()` — показать окно (запуск приложения).

`on_apply()` берёт список полей через `view.get_param_specs()`, а принудительную
отрисовку — через `view.process_pending()` (общие методы обеих версий View).

## view_qt/ — визуализация Qt (PyQt5 + pyqtgraph)

**`view_qt/view_qt.py` — `SimulationView(QWidget)`** (вкладка 1). Реализует **тот
же контракт**, что matplotlib-`SimulationView` (`update_geometry`, `draw_clear`,
`draw_static_frame`, `setup_flight`, `update_flight`, `set_metrics`, `flash_title`,
`set_running_label`, `get_toggles`, `get_param_values/specs`, `process_pending`).
- карта — `pg.PlotWidget` (равный масштаб, зум/пан мышью); масштаб обновляется
  только при смене коридора (`_last_bbox`) — ручной зум сохраняется;
- слои: `ImageItem` (плотность) + `ColorBarItem` (легенда), `PlotDataItem`
  (маршруты), эллипсы-зоны датчиков; `LegendItem` (типы маршрутов);
- анимация без блиттинга — pyqtgraph обновляет только подвижные элементы.

**`view_qt/area_view.py` — `AreaStartView(SimulationView)`** (вкладка 2): добавляет
поля глубины/ширины зоны, выбор движения (дуга/ломаная/манёвр), кнопку «Создать
маршрут» и постановку точек кликами (`_on_scene_click`, `begin_create`,
`prompt_create`); рисует зону старта и ось A→B.

## controller_qt/ — управление Qt

**`controller_qt/controller_qt.py` — `QtSimulationController(SimulationController)`**:
переопределяет `_make_timer()` (адаптер `QTimer` с `add_callback/start/stop`).

**`controller_qt/area_controller.py` — `AreaStartController(QtSimulationController)`**:
- `on_create()` — сброс старого маршрута (модель+графика) и старт постановки точек;
- `on_route_ready(A, dir_pt)` — вычислить B по направлению и `|AB|`, `set_route`;
- `on_movement(key)` — смена модели движения;
- `_sync_geometry()` — синхронизация по **кликнутым** `model.A/B` (не `model.p`);
- гейтинг «Пуск/Шаг/Пакетно» и метрики зоны до создания маршрута.
