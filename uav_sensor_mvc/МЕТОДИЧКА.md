# Методичка по программе «Размещение датчиков обнаружения БПЛА»

Документ объясняет, **как решается задача** (теория) и **из чего состоит код**
(основные элементы). Изложение построено по принципу «общее → частное»: сначала —
оптимизационная задача как класс (понятие, виды, пути решения, требования к
критериям и показателям), затем — постановка и решение применительно к размещению
датчиков. Каждый специальный термин при первом употреблении сопровождается
расшифровкой и пояснением обиходным языком; врезки `[Справочно]` и `Пример`
поясняют существо простыми словами.

Программа реализована на языке Python (библиотеки `numpy` и `matplotlib`) в
архитектуре **MVC** (Model–View–Controller — модель–представление–управление) и
моделирует оптимальное размещение датчиков для обнаружения беспилотного
летательного аппарата (БПЛА), летящего из точки **A** в точку **B**.

## Часть 1. Оптимизационная задача: общие положения

### 1.1. Понятие оптимизационной задачи

**Оптимизационная задача** — задача выбора из множества допустимых вариантов
такого, который доставляет наилучшее (наибольшее либо наименьшее) значение
заданной числовой меры качества. По существу речь идёт о поиске «самого лучшего»
решения при заведомо ограниченных возможностях.

Любая оптимизационная задача задаётся четырьмя элементами:

- **переменные решения** (decision variables) — управляемые величины, значения
  которых подбираются в ходе решения; то, чем распоряжается решающий;
- **целевая функция** (objective function) — функция, сопоставляющая каждому
  варианту число (меру качества); проще говоря, «оценка» варианта, которую
  требуется довести до максимума либо минимума;
- **ограничения** (constraints) — условия, отсекающие недопустимые варианты
  (лимит ресурса, границы области, технические требования);
- **допустимое множество** (feasible set) — совокупность вариантов,
  удовлетворяющих всем ограничениям; иными словами, всё, что в принципе разрешено.

Формально задача записывается как `F(x) → max` при `x ∈ D`, где `x` — переменные
решения, `F` — целевая функция, `D` — допустимое множество. Искомый результат —
**оптимум**: допустимый вариант с наилучшим значением целевой функции. Различают
**глобальный оптимум** (наилучший во всём допустимом множестве) и **локальный
оптимум** (наилучший лишь в своей окрестности); по существу локальный оптимум —
«лучший среди соседних», который может уступать глобальному.

> **[Справочно]** Бытовой пример. Требуется собрать рюкзак ограниченной
> грузоподъёмности так, чтобы суммарная ценность вещей была наибольшей. Переменные
> решения — какие вещи взять; целевая функция — суммарная ценность; ограничение —
> предельный вес; допустимое множество — все наборы, укладывающиеся в вес; оптимум
> — самый ценный из таких наборов.

### 1.2. Классы оптимизационных задач

Постановки различаются по нескольким признакам, и от класса задачи зависит выбор
метода решения:

- по типу переменных — **непрерывные** (величина меняется плавно, например
  координата) и **дискретные/комбинаторные** (выбор из конечного набора
  вариантов);
- по структуре целевой функции и ограничений — **линейные** и **нелинейные**;
- по определённости исходных данных — **детерминированные** (все данные известны
  точно) и **стохастические** (часть данных случайна и описывается распределением
  вероятностей);
- по числу критериев — **однокритериальные** (одна мера качества) и
  **многокритериальные** (несколько мер, как правило конкурирующих).

Рассматриваемая задача относится одновременно к **дискретным** (позиции датчиков
выбираются из конечной сетки кандидатных точек), **стохастическим** (маршрут БПЛА
случаен) и по существу **многокритериальным** (кратность обнаружения и
равномерность сопровождения), которая сворачивается в один критерий взвешенной
суммой (см. §2.6). Указанное сочетание признаков предопределяет выбор метода
решения, рассмотренный в §1.3.

### 1.3. Пути решения оптимизационных задач

Универсального метода, одинаково пригодного для всех классов задач, не существует;
применяются следующие основные группы методов:

- **точные методы** — полный перебор, метод ветвей и границ (branch and bound —
  отсечение заведомо неперспективных вариантов), линейное и целочисленное
  программирование. Гарантируют глобальный оптимум, однако трудоёмкость растёт
  экспоненциально с размерностью, что ограничивает применение малыми задачами;
- **жадные и приближённые алгоритмы** — решение строится по шагам, на каждом шаге
  выбирается локально наилучший вариант. Быстры и просты, а для ряда задач
  специальной структуры дают доказуемую гарантию близости к оптимуму;
- **метаэвристики** — генетические алгоритмы, метод роя частиц (Particle Swarm
  Optimization, PSO), имитация отжига. Реализуют направленный случайный поиск по
  пространству решений; универсальны, но не дают гарантий качества и требуют
  настройки параметров;
- **градиентные методы** — движение по направлению наибольшего роста (либо
  убывания) целевой функции; применимы к непрерывным гладким функциям и
  неприменимы к дискретному выбору позиций из сетки;
- **стохастические методы** — метод выборочного среднего (Sample Average
  Approximation, SAA) и стохастическая аппроксимация; предназначены для задач со
  случайными данными, где оптимизируется оценка целевой функции по выборке.

Для данной задачи применяется **жадный алгоритм поверх метода выборочного
среднего**. Выбор обоснован сочетанием признаков задачи: дискретность и
специальная структура целевой функции (субмодулярность, §2.8) обеспечивают
жадному алгоритму доказуемую гарантию, тогда как стохастичность маршрута требует
оценивания критерия по накопленной выборке (SAA). Точные методы неприменимы из-за
размерности (число кандидатных позиций — тысячи, перебор их сочетаний
экспоненциален), а метаэвристики (включая PSO) при наличии гарантии от жадного
алгоритма избыточны и условиями задачи на данном этапе исключены.

### 1.4. Требования к критериям и показателям

Следует различать два понятия. **Критерий** — величина, по которой ведётся
оптимизация (входит в целевую функцию и определяет выбор решения). **Показатель**
— измеримая характеристика результата, по которой оценивается качество решения;
показатель может не входить в целевую функцию, а служить для контроля и
интерпретации. Проще говоря, критерий — это то, что максимизируется, а показатель
— то, что измеряется и докладывается.

К критерию предъявляются следующие требования:

- **измеримость** — выражается числом, а не качественной оценкой;
- **согласованность с целью** — рост критерия соответствует улучшению по существу
  задачи (а не формальному показателю);
- **чувствительность** — критерий реагирует на изменение решения и не образует
  обширных «плато», на которых разные решения неразличимы;
- **вычислимость** — рассчитывается за приемлемое время, в том числе многократно
  в ходе поиска;
- **сопоставимость разнородных составляющих** — при объединении нескольких мер
  они приводятся к общей шкале нормировкой и взвешиванием.

Отдельно выделяются **структурные свойства** целевой функции, наличие которых
делает задачу эффективно решаемой: монотонность, субмодулярность (§2.8),
выпуклость либо вогнутость. Их присутствие позволяет применять быстрые методы с
гарантией качества, тогда как их отсутствие вынуждает прибегать к метаэвристикам.

К показателям предъявляются требования репрезентативности (показатель отражает
существенное свойство результата), устойчивости и интерпретируемости. Для величин
с асимметричным распределением приводится **медиана**, а не только среднее, с
указанием объёма выборки.

### 1.5. Обозначения и синтаксис математической записи

Раздел поясняет, как читать формулы документа (как §1.1, так и формулы данной
задачи в §2.2, §2.6–§2.8). Сведения даны в форме «запись — значение — чтение
обиходным языком», чтобы математическая постановка была доступна без специальной
подготовки.

**Общие математические обозначения.**

| Запись | Значение | Как читать |
|---|---|---|
| `F(x) → max` | максимизация функции | подобрать `x`, при котором `F` принимает наибольшее значение |
| `x ∈ D` | принадлежность множеству | «`x` принадлежит допустимому множеству `D`» (вариант разрешён) |
| `{ P : условие }` | задание множества условием | «множество всех точек `P`, для которых выполнено условие» |
| `\|PA\|` | расстояние между точками | длина отрезка от `P` до `A` (по прямой) |
| `\|S\|` | мощность множества | число элементов в `S` (здесь — число датчиков) |
| `min(a, b)` | наименьшее из двух | берётся меньшее из значений `a` и `b` |
| `Σ` (`Σ_{i=1..t}`) | сумма | сложить слагаемые при `i = 1, 2, …, t` |
| `𝔼[·]` | математическое ожидание | среднее значение величины по её распределению вероятностей |
| `argmax F(S)` | аргумент максимума | то расположение `S`, на котором `F` достигает максимума (не само значение `F`, а точка, где оно наибольшее) |
| `√`, `a²` | корень и квадрат | квадратный корень; возведение в квадрат |
| `≤`, `≥`, `≈` | сравнения | не больше; не меньше; приблизительно равно |
| `xₜ`, `γᵢ` | нижний индекс | привязка к шагу `t` либо к `i`-му элементу выборки |
| `S*` | звёздочка | оптимальное (искомое) значение |
| `F_t → F` | стрелка-сходимость | `F_t` стремится к `F` с ростом `t` |

Отдельно поясняется **многозначность символа `|·|`**: для пары точек (`|PA|`) это
расстояние, для множества (`|S|`) — число элементов; смысл определяется тем, что
стоит внутри.

**Обозначения данной задачи** (греческие буквы приводятся с произношением).

| Символ | Значение |
|---|---|
| `A`, `B` | начальная и конечная точки маршрута |
| `L_max` | запас хода — предельная длина маршрута |
| `N` | число датчиков (фиксированный ресурс) |
| `R` | радиус обнаружения датчика |
| `k` | требуемая кратность — минимальное число засечек |
| `L_seg` | число сегментов, на которые делится маршрут |
| `S` | расположение датчиков (множество позиций), `\|S\| ≤ N` |
| `γ` («гамма») | конкретный маршрут (траектория) |
| `θ` («тета») | угол отклонения дуги; `θ_max` — предельный угол |
| `t` | номер итерации и одновременно размер накопленной выборки |
| `n(S, γ)` | кратность — число различных засёкших датчиков |
| `m(S, γ)` | число покрытых сегментов маршрута |
| `c(S, γ)` | непрерывное покрытие — доля длины пути под наблюдением |
| `φ(S, γ)` («фи») | полезность расположения `S` на маршруте `γ` |
| `α₁, α₂` («альфа») | веса критериев кратности и равномерности |
| `F(S)`, `F_t(S)` | целевая функция: истинная и оценённая по выборке |
| `a, b, c` | полуоси эллипса и полухорда (`a = L_max/2`, `c = \|AB\|/2`) |

**Запись `φ(S, γ)` — функциональная нотация.** Скобки означают зависимость от
аргументов: полезность `φ` определяется одновременно расположением датчиков `S` и
маршрутом `γ`. Аналогично читаются `n(S, γ)`, `m(S, γ)`, `F(S)`.

> **Пример чтения формул.**
>
> `φ(S, γ) = α₁ · min(n, k)/k + α₂ · m/L_seg` — «полезность складывается из двух
> частей: доля выполнения требования по кратности `min(n, k)/k` (не превышает 1,
> поскольку засечки сверх `k` усечены) с весом `α₁`, и доля покрытых сегментов
> `m/L_seg` с весом `α₂`».
>
> `F(S) = 𝔼[φ(S, γ)] → max при |S| ≤ N` — «среди всех расположений не более чем из
> `N` датчиков (`|S| ≤ N`) найти такое, при котором среднее по случайному маршруту
> (математическое ожидание `𝔼`) значение полезности наибольшее».
>
> `F_t(S) = (1/t) · Σ_{i=1..t} φ(S, γᵢ)` — «оценка целевой функции: сложить
> полезности расположения `S` на всех `t` накопленных маршрутах `γ₁ … γₜ` и
> разделить на их число `t`, то есть взять среднее».

## Часть 2. Постановка и решение данной задачи (частный случай)

Ниже общие положения §1 конкретизируются применительно к размещению датчиков:
переменные решения — позиции `N` датчиков; целевая функция — средняя полезность
размещения; ограничения — заданное число датчиков `N` и их расположение в пределах
коридора движения.

### 2.1. Содержательная постановка

БПЛА летит из A в B, имея ограниченный **запас хода** `L_max` (предельную длину
маршрута). Точный маршрут заранее неизвестен — это **случайная** кривая из
некоторого распределения способов движения. Требуется расставить `N` датчиков с
радиусом обнаружения `R` так, чтобы на типичном маршруте обеспечить:

- **кратность** — не менее `k` обнаружений (засечек различными датчиками);
- **равномерность** — засечки распределены вдоль всего маршрута, а не сгруппированы
  на одном участке.

Важность обоих критериев настраивается режимом оптимизации (§2.6). В терминах §1.1
переменные решения — координаты датчиков; ограничение — ровно `N` датчиков в
пределах достижимой зоны; целевая функция — мера качества сопровождения,
формируемая из кратности и равномерности.

### 2.2. Эллипс достижимости и привязка карты

Если суммарная длина пути ограничена `L_max`, все достижимые точки лежат внутри
**эллипса** с фокусами A, B:

```
E = { P : |PA| + |PB| ≤ L_max },   a = L_max/2,  c = |AB|/2,  b = √(a² − c²)
```

**Обоснование принадлежности маршрута эллипсу.** Для точки P на маршруте длиной
`L`: расстояние по прямой `|PA|` не превышает длины дуги от A до P, а `|PB|` — длины
от P до B. Следовательно, `|PA| + |PB| ≤ L ≤ L_max`, то есть P лежит внутри
эллипса. Тем самым ограничение по запасу хода **автоматически** удерживает
траекторию в пределах эллипса, и отдельная проверка не требуется.

**Большая и малая полуоси.** Величина `a = L_max/2` — **большая полуось** эллипса
(наибольшее удаление достижимой точки вдоль оси A–B); `b` — **малая полуось**
(поперечный размер). При `L_max ≫ |AB|` эллипс становится крупным, поэтому масштаб
карты подгоняется не под эллипс, а под **коридор движения** (§2.10) — зону
фактического прохождения маршрутов. При необходимости A и B задаются в широте и
долготе и проецируются в километры (`geo_to_local_km`).

### 2.3. Модель движения: дуги по углу отклонения (этап 1)

Маршрут — круговая дуга от A до B, заданная **углом отклонения** `θ`
(касательно-хордовым углом в точке A; по существу — насколько траектория «уходит»
от прямой на старте):

- `θ = 0` — полёт по прямой A→B;
- чем больше `|θ|`, тем сильнее выгнута дуга и тем она **длиннее**;
- знак `θ` задаёт сторону отклонения.

Для хорды `c = |AB|` (угол θ в радианах):

```
радиус дуги     Rc = c / (2 sin θ)
длина дуги      L(θ) = c · θ / sin θ          (монотонно растёт по θ)
стрела прогиба  s(θ) = c (1 − cos θ) / (2 sin θ)
```

**Предельный угол** `θ_max` — корень уравнения `L(θ) = L_max`, отыскиваемый
**бинарным поиском** (binary search — деление отрезка пополам; функция
`max_deflection_angle`). Бинарный поиск, по существу, последовательно сужает
интервал возможных значений угла вдвое, пока длина дуги не совпадёт с запасом хода
с требуемой точностью. Предельный угол задаёт границу: дальше отклоняться запас
хода не позволяет.

> **Пример.** `|AB| = 100 км`, запас хода `150 км`. БПЛА может лететь по прямой,
> отклониться на небольшой угол (малая дуга) либо сильнее — пока хватает запаса
> хода. Здесь `θ_max ≈ 85,7°`. **Предельные дуги `±θ_max`** на карте помечаются
> **красным пунктиром** — это наиболее выгнутые из возможных маршрутов.

Случайный маршрут (`sample_arc_trajectory`) формируется случайным выбором угла `θ`
по выбранному **профилю разброса**:

- **обычный** — **усечённое нормальное распределение** (truncated normal —
  «колоколообразное», ограниченное отрезком `[−θ_max, θ_max]` с центром в нуле):
  короткий путь (малая дуга) наиболее частый, предельные дуги редки;
- **смешанный** — равномерное распределение на `[−θ_max, θ_max]`: короткие и
  длинные маршруты равновероятны;
- **сложный** — магнитуда угла тяготеет к `θ_max`: преобладают сильно выгнутые
  (длинные обходные) дуги.

Профиль управляет тем, насколько часто БПЛА выбирает длинные обходные маршруты.

Пространство маршрутов отображается двумя раздельными слоями:

- **10 наиболее вероятных** (`frequent_arcs`) — десять дуг по **квантилям**
  распределения углов выбранного профиля. Квантиль (quantile) — значение,
  делящее распределение в заданной пропорции; проще говоря, дуги берутся так,
  чтобы равномерно «покрыть» типичный разброс углов (для обычного профиля — у
  прямой, для сложного — у предела). Это типичные, а не предельные маршруты;
- **веер по шагу угла** (`arc_fan`) — все возможные дуги с фиксированным шагом
  (5°, 10° и далее) от 0 до ±θ_max; предельные ±θ_max помечены пунктиром. Слой
  показывает геометрию всего пространства маршрутов.

### 2.4. Модель движения: петли (этап 2)

Петляющее движение — синусоида с закреплёнными концами A, B, случайными частотой,
амплитудой и фазой; длина ограничена `L_max`. По аналогии с `θ_max` для дуг
вводится **предельная амплитуда** (`max_serpentine_amplitude`) — наибольшая
амплитуда петли, укладывающаяся в запас хода. Профиль (обычный/смешанный/сложный)
выбирает амплитуду в `[0, amp_max]`, поэтому «сложный» формирует крупные петли без
вырождения в прямую. Метрики, целевая функция и метод оптимизации при этом не
изменяются — заменяется только генератор маршрутов. Слой «10 маршрутов» для петель
— представительные петли по квантилям амплитуды; «веер» — петли по шагу амплитуды.

### 2.5. Модель обнаружения

Датчик фиксирует точку маршрута, если она расположена ближе `R`. Обнаружение
засчитывается как **однократный** факт входа маршрута в зону датчика; повторные
входы того же датчика не учитываются. Поэтому **кратность** `n(S, γ)` —
число **различных** датчиков, засёкших маршрут `γ` при расположении `S`.

Отдельно рассчитывается **непрерывное покрытие** `c(S, γ)` — доля длины пути,
пройденная в зоне хотя бы одного датчика (отвечает на вопрос, какую часть пути БПЛА
находится под наблюдением).

### 2.6. Целевая функция и три режима

Полезность расположения `S` на маршруте `γ`:

```
φ(S, γ) = α₁ · min(n(S, γ), k) / k  +  α₂ · m(S, γ) / L_seg
```

- первое слагаемое — **кратность**, нормированная на `k` и усечённая сверху
  (избыточные засечки сверх `k` не вознаграждаются, и ресурс переносится на
  необеспеченные маршруты);
- второе слагаемое — **равномерность**: `m` — число покрытых сегментов из `L_seg`
  (маршрут делится на `L_seg` равных участков; чем их больше, тем строже требование
  равномерности).

Соотношение составляющих задаётся весами `α₁, α₂` (нормировка и взвешивание по
требованию сопоставимости, §1.4); тем самым многокритериальная постановка сводится
к однокритериальной:

| Режим | α₁ (кратность) | α₂ (равномерность) |
|---|---|---|
| `distribution` (распределение) | 0,25 | 0,75 |
| `crossing` (пересечение)       | 0,75 | 0,25 |
| `balanced` (сбалансированный)  | 0,50 | 0,50 |

### 2.7. Критерий и метод выборочного среднего

Истинный критерий — **математическое ожидание** (среднее значение по всем
возможным маршрутам с учётом их вероятностей) полезности:

```
F(S) = 𝔼[φ(S, γ)] → max   при   |S| ≤ N
```

Распределение маршрутов известно только через случайные реализации, поэтому
математическое ожидание заменяется **эмпирическим средним** по накопленной выборке
— это и есть метод выборочного среднего (Sample Average Approximation, SAA):

```
F_t(S) = (1/t) · Σ_{i=1..t} φ(S, γᵢ),    S_t = argmax F_t(S)
```

Проще говоря, истинное среднее по бесконечному числу маршрутов недоступно, поэтому
оно оценивается средним по уже наблюдавшимся маршрутам, и это среднее уточняется с
каждой новой итерацией.

> **[Справочно] Что именно усредняется (частый вопрос).** Усредняются **не
> маршруты и не координаты датчиков**, а **критерий**. На каждой итерации заново
> решается задача: куда поставить *все N* датчиков, чтобы максимизировать среднюю
> полезность по *всем* накопленным маршрутам. Берётся не «средний маршрут из 100»,
> а оптимум по всей выборке одновременно.
>
> Число датчиков `N` **фиксировано** — это заданный ресурс; оно **не растёт** с
> выборкой (представление «после 10 → 1, после 50 → 2» ошибочно). С ростом выборки
> уточняется *оценка* математического ожидания, и расположение **стабилизируется**
> в силу **закона больших чисел** (с ростом числа наблюдений выборочное среднее
> сходится к истинному): `F_t → F`, `S_t → S*`. Прямое осреднение координат
> недопустимо: среднее двух хороших расположений может оказаться плохим (два
> датчика на разных краях сектора при осреднении сходятся в центр).

### 2.8. Субмодулярность, жадный алгоритм и размещение всех N датчиков

Целевая функция `F_t(S)` **монотонна и субмодулярна**. **Монотонность** означает,
что добавление датчика не ухудшает результат. **Субмодулярность** (submodularity)
— свойство «убывающей отдачи»: прирост от очередного датчика тем меньше, чем больше
датчиков уже размещено. Проще говоря, первые датчики дают много новой пользы,
последующие — всё меньше, поскольку часть маршрутов уже охвачена. Указанные
свойства следуют из структуры функции (композиция вогнутой `min(·,k)` с модулярной
`n` и классической функции покрытия `m`, усреднённые по выборке).

Для монотонных субмодулярных функций **жадный алгоритм** (greedy algorithm —
«жадный»; на каждом шаге добавляется датчик с наибольшим приростом критерия) даёт
результат не хуже **(1 − 1/e) ≈ 0,632** от глобального оптимума (Nemhauser, Wolsey,
Fisher, 1978). Иными словами, простой и быстрый пошаговый выбор гарантированно
обеспечивает не менее 63 % от теоретически наилучшего значения, а на практике —
существенно ближе к нему; тяжёлые методы (полный перебор, метаэвристики) при этом
не требуются.

**Размещение всех N датчиков.** В ранней реализации жадный алгоритм
останавливался, когда прирост основного критерия обращался в нуль (на малой
выборке `k` засечек и полное покрытие сегментов достигались малым числом датчиков),
вследствие чего размещались не все датчики. В текущей реализации размещаются
**всегда все N**: при насыщении основного критерия включается **вторичный критерий
распределения** — прирост охваченной доли маршрутов по их **плотности**, за счёт
чего оставшиеся датчики разносятся по наиболее частым путям. Выбор организован
**лексикографически** (lexicographic — сначала сравнение по основному критерию, и
лишь при равенстве — по вторичному), поэтому при положительном основном приросте
поведение не изменяется и свойства решения сохраняются.

### 2.9. Динамика и случайность

Расположение пересчитывается **на каждой итерации** по всей накопленной выборке
(инкрементальный SAA — добавление одного маршрута и перерасчёт). Структура
эволюционирует и стабилизируется при росте выборки (порядка 1000 итераций), что и
демонстрирует итеративный режим просмотра.

**Случайность.** Зерно генератора случайных чисел (ГСЧ) по умолчанию не фиксировано
(`seed=None`), вследствие чего каждый прогон («Пуск» после «Сброс», «Пакетно»,
«Применить») использует новую случайную выборку и даёт другой результат. Для
воспроизводимости задаётся параметр `--seed`.

### 2.10. Коридор движения (зона датчиков и масштаб карты)

**Коридор движения** — область, в пределах которой лежат все возможные маршруты:

- для дуг — лунка между предельными дугами `±θ_max`;
- для петель — область под огибающей `|y| ≤ b · sin(πx/d)`.

Коридор используется двояко:

- **кандидатные позиции датчиков ограничиваются коридором** (`corridor_filter`);
  точки эллипса вне коридора недостижимы маршрутами, поэтому датчик там бесполезен,
  что устраняет размещение датчиков в мёртвых зонах (за точками A/B и в дальних
  углах эллипса);
- **масштаб карты подгоняется под коридор** (`corridor_bbox`, `fit_axes`), а не под
  весь эллипс, что обеспечивает удобный обзор при любом отношении `L_max/|AB|`.

Дополнительно масштаб поджимается под **зону типичных маршрутов** (профиль-зависимо,
охват около 96 % траекторий); при включённом слое «веер» масштаб разворачивается на
полный коридор, что обеспечивает одновременную видимость предельных маршрутов.

## Часть 3. Структура кода (основные элементы)

Архитектура **MVC** (Model–View–Controller) разделяет вычисления (Model),
отображение (View) и управление (Controller), за счёт чего вычислительное ядро
работает автономно и независимо тестируется.

```
uav_sensor_mvc/
├── config.py          параметры (Params), режимы (MODES), цветовая тема (THEME)
├── main.py            точка входа: режимы gui / selftest / render
│
├── model/             MODEL — вычислительное ядро (без графики)
│   ├── geometry.py        эллипс достижимости, авто-масштаб карты, гео-проекция
│   ├── trajectories.py    дуги по углу, веер дуг, петли, предельный угол
│   ├── detection.py       модель обнаружения и метрики
│   ├── optimization.py    сетка кандидатов, структура покрытия, жадный выбор
│   └── simulation.py      SimulationModel — состояние и весь расчёт
│
├── view/              VIEW — визуализация (matplotlib, тёмная тема)
│   └── view.py            сцена, тепловая карта, веер путей, виджеты, показатели
│
├── controller/        CONTROLLER — управление
│   └── controller.py      события, правка параметров, анимация
│
├── docs/              Теория_и_математика.docx и генератор
├── README.md          краткое описание и запуск
├── МЕТОДИЧКА.md       этот документ
└── ЖУРНАЛ_ПРОЕКТА.md  журнал: идея, решения, ошибки, история
```

### 3.1. MODEL — ключевые элементы

**`model/geometry.py`**
- `ellipse_geometry(A, B, L_max)` — центр, полуоси `a, b, c`, угол эллипса;
- `geo_to_local_km(A_geo, B_geo)` — перевод широты и долготы в локальные километры.

**`model/trajectories.py`**
- `make_arc_by_angle(A, B, θ°)` — дуга по углу отклонения (прямая параметризация
  центральным углом, корректная для любого θ, включая θ > 90°);
- `arc_length_from_angle`, `max_deflection_angle` — длина дуги и предельный угол;
- `sample_arc_trajectory(..., profile)` — случайная дуга по профилю разброса
  (`normal` / `mixed` / `complex`);
- `arc_fan(A, B, L_max, шаг°)` — веер вероятных дуг с весами и пометкой крайних;
- `corridor_outline / corridor_polygon / corridor_filter / corridor_bbox` —
  коридор движения (граница, фильтр кандидатов, габариты для масштаба);
- `make_serpentine`, `sample_serpentine_trajectory` — петляющее движение (этап 2);
- `SAMPLERS` — реестр генераторов `{"arc", "serpentine"}` (взаимозаменяемы).

**`model/detection.py`**
- `n_detections(traj, sensors, R)` — кратность (число различных засёкших датчиков);
- `continuous_coverage(...)` — доля длины пути под наблюдением;
- `segment_coverage(...)` — доля покрытых сегментов (равномерность);
- `utility(...)` — полезность `φ(S, γ)`.

**`model/optimization.py`**
- `candidate_grid(..., traj_model)` — сетка кандидатных позиций, ограниченная
  коридором движения;
- `CoverageCache` — **структура покрытия**: для каждого маршрута и кандидата хранит
  засечку (`hit`), битовую маску покрытых сегментов (`segmask`) и долю покрытия
  (`covfrac`), что обеспечивает **векторизованный** расчёт приростов (векторизация
  — обработка массивов целиком средствами `numpy` вместо поэлементных циклов, что
  кратно ускоряет вычисления);
- `CoverageCache.greedy(N, weights)` — жадный субмодулярный выбор **всех N** позиций
  (основной критерий и вторичный критерий распределения).

**`model/simulation.py` — `SimulationModel`** (главный класс):
- `reset()` — пересоздать выборку и производные структуры (включая кэш геометрии);
- `step()` — одна итерация SAA (породить маршрут, добавить, пересчитать размещение);
- `run_batch(T)` — полный расчёт по выборке;
- `frequent_paths(n)` — наиболее вероятные маршруты (квантили профиля);
- `fan_paths()` — веер всех возможных маршрутов по шагу (предельные — пунктир);
- `density_field()` — поле плотности маршрутов для тепловой карты;
- `corridor_outline() / corridor_bbox() / view_bbox()` — границы, габариты коридора
  и габариты зоны типичных маршрутов;
- `evaluate()` — итоговые показатели; `compare_modes()` — сравнение трёх режимов.

### 3.2. VIEW — ключевые элементы (`view/view.py`)

- `fit_axes(ax, bbox)` — подгонка масштаба под коридор (равный масштаб осей,
  при котором зоны датчиков отображаются кругами без искажения);
- `draw_static / draw_density / draw_probable / draw_sensors` — слои сцены: контур
  коридора и точки A/B; тепловая карта с гамма-подъёмом и яркой палитрой; линии
  маршрутов; датчики. Легенда-шкала тепловой карты вынесена на отдельную ось;
- `setup_flight / update_flight` — **плавная анимация через блиттинг** (blitting —
  приём, при котором неизменный фон рисуется один раз, а в каждом кадре
  перерисовываются только подвижные элементы — БПЛА и пройденный путь); фон
  переинициализируется при изменении размера окна;
- `SimulationView` — окно: редактируемые поля (TextBox, Enter → пересчёт),
  переключатели режима/движения/профиля (RadioButtons), три чекбокса слоёв
  (CheckButtons: тепловая карта / 10 маршрутов / веер по шагу угла), регулятор
  скорости (Slider), кнопки и показатели. Логика во View отсутствует.

### 3.3. CONTROLLER — ключевые элементы (`controller/controller.py`)

- `on_apply()` — считать поля, проверить ввод и **перезапустить** расчёт (с откатом
  при недопустимом значении);
- `on_start_pause / on_step / on_reset / on_batch` — режимы просмотра;
- `on_mode / on_traj / on_profile / on_speed / on_toggle` — переключатели и слои;
- `_tick()` — кадр анимации итеративного режима (блиттинг через таймер холста).

## Часть 4. Запуск

```bash
pip install -r requirements.txt

python main.py                       # интерактивное окно
python main.py --mode selftest       # прогон ядра без графики
python main.py --mode render         # PNG по режимам + GIF в ./out

python main.py --ab 100 --Lmax 150 --N 6 --R 12 --k 3 --angle 10
```

В окне правятся числа в полях слева-сверху с подтверждением клавишей **Enter** (либо
кнопкой «Применить») — карта и расчёт перестраиваются автоматически. Кнопка
«Пакетно» строит итог сразу по всей выборке; «Пуск» и «Шаг» показывают накопление
по итерациям.

- Shapiro, Dentcheva, Ruszczyński — метод выборочного среднего (SAA).
- Taha H. — «Введение в исследование операций» (классы задач и методы оптимизации).
- Hillier, Lieberman — «Introduction to Operations Research» (общая теория).
