# Методичка по программе «Размещение датчиков обнаружения БПЛА»

Документ объясняет **как решается задача** (теория) и **из чего состоит код**
(основные элементы). Программа реализована на Python (`numpy` + `matplotlib`) в
архитектуре **MVC** и моделирует оптимальное размещение датчиков для обнаружения
беспилотного летательного аппарата, летящего из точки **A** в точку **B**.

---

## Часть 1. Теория: как решается задача

### 1.1. Содержательная постановка

БПЛА летит из A в B, имея ограниченный **запас хода** `L_max` (предельную длину
маршрута). Точный маршрут заранее неизвестен — это **случайная** кривая из
некоторого распределения способов движения. Нужно расставить `N` датчиков с
радиусом обнаружения `R` так, чтобы на типичном маршруте обеспечить:

1. **кратность** — не менее `k` обнаружений (засечек разными датчиками);
2. **равномерность** — засечки распределены вдоль всего маршрута, а не сгруппированы
   на одном участке.

Важность обоих критериев настраивается режимом оптимизации.

### 1.2. Эллипс достижимости и привязка карты

Если суммарная длина пути ограничена `L_max`, то все достижимые точки лежат внутри
**эллипса** с фокусами A, B:

```
E = { P : |PA| + |PB| ≤ L_max },   a = L_max/2,  c = |AB|/2,  b = √(a² − c²)
```

**Почему любой маршрут не выходит за эллипс.** Для точки P на маршруте длиной `L`:
расстояние по прямой `|PA|` не больше длины дуги от A до P, а `|PB|` не больше длины
от P до B. Значит `|PA| + |PB| ≤ L ≤ L_max`, то есть P внутри эллипса. Поэтому
ограничение по запасу хода **автоматически** удерживает траекторию внутри эллипса —
отдельной проверки не требуется.

Карта (оси графика) **масштабируется автоматически** под этот эллипс: при изменении
`L_max` или `|AB|` границы осей пересчитываются (`auto_axes_limits`). При желании A и
B задаются в **широте/долготе** и проецируются в километры (`geo_to_local_km`).

### 1.3. Модель движения: дуги по углу отклонения (этап 1)

Маршрут — круговая дуга от A до B, заданная **углом отклонения** `θ` (касательно-
хордовый угол в точке A):

- `θ = 0` — полёт по прямой A→B;
- чем больше `|θ|`, тем сильнее выгнута дуга и тем она **длиннее**;
- знак `θ` задаёт сторону отклонения.

Для хорды `c = |AB|` (θ в радианах):

```
радиус дуги     Rc = c / (2 sin θ)
длина дуги      L(θ) = c · θ / sin θ          (монотонно растёт по θ)
стрела прогиба  s(θ) = c (1 − cos θ) / (2 sin θ)
```

**Предельный угол** `θ_max` — корень уравнения `L(θ) = L_max` (бинарный поиск,
`max_deflection_angle`). Это и есть граница: дальше отклоняться запас хода не
позволяет.

> **Пример.** `|AB| = 100 км`, запас хода `150 км`. БПЛА может лететь по прямой,
> либо отклониться на небольшой угол (малая дуга), либо сильнее — пока хватает
> запаса хода. Здесь `θ_max ≈ 85,7°`. **Предельные дуги `±θ_max`** на карте
> помечаются **красным пунктиром** — это самые «выгнутые» из возможных маршрутов.

Случайный маршрут (`sample_arc_trajectory`): угол `θ` берётся из **усечённого
нормального распределения** на `[−θ_max, θ_max]` с нулевым средним и шириной
`σ = sigma_frac · θ_max`. Поэтому полёты у прямой — самые частые, у предела — редкие.

**Веер вероятных путей** (`arc_fan`): набор дуг с настраиваемым **шагом угла**
(например, каждые 5°, 10°, …) от 0 до ±θ_max. Каждой дуге приписан вес — плотность
нормального распределения в этой точке (толщина и яркость линии). Так на карте сразу
видно «наиболее вероятные пути».

### 1.4. Модель движения: петли (этап 2)

Петляющее движение — синусоида с закреплёнными концами A, B, случайной частотой,
амплитудой и фазой; длина ограничена `L_max`. Метрики, целевая функция и метод
оптимизации **не меняются** — заменяется только генератор маршрута. Вероятные пути
для петель выявляются **кластеризацией** накопленной выборки по боковому отклонению
(10 представителей частых кластеров, крайние — пунктиром).

### 1.5. Модель обнаружения

Датчик «видит» точку маршрута, если она ближе `R`. Обнаружение засчитывается как
**однократный** факт входа маршрута в зону датчика; повторные входы того же датчика
не считаются. Поэтому **кратность** `n(S, γ)` = число РАЗЛИЧНЫХ датчиков, засёкших
маршрут.

Отдельно считается **непрерывное покрытие** `c(S, γ)` — доля длины пути, пройденная в
зоне хотя бы одного датчика (отвечает на вопрос «какую часть пути ведётся БПЛА»).

### 1.6. Целевая функция и три режима

Полезность расположения `S` на маршруте `γ`:

```
φ(S, γ) = α₁ · min(n(S, γ), k) / k  +  α₂ · m(S, γ) / L_seg
```

- первое слагаемое — **кратность**, нормирована на `k` и усечена сверху (избыточные
  засечки сверх `k` не вознаграждаются — ресурс переносится на необеспеченные
  маршруты);
- второе — **равномерность**: `m` — число покрытых сегментов из `L_seg` (маршрут
  делится на `L_seg` равных участков).

Три режима задаются весами:

| Режим | α₁ (кратность) | α₂ (равномерность) |
|---|---|---|
| `distribution` (распределение) | 0,25 | 0,75 |
| `crossing` (пересечение)       | 0,75 | 0,25 |
| `balanced` (сбалансированный)  | 0,50 | 0,50 |

### 1.7. Критерий и метод выборочного среднего (ответ на вопрос «как усредняется»)

Истинный критерий — **математическое ожидание** полезности по всем возможным
маршрутам:

```
F(S) = 𝔼[φ(S, γ)] → max   при   |S| ≤ N
```

Распределение маршрутов известно только через случайные реализации, поэтому
матожидание заменяется **эмпирическим средним** по накопленной выборке (метод
выборочного среднего, **SAA — Sample Average Approximation**):

```
F_t(S) = (1/t) · Σ_{i=1..t} φ(S, γᵢ),    S_t = argmax F_t(S)
```

> **Важно (это частый вопрос).** Усредняются **НЕ маршруты и НЕ координаты
> датчиков**, а **критерий**. На каждой итерации мы решаем заново: «куда поставить
> *все N* датчиков, чтобы максимизировать среднюю полезность по *всем* накопленным
> маршрутам». Берётся не «средний маршрут из 100», а оптимум по всей выборке сразу.
>
> Число датчиков `N` **фиксировано** — это заданный ресурс. Оно **не растёт** с
> выборкой («после 10 → 1, после 50 → 2» — это неверная модель). С ростом выборки
> уточняется *оценка* матожидания, и расположение **стабилизируется** (закон больших
> чисел): `F_t → F`, `S_t → S*`. Прямое осреднение координат недопустимо — среднее
> двух хороших расположений может оказаться плохим (два датчика на разных краях
> сектора при осреднении сходятся в центр).

### 1.8. Субмодулярность, жадный алгоритм и «все N датчиков»

Функция `F_t(S)` **монотонна и субмодулярна** (композиция вогнутой `min(·,k)` с
модулярной `n`, плюс классическая функция покрытия `m`, усреднённые по выборке).
Для таких функций **жадный алгоритм** (на каждом шаге добавляем датчик с наибольшим
приростом) даёт гарантию не хуже **(1 − 1/e) ≈ 0,632** от оптимума (Nemhauser,
Wolsey, Fisher, 1978).

**Почему раньше появлялись не все датчики и как исправлено.** Жадный алгоритм
останавливался, когда прирост основного критерия становился нулевым (на малой
выборке `k` засечек и полное покрытие сегментов достигались малым числом датчиков).
Теперь размещаются **всегда все N**: когда основной критерий насыщается, включается
**вторичный критерий распределения** — прирост покрытой доли маршрутов по их
**плотности**. Оставшиеся датчики разносятся по наиболее частым путям, а не
останавливаются досрочно. При положительном основном приросте поведение не меняется
(лексикографический выбор), поэтому свойства решения сохраняются.

### 1.9. Динамика

Расположение пересчитывается **на каждой итерации** по всей накопленной выборке
(инкрементальный SAA). Структура эволюционирует и стабилизируется при росте выборки
(порядка 1000 итераций). Это и показывает итеративный режим просмотра.

## Часть 2. Структура кода (основные элементы)

Архитектура **MVC**: вычисления (Model) полностью отделены от отображения (View) и
управления (Controller).

```
uav_sensor_mvc/
├── config.py          параметры (Params), режимы (MODES), цветовая тема (THEME)
├── main.py            точка входа: режимы gui / selftest / render
│
├── model/             MODEL — вычислительное ядро (без графики)
│   ├── geometry.py        эллипс достижимости, авто-масштаб карты, гео-проекция
│   ├── trajectories.py    дуги по углу, веер дуг, петли, предельный угол
│   ├── detection.py       модель обнаружения и метрики
│   ├── optimization.py    сетка кандидатов, структура покрытия, жадный выбор
│   └── simulation.py      SimulationModel — состояние и весь расчёт
│
├── view/              VIEW — визуализация (matplotlib, тёмная тема)
│   └── view.py            сцена, тепловая карта, веер путей, виджеты, показатели
│
├── controller/        CONTROLLER — управление
│   └── controller.py      события, правка параметров, анимация
│
├── examples/          примеры рендера (PNG/GIF)
├── README.md          краткое описание и запуск
└── МЕТОДИЧКА.md       этот документ
```

### 2.1. MODEL — ключевые элементы

**`model/geometry.py`**
- `ellipse_geometry(A, B, L_max)` — центр, полуоси `a, b, c`, угол эллипса.
- `auto_axes_limits(geom, margin)` — границы осей карты под эллипс (авто-масштаб).
- `geo_to_local_km(A_geo, B_geo)` — перевод широты/долготы в локальные километры.

**`model/trajectories.py`**
- `make_arc_by_angle(A, B, θ°)` — дуга по углу отклонения.
- `arc_length_from_angle`, `max_deflection_angle` — длина дуги и предельный угол.
- `sample_arc_trajectory(...)` — случайная дуга (усечённый нормальный угол).
- `arc_fan(A, B, L_max, шаг°)` — веер вероятных дуг с весами и пометкой крайних.
- `make_serpentine`, `sample_serpentine_trajectory` — петляющее движение (этап 2).
- `SAMPLERS` — реестр генераторов `{"arc", "serpentine"}` (взаимозаменяемы).

**`model/detection.py`**
- `n_detections(traj, sensors, R)` — кратность (число различных засёкших датчиков).
- `continuous_coverage(...)` — доля длины пути под наблюдением.
- `segment_coverage(...)` — доля покрытых сегментов (равномерность).
- `utility(...)` — полезность `φ(S, γ)`.

**`model/optimization.py`**
- `candidate_grid(...)` — сетка кандидатных позиций внутри эллипса.
- `CoverageCache` — **структура покрытия**: для каждого маршрута и кандидата хранит
  засечку (`hit`), битовую маску покрытых сегментов (`segmask`) и долю покрытия
  (`covfrac`). Позволяет **векторизованно** считать приросты.
- `CoverageCache.greedy(N, weights)` — жадный субмодулярный выбор **всех N**
  позиций (основной критерий + вторичный критерий распределения).

**`model/simulation.py` — `SimulationModel`** (главный класс):
- `reset()` — пересоздать выборку и производные структуры;
- `step()` — одна итерация SAA (породить маршрут, добавить, пересчитать размещение);
- `run_batch(T)` — полный расчёт по выборке;
- `probable_paths()` — вероятные пути (веер дуг или кластеры петель);
- `density_field()` — поле плотности маршрутов для тепловой карты;
- `evaluate()` — итоговые показатели; `compare_modes()` — сравнение трёх режимов.

### 2.2. VIEW — ключевые элементы (`view/view.py`)

- `draw_static / draw_density / draw_probable / draw_sensors` — слои сцены
  (эллипс и точки; тепловая карта; веер путей с пунктирными пределами; датчики).
- `SimulationView` — окно: **редактируемые поля параметров** (TextBox, Enter →
  пересчёт), выбор режима и модели движения (RadioButtons), скорость (Slider),
  кнопки (Применить / Пуск / Шаг / Пакетно / Сброс), панель показателей.
  View **не содержит логики** — только рисует и вызывает обработчики контроллера.

### 2.3. CONTROLLER — ключевые элементы (`controller/controller.py`)

- `on_apply()` — считать поля, проверить, **перезапустить** расчёт (с откатом при
  недопустимом вводе);
- `on_start_pause / on_step / on_reset / on_batch` — режимы просмотра;
- `on_mode / on_traj / on_speed` — переключатели;
- `_tick()` — кадр анимации итеративного режима (через таймер холста).

## Часть 3. Запуск

```bash
pip install -r requirements.txt

python main.py                       # интерактивное окно
python main.py --mode selftest       # прогон ядра без графики
python main.py --mode render         # PNG по режимам + GIF в ./out

python main.py --ab 100 --Lmax 150 --N 6 --R 12 --k 3 --angle 10
python main.py --geo --A 55.75 37.62 --B 56.20 38.40   # широта долгота
```

В окне: правьте числа в полях слева-сверху и нажимайте **Enter** (или «Применить») —
карта и расчёт перестроятся автоматически. «Пакетно» строит итог сразу по всей
выборке; «Пуск»/«Шаг» показывают накопление по итерациям.

## Часть 4. Источники

- Nemhauser, Wolsey, Fisher (1978) — субмодулярная максимизация, гарантия (1−1/e).
- Robbins, Monro (1951) — стохастическая аппроксимация (плавная динамика).
- Kumar, Lai, Arora (2007) — барьерное покрытие кратности k.
- Church, ReVelle (1974) — задача максимального покрытия размещением (MCLP).
- Shapiro, Dentcheva, Ruszczyński — метод выборочного среднего (SAA).
