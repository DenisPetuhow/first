# Оптимальное размещение датчиков обнаружения БПЛА (MVC)

Приложение моделирует оптимальное размещение `N` датчиков для обнаружения БПЛА,
летящего из точки **A** в точку **B** при ограничении запаса хода `L_max`.
Архитектура **MVC** (Model–View–Controller), зависимости — только `numpy` и
`matplotlib` (для GUI не требуется ни tkinter, ни Qt).

> Полная теория и разбор кода — в **`МЕТОДИЧКА.md`**.

---

## Возможности

- **Редактируемые параметры прямо в интерфейсе** (|AB|, запас хода, N, R, k,
  число сегментов, шаг угла, число итераций). Правка + **Enter** → расчёт
  перезапускается, карта масштабируется автоматически.
- **Дуги по углу отклонения** с настраиваемым шагом (веер дуг каждые 5°, 10°…).
  **Предельные дуги** (граница запаса хода) помечены **красным пунктиром**.
- **Вероятные пути** показываются в обоих режимах движения: для дуг — веер по углу,
  для петель — кластеры частых пролётов.
- **Тепловая карта плотности** маршрутов (где «трафик» БПЛА выше).
- **Всегда задействованы все N датчиков** — они распределяются по наиболее частым
  путям (основной субмодулярный критерий + вторичный критерий распределения).
- **Два режима просмотра**: итеративный (анимация накопления) и пакетный (итог сразу).
- **Три режима оптимизации**: распределение / пересечение / сбалансированный.
- **Гео-режим**: A и B можно задать в широте/долготе (проекция в километры).
- Авто-масштаб карты, тёмная тема, панель показателей и сравнение режимов.

## Установка и запуск

```bash
pip install -r requirements.txt

python main.py                       # интерактивное окно (по умолчанию)
python main.py --mode selftest       # прогон ядра без дисплея (печать показателей)
python main.py --mode render         # PNG по режимам + GIF анимации в ./out
```

Примеры с параметрами:

```bash
python main.py --ab 100 --Lmax 150 --N 6 --R 12 --k 3 --angle 10
python main.py --opt crossing --traj serpentine
python main.py --geo --A 55.75 37.62 --B 56.20 38.40   # широта долгота
```

### Параметры командной строки

```
--mode {gui,selftest,render}   режим запуска
--opt  {distribution,crossing,balanced}   режим оптимизации
--traj {arc,serpentine}        модель движения (дуги / петли)
--ab     расстояние |AB|, км   --Lmax  запас хода, км
--N  число датчиков            --R  радиус обнаружения, км
--k  требуемая кратность       --Lseg  число сегментов
--angle  шаг угла веера, °      --T  число итераций
--seed   зерно ГСЧ             --speed  точек за кадр   --iters  кадров GIF
--geo --A LAT LON --B LAT LON  гео-координаты A, B
```

## Работа в интерфейсе

- Слева-сверху — **поля параметров**. Измените число и нажмите **Enter** (или
  «Применить») — модель перестроится, расчёт начнётся заново.
- **«Пуск»/«Пауза»**, **«Шаг»** — итеративный режим: пролёт БПЛА и перестройка
  датчиков по мере накопления маршрутов; в заголовке — процент пути под наблюдением
  и число пересечений.
- **«Пакетно»** — полный расчёт по всей выборке: итоговое размещение, вероятные
  пути и сравнение трёх режимов.
- **«Скорость»** — число точек траектории за кадр (ускоряет пролёт).
- Переключатели **режима оптимизации** и **модели движения** — справа.

## Архитектура

```
uav_sensor_mvc/
├── config.py          параметры, режимы, тема
├── main.py            точка входа (gui / selftest / render)
├── model/             MODEL — ядро (геометрия, траектории, метрики, оптимизация)
├── view/              VIEW  — визуализация (matplotlib)
├── controller/        CONTROLLER — события и анимация
├── examples/          примеры рендера (PNG/GIF)
├── README.md
└── МЕТОДИЧКА.md       теория и разбор кода
```

- **Model** не зависит от графики (автономный прогон `--mode selftest`).
- **View** только рисует и вызывает обработчики; бизнес-логики не содержит.
- **Controller** связывает их: правка параметров, анимация, расчёт.

---

## Выходные показатели

- среднее число пересечений зон обнаружения `𝔼[n(S, γ)]`;
- средний процент длины пути под наблюдением (непрерывное покрытие);
- среднее расстояние, пройденное вне зон видимости;
- доля маршрутов с выполнением требования не менее `k` засечек;
- число фактически задействованных датчиков (равно `N`).
