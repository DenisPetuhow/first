# Оптимальное размещение датчиков обнаружения БПЛА (MVC)

Программная реализация математической модели размещения датчиков обнаружения
беспилотных летательных аппаратов. Этап 1 — пучок дуг между точкой старта **A**
и точкой цели **B** при ограничении запаса хода `L_max`; этап 2 (петляющее
движение) поддержан архитектурно через сменный генератор маршрутов.

Приложение построено по архитектуре **MVC** (Model–View–Controller) на `numpy`
(вычисления) и `matplotlib` (визуализация и анимация). Дополнительных GUI-зависимостей
(tkinter, Qt) не требуется — интерфейс собран на нативных виджетах matplotlib.

---

## 1. Математическая модель (кратко)

Множество допустимых траекторий ограничено **эллипсом достижимости**
`E = { P : |PA| + |PB| ≤ L_max }` с фокусами A, B, большой полуосью `a = L_max/2`,
фокальным параметром `c = |AB|/2` и малой полуосью `b = √(a² − c²)`.

**Обнаружение** — однократный факт входа траектории в зону радиусом `R` хотя бы
одного датчика. Число обнаружений `n(S, γ)` — число РАЗЛИЧНЫХ засёкших датчиков.

**Полезность** расположения `S` на маршруте `γ` (равномерность через сегментацию
маршрута на `L_seg` участков):

```
φ(S, γ) = α₁ · min(n(S, γ), k) / k  +  α₂ · m(S, γ) / L_seg
```

где `m` — число покрытых сегментов, `k` — требуемая кратность. Первое слагаемое
усечено сверху на `k` (избыточные засечки не вознаграждаются), второе реализует
равномерность.

**Критерий** — математическое ожидание полезности `F(S) = 𝔼[φ(S, γ)] → max` при
`|S| ≤ N`, заменяемое эмпирическим средним по накопленной выборке (метод
выборочного среднего, инкрементальный **SAA**):

```
F_t(S) = (1/t) · Σ φ(S, γᵢ),   S_t = argmax_{|S|≤N} F_t(S)
```

Функция `F_t` монотонна и субмодулярна, поэтому применяется **жадный алгоритм** с
гарантией `(1 − 1/e) ≈ 0,632` от оптимума (Nemhauser, Wolsey, Fisher, 1978).
Расположение пересчитывается на каждой итерации по всей накопленной выборке —
усредняется статистика маршрутов, а не координаты датчиков.

**Три режима оптимизации** (веса α₁, α₂):

| Режим | α₁ (кратность) | α₂ (равномерность) |
|---|---|---|
| `distribution` (распределение) | 0,25 | 0,75 |
| `crossing` (пересечение)       | 0,75 | 0,25 |
| `balanced` (сбалансированный)  | 0,50 | 0,50 |

## 2. Архитектура MVC

```
uav_sensor_mvc/
├── config.py                 # параметры модели (Params) и режимы (MODES)
├── main.py                   # точка входа: gui / selftest / render
│
├── model/                    # MODEL — вычислительное ядро (без графики)
│   ├── geometry.py           #   эллипс достижимости
│   ├── trajectories.py       #   генераторы маршрутов (дуги, петли)
│   ├── detection.py          #   модель обнаружения и метрики
│   ├── optimization.py       #   сетка кандидатов + жадный субмодулярный выбор
│   └── simulation.py         #   SimulationModel — состояние и расчёт
│
├── view/                     # VIEW — визуализация (matplotlib)
│   └── view.py               #   SimulationView — сцена, виджеты, показатели
│
├── controller/               # CONTROLLER — управление
│   └── controller.py         #   SimulationController — события, анимация
│
├── examples/                 # примеры рендера (PNG/GIF)
├── requirements.txt
└── README.md
```

- **Model** не зависит от средств отображения, допускает автономный прогон.
- **View** получает готовые данные и вызывает зарегистрированные обработчики; не
  содержит бизнес-логики.
- **Controller** связывает их: обрабатывает события виджетов, ведёт анимацию
  через таймер холста, делегирует расчёт модели, а отрисовку — представлению.

## 4. Запуск

### Интерактивное приложение (по умолчанию)

```bash
python main.py
```

Откроется окно с двумя режимами просмотра и панелью управления.

**Режимы просмотра:**

- **Итеративный** (кнопка «Пуск»/«Пауза», «Шаг») — покадровый показ: пролёт БПЛА
  вдоль маршрута при текущем расположении датчиков, затем перестройка расположения
  с учётом нового маршрута. Темп нарастает с номером итерации. В заголовке —
  текущий процент пути под наблюдением и число пересечений.
- **Пакетный** (кнопка «Пакетно») — полный расчёт по всей выборке: итоговое
  оптимальное расположение и десять наиболее частых пролётов (толщина и цвет линии
  пропорциональны частоте).

**Элементы управления:**

- *Режим оптимизации* — распределение / пересечение / сбалансированный;
- *Модель движения* — дуги (этап 1) / петли (этап 2);
- *Скорость* — число точек траектории за кадр (ускоряет пролёт);
- *Сброс* — очистка выборки; панель *показателей* — сводные метрики и сравнение
  режимов.

### Автономный прогон ядра (без дисплея)

```bash
python main.py --mode selftest --T 400
```

Печатает динамику инкрементального SAA, итоговое расположение датчиков и
сравнение трёх режимов на единой выборке.

### Headless-рендер в файлы (без дисплея)

```bash
python main.py --mode render --T 400 --iters 12 --out examples
```

Сохраняет `batch_<mode>.png` по трём режимам и `iterative.gif`.

### Параметры командной строки

```
--mode {gui,selftest,render}   режим запуска (по умолчанию gui)
--opt {distribution,crossing,balanced}   режим оптимизации
--traj {arc,serpentine}        модель движения (этап 1 / этап 2)
--A X Y   --B X Y              координаты старта и цели
--Lmax    запас хода           --N  число датчиков
--R       радиус обнаружения   --k  требуемая кратность
--Lseg    число сегментов      --T  число итераций накопления
--seed    зерно ГСЧ            --speed  точек за кадр
--iters   итераций для GIF     --out  каталог вывода (render)
```

Пример:

```bash
python main.py --opt crossing --N 6 --R 14 --k 3 --Lseg 10
```

## 5. Выходные показатели

- среднее число пересечений зон обнаружения `𝔼[n(S, γ)]`;
- средний процент длины пути под наблюдением (непрерывное покрытие, отличное от
  дискретного счёта засечек);
- среднее расстояние, пройденное вне зон видимости `𝔼[(1 − c) · L(γ)]`;
- доля маршрутов с выполнением требования не менее `k` засечек.

## 6. Проверочный прогон

Прогон `A=(0,0)`, `B=(100,0)`, `L_max=130`, `N=6`, `R=14`, `k=3`, `L_seg=10`,
`T=400`, `seed=1` воспроизводит эталонную таблицу требований:

| Режим | Покрытие пути | Ср. пересечений | Вне зоны | Доля ≥ k |
|---|---|---|---|---|
| distribution | 75 % | 4,1 | 25,9 | 98 % |
| crossing     | 79 % | 4,4 | 22,1 | 99 % |
| balanced     | 80 % | 4,6 | 20,8 | 99 % |

Воспроизвести: `python main.py --mode selftest --T 400 --seed 1`.

## 7. Этап 2 и расширения

Модель движения отделена от расчёта метрик и размещения. Переключение
`--traj serpentine` заменяет генератор на петляющее движение (синусоида с
закреплёнными концами и ограничением длины), не меняя метрик, целевой функции и
метода оптимизации. Реализованная структура покрытия `CoverageCache`
векторизует жадный выбор (битовые маски сегментов), что делает пересчёт на каждой
итерации быстрым даже при `T ~ 1000`.

## 8. Источники

- Nemhauser, Wolsey, Fisher (1978) — субмодулярная максимизация, гарантия (1−1/e).
- Kumar, Lai, Arora (2007) — барьерное покрытие кратности k.
- Church, ReVelle (1974) — задача максимального покрытия размещением.
- Shapiro, Dentcheva, Ruszczyński — метод выборочного среднего (SAA).
