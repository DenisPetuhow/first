# Переносимые скрипты

> **Что значит «переносимые».** Эти скрипты ничего не знают про БПЛА, весовые сетки и
> тайлы — они работают с документацией и кодом **любого** проекта. Копируются в новый
> проект как есть; настройки под предметную область — в нескольких списках наверху
> каждого файла. Скрипты, привязанные к этой программе, лежат уровнем выше, в
> [tools/](../README.md).
>
> **Правила** к ним — в [теория/переносимое/](../../теория/переносимое/README.md).

Скрипты для шагов сверки, описанной в [CLAUDE.md](../../CLAUDE.md) («ПРОВЕРЬ НА
ДОСТОВЕРНОСТЬ»). Раньше они писались заново при каждой проверке — и каждый раз
повторялись одни и те же ошибки. Теперь сохранены.

| Скрипт | Шаг сверки | Что ловит |
|---|---|---|
| [check_names.py](check_names.py) | 1 · имена | текст ссылается на функцию, параметр или класс, которых в коде уже нет |
| [check_numbers.py](check_numbers.py) | 2 · значения | значение параметра поменяли в коде, а в тексте осталось прежнее |
| [check_claims.py](check_claims.py) | **6 · текст против текста** | один документ говорит «сделано», другой про то же — «задел». С кодом каждый по отдельности не спорит, спорят они друг с другом |
| [docmap.py](docmap.py) | оглавления, ссылки, структура | сдвинувшиеся номера строк, битые ссылки, папка без `README`, файл длиннее 1 500 строк |
| [make_figures.py](make_figures.py) | — (не сверка) | рисунки к пособию: график **считается по той же формуле**, что записана в тексте, поэтому картинка не может разойтись с формулой |

⚠️ **Прогон затратный** (минуты счёта на всю документацию), поэтому запускается не
походя, а по решению — см.
[5_РАЗРЕШЕНИЯ_КОМАНД.md](../../теория/переносимое/5_РАЗРЕШЕНИЯ_КОМАНД.md).

### Где скрипт ищет корень проекта

Не «на N уровней вверх», а **поиском ближайшей папки с маркером** (`CLAUDE.md` либо
`config.py`) — функция `_find_root` в начале каждого файла.

Так сделано после двух одинаковых поломок: при переносе папки счётчик уровней врал
**молча** — скрипт запускался и проверял не те файлы (однажды «нашёл 0 файлов вместо
37»). При переносе в другой проект менять только список маркеров.

Шаги 3 (повторный замер), 4 (сверка формул) и 5 (утверждения о готовности) скриптами
не покрываются: третий и четвёртый пишутся под конкретную правку, пятый
**не автоматизируется в принципе** — там все имена живые и все числа верные, врёт одно
утверждение.

```bash
python tools/переносимое/check_names.py           # методички, ОГРАНИЧЕНИЯ, CLAUDE
python tools/переносимое/check_names.py --all     # плюс журнал и архив
python tools/переносимое/check_numbers.py
python tools/переносимое/check_claims.py          # противоречия между документами
python tools/переносимое/check_claims.py --selftest   # ловит ли он то, ради чего написан
python tools/переносимое/docmap.py --check
```

## Главное правило пользования

**Скрипт сокращает выборку, а не выносит приговор.** Каждую оставшуюся находку смотреть
глазами: часть из них всегда окажется законной.

История цифр показывает, зачем стоило возиться с фильтрами:

| Проверка | Было находок | Стало | Настоящих ошибок |
|---|---|---|---|
| имена | 146 | **0–1** | 1 (`angle_step` вместо `angle_step_deg`) + 1 мёртвая ссылка `etap2` |
| противоречия | сплошное чтение 27 файлов | **1** | 3 при первом применении (задел о сделанном) |

### ⚠️ Слабое место проверки противоречий

`check_claims.py` знает только те механизмы, что перечислены в словаре `TOPICS` —
сейчас их **19**. Механизма, которого в словаре нет, для проверки не существует, и
она честно скажет «противоречий нет». Именно так пропустили расхождение о том, **по
чему ставятся датчики**: §6.2 методички говорил «по весовой карте», правило 1.7
ОГРАНИЧЕНИЙ — «по маршрутам», и оба жили полгода (журнал п. 188).

**Правило:** появился крупный механизм — добавь тему. Проверить, что тема не молчит
из-за опечатки в шаблоне, можно так: если она находит **ноль** абзацев, шаблон
неверен. Все 19 тем сейчас находят от 1 до 167 абзацев.

Второй подводный камень — регистр: поиск нечувствителен к нему, поэтому шаблон
`threat_layers` ловил и словарь весов `THREAT_LAYERS`, и кэш `threat_layers.npz`.
Пришлось указывать расширение явно.
| числа | 50 | **0** | ни одной |

Сокращение дало не «меньше работы», а **возможность доверять результату**: разбирать
146 записей вручную никто не станет, и настоящая ошибка утонет среди шума.

## Что именно отсеивается и почему

**В именах** (`check_names.py`):

* чужие библиотеки и модули — берутся из `import` по всему коду;
* классы Qt — по признаку `Q` + заглавная буква;
* встроенные слова Python и исключения — `True`, `except`, `ValueError`;
* **строковые значения** — `town`, `road_major`, `late`: они лежат в коде внутри кавычек,
  их собирает отдельный проход по литералам;
* имена папок и модулей проекта — `tile_cache`, `view_qt`, `geomap`;
* чужие термины списком `EXTERNAL` — поля рецепта PyInstaller, библиотеки-альтернативы,
  обозначения из формул;
* имена ветки `demo-build` (`HELP_HTML`, `DEMO_*`) — в рабочей ветке их нет намеренно;
* строки с пометкой «удалено / не актуально» — **в окне ±2 строки**: пометка часто
  стоит на соседней строке из-за переноса, и по одной строке не находилась;
* **журнал и архив не проверяются** без флага `--all`: там имена удалённых функций
  законны, о них и написано.

**В числах** (`check_numbers.py`):

* имена короче 4 символов — однобуквенные `N`, `R`, `k`, `T` дают только шум: ловятся
  внутри чужих слов (`LEGEND_PT` → «`T` = 7.8») и в условиях чужих замеров;
* строки с оборотами «возвращает прежнее поведение», «выключается», «было», «замер при»,
  «авто-» — там число описывает вариант или вычисленное значение, а не настройку.
  Сравнение регистронезависимое: «Выключается» с заглавной иначе не совпадает — на этом
  фильтр однажды промахнулся;
* доли против процентов: `0.35` в коде и «35 %» в тексте — одно и то же;
* журнал и архив не проверяются: там числа исторические по определению.

## Если находка выглядит настоящей

1. открыть указанные файл и строку, прочитать **фразу целиком** — часто это оборот,
   который фильтр не знает;
2. проверить имя в коде поиском — возможно, оно просто переехало в другой модуль;
3. если ошибка подтвердилась — исправить текст и **дописать пункт в журнал**;
4. если это законный оборот — **дополнить фильтр в скрипте**, чтобы находка не
   всплывала при каждой следующей проверке.
