# `tools/` — утилиты командной строки

Это вспомогательные программы, которые запускают **руками из командной строки**, а не из
интерфейса. Сама программа (`python main_qt.py`) их не вызывает: они готовят для неё
данные и обслуживают проект.

**Папка поделена по одному признаку — привязке к этому проекту:**

| | Где лежит | Что там |
|---|---|---|
| 🔧 **только для этой программы** | прямо в `tools/` | знают про весовую сетку, тайлы, формат `.osm.pbf` — в другом проекте бесполезны |
| 📦 **переносимое** | [tools/переносимое/](переносимое/README.md) | про документацию вообще, а не про БПЛА: копируются в любой проект как есть |

## 🔧 Только для этой программы

| Утилита | Когда запускать | Что делает |
|---|---|---|
| [build_threat_grid.py](build_threat_grid.py) | появились новые данные местности; **изменились коды типов НП** | `.osm.pbf` → `geo_cache/threat_layers.npz`: раскладывает реки, дороги и застройку по сетке 500×500 м |

## Шесть утилит, написанных, чтобы не писать их заново

Все они раньше набирались на месте — каждый раз заново и с одними и теми же ошибками.
Сколько раз это повторилось, столько раз и потеряно время:

| Утилита | Что раньше делалось руками | На чём спотыкались |
|---|---|---|
| `reference_run.py` | прогон модели с проверкой инвариантов | `add_relief` вместо `set_relief`; `iter_batch(150)` вместо `iter_batch()`; рельеф включали ПОСЛЕ `build()` — и число коридоров «загадочно» менялось |
| `area_bounds.py` | чтение границ `.osm.pbf` | `osmium` не установлен, `pyrosm` заголовок не отдаёт — приходилось каждый раз писать разбор protobuf заново |
| `tile_coverage.py` | подсчёт тайлов в кэше | считали одним числом, а оно обманчиво: 7 % суммарно при 100 % на обзорных зумах |
| `codemap.py` | поиск функции грепом по файлу на 3 000 строк | греп показывает имя, но не сигнатуру — и она достраивалась по памяти |
| `flow_check.py` | прогон «карта → датчики → итерации → сброс» с замером времени | писался вручную ЧЕТЫРЕ раза за один день; первый же запуск готового нашёл дефект, которого не искали |
| `gui_check.py` | проверка вида: рамки, оси, блокировка панели | Qt не поднимался из-за кириллицы в пути к плагинам — приём обхода лежал в `check_env.py` и каждый раз искался заново |

**Правило:** если скрипт понадобился во второй раз — он переезжает сюда. Написать его
набело стоит десять минут, а вспоминать порядок вызовов и ловушки приходится каждый раз.

## build_threat_grid.py — подготовка карты для вкладки 3

```bash
python tools/build_threat_grid.py geo_cache/severodonetsk.osm.pbf
```

Разбор 45 МБ исходных данных занимает секунды, но делать это при каждом запуске
программы незачем — результат складывается в `.npz`, дальше он читается мгновенно.

> ⚠️ **Пересобирать после правки `PLACE_CODES`.** Кэш хранит **уже закодированный** тип
> населённого пункта. Поменяли коды в `config.py`, но не пересобрали — новая кодировка
> молча не подействует, а класс с изменившимся кодом выпадет из градации. На этом уже
> терялось время; правило записано в [ОГРАНИЧЕНИЯ.md](../теория/ОГРАНИЧЕНИЯ.md) 3.10г.

Подробно: [МЕТОДИЧКА_КАРТА_УГРОЗ.md §7](../теория/вкладка_3/МЕТОДИЧКА_КАРТА_УГРОЗ.md) —
как скачать данные под участок; [МЕТОДИЧКА_ЗАГРУЗКА_КАРТ.md](../теория/карты/МЕТОДИЧКА_ЗАГРУЗКА_КАРТ.md) —
где брать `.osm.pbf` и чем резать по границам.

## flow_check.py — сквозной прогон модели без интерфейса

```bash
python tools/flow_check.py            # полный: карта → датчики → итерации → рельеф → сброс
python tools/flow_check.py --quick    # без итераций
```

**Чем отличается от `reference_run.py`.** Тот проверяет ЧИСЛА готового расчёта (коридоры,
датчики, засечка) — он ловит, что модель стала считать иначе. Этот проверяет **порядок и
состояние**: что считается на каждом шаге, сколько это стоит, и что остаётся в модели
после снятия района. Такие дефекты числами не ловятся вовсе — расчёт-то верный, просто
делается не вовремя или не сбрасывается.

Все шесть проверок написаны по реальным поломкам 04.09.2026: маршруты считались при
построении карты; слои и высоты перечитывались с диска каждый раз (9.5 с вместо 0.0);
после снятия района оставались датчики и включённый рельеф; повторное включение рельефа
роняло программу. ⚠️ Первый же запуск нашёл седьмую: район из `config` не приводился к
целому числу ячеек (120.3 км при 241 ячейке = 120.5).

## gui_check.py — интерфейс без экрана

```bash
python tools/gui_check.py
```

Проверяет то, что раньше видел только заказчик на своём мониторе: чёрная рамка области и
синяя рамка района, ноль осей (в углу района или области), блокировка панели пока район
не задан, слой своей карты и его Z, координаты по клику.

⚠️ **Почему Qt поднимается без экрана.** Кириллица в имени пользователя ломает
автоопределение пути к плагинам Qt — «Could not find the Qt platform plugin». Путь
задаётся готовой строкой от Windows (`%APPDATA%`) строго ДО импорта QtWidgets; приём взят
из `check_env.py`. Без него интерфейс не проверить вовсе.

**Чего не заменяет:** скрипт видит состояние виджетов, а не картинку. Что слой включён и
лежит на своём Z — подтвердит; красиво ли это выглядит — нет.

## download_tiles.py — оффлайн-кэш подложки

```bash
# смета: сколько тайлов, мегабайт и минут — ничего не качает
python tools/download_tiles.py --layer osm --pad-km 100 --zmin 6 --zmax 12 --dry-run

# рабочая команда: рамка АКТИВНОГО участка + 100 км, обзорные уровни
python tools/download_tiles.py --layer osm --pad-km 100 --zmin 6 --zmax 12 --delay 0.1

python tools/download_tiles.py --layer satellite --zmax 15 --zmin 9
```

Без интернета программа рисует подложку из этого кэша. Обязательный шаг перед
демонстрацией на чужой машине.

**Ключи `--area` и `--pad-km`** (03.09.2026) избавляют от ручного счёта координат:
рамка берётся из `config.THREAT_AREAS` (без `--area` — активный участок) и раздвигается
на заданное число **километров** (долгота пересчитывается по косинусу широты). `--dry-run`
показывает смету до запуска — цена ошибки в границах высокая, лишний уровень зума даёт
рост вчетверо.

⚠️ **Детальные уровни z13–15 заранее не качают.** На район 295×255 км это 3.4 ГБ и часы
работы, а просмотрят единицы процентов площади. Приложение докачивает их само при
приближении (`geomap.fetch_tile_bytes` кладёт скачанный тайл в кэш) — при условии, что
чекбокс «офлайн» снят. Подробно, с таблицей объёмов —
[план 8, задача 8.1](../теория/планы/8_ПЛАН_КАРТА_И_ИНТЕРФЕЙС.md).

Подробно: [МЕТОДИЧКА_КАРТА.md](../теория/карты/МЕТОДИЧКА_КАРТА.md) — устройство тайлов,
проекция, подбор масштаба.

## Про папку `__pycache__`

Её создаёт сам Python: складывает туда ваш же код, переведённый во внутренний вид
(байт-код, файлы `.pyc`). Нужна для скорости запуска — работа перевода не повторяется
при каждом старте. Python сам следит за свежестью и пересоздаёт файлы после правок.

**Удалять безопасно** в любой момент, **в git не попадает** (записана в `.gitignore`),
**открывать бессмысленно** — внутри двоичные данные. Таких папок в проекте семь: по одной
рядом с каждым каталогом кода.
