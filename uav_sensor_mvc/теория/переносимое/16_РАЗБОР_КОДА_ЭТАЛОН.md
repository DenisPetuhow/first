## 1. Суть

Разбор механизма — **код, а не пересказ**, но с объяснением для того, кто кода не читает. Он лежит в ОДНОМ месте (папка
разборов кода); методички, журнал и планы ссылаются на него, а не пересказывают: копия расходится с кодом вдвое быстрее.

## 2. Формат — у каждого механизма по порядку

1. **где** — `файл :: функция`;
2. **суть простыми словами** — 2–4 фразы без кода и без имён из кода: что делает механизм и зачем — обычными словами
   предметной области, без жаргона и **без сравнений из жизни** («ползунок группы уменьшает прозрачность всех слоёв
   группы в одно и то же число раз: соотношение между слоями сохраняется»);
3. **взаимодействие** — дерево вызовов в блоке ` ```text `: строка на функцию `имя(вход) → что отдаёт, единицы`;
   вложенность — вызов; последняя строка «дальше: …» — кто зовёт и куда уходит результат (раздел или разбор).
   Каркас — `code_blocks.py --stub` (кого зовёт функция и кто зовёт её — из кода), описания — автор. Путь вызовов на
   весь документ (как §0 МОДУЛЬ_ВЫВОДА_РИСУНКИ) связывает разделы, дерево — функции внутри раздела (заказчик 11.10.2026: «в блоке 2 просто пишешь функции, но надо ещё добавить блок взаимодействие функций — что делает вкратце и как потом взаимодействует»);
4. **как работает** — 3–6 строк уже с именами: почему так, а не перечень функций — он в дереве;
5. **сам код** с комментариями к функциям, переменным, циклам, ветвлениям — **вставленный из модулей скриптом** по
   пометке над блоком (§3), а не скопированный руками;
6. **пример с расчётом** — по шагам, с арифметикой («0,62 × 0,5 = 0,31»), числа — из замера или вызова самой функции;
   условные — так и помечать, оценку — «оценка по формуле»;
7. **где легко сломать** — таблица «что сделать нельзя → почему».

## 3. Пометка над кодом и сверка

Разделение труда: **объяснение пишет человек (или Claude) прямо в `.md`, скрипт только вставляет код и сверяет.** Над
каждым блоком кода — пометка, что в нём показано:

* функция или класс — `<!-- код: src/a.py::Класс.метод -->` (у свойства — чтение и запись вместе);
* кусок — `<!-- код: src/a.py::функция | от: строка | до: строка -->`: границы по началу строки с этим текстом, «до»
  не входит; кусок файла — то же без `::`.

Скрипт (`code_blocks.py`) находит функцию разбором файла (`ast`) — без импорта модулей, поэтому годится для любого
проекта на Python — и кладёт под пометку её текущий текст. `--check` не пишет, а сравнивает: «код изменился» или «битая
пометка» (нет файла, имени, границы, блока под пометкой) — код возврата 1; входит в единый запуск проверок документов.
⚠️ Скрипт следит только за кодом: устаревшее объяснение или пример он не найдёт — это работа автора после его сигнала.

**Порядок работы над разбором:** прочитать функцию и её вызовы → `--stub файл::имя` (заготовка по §2: каркас дерева
вызовов из кода, пометка, код) → написать суть, взаимодействие, «как работает», «где сломать» → числа примера — вызовом функции на настоящих данных → запустить
скрипт (вставит код) → оглавления. Учёт: `--list файл.py` — в каких разборах показан код файла (смотреть до правки
кода); `--unmarked` — блоки, скопированные руками, и совпадают ли они с кодом.

## 4. Пример

Разбор «распределение по целям»: суть («ПВН делятся по приоритету, но не больше потребности цели»), код `allot` из
модуля, таблица из пяти случаев, каждый проверен вызовом функции (бюджет 14, потребности 14 и 3 → 11 · 3). После
перестройки папок `--check` показал «46 блоков кода — разошлось 0»: разборы пересобраны той же командой. Перевод на
пометки: 4 разбора, 89 блоков; без пометок текст совпал с прежним байт в байт, код — с `inspect` во всех 89.

| Где легко сломать | Почему |
|---|---|
| копировать код в разбор руками | через неделю разбор описывает чужой код |
| писать пример «из головы» | правдоподобное число неверно; проверять вызовом функции |
| перечислять функции раздела без связей | видны детали, но не путь данных: кто кого зовёт и куда уходит результат (11.10.2026) |
| держать скрипт в черновиках сессии | после `/clear` код в разборах нечем сверить, и они молча стареют |
| держать текст разбора внутри скрипта | править неудобно, и скрипт годится только для своих разборов (так было до журнала 371) |
| править код в блоке под пометкой руками | следующий запуск вернёт код из модуля; поясняют — текстом рядом или комментарием в коде |
| считать «0 расхождений» проверкой объяснения | скрипт сверяет код, а не слова: объяснение у обновлённого блока перечитать |
