# 2 · Оглавления и поиск: как перестать открывать файлы целиком

> **Переносимый документ.** Скрипт к нему — [`tools/переносимое/docmap.py`](../../tools/переносимое/docmap.py):
> делает оглавления с номерами строк, проверяет битые ссылки и структуру папок.
> Пояснение к скриптам — [tools/переносимое/README.md](../../tools/переносимое/README.md).
>
> Соседние части: [1 · контекст и навигация](1_КОНТЕКСТ_И_НАВИГАЦИЯ.md) ·

```bash
python tools/переносимое/docmap.py           # пересобрать оглавления + отчёт
python tools/переносимое/docmap.py --check   # ничего не менять, код 1 при проблеме
```

## 1. Указатели вместо файлов

Журнал на несколько тысяч строк нельзя открывать ради одного вопроса. Поэтому у него —
**отдельный файл-оглавление**, который читается первым:

| Что в указателе | Зачем |
|---|---|
| таблица «диапазон пунктов → тема → **номер строки**» | открыть журнал сразу с нужного места |
| **точное** число строк — только здесь | иначе каждая запись в журнал делает неверными все файлы, где оно продублировано |
| таблица «симптом → номера пунктов» | вход по вопросу заказчика, а не по структуре |
| ключевые слова у каждого раздела | попасть в тему, даже если она названа иначе |
| правило обновления | чтобы указатель не отстал |

Тот же приём — для кода: таблица «механизм → `файл :: имя`». Она заменяет поиск грепом
по всему проекту: помощник сразу открывает нужную функцию.

**Номера строк устойчивее, чем кажется.** Журнал дописывается в конец, поэтому строки
ранних пунктов не сдвигаются. Пересчёт нужен, только если правили середину.

**Ссылаться на РАЗДЕЛ, а не на файл.** `МЕТОДИЧКА §12.0` вместо просто `МЕТОДИЧКА`:
разница между «прочитать 40 строк» и «прочитать 1 300».

## 2. Автоматизировать то, что устаревает

Номера строк — самая полезная часть указателя и самая быстро устаревающая. Ручное
оглавление начинает врать после первой же правки середины файла, а враньё в навигации
хуже её отсутствия: помощник открывает не тот кусок и делает выводы по чужому тексту.

Поэтому оглавления **генерируются скриптом** (у нас — `tools/переносимое/docmap.py`, ~200 строк):

| Что делает | Зачем |
|---|---|
| вставляет блок между маркерами `<!-- ОГЛАВЛЕНИЕ -->` … `<!-- /ОГЛАВЛЕНИЕ -->` | остальной текст файла не трогается |
| считает номера строк по тексту БЕЗ старого блока, **прибавляя высоту нового** | оглавление не сдвигает само себя, но и не врёт на свою высоту (см. ниже) |
| пропускает заголовки внутри ``` | примеры разметки не попадают в оглавление |
| проверяет битые ссылки и структуру папок | папка без `README`, файл длиннее порога деления |
| режим `--check` возвращает код 1, если что-то не так | встраивается в проверку достоверности ([документ 3](3_СВЕРКА_С_КОДОМ.md)) |
| порог по размеру (300 строк) | коротким файлам оглавление только мешает |

**Требование к такому скрипту — идемпотентность:** повторный запуск не меняет ни одного
файла. Проверяется прогоном дважды со сравнением содержимого.

**⚠️ Ловушка, на которой я попался.** Номера строк считались по тексту БЕЗ блока
оглавления — «чтобы блок не сдвигал сам себя». Логика верная ровно наполовину: читатель
открывает файл **вместе с блоком**, и всё, что ниже места вставки, уезжает вниз на его
высоту. Оглавления врали на 20–44 строки — **во всех файлах сразу**, и `--check`
рапортовал «актуально»: он сверял блок с тем, что генератор считает правильным, а не с
файлом. Ошибку нашёл заказчик, открыв документ по указанному номеру.

Отсюда главное требование к любой такой автоматике:

> **Проверять РЕЗУЛЬТАТ, а не намерение.** Проверка должна открыть готовый файл так же,
> как его откроет читатель, и убедиться, что раздел лежит на обещанной строке. Сверка
> «сгенерированное совпадает с тем, что сгенерировал бы я» не поймает систематический
> сдвиг: она подтверждает лишь то, что генератор согласен сам с собой.

Та же проверка сразу нашла и вторую поломку — задвоенный заголовок, оставшийся от
деления файла на части.

Хорошее правило отбора: **автоматизировать надо то, что зависит от расположения текста**
(номера строк, списки разделов, перечни файлов), и не пытаться автоматизировать то, что
зависит от смысла (актуальность утверждений — см. [3_СВЕРКА_С_КОДОМ.md §2](3_СВЕРКА_С_КОДОМ.md)).

## 2а. То же самое, но для КОДА: карта кода

Оглавления решают проблему больших документов. С кодом она ровно та же, только острее:
в этом проекте `model/threat_grid.py` — около 3 000 строк ≈ **39 тыс. токенов**, пятая
часть окна (точное число — в самой карте, оно там пересчитывается). Открывать целиком нельзя, а без оглавления остаётся греп.

**Греп — и есть источник выдуманных сигнатур.** Он показывает, что имя существует, но не
показывает аргументы; дальше вызов достраивается по памяти. У нас так дважды: `add_relief`
вместо `set_relief`, `iter_batch(150)` вместо `iter_batch()` — и время ушло на разбор
собственной ошибки. Ошибка дешёвая по отдельности и дорогая по накоплению.

Скрипт [`codemap.py`](../../tools/переносимое/codemap.py) собирает из исходников папку
`теория/карта_кода/` — устроенную **как журнал**: `README.md` со сводкой и характеристиками
+ части `КАРТА_N.md` с самими таблицами «строка · сигнатура · первая строка докстринга»,
разделами по якорям-комментариям и строкой «**отдаёт наружу**» (какие имена модуля реально
импортируют другие модули).

Два порога, оба взяты у документов:

| Порог | Значение | Что делает |
|---|---|---|
| подробного описания | **300 строк** | модуль короче — не расписывается по функциям, а идёт в README одной строкой со списком имён: открыть такой файл целиком дешевле (≈4 тыс. токенов), чем описывать |
| деления на части | **1 500 строк** | часть карты не растёт бесконечно; модуль целиком лежит в одной части — рвать таблицу функций посередине нельзя |

⚠️ **ДВА ГЕНЕРАТОРА НЕ ДЕЛЯТ ОДИН ФАЙЛ.** `docmap.py` вставляет оглавления во все
документы длиннее 300 строк — и успел вставить своё оглавление в сгенерированную карту.
Дальше это ходило бы по кругу: `docmap` добавляет блок, `codemap` затирает его при
пересборке, `--check` обоих ругается. Папка карты внесена в исключения `docmap`
(`SKIP_GENERATED`). Общее правило: **у каждого сгенерированного файла ровно один хозяин**.

| | Стоимость |
|---|---|
| прочитать `threat_grid.py` целиком | ≈39 тыс. токенов |
| его раздел в карте кода | **≈2.6 тыс.** — в пятнадцать раз дешевле |
| вся карта проекта (42 файла, 16 тыс. строк кода) | **≈6 тыс.** (была 17 тыс., пока в неё шли и мелкие модули) |

**В README указана и строка**, с которой раздел модуля начинается в своей части:

```
| `model/threat_grid.py` | 2986 | 38818 | 2 | 126 | КАРТА_1.md стр. 10 |
```

Путь получается сквозным, без единого лишнего чтения: README → часть с нужной строки →
номер строки функции → сам модуль с этой строки.

⚠️ **Строки считаются ВМЕСТЕ с шапкой части** — читатель открывает файл целиком, а не
«тело без заголовка». Ровно здесь однажды ошибся `docmap`: считал строки без блока
оглавления, и номера врали на его высоту во всех файлах сразу.

Чтобы это не повторилось, генератор **сверяет собственный результат**: открывает каждую
часть на строке, обещанной в README, и проверяет, что там стоит заголовок нужного модуля.
Печатается «строк README сверено с частями: 14»; при расхождении — список и код возврата 1.
Проверено искусственным сдвигом на одну строку: все 14 записей были помечены как неверные.

Порядок работы тот же, что с документами: **карта → `Read` с `offset`**. И то же правило:
карта генерируется, руками её не правят — номера строк сдвигаются при каждой правке.

⚠️ **Чего карта не заменяет.** Она отвечает «где это и как называется», но не «почему так
сделано». Причины, отвергнутые варианты и замеры живут в журнале и методичках; карта лишь
приводит к нужной строке.

## 2б. Срок годности контекста: измерять, а не вспоминать

У документации есть срок годности, и его видно по git. Замер этого проекта: файлы модели
и представления менялись **61 раз**, а `СТРУКТУРА_ПРОЕКТА.md`, где руками выписан
**221 объект из кода**, — **13 раз**. Сорок восемь правок прошли мимо документа, который
их описывает; какие из 221 имени уже неверны — неизвестно, пока кто-нибудь не поверит
документу и не ошибётся.

`codemap.py --stale` печатает список кандидатов на сверку:

```
~ теория\вкладка_3\ВКЛАДКА_3_КАК_РАБОТАЕТ.md   (правился 2026-08-30)
    threat_view.py: 1, config.py: 1
```

Читается так: «этот документ сам упоминает `threat_view.py`; после последней правки
документа тот менялся 1 раз — сверь». Связь берётся **из текста документа** (какие файлы
он упоминает), а не назначается вручную: список не надо поддерживать.

⚠️ Первая версия считала коммиты по всему коду сразу — и была бесполезна: одно и то же
число у всех документов, включая те, что кода не касаются вовсе. Полезным отчёт делает
именно адресность. Проверено на деле: отчёт указал на `ВКЛАДКА_3_КАК_РАБОТАЕТ.md`, и там
действительно **ноль** упоминаний механизма, добавленного двумя днями раньше.

**Что это НЕ делает:** не правит документы и не считает их неверными. Число — повод
открыть и сверить, не более. Автоматика знает про расположение текста, а не про смысл.

## 2в. Когда карты мало: граф связей — задел

Если описаний становится так много, что даже указатели не помещаются в окно, следующий
шаг — **граф**: узлы (функции, документы, сущности), рёбра (вызовы, ссылки, упоминания) и
запросы к нему вместо линейного чтения. В известном разборе такой подход применяли к базе
из 93 файлов и 2,4 млн слов — получилось 3 508 узлов и 7 016 рёбер.

**Нам это пока не нужно, и вводить не следует:** 16 тыс. строк кода и 21 тыс. строк
документации закрываются двумя оглавлениями (`docmap` + `codemap`) общей ценой ≈17 тыс.
токенов. Граф стоит собственной поддержки: его надо строить, хранить и синхронизировать,
иначе он устареет так же, как ручное оглавление. Признак, по которому к нему стоит
вернуться: **карта кода перестала помещаться в окно** либо связи «кто кого зовёт» стали
важнее, чем «где это лежит».

## 3. Как писать, чтобы находилось

Пять приёмов, каждый проверен на практике:

1. **Устойчивые номера разделов.** На них ссылаются другие файлы, поэтому номер —
   часть интерфейса. Менять его дороже, чем терпеть кривоватую нумерацию: у нас
   подраздел `§2.0` физически стоял после `§3`, и правильным решением было переставить
   БЛОК, сохранив номер, а не перенумеровать.
2. **Уникальные заголовки.** Два раздела с номером 2.1 в одном файле делают ссылку
   неоднозначной. Проверяется одной командой `grep -n "^#\{2,3\} "`.
3. **Точные имена из кода** — `_cost_mul`, `THREAT_VILLAGE_FLOOR`, а не «коэффициент
   штрафа». Имя грепается, описание — нет.
4. **Ключевые слова синонимами.** Заказчик спросит «почему хвост торчит из цели», а в
   методичке написано «заход с обратной стороны». Добавьте оба.
5. **Условия замера рядом с числом** — см. [1_КОНТЕКСТ_И_НАВИГАЦИЯ.md §3.2](1_КОНТЕКСТ_И_НАВИГАЦИЯ.md).
