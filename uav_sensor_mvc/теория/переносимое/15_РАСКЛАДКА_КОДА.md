## 1. Суть

Код программы — в **одной папке `src/`**, внутри — пакеты по слоям (модель, показ, связь) и **подпапки по категориям**:
«не дробить ради цифры, но и не держать в одной куче». Точки входа (`main.py`) и проверки (`tools/`) лежат в корне и
добавляют `src/` в `sys.path`, поэтому пакеты импортируются **без** `src.`. Данные (кэши, слои, файлы пользователя) — в
корне рядом с `src/`, а их корень считает **один модуль** `src/project_root.py`.

## 2. Правила

| Правило | Почему |
|---|---|
| имя папки кода — латиницей (`src`), не `code` | кириллица в путях импорта ломает сборку `.exe`; `code` — модуль стандартной библиотеки |
| модель (`model/`) не импортирует интерфейс | модель проверяется скриптом без экрана |
| подпапки — по категориям: вкладки, второстепенные окна, карта, общее; в модели — по задачам | 26 файлов в одной папке не находятся глазами |
| новый крупный функционал — **отдельный файл в своей подпапке** | связанное лежит вместе, файл не пухнет; порога «N строк» нет |
| параметры — только в одном файле (`config.py`) | число, разбросанное по коду, меняют в одном месте и забывают в другом |
| данные, привязанные к сущности (участку, проекту), — в **её папку** | переносится и удаляется одной папкой |
| корень данных — `project_root.ROOT`, не «два уровня вверх от себя» | после переноса файла в подпапку такой путь молча указывает не туда |

## 3. Как переложить разросшийся код — порядок, проверенный на 60 файлах

1. **Разведка скриптом:** назначение каждого модуля, относительные импорты, `from pkg import mod`, строки с именами
   модулей, `sys.path` в инструментах, **места, где путь считается от `__file__`**.
2. **Перепись импортов скриптом:** относительные → абсолютные с новыми путями; пути и имена модулей в комментариях и
   строках — **только внутри комментариев и строк** (`tokenize`), иначе пострадает код вида `self.model.targets`.
3. **Перенос `git mv`** — история файлов сохраняется.
4. **Корень данных** — один модуль; в собранной `.exe` — прежняя папка распаковки.
5. **`src/` в `sys.path`** у точек входа и всех инструментов; у **дочерних процессов** — через `PYTHONPATH`.
6. **Проверки:** компиляция всех файлов, импорт каждого модуля без экрана, самопроверка точки входа (данные находятся),
   весь набор проверок программы и документов.
7. **Документы:** пути — скриптом во всех текстах, включая журнал, с отметками «Правился»; дерево структуры —
   пересобрать из прежних описаний.

## 4. Пример

Перенос 60 файлов: компиляция 105 файлов и импорт 68 модулей — без ошибок, самопроверка нашла данные в корне. Проверки
поймали две поломки, которых не видит компиляция: дочерний процесс без `src/` в пути и проверка, искавшая `config.py` в
корне. Проверка оформления кода приняла бы перенос за 22 «новые» строки — научена различать правку только путей.

| Где легко сломать | Почему |
|---|---|
| считать корень от `__file__` в каждом модуле | перенос в подпапку молча уводит пути к данным |
| переписывать имена модулей регуляркой по всему коду | заденет атрибуты с тем же именем (`self.model.targets`) |
| забыть дочерние процессы и строки `importlib` | компиляция и импорт их не проверяют |
| переносить без проверки точки входа | программа не стартует, хотя все проверки модели зелёные |
