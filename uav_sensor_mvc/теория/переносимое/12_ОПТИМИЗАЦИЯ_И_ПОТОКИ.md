# Оптимизация и фоновые потоки — как планировать и делать, чтобы сразу правильно

> **Правился:** 02.10.2026 — правило заведено по поручению заказчика: «по правилам оптимизации тоже — по плану реализации
> пиши, чтобы сразу делать правильно (переносимое/)» (план 13.5, 13.5.13; журнал 360). Основа — опыт шагов 5, 6, 9, 11
> ([оптимизация/](../оптимизация/README.md)) и разбор кода [код/ОПТИМИЗАЦИЯ_В_КОДЕ](../код/ОПТИМИЗАЦИЯ_В_КОДЕ.md).

> **Переносимое**: правило не привязано к этому проекту — годится для любого настольного расчётного приложения на
> Python + Qt + numpy.

## 1. В плане — раздел «Время и память» у каждой задачи с кодом

Каждая задача плана, которая трогает расчёт или показ, получает строку (в разделе «Как решать» —
[7_СОСТАВЛЕНИЕ_ПЛАНА §3](7_СОСТАВЛЕНИЕ_ПЛАНА.md)):

| Что записать | Пример |
|---|---|
| **где тратится** время и память (замер ДО, а не догадка) | «кэш строится по всей выборке — 70–78 % пересчёта» |
| **в каком потоке** это будет работать | «главный — только рисует; расчёт — `_run_async` или свой поток» |
| **как растёт** с размером данных | «линейно по T; пересчётов T / 5 — сумма квадратична» |
| **чем проверить, что числа не сдвинулись** | «до бита: позиции, типы, отчёт — против кода без правки» |

⚠️ Без замера пишется «оценка по формуле», а не число.

## 2. Приёмы ускорения — по порядку предпочтения

1. **Не считать лишнего**: заранее не нужное — по запросу, повторяющееся — из кэша, растущее — нарастающим итогом
   (шаг 9: строки старых маршрутов не пересчитываются — пересчёт ×5).
2. **Не копировать**: держать массивы в типе хранения, считать на месте (`out=`, `*=`), большие таблицы — кусками
   (шаги 5–6: пик 649 → 216 МБ).
3. **Не рисовать заново**: дописывать к нарисованному (накопленные линии — кусками, 13.5.11б).
4. **Унести из главного потока** то, что всё равно долго (шаг 11).
5. Только потом — параллельный счёт в нескольких процессах: он меняет порядок случайных чисел (эталоны переснимать).

## 3. Фоновые потоки — пять правил

1. **Считать в фоне — принимать в главном.** Фоновая функция трогает только модель и numpy, ни одного окна; результат
   — сигналом с `QueuedConnection`, рисует главный поток.
2. **Одна модель — одна пишущая сторона.** Пока фон меняет модель, всё, что её меняет в главном, сначала
   останавливает фон и ждёт его (`stop()` + `wait()`); кнопки обстановки блокировать без курсора ожидания.
3. **Договорённости вместо замков**: фон не уходит далеко вперёд показа (семафор), после крупной правки модели ждёт,
   пока главный её нарисует (событие).
4. **Один розыгрыш — один поток.** Тогда порядок случайных чисел прежний, и выборка совпадает до бита — это проверяется
   прогоном с закреплённым зерном против прежнего кода.
5. **Новый механизм — новый файл** (поток итераций — `controller_qt/iter_worker.py`), в коде у функции, идущей в фоне, —
   пометка «окна не трогает».

## 4. Проверки — какие и почему

| Проверка | Ловит |
|---|---|
| **до бита** против кода без правки (одна выборка, закреплённое зерно) | ускорение, которое тихо сдвинуло результат |
| **время и пик памяти** до и после (`tracemalloc`, `time`) | ускорение, которого нет |
| **занятость главного потока**: самый долгий проход цикла событий | «окно глючит» — то, что видит человек |
| **повторяемость**: два прогона подряд с одним зерном | состояние, которое сброс не обнуляет (13.5.11: история стартов) |

⚠️ Упало сравнение «до бита» — сперва прогнать два раза **старый** код: если и он расходится сам с собой, дело не в правке.
