# 11. Настройка Claude Code: разрешения, хуки, память

> **Правился:** 22.09.2026 — документ заведён по итогам проверки `/doctor`: разобраны шесть
> находок, две из них исправлены механикой (хук и точные разрешения), а не текстом правила.

> **Зачем этот документ.** Правило, записанное только словами, нарушается — и каждое
> нарушение стоит заказчику запроса на подтверждение. Проверка 22.09.2026 намерила цену:
> **58 отказов из 130 за 23 дня** пришлись на одно-единственное правило, записанное в двух
> местах и всё равно не соблюдавшееся. Здесь — что нашлось, почему так вышло и чем
> лечится; плюс правила самой настройки, чтобы не наделать дыр, латая неудобства.

## 1. Где что лежит

| Слой | Файл | Что задаёт | В git? |
|---|---|---|---|
| **пользователь** | `~/.claude/settings.json` | разрешения и режим для ВСЕХ проектов | нет |
| **проект** | `.claude/settings.json` | разрешения команды, общие для всех | ✅ да |
| **локальный** | `.claude/settings.local.json` | личные разрешения и хуки этой машины | нет |
| **память проекта** | `CLAUDE.md` | правила, которые читаются в НАЧАЛЕ каждой сессии | ✅ да |
| **память пользователя** | `~/.claude/CLAUDE.md` | то же, но во всех проектах | нет |
| **команды** | `.claude/commands/*.md` | слэш-команды проекта (`/bez-ostanovok`) | ✅ да |

⚠️ **Порядок важен: пользователь → проект → локальный**, и каждый следующий перекрывает
предыдущий. Отсюда практическое следствие: `defaultMode`, заданный в checked-in
`.claude/settings.json`, отменяет пользовательскую настройку — менять надо там же, где
задано, а не в своём файле.

## 2. Что нашла проверка 22.09.2026 и как исправлено

Замер: 5 сессий, 23 дня, **130 отказов** (когда команда не выполнилась и потребовала
решения человека).

| # | Что было не так | Почему так вышло | Чем исправлено |
|---|---|---|---|
| **1** | ⭐ **58 отказов из 130 (45 %)** — на командах вида `cd "путь" && …` | Разрешения сверяются с **началом строки**: правило `Bash(git status:*)` не срабатывает на `cd "…" && git status`. Правило «не предварять `cd`» было записано в `CLAUDE.md` **и** в памяти сессии — и всё равно нарушалось, потому что держалось на внимании | **Хук** [hook_bez_cd.py](../../tools/переносимое/hook_bez_cd.py) на `PreToolUse`: команда с приставкой отклоняется ДО запуска, человека не спрашивают |
| **2** | Проверочные скрипты (`reference_run`, `docmap`, `check_*`) требовали подтверждения каждый раз | Разрешений на них не было вовсе: `python` целиком аллоулистить нельзя — это выполнение любого кода | **24 точных** правила в `.claude/settings.local.json` — по строке на скрипт |
| **3** | В разрешениях стояли `Bash(git fetch:*)` и `PowerShell(git fetch:*)` | `git fetch` **выглядит** безобидным, но выполняет произвольные команды: `--upload-pack='<команда>'` и адреса вида `ext::` | Правила сняты. `fetch` теперь спрашивает, как `push` |
| **4** | `CLAUDE.md` — 35 982 символа (≈ 9 000 токенов в каждой сессии) | Часть содержимого дублировала документы, ссылка на которые стояла строкой рядом: дерево папок, перечень файлов по вкладкам, пять абзацев обоснований проверок | Ужат до 30 978 символов (**−5 004**, ≈ 1 250 токенов на сессию). Убраны только дубли и то, что выводится из кода; правила и запреты целы |
| **5** | `ЖУРНАЛ_6.md` — 1 511 строк при правиле «больше 1 500 — заводить следующую часть» | Живая часть растёт по пункту в день | ⬜ **не сделано**: деление — отдельная работа (перенос пунктов и правка ссылок), решение за заказчиком |
| **6** | 16 синхронизированных навыков с claude.ai — ≈ 2 960 токенов в каждой сессии, ни одного запуска за 23 дня | Синхронизация включена по умолчанию, скиллы приезжают все разом | ✅ **оставлены сознательно**: `docx`, `pdf`, `xlsx` нужны для работы с Word-документами проекта. Отключаются `syncClaudeAiSkills: false` |

### Что из этого правило, а не случай

⭐ **Правило, которое нарушается при записанном тексте, надо переводить в механику.**
Находка 1 — образец: текст был, повторён дважды, и не работал. Заработало, только когда
проверка стала автоматической. То же и с документацией: `docmap --check`, `check_names`,
`check_dates` существуют ровно потому, что «помнить» не получается.

## 3. Правила настройки разрешений

### 3.1. Точные правила, а не `:*`

⚠️ **Шаблон сверяется с началом строки и НЕ разбирает аргументы.** Поэтому
`Bash(python tools/x.py:*)` разрешает и вот это:

```
python tools/x.py && rm -rf что-угодно
```

— строка начинается с разрешённого текста, остальное шаблон не смотрит. Ровно та же
механика, что порождала находку 1. Вывод: **писать полную команду целиком**, по правилу
на каждую форму запуска:

```json
"Bash(python tools/reference_run.py)",
"Bash(python tools/reference_run.py --quick)"
```

Двадцать точных правил лучше одного шаблона с `*`.

### 3.2. Что не аллоулистить никогда

| Нельзя | Почему |
|---|---|
| `python`, `node`, любой интерпретатор | выполнение произвольного кода |
| `npm run *`, `make *` | цель задаётся в файле проекта, который можно подменить |
| `curl`, `wget` | умеют POST — то есть вынос данных наружу |
| `git fetch`, `git pull` | `--upload-pack` и `ext::` выполняют команды (находка 3) |
| `find -exec`, `find -delete` | выполнение и удаление |
| `gh api *` | «только GET» шаблоном не выразить — тот же шаблон поймает POST и DELETE |

**Читающие команды** (`git status`, `git log`, `git diff`, `ls`, `cat`) разрешать можно —
они ничего не меняют. ⚠️ Но и у них есть пишущие флаги: `git log --output=<файл>` пишет
файл. Это ещё один довод за точные правила.

### 3.3. Куда писать

* **личные удобства этой машины** → `.claude/settings.local.json` (в git не идёт);
* **правила для всей команды** → `.claude/settings.json` (checked-in, виден в обзоре);
* **на все проекты сразу** → `~/.claude/settings.json`. ⚠️ Осторожно: правило, выданное
  здесь, действует и в чужих репозиториях.

## 4. Хуки: когда и как

**Хук** — команда, которую Claude Code запускает сам на событии. Для правил вида «так
делать нельзя» подходит `PreToolUse`: он получает вызов ДО выполнения и может его
отклонить.

```json
"hooks": {
  "PreToolUse": [
    { "matcher": "Bash|PowerShell",
      "hooks": [ { "type": "command",
                   "command": "python tools/переносимое/hook_bez_cd.py",
                   "timeout": 10 } ] }
  ]
}
```

Хук читает JSON со stdin и либо молчит (команда идёт дальше), либо печатает отказ:

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse",
                        "permissionDecision": "deny",
                        "permissionDecisionReason": "…за что отказ…"}}
```

### Три правила, без которых хук вреден

1. ⚠️ **Своя ошибка = пропустить команду.** Хук висит на КАЖДОМ вызове; если он падает на
   неожиданном входе, встаёт вся работа. Весь разбор — в `try`, в `except` — тихий выход;
2. ⚠️ **Быстро.** `PreToolUse` блокирует каждый вызов. Холодный запуск Python ≈ 0.1 с —
   терпимо; сетевой запрос или установка пакетов здесь недопустимы;
3. ⚠️ **Проверять до включения** — подать на вход те случаи, которые он будет видеть:
   нарушение (ждём отказ), обычная команда (ждём тишину), похожий, но законный случай
   (`grep -n "cd "` — тишина), мусор (тишина). Четыре прогона занимают минуту и ловят
   ошибку, которая иначе остановит работу целиком.

## 5. Память: что в ней держать

`CLAUDE.md` читается в начале КАЖДОЙ сессии, поэтому каждая его строка стоит токенов
всегда. Правило отбора простое: **можно ли это восстановить, прочитав код?**

| Убирать | Оставлять |
|---|---|
| дерево папок, перечень файлов (`ls` покажет) | грабли: «выглядит безопасно, а делает вот что» |
| список библиотек (в манифесте) | почему сделано именно так |
| куски, дублирующие документ со ссылкой рядом | соглашения, отличающиеся от общепринятых |
| общие советы («пишите чисто») | ⚠️ запреты «никогда не делай X» — **держать всегда** |

⚠️ **Предупреждение о длине** появляется примерно на **40 000 символов**. До него файл
всё равно стоит денег: 30 000 символов ≈ 7 500 токенов в каждой сессии.

## 6. Как проверить настройку

```bash
claude --version              # версия; обновление — claude update
```

Команда `/doctor` сама пройдёт всё: установку, разрешения, хуки, память, неиспользуемые
расширения, частые отказы. Она **ничего не меняет без подтверждения** и показывает отчёт
до правок.

⚠️ **Ловушки этой машины** (Windows, кириллица в пути):

* `jq` не установлен — разбирать JSON через `python -c` или скриптом;
* вывод русского текста уходит в cp1251 — в скриптах ставить
  `sys.stdout.reconfigure(encoding="utf-8")`, иначе в отчёте будут «крякозябры»;
* путь `C:\Users\Денис` ломает сборку `.exe` (Qt отдаёт его в системной кодировке) —
  собирать из `C:\uav_build\`.
