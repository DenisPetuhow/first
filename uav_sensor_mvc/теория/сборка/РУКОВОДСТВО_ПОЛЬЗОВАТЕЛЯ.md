# Карта угроз — руководство пользователя

> Программа определяет, где разместить датчики обнаружения, чтобы засекать беспилотные
> аппараты при минимальном числе датчиков. Расчёт ведётся по данным реальной местности
> выбранного участка (реки, дороги, ЛЭП, застройка, рельеф, населённые пункты).

---

## 1. Запуск

1. Распакуйте архив **`Карта угроз.zip`** в любую папку — например `C:\Карта угроз\`.
2. Откройте распакованную папку и запустите **`Карта угроз.exe`**.

```
Карта угроз\
├── Карта угроз.exe     ← запускать это
└── _internal\          ← служебная папка, не удалять и не переименовывать
```

**Что происходит при запуске:** несколько секунд показывается заставка с эмблемой,
затем открывается окно программы, развёрнутое на весь экран.

**Требования:** Windows 10 или новее, 64-разрядная. Ничего устанавливать не нужно —
ни Python, ни библиотек. **Интернет не нужен**: карта-подложка берётся из встроенного
кэша.

⚠️ **Папку `_internal` нельзя удалять, переименовывать или переносить отдельно от
`.exe`** — в ней лежит всё, что нужно программе для работы. Копировать и передавать
программу можно только целиком, вместе с этой папкой.

⚠️ **Windows 7 не поддерживается.** На ней программа не запустится: причина в самом
языке, на котором она написана, а не в настройках. Для Win7 нужна отдельная сборка.

---

## 2. Что программа делает

Задача: неизвестно, откуда и куда полетит аппарат — известна только местность и
охраняемая цель. Программа решает её в три шага:

```
① по цифровой карте (реки, дороги, ЛЭП, застройка, рельеф)
   строится ВЕСОВАЯ КАРТА: где пролёт правдоподобен
                    ↓
② по весовой карте набирается ВЫБОРКА МАРШРУТОВ —
   сотни правдоподобных траекторий, а не одна «средняя»
                    ↓
③ по выборке РАССТАВЛЯЮТСЯ ДАТЧИКИ: каждый следующий
   ставится туда, где он добавляет больше всего покрытия
```

## 3. Порядок работы

| Шаг | Кнопка | Что происходит |
|---|---|---|
| 1 | **Построить карту** | цифровые слои накладываются на сетку 500 м, у каждой ячейки появляется вес |
| 2 | **Добавить рельеф** | карта пересобирается с учётом высот: та же дорога в низине «весит» больше, чем на гребне. Маршруты и датчики при этом сбрасываются — они были рассчитаны по прежней карте |
| 3 | **Указать цель** | щелчок по карте задаёт охраняемый объект |
| 4 | **Задать сектор** | щелчок по **краю** карты задаёт направление, откуда может появиться аппарат: от цели к указанной точке проводится ось, от неё откладывается по 30° в каждую сторону. На попавшем в сектор крае отбираются **пять точек входа** |
| 5 | **Применить** | ⚠️ только теперь считаются маршруты. Щелчки на шагах 3–4 лишь задают обстановку |
| 6 | **Пуск / Шаг / Пакетно** | накопление выборки маршрутов. «Пуск» показывает полёт, «Пакетно» считает всё сразу |
| 7 | **Расставить датчики** (или «Исходные данные» → «Задать позиции») | размещение датчиков — алгоритмом или вручную (§6) |
| 8 | **Анализ моделирования** | по желанию — полная статистика засечки одним снимком (§7) |

**Сброс** — убирает датчики, цель, сектор и запретные зоны; карта остаётся.
**Очистить** — убирает только накопленные маршруты (возврат к состоянию до
моделирования); заданные датчики остаются. **Очистить датчики** — убирает С КАРТЫ
все датчики (и подобранные, и заданные), не трогая маршруты.

**Координаты по краям карты** — километры от угла участка. Отрицательных значений
нет, расстояние между двумя точками считается вычитанием.

## 4. Кнопки и окна

| Кнопка / окно | Назначение |
|---|---|
| **Исходные данные…** | ОДНО окно вместо прежних двух: запас хода, скорость, крен, кратность засечки, число и радиус каждого из четырёх типов датчиков; переключатель «Рассчитать позиции» ⇄ «Задать позиции» (§6); таблица уже поставленных датчиков (можно править и удалять прямо в ней); кнопка «Посмотреть маршруты» (§8) |
| **Выбрать цифровые карты…** | источник данных и какие слои идут **в вес** карты. Требует пересборки карты |
| **Векторные слои…** | какие слои **показывать**. На расчёт не влияет |
| **Задать сектор / Убрать** | направление появления аппарата и его отмена |
| **Запретная зона / Убрать зону** | область, где пролёт невозможен: щелчки — вершины, колёсико замыкает контур, `Esc` отменяет. Маршруты пойдут в обход |
| **Добавить датчик** | ставить датчики ДВОЙНЫМ щелчком по карте (спросит тип и режим); правая кнопка мыши или `Esc` — выход |
| **Редактировать датчики** | щелчок выбирает ближайший датчик, перетаскивание переносит его, `Delete` удаляет; правая кнопка мыши или `Esc` — выход |
| **Очистить датчики** | убрать с карты ВСЮ расстановку — и подобранную, и заданную вручную (с подтверждением) |
| **Анализ моделирования** | окно с полной статистикой засечки — §7 |
| **Выгрузить / Загрузить / Удалить историю полётов** | сохранить накопленные маршруты в файл, подгрузить чужой файл как выборку для расстановки, убрать загруженную выборку — §8 |
| **Весь участок** | вернуть обзор ко всей карте |
| Линейка **«Расстояние»** (плашка над картой, правый верхний угол) | измерение по карте: клик — точка, между соседними — отрезок с длиной, у последней точки — сумма всей цепочки. Правая кнопка мыши, `Esc` или повторное нажатие — выход |
| Галочка **«режим анализа»** (та же плашка) | во время моделирования расстановка не пересчитывается — держит датчики на месте, чтобы честно сравнить «до» и «после» (§7). Включать ДО «Пуска» |

## 5. Что видно на карте

| Цвет / знак | Что это |
|---|---|
| тепловая заливка (синий → зелёный → жёлтый → красный) | **вес местности**: где пролёт правдоподобнее |
| белые треугольники у края | **точки входа** — откуда начинаются маршруты |
| белый пунктир от цели | **границы сектора** (по умолчанию скрыты, включаются галкой) |
| **названия пунктов** чёрным на белой плашке | города и посёлки; при приближении добавляются сёла и деревни. Прячутся галкой «Названия пунктов» |
| красный крест | **цель** |
| красноватые линии | **маршруты** накопленной выборки |
| розовая заливка | **зона пролёта** — куда аппарат вообще способен долететь |
| **оранжевые / синие / малиновые** круги | малые датчики трёх типов (свой радиус у каждого) |
| **сине-фиолетовые** круги | большие датчики, кольцом вокруг цели |
| чёрная обводка датчика | место назвал ЧЕЛОВЕК (клик, строка таблицы, файл) |
| белая обводка датчика | место подобрал алгоритм |
| квадратный значок датчика | «статический» — не переезжает при моделировании |
| круглый значок датчика | «динамический» — может быть переставлен алгоритмом |
| пурпурная штриховка | запретная зона, нарисованная пользователем |
| серый круг + чёрная стрелка с расстоянием (галка «Анализ размещения») | было/стало: позиция первого построения и куда датчик переехал к текущему моменту |
| 12 лучей от цели, белые/красные (галка «Сектора») | направления компаса — красным то, откуда датчики не набирают нужную кратность (§7) |

Галки в блоке **«показ»** только включают и выключают отображение — на расчёт они не
влияют. Ползунок под группой задаёт прозрачность. Слой, который ещё не рассчитан,
показан неактивным.

## 6. Датчики: четыре типа, два способа расстановки

| Тип | Задача |
|---|---|
| **1–3 (малые)** | перехват пролётов вдоль коридоров: каждый свой радиус, своя кратность, ставятся там, где проходит больше маршрутов |
| **4 (большие)** | круговое наблюдение вокруг цели: кольцо делится на равные доли, в каждой один датчик |

Числа и радиусы — в окне «Исходные данные…». Ноль датчиков типа 4 — щит не строится.

**Два способа задать датчики (переключатель в том же окне):**
* **«Рассчитать позиции»** — датчики подбирает алгоритм; таблица показывает результат.
  Можно закрепить часть датчиков вручную (клик по карте, строка таблицы или файл) —
  остальные алгоритм доберёт вокруг них.
* **«Задать позиции»** — датчики стоят РОВНО там, где их поставил человек; алгоритм
  ничего не подбирает, только считает показатели по заданным местам.

**Статический ⇄ динамический** (выбирается при постановке каждого датчика): статический
не двигается никогда; динамический во время моделирования может быть переставлен
алгоритмом, если так лучше для покрытия. До первого запуска моделирования оба стоят
там, где заданы.

⚠️ **Зоны больших датчиков слегка перекрываются, и это правильно.** Чтобы они совсем не
пересекались, их пришлось бы развести дальше, чем радиус обзора, — и тогда цель осталась
бы вне наблюдения. Выбран вариант «минимальное перекрытие, но цель под наблюдением у
каждого».

## 7. Показатели и анализ

Под картой выводятся числа расчёта. Главный из них — **засечка ≥ k**: доля маршрутов
выборки, обнаруженных не менее чем `k` разными датчиками. Значение 1.000 означает, что
все маршруты выборки надёжно перехватываются. Остальные: сколько маршрутов построено,
сколько итераций накоплено, сколько датчиков размещено, средняя кратность, покрытая
доля веса карты.

**Кнопка «Анализ моделирования»** открывает окно с полной статистикой снимком на момент
нажатия:
* сумма засечки — то же, что под картой, но с явным количеством и процентом рядом;
* то же самое ОТДЕЛЬНО по каждому из четырёх типов датчиков, включая долю покрытия
  веса именно этим типом;
* разбивка по **12 направлениям компаса** вокруг цели (шаг 30°) — с какой стороны
  сколько маршрутов пришло и скольким из них хватило кратности. Направления, которым
  не хватило, — красным. Те же 12 направлений можно увидеть прямо на карте — галка
  «Сектора» в группе «пролёт БПЛА» (§5).

**Галка «Анализ размещения»** (группа «датчики и подписи») сравнивает ПЕРВОЕ построение
расстановки с ТЕКУЩИМ: серый круг — где датчик стоял изначально, чёрная стрелка —
куда он переехал, подпись — на сколько километров. Если стрелки нет — датчик стоит
там же, где и встал первым.

**Чекбокс «режим анализа»** (плашка над картой) делает это сравнение честным: без него
расстановка периодически пересчитывается по ходу моделирования и «до/после» отличались
бы даже без содержательной причины. С галкой — расстановка замирает, как только что-то
уже поставлено; включать ДО «Пуска».

## 8. История полётов и просмотр маршрутов

* **Выгрузить историю полётов** — сохранить все накопленные к этому моменту маршруты
  в текстовый файл (по одной строке на маршрут).
* **Загрузить историю полёта** — подгрузить чужой файл; ДО начала своих итераций эта
  выборка используется для расстановки датчиков (в заголовке будет видно — «по
  загруженной истории»). С «Пуском»/«Пакетно» программа переключается на свою выборку.
* **Удалить выборку** — убрать загруженную историю, не трогая свои маршруты и датчики.
* **Посмотреть маршруты** (кнопка в окне «Исходные данные») — список своих пройденных
  и, отдельно, загруженных маршрутов; выбор строки показывает все его точки в таблице
  и подсвечивает маршрут на карте толстой линией.

## 9. Если что-то идёт не так

| Симптом | Причина и что делать |
|---|---|
| под картой пусто, фон белый | в кэше нет тайлов подложки на этот район. На расчёт не влияет: карта угроз, маршруты и датчики считаются без подложки |
| «Добавить рельеф» неактивна | не найден файл высот в `_internal\geo_cache\<участок>\` |
| маршрутов нет совсем | цель недостижима: скорее всего, запретная зона перекрыла единственный коридор либо не хватает запаса хода. Программа пишет об этом в строке состояния |
| после щелчка по карте ничего не пересчиталось | так и задумано — нажмите **«Применить»** |
| окно долго не отвечает при «Пакетно» | идёт расчёт сотен маршрутов; при 400 маршрутах это несколько секунд |
| «Очистить датчики» ничего не убрала в таблице «Исходные данные» | нажата не та кнопка окна: в режиме «Рассчитать позиции» таблица показывает результат расстановки — убирать её нужно кнопкой «Очистить датчики» на панели или «Очистить» в самом окне (оно смотрит на текущий режим) |
| датчики каждые несколько итераций слегка «уезжают» | это нормально для ДИНАМИЧЕСКИХ датчиков без включённого «режима анализа» (§7) — алгоритм подстраивает их под накопленную выборку |
| программа не запускается на Windows 7 | эта сборка работает только на Windows 10 и новее |

## 10. Что можно заменить, не переустанавливая программу

Тайлы подложки, файл карты, рельеф и картинку заставки можно заменить прямо в папке
`_internal`, не пересобирая программу. Порядок — [ПРАВКИ_БЕЗ_ПЕРЕСБОРКИ.md](ПРАВКИ_БЕЗ_ПЕРЕСБОРКИ.md).

Настройки расчёта (числа датчиков, радиусы, запас хода и прочее) менять в файлах не
нужно — они задаются в окнах программы.
