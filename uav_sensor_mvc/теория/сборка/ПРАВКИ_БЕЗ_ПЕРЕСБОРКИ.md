# Правки в готовой программе без пересборки

> **Зачем.** Пересборка занимает полторы минуты плюс копирование исходников, требует
> установленного окружения и заново «съедает» проверку. Но часть содержимого программы —
> это обычные файлы рядом с `.exe`, и их можно заменить прямо в готовой папке. Здесь —
> что именно можно, что нельзя и почему.

**Главное правило одной строкой:** **данные — можно, код — нельзя.**

---

## 1. Почему так: что внутри собранной папки

```
Карта угроз\
├── Карта угроз.exe        загрузчик
└── _internal\
    ├── base_library.zip    ┐
    ├── *.pyd, *.dll        │ КОД: интерпретатор, библиотеки, ваши модули,
    ├── PyQt5\, PIL\, …     │ упакованные в архив. Исходников .py здесь НЕТ
    │                       ┘
    ├── geo_cache\<участок>\   ← ДАННЫЕ: слои карты и рельеф
    ├── tile_cache\<слой>\     ← ДАННЫЕ: тайлы подложки
    ├── resurce\Эмблема.png    ← ДАННЫЕ: заставка
    └── docs\…docx             ← ДАННЫЕ: методичка пользователя
```

Проверено на сборке: файлов `.py` в `_internal` **ноль** — весь код лежит в упакованном
виде. Поэтому «поправить `config.py` в собранной программе» невозможно: править нечего.
А `geo_cache`, `tile_cache`, `resurce`, `docs` — это те же файлы, что в проекте, и
программа читает их с диска при запуске.

---

## 2. Что МОЖНО заменить руками

| Что меняем | Куда положить | Когда подхватится |
|---|---|---|
| **тайлы подложки** (докачали район) | `_internal\tile_cache\<слой>\<зум>\<x>\<y>.png` | при следующем запуске |
| **слои карты** (пересобрали `.npz`) | `_internal\geo_cache\<участок>\` — заменить файл тем же именем | по кнопке «Построить карту» |
| **рельеф** (другой растр) | туда же, имя то же (у сборки «Пл» — `ARX_hh.tif`) | по кнопке «Добавить рельеф» |
| **заставку** | `_internal\resurce\Эмблема.png` — заменить картинку | при следующем запуске |
| **методичку пользователя** | `_internal\docs\Методичка_пользователя.docx` | она просто лежит рядом |

### 2.1. Тайлы подложки — самый частый случай

Кэш общий на все участки, и в сборку кладутся **только тайлы, накрывающие участок**.
Если подложка пустая или неполная — докачать и скопировать:

```powershell
# 1) скачать (нужен интернет), из папки проекта:
python tools\download_tiles.py --layer osm --bbox 40.0842 62.5717 41.5959 63.1080

# 2) скопировать в готовую программу, сохраняя структуру папок:
Copy-Item "tile_cache\osm\*" "C:\uav_build\dist\Пл\Карта угроз\_internal\tile_cache\osm\" -Recurse -Force
```

⚠️ Структура `слой\зум\x\y.png` обязана сохраниться — программа ищет тайлы по этим
номерам. Лишние тайлы соседних районов не мешают, просто занимают место.

### 2.2. Новые данные карты

Если пересобрали `.npz` для того же участка — просто положите файл с тем же именем
поверх старого. Если участок **другой**, одной подменой файлов не обойтись: границы
участка заданы в `config.py`, который упакован в код. Нужна пересборка.

## 3. Что НЕЛЬЗЯ без пересборки

| Что | Почему |
|---|---|
| **любые параметры `config.py`** (`threat_N`, радиусы, `THREAT_AREA`, границы участка, пороги рельефа и НП) | код упакован в архив, файла для правки нет |
| **тексты заставки** (название, «25 отдел ВИ(НИ)», разработчики) | это тоже `config.py` |
| **цвета, подписи слоёв, состав панели** | `view_qt/threat_view.py` — код |
| **справка в программе** | `HELP_HTML` — код |
| **режим показа** (одна вкладка / три, офлайн) | флаги `DEMO_*` в `config.py` |
| **сама логика** — модель, расстановка, маршруты | код |

**Признак простой:** если правка касается файла с расширением `.py` — только пересборка.

---

## 4. Что из этого пользователь всё-таки может настроить сам — в интерфейсе

Многое из «непеременяемого» списка не нужно править в коде вовсе, потому что вынесено
в окна программы:

| Что настраивается | Где в программе |
|---|---|
| число и радиус датчиков обоих типов, кратность засечки, шаг сетки | окно **«Датчики: параметры…»** |
| запас хода, скорость, крен, длина прямого участка, разрыв, уход от ориентира | окно **«Входные данные…»** |
| число маршрутов, режимы веса, разброса и расхода | панель справа |
| цель и сектор появления | кнопки **«Указать цель»**, **«Задать сектор»** |
| какие слои показывать, прозрачность, подложка | блок **«показ»**, окно **«Векторные слои…»** |
| какие слои идут в вес карты, источник данных | окно **«Выбрать цифровые карты…»** |

То есть в код лезть приходится только за тем, что задаёт **устройство** программы, а не
её настройку: участок, палитра, состав интерфейса, тексты.

## 5. Порядок безопасной правки

1. **Скопировать папку сборки целиком** (или убедиться, что архив `.rar` рядом цел) —
   откат должен быть возможен;
2. заменить файлы;
3. запустить программу и проверить именно то, что меняли;
4. **переархивировать** папку: архив рядом со сборкой должен соответствовать её
   содержимому, иначе при передаче уедет старая версия.

⚠️ **Не редактировать файлы внутри `.rar` «на месте»** — архиватор может сохранить их с
другой структурой путей, и программа перестанет их находить. Правьте распакованную
папку, потом собирайте архив заново.

---

## 6. Если правка всё-таки требует пересборки

Порядок — [СБОРКА_EXE.md §4](СБОРКА_EXE.md), и главное оттуда:

* собирать **в новую папку** `dist\<имя>\` — PyInstaller удаляет каталог назначения, и
  прежняя сборка пропадёт;
* **старую сборку не пересоздавать**: она отвечает прежней модели, её числа в отчётах, и
  повторить её из текущего кода уже нельзя.
