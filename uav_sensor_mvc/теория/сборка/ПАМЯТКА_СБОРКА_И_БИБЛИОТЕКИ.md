## 1. Что за программа

Определяет, где поставить датчики обнаружения БПЛА, чтобы засечь аппарат при
минимальном их числе — точка появления и маршрут заранее не известны, известна
местность и охраняемая цель. Три вкладки Qt-интерфейса (`main_qt.py`); в сборке
для показа заказчику остаётся только вкладка 3 «Карта угроз» (`config.DEMO_ONLY_THREAT`).

## 2. Запуск из исходников

```bash
python main_qt.py
```
Библиотеки нужны заранее (раздел 4). Диагностика без окна: `UAV_SELFTEST=1 python main_qt.py`
— печатает, что из данных участка найдено, и выходит, ничего не открывая.

## 3. Сборка `.exe` — минимум команд

Окружение и путь сборки уже подготовлены в `C:\uav_build\` (venv, `src\`, готовые
библиотеки). Если это так и на вашей машине — сборка в три шага:

```powershell
# 1) скопировать код и данные в путь БЕЗ КИРИЛЛИЦЫ (кириллица в пути ломает сборку)
$dst = "C:\uav_build\src"
foreach ($d in "model","view_qt","controller_qt","view","controller","resurce","docs") {
    New-Item -ItemType Directory -Force "$dst\$d" | Out-Null
    Copy-Item "$d\*.py" "$dst\$d" -Force
}
Copy-Item config.py, main_qt.py, build_demo.spec $dst -Force
Copy-Item "resurce\Эмблема.png" "$dst\resurce" -Force
Copy-Item "docs\Методичка_пользователя.docx" "$dst\docs" -Force
Copy-Item "geo_cache\<участок>" "$dst\geo_cache\<участок>" -Recurse -Force
Copy-Item "tile_cache\<участок>" "$dst\tile_cache\<участок>" -Recurse -Force

# 2) собрать — ОБЯЗАТЕЛЬНО в СВОЮ папку dist\<имя>, PyInstaller её перед сборкой удаляет
Set-Location "C:\uav_build\src"
C:\uav_build\venv\Scripts\python.exe -m PyInstaller --noconfirm `
    --distpath "C:\uav_build\dist\<имя>" --workpath "C:\uav_build\work" build_demo.spec

# 3) проверить без окна
$env:UAV_SELFTEST = "1"
& "C:\uav_build\dist\<имя>\Карта угроз\Карта угроз.exe"
```

`<участок>` — значение `config.THREAT_AREA_DIR` (сейчас `arh`). Результат —
`C:\uav_build\dist\<имя>\Карта угроз\` (папка + `.exe`, ≈ 850 МБ), архивировать и
передавать целиком.

**Три вещи, которые ломают сборку молча:**
* кириллица в пути сборки → «Qt plugin directory does not exist»;
* повторная сборка в ТУ ЖЕ папку `dist\<имя>` → старая сборка удалена без предупреждения;
* **тайлы подложки лежат в ДВУХ местах** — `tile_cache/<участок>/…` (новое) и
  `tile_cache/<слой>/…` (скачанное до 03.09.2026, не переложено). Программа при показе
  перебирает оба, и копировать надо оба: взять одно — подложка приедет дырявой, причём
  молча. Замер по участку `arh` (рабочая рамка, слой `osm`): только корень кэша —
  зумы 7…10 полные, но z13 лишь 69 %; только папка участка — z13 30 %, а **зумы 7…10
  пусты**, то есть на стартовом обзорном зуме карты не будет вообще. Оба перекоса были
  в `build_demo.spec` по очереди и исправлены 08.09.2026 объединением источников.

**Подробно:** [СБОРКА_EXE.md](СБОРКА_EXE.md) — окружение с нуля, ловушки, Windows 7
(нужен отдельный Python 3.8.10), четыре решения из `build_demo.spec` разобраны построчно;
[ПРАВКИ_БЕЗ_ПЕРЕСБОРКИ.md](ПРАВКИ_БЕЗ_ПЕРЕСБОРКИ.md) — что поправить в готовой папке,
не собирая заново.

## 4. Библиотеки

Обычная машина с интернетом: `pip install -r requirements.txt` (или PyQt5 pyqtgraph
numpy matplotlib pillow rasterio по отдельности). Машина БЕЗ интернета — тем же
`pip`, но с локальным источником пакетов:

```powershell
pip install --no-index --find-links offline_packages PyQt5 pyqtgraph numpy matplotlib pillow rasterio
```

Сам `pyinstaller` в `offline_packages/` не лежит — его надо поставить с интернетом один
раз, до переноса на машину без сети.

**Подробно:** [УСТАНОВКА_БИБЛИОТЕК.md](../УСТАНОВКА_БИБЛИОТЕК.md) — что ставить, если
на чужой машине программа падает на «нужен pyrosm/geopandas» (в сборку `.exe` они не
входят намеренно — нужны только для подготовки данных участка, не для показа), и
ловушка с `cykhash`.

# Часть II. Подробно

## 5. Как это вообще устроено

Обычная программа на Python запускается так: на машине стоит **интерпретатор** (сам
Python), рядом лежат **библиотеки** (PyQt5 рисует окно, numpy считает, matplotlib даёт
палитры, rasterio читает высоты), и всё это исполняет наш код (`main_qt.py` и модули
`model/`, `view_qt/`, `controller_qt/`). На компьютере заказчика ничего этого нет и
ставить не разрешено.

**PyInstaller** решает задачу в лоб: анализирует, что именно импортирует программа, и
складывает в одну папку интерпретатор, все нужные библиотеки и сам код. Получается
`.exe`, который при запуске поднимает встроенный Python и выполняет `main_qt.py`. Это
не компиляция в машинный код — это «Python в коробке», отсюда и размер (≈ 850 МБ на
эту сборку: внутри лежит вся кухня, включая rasterio с GDAL).

Рецепт того, ЧТО именно упаковывать, — файл `build_demo.spec` в корне проекта. Его
не пишут заново на каждую сборку: меняется только `--distpath` (имя папки результата)
и, если сменился участок, — `config.THREAT_AREA`.

## 6. Пять решений, из-за которых `build_demo.spec` устроен именно так

### 6.1. Папка, а не один файл (`--onedir`, не `--onefile`)

PyInstaller умеет собирать в единственный `.exe`. Здесь это НЕ используется: такой файл
при каждом запуске распаковывает себя во временный каталог. Это долгий старт, а
главное — пути к `geo_cache` и `tile_cache` начинают вести внутрь временной папки, а не
туда, где реально лежат данные участка. Режим «папка» (`_internal` рядом с `.exe`) от
этого свободен: код всегда точно знает, где искать свои файлы.

### 6.2. Тяжёлая геообвязка исключена — но НЕ rasterio

`requirements.txt` тянет `pyrosm`, `geopandas`, `shapely`, `pyproj` — это чтение
СЫРЫХ карт OpenStreetMap (`.osm.pbf`). Они весят сотни мегабайт и хуже всего
упаковываются. В коде они импортируются ЛЕНИВО — не в начале файла, а внутри функции
чтения `.osm.pbf` (`model/threat_grid.py`) — и для показа они не нужны вовсе: карта
берётся из готового `geo_cache/<участок>/threat_layers_*.npz`. Поэтому в `build_demo.
spec` они прямо перечислены в `excludes`.

⚠️ **`rasterio` исключать НЕЛЬЗЯ** — им читается `geo_cache/<участок>/*.tif`, файл
высот. В самой первой сборке его исключили заодно с остальной геообвязкой — и
собранная программа переставала грузить карту высот, кнопка «Добавить рельеф» не
работала, чекбоксы «Карта высот» и «Приоритет высот» оставались серыми (они гаснут,
когда данных нет). Снаружи это выглядело как поломка интерфейса, а причина была одна:
нечем прочитать высоты.

Мало просто НЕ исключить `rasterio` — его надо собрать ЦЕЛИКОМ. Его подмодули
загружаются динамически, и обычный анализ импортов их не видит: без явного указания
программа падала на `No module named 'rasterio.sample'`. Нужны ещё и файлы данных
GDAL, иначе библиотека жалуется `Cannot find gdalvrt.xsd (GDAL_DATA is not defined)`.
В спецификации это решено двумя вызовами:

```python
from PyInstaller.utils.hooks import collect_submodules, collect_data_files
rasterio_hidden = collect_submodules("rasterio")   # все подмодули, а не только явные import
rasterio_datas  = collect_data_files("rasterio")   # gdal_data, proj_data
```

Цена работающего рельефа — рост сборки на добрую сотню мегабайт; отказ от неё
неприемлем, поскольку рельеф — часть модели, а не украшение.

### 6.3. Только тайлы и данные СВОЕГО участка — не всего кэша

`geo_cache/` и `tile_cache/` — общие каталоги на несколько участков сразу (сейчас там,
например, ещё `plesetsk`, `severodonetsk`, старые тайлы других районов). Копировать их
целиком в сборку — раздувать её на сотни мегабайт и гигабайты чужих данных, которые в
этой конкретной программе никогда не покажутся (камера ограничена рамкой участка).
`build_demo.spec` поэтому:

* берёт `geo_cache/<config.THREAT_AREA_DIR>/` — только файл слоёв и файл рельефа
  активного участка, не весь `geo_cache`;
* для тайлов подложки САМ вычисляет диапазон `x`/`y` по рамке участка на каждом
  уровне 7…15 (`THREAT_BBOX_LONLAT` → формула тайлов Web-Меркатора) и включает только
  те файлы, что реально накрывают участок.

⚠️ **Тайлы лежат в ДВУХ раскладках сразу, и собирать надо обе.** С 03.09.2026 действует
правило «данные участка — в папку участка»: `tile_cache/<участок>/<слой>/<z>/<x>/<y>.png`.
Но правило распространяется только на то, что качается ЗАНОВО: 13 273 тайла, скачанные
раньше, намеренно оставлены в старой общей раскладке `tile_cache/<слой>/…`
([ОГРАНИЧЕНИЯ 5.1д](../ОГРАНИЧЕНИЯ.md)). Поэтому показ ищет тайл в двух местах по
порядку — `geomap.find_cached_tile`: сперва папка участка, затем корень кэша, и второе
там названо «не на всякий случай, а рабочим путём».

Сборка обязана повторять ровно это. Замер по участку `arh` от 08.09.2026, слой `osm`,
**рабочая рамка** Плесецка 117 × 73 км — что попадает в сборку из одного источника:

| источник | тайлов | чем плохо |
|---|---|---|
| только корень кэша (было до 06.09) | 2 759 | зумы 7…10 полные, но z13 покрыт на 69 % — при приближении дыры |
| только папка участка (правка 06.09) | 1 200 | z13 30 %, а **зумы 7…10 пусты (0 из 53)** — на стартовом обзоре подложки нет вовсе |
| **оба, с приоритетом папки участка** | **5 796** | z7…z11 — 100 %, z12 — 97 %, z13 — 99.9 % |

Обе однобокие версии были в `build_demo.spec` по очереди, и обе портили подложку молча.
С 08.09.2026 спека берёт объединение: список источников `_tile_roots`, дедупликация по
ключу `(слой, z, x, y)` — тайл из папки участка выигрывает у одноимённого из корня, как
и при показе. Всего в сборку по рамке ОБЛАСТИ идёт 32 933 тайла, 109.9 МБ.

### 6.4. Самопроверка внутри собранной программы

Ошибки чтения карты и высот программа гасит сама — файла может не быть, и это не
повод падать целиком. Из-за этого снаружи видно только «рельеф не работает», без
причины. Режим самопроверки печатает всё, что нужно для диагноза, и завершается, не
открывая окна:

```powershell
$env:UAV_SELFTEST = "1"
& "C:\uav_build\dist\<имя>\Карта угроз\Карта угроз.exe"
```

Печатает: активный участок и его рамку, каталоги карты/участка/тайлов, наличие файла
слоёв и исходного `.osm.pbf`, число найденных файлов рельефа, доступность пяти
модулей (`rasterio`, `numpy`, `matplotlib`, `pyqtgraph`, `PyQt5`), и — самое ценное —
**полную ошибку чтения высот**, если она есть, а не только факт «не загрузились».
Затем — итог сборки карты: источник слоёв, размер сетки, загружены ли высоты, применён
ли рельеф к весу. Именно так была найдена пропажа `rasterio.sample` (§6.2).

⚠️ **Проверять надо запуском СОБРАННОГО `.exe`, а не окружением сборки.** В окружении
библиотека может быть установлена и прекрасно работать, а в собранную программу — не
попасть; ровно так эта ошибка и была пропущена в первый раз.

Проверить состав можно и без запуска, глазами: `_internal\rasterio\` с подмодулями
(`.pyd`) и `gdal_data\`, файлы участка в `_internal\geo_cache\<участок>\`, тайлы в
`_internal\tile_cache\<участок>\`, `resurce\Эмблема.png`, `docs\Методичка_
пользователя.docx` — и ноль файлов `.py` в `_internal` (весь код упакован в архив).

### 6.5. ⚠️ Кириллица в пути ломает сборку

Самое неочевидное из пяти. Сборка из папки проекта (она лежит по пути с русскими
буквами) падает с ошибкой вида:

```
Exception: Qt plugin directory 'C:/Users/?????/AppData/Roaming/Python/Python314/
site-packages/PyQt5/Qt5/plugins' does not exist!
```

Каталог существует, но в пути вместо `Денис` — `?????`. Причина: PyInstaller спрашивает
у Qt, где лежат плагины, а Qt возвращает путь в системной кодировке Windows, и
кириллица теряется. `PYTHONUTF8=1` не помогает — искажение происходит на стороне Qt, до
Python. Решение — не чинить кодировку, а обойти её: отдельное окружение и рабочий
каталог сборки на латинице, `C:\uav_build\`. Сам проект при этом может лежать где
угодно, в том числе по пути с русскими буквами, — путь без кириллицы нужен только
`venv` и `src\`, откуда идёт сама сборка.

## 7. Пересборка с нуля — если `C:\uav_build\` ещё не готов

### 7.1. Окружение (один раз)

```powershell
python -m venv C:\uav_build\venv
```

### 7.2. Библиотеки в это окружение

С интернетом — обычным `pip`; без интернета — из локальных пакетов проекта
(`offline_packages/`, подробности §9):

```powershell
C:\uav_build\venv\Scripts\python.exe -m pip install --no-index `
    --find-links "<путь к проекту>\offline_packages" `
    PyQt5 pyqtgraph numpy matplotlib pillow rasterio
```

Сам сборщик в `offline_packages` не лежит — его ставят отдельно, с интернетом, один раз:

```powershell
C:\uav_build\venv\Scripts\python.exe -m pip install pyinstaller
```

### 7.3. Копия проекта в путь без кириллицы

См. команду в Части I, §3 — те же семь строк, только выполняются один раз для новой
машины, а не при каждой пересборке (данные участка можно докопировать только при их
обновлении).

### 7.4. Сборка и проверка

Команды — там же, в Части I, §3, пункты 2–3. Занимает около полутора минут на этой
машине; результат — `C:\uav_build\dist\<имя>\Карта угроз\`.

⚠️ **Каждая сборка — в СВОЮ папку.** PyInstaller УДАЛЯЕТ каталог `--distpath` перед
сборкой. Старую сборку («Дон», «Пл», «Пл2» — уже сделанные для прежних участков) не
пересоздавать и не затирать: она отвечает прежней модели, повторить её из текущего
кода нельзя. Готовую папку сразу архивировать рядом.

## 8. Windows 7 — отдельная сборка, не флаг

Windows 7 не запустит `.exe`, собранный текущим Python (3.14): ограничение самого
языка (актуальные версии CPython не поддерживают эту ОС), а не настроек сборки.
Нужен ПОЛНОСТЬЮ ОТДЕЛЬНЫЙ Python **3.8.10** — последняя версия с поддержкой Win7:

```powershell
C:\uav_build\venv38\Scripts\pyinstaller --noconfirm `
    --distpath C:\uav_build\dist\Win7 --workpath C:\uav_build\work7 build_demo.spec
```

Python 3.8 давно снят с поддержки — перед сборкой стоит проверить, ставятся ли под
него нужные колёса (`PyQt5`, `numpy`, `rasterio`) в имеющемся `offline_packages/` (там
колёса собраны под 3.14, под 3.8 не подойдут — имя файла `.whl` содержит версию
интерпретатора, например `cp314`). Если готовых колёс под 3.8 нет — качать их отдельно
(`pip download`, §9.5 методички библиотек) на машине с интернетом.

## 9. Библиотеки — подробно

### 9.1. Что вообще нужно ставить, а что — нет

⚠️ **Геостек (`pyrosm`, `geopandas`, `shapely`, `pyproj`) нужен ТОЛЬКО для подготовки
данных нового участка** — разбор `.osm.pbf` в `tools/build_threat_grid.py`. Программа
в работе читает готовый кэш `<участок>/threat_layers_*.npz` — а это **обычные массивы
numpy**, для них геостек не нужен вовсе. Разница ощутима: файл слоёв на область
291×250 км весит 7.2 МБ и читается 0.03 с; исходный `.osm.pbf` того же участка — 17.1 МБ
и 4.3 с, да ещё и тремя дополнительными библиотеками.

Проверка одной командой, без открытия окон (работает даже там, где интерфейс не
поднимается):

```bash
UAV_SELFTEST=1 python main_qt.py
```

### 9.2. Обычная установка (в `offline_packages/` — 36 файлов, 169 МБ)

```powershell
python -m pip install --no-index --find-links offline_packages `
    numpy PyQt5 pyqtgraph matplotlib pillow rasterio
```

Геостек (только если готовите кэш нового участка сами):

```powershell
python -m pip install --no-index --find-links offline_packages `
    pyrosm geopandas shapely pyproj
```

⚠️ Файлы `.whl` собраны под КОНКРЕТНУЮ версию Python и разрядность: имя вида
`numpy-2.5.1-cp314-cp314-win_amd64.whl` означает CPython 3.14, Windows 64-бит. На
другой версии Python pip ответит «not a supported wheel on this platform» — версию
смотреть командой `python -V` ДО установки.

### 9.3. Ловушка `cykhash` — если геостек не ставится

`pyrosm` тянет `cykhash`, а он в `offline_packages/` лежит ИСХОДНИКОМ
(`cykhash-2.0.1.tar.gz`), не готовым колесом: `.tar.gz` собирается на месте, а для
этого нужен компилятор C++ (Visual Studio Build Tools). Без него — ошибка «Microsoft
Visual C++ 14.0 or greater is required». Три выхода по возрастанию мороки:

1. не ставить геостек вовсе — принести готовый `threat_layers_*.npz` с машины, где он
   уже собран (файл небольшой, §9.1);
2. скачать готовое колесо `cykhash` под нужную версию Python на машине с интернетом
   (`pip download cykhash`) и положить в `offline_packages`;
3. поставить Build Tools и собрать из исходника — дольше всего, нужно только если
   первые два пути закрыты.

### 9.4. Проверка после установки

```bash
UAV_SELFTEST=1 python main_qt.py     # библиотеки, файлы участка, построение карты
python tools/flow_check.py           # порядок работы модели
python tools/gui_check.py            # интерфейс: рамки, оси, слои
```

### 9.5. Пополнить `offline_packages/` с машины, где есть интернет

```powershell
python -m pip download -d offline_packages <имя пакета>
```

⚠️ `pip download` без ключей тянет то, что подходит ТЕКУЩЕЙ машине. Если у заказчика
другая версия Python или разрядность — указать явно, иначе получите колесо не под ту
платформу:

```powershell
python -m pip download -d offline_packages --only-binary=:all: `
    --python-version 314 --platform win_amd64 <имя пакета>
```

`--only-binary=:all:` заставляет pip брать готовые колёса и честно отказываться там,
где готового нет — вместо того чтобы молча положить исходник, который потом не
соберётся (как получилось с `cykhash`).

## 10. Если что-то не так — сводная таблица

| Симптом | Причина | Что делать |
|---|---|---|
| `Qt plugin directory ... does not exist!` | кириллица в пути сборки (§6.5) | собирать из `C:\uav_build\`, не из папки проекта |
| повторная сборка стёрла прежнюю в `dist\` | один и тот же `--distpath` дважды | каждой сборке — своё имя папки (§7.4) |
| в собранной программе не работает рельеф, чекбоксы серые | `rasterio` в `excludes` либо собран не целиком (§6.2) | убрать из `excludes`, добавить `collect_submodules`/`collect_data_files` |
| подложка дырявая: пусто на обзоре либо дыры при приближении | `build_demo.spec` собрал тайлы из ОДНОЙ раскладки вместо двух (§6.3, исправлено 08.09.2026) | брать объединение `tile_cache/<участок>/…` и `tile_cache/<слой>/…`, как `geomap.find_cached_tile` |
| `No module named 'rasterio.sample'` | не собраны скрытые подмодули rasterio | `collect_submodules("rasterio")` в `hiddenimports` |
| `Cannot find gdalvrt.xsd` | не собраны файлы данных GDAL | `collect_data_files("rasterio")` в `datas` |
| `pip`: «not a supported wheel on this platform» | версия/разрядность Python не совпадает с `.whl` | проверить `python -V`, скачать колесо под нужную версию |
| `Microsoft Visual C++ 14.0 or greater is required` | `cykhash` ставится из исходника | см. §9.3 — три выхода |
| .exe не запускается на Windows 7 | собран текущим (≥ 3.9) Python | отдельная сборка на Python 3.8.10, §8 |
| ошибка гасится, снаружи просто «не работает» | штатное поведение — данных может не быть | `UAV_SELFTEST=1`, смотреть полный вывод (§6.4) |
