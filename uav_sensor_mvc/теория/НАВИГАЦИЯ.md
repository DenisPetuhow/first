## 2. По механизму — где он в КОДЕ

Точка входа для каждого механизма, который чаще всего правят, — чтобы не искать грепом.

⚠️ **Сигнатуру не угадывать.** Греп показывает имя, но не аргументы, и они достраиваются
по памяти. Так уже было: `add_relief` вместо `set_relief`, `iter_batch(150)` вместо
`iter_batch()`. Настоящая сигнатура — в [карте кода](карта_кода/README.md).

| Механизм | Файл :: имя |
|---|---|
| вес ячейки, наложение слоёв | `model/threat_grid.py` — сборка сетки, `self.weight`, `self.layers` |
| штраф деревни, пол штрафа | `threat_grid.py` :: `_village_penalty`, `THREAT_VILLAGE_FLOOR` |
| размер пункта по своему пятну | `threat_grid.py` :: `own_place_area_km2`, `settlement_stats` |
| градация пунктов по данным | `threat_grid.py` :: `place_profiles`, `grade_places`, `PLACE_CODES` |
| рельеф: множитель и отсечка | `threat_grid.py` :: `relief_cut`, коэффициент `k` |
| цена шага, тяга по стоимости | `model/threat_routes.py` :: `_cost_mul`, `_dijkstra_cost` |
| что вообще проходимо | `threat_routes.py` :: `passable_mask` |
| предел поворота, окно разворота | `threat_routes.py` :: `TURN_MAX_DEG`, `TURN_WINDOW_KM` |
| **сколько всего возможных маршрутов** | `threat_routes.py` :: `count_possible_routes`; `threat_grid.py` :: `count_routes` |
| выборка маршрутов (итерации) | `threat_routes.py` :: `sample_one_route`; `threat_grid.py` :: `iter_batch` |
| «возможные маршруты» (голубые линии) | `threat_grid.py` :: `plan_routes`; показ — `threat_view.py` :: `render_routes` |
| сектор появления БПЛА, пять точек входа | `threat_grid.py` :: `set_sector`, `compute_entry_points`; `threat_routes.py` :: `ctx["entries"]` |
| **расстановка датчиков: два пути** | `threat_grid.py` :: `place_sensors` (развилка), `_place_by_routes` (основной), `_place_by_weight` (запасной) |
