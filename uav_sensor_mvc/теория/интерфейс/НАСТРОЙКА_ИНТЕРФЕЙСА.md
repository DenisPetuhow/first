## 1. Начальные значения полей панели

**Файл:** `config.py`, класс `Params`.

Это то, что подставляется при запуске программы. В самом интерфейсе всё это меняется
мышкой, но стартовые значения задаются здесь.

| поле | что задаёт | сейчас |
|---|---|---|
| `threat_N` | сколько МАЛЫХ датчиков расставлять | 20 |
| `threat_R` | радиус обнаружения малого датчика, км | 2.0 |
| `threat_k` | сколько датчиков должны увидеть БПЛА, чтобы засчитать засечку | 3 |
| `threat_N_big` | сколько БОЛЬШИХ датчиков (щит у цели); 0 — не ставить | 3 |
| `threat_R_big` | радиус обнаружения большого датчика, км | 15.0 |
| `threat_cand_step_km` | шаг сетки кандидатных позиций датчика, км | **сам от радиуса** (R/2) |
| `threat_spend` | профиль расхода запаса хода | `"even"` (равномерно) |
| `threat_iter_mode` | приоритет по весу для итераций | `"mix"` |
| `threat_iter_spread` | разброс маршрутов по карте | `"mix"` |
| `threat_iter_approach` | облёт цели: обычный 85/10/5 · умеренный 60/25/15 · максимальный 30/35/35 · смесь (план 11) | `"mix"` |
| `threat_sector_half_deg` | полураствор сектора налёта, градусы (в окне — полный раствор) | 30.0 |
| `threat_sector_entries` | сколько точек входа отбирает сектор | 5 |
| `threat_iter_routes` | сколько маршрутов набирать | 150 |
| `threat_max_gap_km` | разрыв между весовыми секторами (мостик через пустоту) | 2.0 |
| `threat_corridor_slack_km` | насколько можно уйти вбок от ориентира | 1.0 |
| `threat_L_max` | запас хода, км (0 = считать автоматически) | авто |
| `map_layer3` | подложка при запуске | `"osm"` |

**Шаг сетки датчиков сам подстраивается под радиус** — половина R (пределы 0.5…6 км).
Пересчёт происходит при СМЕНЕ РАДИУСА, поэтому введённое руками значение работает до
следующей смены R, а не затирается на каждом «Применить».

Почему так: `threat_cand_step_km` — это шаг, с которым расставлены КАНДИДАТНЫЕ позиции, из
них жадный алгоритм выбирает лучшие. Если шаг крупнее радиуса, между кандидатами остаются
дыры шире зоны обзора, и лучшая точка недоступна для выбора. Раньше шаг был жёстко 3 км
(подбирался под R = 12 км), а после перехода на R = 2 км стал в полтора раза крупнее
радиуса.

Замер при R = 2 км и **пяти** датчиках: засечка 96.7 % (шаг 0.5 км) → 82.7 % (3 км) →
17.3 % (6 км). Чем шире обзор и чем больше датчиков, тем меньше значит шаг: при R = 6 км
разницы нет вовсе. Половина радиуса — компромисс по цене: 4 436 кандидатов и 0.8 с против
17 847 и 3.2 с у шага 0.5 км, а выигрыш последнего — доли процента.

## 2. Подписи слоёв, группы и подсказки

**Файл:** `src/view_qt/tabs/threat_view.py`, таблица `LAYER_GROUPS` в классе `ThreatMapView`.

Одна строка = один слой в панели «ПОКАЗ»:

```python
("chk_layers", "Векторные слои", True, "Реки, дороги, ЛЭП, железные дороги — …"),
#      │              │            │                      │
#      │              │            │                      └─ подсказка при наведении
#      │              │            └─ включён ли при запуске
#      │              └─ подпись в панели (её видит пользователь)
#      └─ ИМЯ ПЕРЕМЕННОЙ — не трогать, на него ссылается контроллер
```

* **менять подпись и подсказку** — свободно, это просто текст;
* **менять `True`/`False`** — включён ли слой при запуске;
* **переносить строку в другую группу** — можно, слой переедет в панели;
* ⚠️ **имя (`chk_...`) менять нельзя** — по нему контроллер узнаёт слой (`get_toggles`),
  и переименование сломает отрисовку.

Названия групп («местность», «весовая карта», …) — первый элемент каждой пары в
`LAYER_GROUPS`. У группы есть свой переключатель: он гасит всех её детей разом.

**Постройки по ячейкам** (план 13.1, Д2, 25.09.2026) — в группе «весовая карта» две галки: «Постройки: число в
ячейке» (логарифмическая шкала светло-жёлтый → бурый, `bld_lo`/`bld_hi`) и «Постройки: средняя этажность» (линейная
голубой → тёмно-синий, `flr_lo`/`flr_hi`); пустые ячейки прозрачны, верх шкалы — максимум участка (в подсказке галки).
Только показ — в вес не идут; нет файла мест — галки серые (`render_buildings`, правило `bld`).

**Надписи режимов** (выпадающие списки) — в `config.py`:
`MODE_LABELS`, `THREAT_SPEND_LABELS`, `THREAT_ITER_MODE_LABELS`, `THREAT_ITER_SPREAD_LABELS`.
Слева ключ (его знает модель — не трогать), справа надпись (меняйте свободно).

## 3. Цвета и вид линий цифровой карты

**Файл:** `src/view_qt/tabs/threat_view.py`, таблица `LAYER_STYLE` (в самом верху файла).

```python
"road_major": dict(color="#9e4825", width=3.0, dash=None, z=-5.1,
                   casing="#ffffff", casing_w=5.0, alpha=250),
```

| поле | что делает |
|---|---|
| `color` | цвет линии, `"#rrggbb"` |
| `width` | толщина в пикселях |
| `dash` | штрих: `None` — сплошная, `[7, 4]` — 7 закрашено, 4 пусто |
| `z` | ПОРЯДОК отрисовки: меньше — ниже, больше — поверх остальных |
| `casing` | цвет обводки (`None` — без неё) |
| `casing_w` | ширина обводки, должна быть больше `width` |
| `alpha` | непрозрачность самой линии, 0…255 |

Легенда берёт цвета отсюда же — поправите цвет, поменяется и карта, и легенда.

### Порядок отрисовки (`z`) — снизу вверх

```
built_up (-5.9) → tree_row → track → ditch → stream → cutline → river
                → railway_old → railway → pipeline → power → road_local
                → road_major → bridge (-5.0)
```

Логика: дороги наверху (по ним ориентируются), инфраструктура ниже, застройка в самом
низу. ⚠️ Раньше у всех слоёв стоял один `z = -5`, и порядок получался случайным — кто
нарисован последним, тот и сверху. Если задаёте свой `z`, держите шаг не меньше 0.1:
обводка слоя рисуется на `z − 0.04`.

### Три правила, которые легко нарушить

1. **Не гонитесь за максимальным контрастом.** Все фоны OSM светлые, поэтому «самый
   контрастный» цвет — чёрный. Сделав так, вы получите десяток одинаково чёрных линий:
   контраст к фону идеальный, а слои неразличимы между собой. Берите САМЫЙ СВЕТЛЫЙ тон,
   который ещё читается.
2. **Проверяйте на худшем фоне.** Карта OSM — это лес, поля, вода, дороги, застройка.
   Худший (самый тёмный) — лес. Если линия читается на нём, читается везде.
3. **Цвета мало — нужен ещё штрих или толщина.** Тонкие линии при отдалении сжимаются в
   пиксель, и соседние оттенки смешиваются. Поэтому ЛЭП — частые точки `[2,3]`,
   трубопровод — длинный пунктир `[9,5]`, лесополоса — короткий `[3,4]`, ж/д — «шпалы»
   (тёмный пунктир поверх белой обводки), просека — «линия-точка» `[8,3,1,3]`, лесная
   дорога — `[5,2]`, брошенная ж/д — «двойной пунктир» `[4,2,4,6]`, канава — `[4,2]`.
   Даже если цвета сошлись, штрих разведёт. Совпадение штрихов ловит `gui_check.py`, раздел 11.
4. ⚠️ **Яркость обратна толщине** (заказчик 13.09.2026). Толстую линию видно и блёклой,
   тонкая при той же прозрачности теряется. Пример: крупная дорога 3.0 px идёт с
   `alpha` 195, местная 2.1 px — 245, лесная 1.6 px — 255. Разбор —
   [МЕТОДИЧКА_КАРТА_УГРОЗ §12.0а](../вкладка_3/МЕТОДИЧКА_КАРТА_УГРОЗ.md).

⚠️ **Слишком редкий штрих убивает линию.** `[1, 5]` закрашивает лишь шестую часть длины —
на общем виде такая линия вырождается в еле заметную пыль, и никакой цвет её не спасёт.
Держите закрашенную долю не ниже трети.

## 4. Цвета маршрутов, датчиков и зон

**Файл:** `src/view_qt/tabs/threat_view.py`, таблица `THREAT_COLORS`. Рядом с каждым цветом в
комментарии указано, где на карте он применяется.

| ключ | что красит |
|---|---|
| `route_all` | синие линии «возможные маршруты» |
| `route_iter` | накопленные итерационные маршруты |
| `route_gen` | обобщённая выборка (10 %) |
| `route_main` | текущий маршрут итерации (чёрный) |

Цвета рельефа — `RELIEF_*` там же: карта высот, укрытия, возвышенности, снятый коридор.

## 5. Подложка (карта-основа)

**Файл:** `src/view_qt/tabs/threat_view.py`, `ThreatMapView.BASEMAP_FADE = (0.20, 0.10)`.

Два числа: насколько **обесцветить** и насколько **осветлить** тайлы подложки.
`(0.0, 0.0)` — оставить как есть.

**Зачем.** OSM рисует СВОИ дороги, воду и лес, а мы кладём сверху свои — оранжевое на
оранжевом, синее на синем. Это главный источник каши на общем виде, и лечится он не
подбором палитры, а тем, что подложка уходит в фон.

⚠️ **Не перебарщивайте.** При `(0.62, 0.30)` карта выцветала почти в белый лист: лес,
поля и вода переставали различаться, и терялся контекст. Разумный предел — около 20 %.

⚠️ **Меняете гашение — пересчитайте палитру.** Контраст линий считался под ЭТОТ фон.
Сделаете подложку ярче — линии, подобранные под бледную, поплывут.

Гашение включено только для вкладки 3 (в `BasemapMixin` по умолчанию `(0.0, 0.0)`) —
у вкладки 2 поверх карты почти ничего не лежит, ей это не нужно.

## 6. Что меняется при отдалении

**Файл:** `src/view_qt/tabs/threat_view.py`, класс `ThreatMapView`.

| настройка | что делает | сейчас |
|---|---|---|
| `MARKER_SIZE` | базовый размер маркеров (мосты, развилки) | 11 и 7 px |
| `MARKER_MIN` | до какой доли они уменьшаются на общем виде | 0.45 |
| `CASING_MIN` | до какой доли худеет ОБВОДКА линий | 0.35 |
| `LINE_MIN` | до какой доли худеет сама линия | 0.75 |

**Почему обводка худеет сильнее линии.** Вблизи белый кант разделяет линии на
пересечениях — это его работа. Но на общем виде, где дороги идут густой сетью, канты
соседних дорог сливаются в сплошное белёсое пятно вокруг посёлков. Поэтому кант
ужимается втрое, а сама линия почти не меняется — иначе слой просто исчезнет.

Маркеры мельчают по той же причине: их сотни, и в полном размере они застилают карту.

| `LEGEND_PT` = 7.8 | кегль общей легенды (левый нижний угол) |
| `LEGEND_PT_MIN` = 4.8 | нижний предел (сейчас не используется — размер постоянный) |
**Размер постоянный — намеренно.** Легенда длинная, и при зуме, ужимаясь, она становилась нечитаемой ровно тогда, когда по ней и сверяют объекты. Расшифровка «приоритета по высоте» — не отдельной панелью, а строками шкалы градаций (§9); прежняя панель с кеглем, мельчавшим при зуме, снята 02.10.2026 (план 13.5.1, журнал 359).

Сам текст легенды — метод `_legend_html`. Цвета он берёт из `LAYER_STYLE` и
`THREAT_COLORS`, так что правка цвета меняет карту и легенду разом.

По умолчанию легенда **скрыта** (`chk_legend` в `LAYER_GROUPS` со значением `False`).

## 8. Прозрачность по группам

**Файл:** `src/view_qt/tabs/threat_view.py`, таблица `OPACITY_TARGETS`.

Ползунок под группой гасит ВСЁ, что эта группа рисует. Таблица говорит, какие элементы
сцены относятся к какому слою:

```python
"chk_routes": ("route_area_img", "route_item"),   # заливка И синие линии
"chk_layers": ("*vectors", "bridge_scatter"),     # все линии карты и их обводки
```

Спецключ `"*vectors"` разворачивается в десяток векторных линий и их обводки — они живут
в словарях `_layer_items` / `_layer_casing`, а не отдельными полями. Ключ `"@имя"` — **список** элементов,
который пересоздаётся при отрисовке (датчики, названия пунктов, анализ размещения, компас): множитель группы
помнится (`_group_alpha`) и применяется к новым элементам (`_reapply_opacity`, план 13.5.2). До 02.10.2026 у группы
«датчики и подписи» в таблице были одни кандидатные позиции — ползунок не гасил ничего видимого. Разбор — [код/ПОКАЗ_ГРАДАЦИЙ_И_СЛОЁВ](../код/ПОКАЗ_ГРАДАЦИЙ_И_СЛОЁВ.md) §2.

⚠️ **Ползунок МАСШТАБИРУЕТ родную прозрачность, а не задаёт её.** У рельефа она 0.55, у
тепловой карты 0.62. Выставив 1.0 напрямую, вы сделали бы их непрозрачными и закрыли всё
под ними. При 100 % слой выглядит ровно так, как задуман.

⚠️ Если добавляете слою новый элемент на карте — впишите его сюда, иначе ползунок будет
гасить слой наполовину. Именно так и было: гасилась розовая зона пролёта, а синие линии
поверх неё оставались яркими.

## 10. Окно «Векторные слои…»

Кнопка под группой «местность». Список рек, дорог, ЛЭП и прочего — что показывать по
отдельности.

* **не модальное** — с ним можно работать, глядя на карту;
* переключение действует **сразу**, ничего не пересчитывая: веса, маршруты и датчики

## 10а. Запретные зоны (рисует пользователь)

Кнопка **«Запретная зона»**: клики задают вершины, колёсико замыкает, `Esc` отменяет.
Рядом «Убрать зону» — снимает последнюю. Все разом убирает «Сброс».

**Цвета** — в `THREAT_COLORS` (`src/view_qt/tabs/threat_view.py`):

| ключ | что красит |
|---|---|
| `zone` | контур заданной зоны (штриховая линия) |
| `zone_hatch` | диагональная штриховка внутри, формат `(r, g, b, a)` |
| `zone_fill` | лёгкая подложка под штриховкой |
| `zone_draw` | линия зоны, которую рисуют **прямо сейчас** |
| `zone_pt` / `zone_pt_edge` | поставленные вершины и их обводка |

**Штриховка вместо сплошной заливки** — чтобы зона читалась как «закрашенная», но не
прятала карту под собой, и отличалась от сплошных заливок рельефа ещё и текстурой.
Плотность — `ThreatMapView.ZONE_HATCH_STEP_KM` (сейчас 1.6 км): мельче шаг — плотнее
заливка и больше линий на карте.

Штрихи строятся не по прямоугольнику вокруг зоны, а обрезаются **по самому контуру**:
для каждой линии находятся пересечения со сторонами, точки сортируются вдоль неё и
соединяются парами «вход — выход». Поэтому невыпуклая зона (а мышью рисуют что угодно)
штрихуется верно — в вырезах штрихов нет.

**Как подбирался цвет — задача была неочевидная.** Зона лежит поверх ВЕСОВОЙ КАРТЫ, а та
в палитре turbo: синий → циан → зелёный → жёлтый → красный, то есть занимает почти весь
спектр. Плюс подложка OSM зелёная. Красный не годится — он занят возвышенностями
«приоритета высот» и городом. Считалось расстояние до всей палитры turbo и контраст к
фонам:

| кандидат | до turbo | контраст к лесу | к полям |
|---|---|---|---|
| маджента `#b5179e` | 124 | 3.53 ✗ | 5.06 |
| **глубокий пурпур `#8e0e6b`** | **89** | **5.57** | **7.56** |
| индиго `#3d3bd6` | 32 ✗ | 4.53 | 6.48 |
| зелёно-бирюзовый | — | 3.9 ✗ | — |

Взят глубокий пурпур: он единственный проходит и по удалению от turbo, и по контрасту на
обоих фонах. Тон 316° — вне красного сектора.

Цвет линии построения раньше был `#ffd166` — ровно цвет перекрёстков-развилок, и при
включённом слое развилок рисуемый контур в них терялся. Взят свободный сектор тона
(бирюзово-зелёный). Вершины — цветом будущей зоны, чтобы сразу видеть, во что превратится
контур; обводка вершин цветом линии построения связывает их с ней.

**Толщина линий** — `ZONE_WIDTH` и `ZONE_LINE_MIN`. Зона ведёт себя не как векторные слои:
там канты худеют при ОТДАЛЕНИИ (иначе сливаются в кашу), а зона на общем виде должна быть
заметной — она одна-две на карту. Поэтому она худеет при ПРИБЛИЖЕНИИ и всего на четверть
(3.4 → 2.55 px), чтобы толстый контур не закрывал местность. Между соседними уровнями
зума разница выходит около 2 % — линия не «прыгает».

**Что зона делает с расчётом** — [ОГРАНИЧЕНИЯ.md §5.2](../правила/ОГРАНИЧЕНИЯ.md). Коротко: запрещает
пролёт (как город), сужает область пролёта — это её назначение, весов карты не трогает,
датчики в ней ставить можно, переживает пересборку карты. Если зона перекрыла коридор
целиком, цель становится недостижимой — программа пишет об этом в заголовок карты.

## 10б. Сектор появления БПЛА (задаёт пользователь)

⚠️ **С 16.09.2026 кнопок «Задать сектор» и «Убрать» в панели нет** (план 11, 11.6): сектор
переехал в окно. В строке панели теперь **«Указать цель» · «Сектор налёта»**; кнопка «Точки старта» с 30.09.2026
тоже в окне сектора — «Редактировать точки» и «Добавить точки» (заказчик: «эту кнопку перенеси в окно сектор»).

**Окно «Сектор налёта»** (`src/view_qt/windows/sector_window.py`, немодальное):

| элемент | что делает |
|---|---|
| **Раствор сектора** (10…360°, шаг 10) | полный раствор сектора по клику; через 0.5 с после правки точки переотбираются |
| **Точек входа** (1…36) | сколько точек отбирать; так же сразу |
| **Построить сектор (360°, по 10°)** | все стороны: край делится по 10°, из долей — приоритетные направления |
| **Задать сектор кликом** | режим на карте: каждый щелчок по краю — ось «цель → точка» заново; **правая кнопка мыши — выход и закрытие окна**, Esc — выход без закрытия |
| **Убрать сектор** | точки сектора уходят вместе с перенесёнными, добавленные вручную остаются |
| **Редактировать точки** | режим мыши: щелчок — выбрать точку входа, тащить — перенести, DELETE — удалить, двойной клик — добавить; перенесённая точка **остаётся белой** |
| **Добавить точки** | режим мыши: каждый щелчок внутри района — новая точка (розовая); вторая кнопка меняет подрежим, та же — выход; правая кнопка / Esc — выход |
| строка состояния | вид сектора, сколько точек сектора и добавленных, легенда «белые — сектор (и перенесённые), розовые — добавленные», идущий режим |

Поменять раствор по умолчанию без пересборки программы теперь не нужно — он правится в окне.
Умолчание при запуске — `THREAT_SECTOR_HALF_DEG` в `config.py` (поле `Params.threat_sector_half_deg`).

**Точки входа мышью** (кнопки окна сектора; до 30.09.2026 — кнопка «Точки старта» панели): один режим с двумя
подрежимами (`_begin_edit_entry(add)`, флаг `_entry_add`). Панель на время режима гаснет, выход — кнопкой окна,
правой кнопкой или Esc. Метка выбранной точки — пустой треугольник 30 px поверх точки 18 px: прежняя, с белой
заливкой, закрывала цвет точки. **Перенесённая точка сектора остаётся белой** (`moved_entries`, заказчик 30.09.2026:
«розовые не надо»), переотбор сектора её не сдвигает и на прежнее место белую копию не ставит. Добавленные
человеком — тот же треугольник `entries_manual_scatter` с розовой заливкой `THREAT_COLORS["entry_manual"]` = `#ff4fd8`. ⚠️ Сначала была чёрная обводка
«поставлено рукой», как у датчиков, — на скриншоте она не отличалась от тёмной обводки точек
сектора; розового в шкале turbo нет, на весовой карте он не сливается.

**Рамка района** — `THREAT_COLORS["area_frame"]` = `#ff1a1a`, ярко-красный пунктир (заказчик 30.09.2026: «не голубая,
прям ярко-красная»): `bbox_item` — рамка на карте, `area_draw_item` — рамка, которую тянут мышью при выборе района.
Толщина и штрих — там, где создаётся `bbox_item` (`width=3.0, dash=[12, 6]`). Прежде обе брали `THEME["accent"]` —
его не трогать: он красит и кнопки.

**Переключатель «район / радиус»** — справа от заголовка «КАРТА УГРОЗ»
(`chk_shape_rect`, `chk_shape_circle`). Выбирает форму СЛЕДУЮЩЕГО района: «Задать район» у
круга — щелчок в центр, щелчок в точку окружности, колёсико. Кнопка района показывает
«Район 120 × 73 км» либо «Радиус 36 км». Синяя рамка у круга — окружность (`bbox_item`).

**Два чекбокса в блоке ПОКАЗ, по слою на каждый:**

| Чекбокс | По умолчанию | Слой |
|---|---|---|
| «Точки входа» | ✅ включён | `entries_scatter` — точки сектора и `entries_manual_scatter` — свои, участвуют в расчёте |
| «Границы сектора» | ☐ выключен | `sector_lines` + `sector_shadow` — служебная разметка |

Линии скрыты по умолчанию: они показывают, ОТКУДА отбирались точки, и после отбора
своё дело сделали. Галки только прячут разметку — сектор остаётся заданным.

⚠️ **Клики ничего не пересчитывают.** Сектор и точки старта лишь задают обстановку
(маршруты и датчики при этом сбрасываются — они от прежней), а расчёт запускает
**«Расставить датчики»**: обстановка менялась — сперва зона пролёта и выборка (маршруты или
итерации, смотря что включено), потом расстановка. Иначе при обычном порядке действий «поставил
цель → очертил сектор» пересчёт шёл дважды, и первый раз — по промежуточному состоянию. Объекты
защиты (§10б′) после постановки пересобирают только карту.

⚠️ **«Применить» только принимает изменения** (заказчик 25.09.2026): числа панели, сетка кандидатов,
перерисовка и показатели — **без** пересчёта маршрутов, зоны пролёта и перестановки датчиков.
Прежде кнопка сама переставляла датчики. То же — «Применить» окна исходных данных при правке
запаса хода или разрыва: прежняя зона пролёта прячется, новая — по «Расставить датчики».

## 10б′. Объекты защиты — окно «Указать цель» (план 13, 13.13)

С 23.09.2026 кнопка **«Указать цель»** открывает окно **«Объекты защиты»**
(`src/view_qt/windows/targets_window.py`, немодальное). Целей может быть несколько — до
`THREAT_TARGETS_MAX` = 5 (`config.py`).

| элемент | что делает |
|---|---|
| **Количество объектов** (1…5) | сколько целей поставить за один заход — **добавляются** к уже стоящим |
| **Задать объект** | окна прячутся; **двойной клик** по карте ставит цель; набрали заданное число — режим закрывается сам и цели **применяются** (карта и зона пролёта пересчитываются в фоне); **правая кнопка** или Esc — закончить раньше, поставленные остаются |
| таблица | № · широта · долгота · X, Y км · **приоритет** · **Сектора** · Зона ПВН · **Район** (Д5, 25.09.2026 — галка «показать район защиты», свой или по застройке; обе галки — только показ; с 29.09.2026 у
новой цели **обе сняты**, начерченный мышью район включает «Район» сам); широта, долгота и приоритет правятся; галочка «Сектора» (с 23.09.2026) — рисовать ли у этой цели компас «анализа моделирования» (сама галочка «Сектора» в группе «пролёт БПЛА» — общий выключатель) |
| строка под таблицей | сколько целей, сумма приоритетов, у какой цели кольцо больших датчиков; при равных долях — «большие датчики автоматически не ставятся» |
| **Очистить** | убрать все цели — расчёт вернётся к цели по умолчанию (метка участка или центр круга) |
| **Изменить цели** (29.09.2026) | окна прячутся; щелчок у крестика — выбрать цель, её метку можно тащить (перенос снимает район); щелчок в стороне — угол района защиты выбранной цели, второй — противоположный, **колёсико** — принять; правая кнопка или Esc — выход. Та же кнопка «Изменить цель…» — в вопросе «Укажите район защиты» |

**Приоритеты** раздаются поровну при каждом добавлении: 1 · 0.5 / 0.5 · 0.33 × 3.
Правка принимается, если сумма **не больше 1** (иначе — отказ с пояснением под таблицей).
В розыгрыш маршрутов приоритет пока не идёт; работает он на кольцо больших датчиков — у
цели с наибольшей долей, при равных долях кольца нет.

**На карте** каждая цель — крест `target_scatter`; при двух и больше — номер над крестом,
чёрный жирный (`THREAT_COLORS["sensor_num"]`, как номера датчиков). Номер совпадает с
номером строки таблицы. Разбор кода — [код/ЦЕЛИ_И_РОЗЫГРЫШ §7](../код/ЦЕЛИ_И_РОЗЫГРЫШ.md).

**Окно «Аналитика»** (до 06.10.2026 — «Анализ моделирования») **при нескольких целях** (с 23.09.2026): сверху список «Что

светлой подложке чистый белый пунктир сам по себе теряется.

## 10в. Окна «Датчики» и «Тип датчика» (план 13, 13.2–13.3)

С 24.09.2026 датчики живут в **своём окне**: «Исходные данные» → кнопка **«Датчики…»**
(`src/view_qt/windows/sensors_window.py` :: `SensorsWindow`). В «Исходных данных» остались условия,
область, маршрут и расстановка (`threat_cand_step_km`, кольцо больших `threat_big_ring_*`),
число сегментов `L_seg`. Оба окна немодальные: карту можно двигать, не закрывая их.

| Блок окна «Датчики» | Что в нём | Поля `Params` |
|---|---|---|
| **Режим работы** | «Рассчитать / Задать позиции» · кратность «общая / у каждого своя» · «распределённое размещение» · **очерёдность типов** (правило общего прохода, 13.6) | `threat_manual_mode`, `threat_k_same`, `threat_spread_types`, `threat_type_order` |
| **Типы датчиков** — мини-таблица «№ · тип · цвет · N · R · k» | строка на тип; щелчок по образцу цвета — палитра; кнопки «Настроить тип…», «Добавить тип», «Удалить тип» | номера 1–4: `threat_N*`, `threat_R*`, `threat_k*`; номера ≥ 5: `threat_N_types` |
| **Датчики на карте** | таблица, файл, «Добавить», «По клику на карте», «Изменить / Удалить / Очистить» | — (записи `manual_sensors`) |

⚠️ **ПЕРЕХОДНЫЙ МОСТ** (план 13 §13.1.4): у номеров 1–4 числа N, R, k — поля `Params`; у типов
справочника с номером ≥ 5 число — `threat_N_types`, а R и k — в паспорте, поэтому в мини-таблице
они серые и правятся в окне типа. Номера 1–4 не удаляются — выключаются числом N = 0.

**Окно «Тип датчика»** («Настроить тип…», `src/view_qt/windows/sensor_types_window.py` :: `SensorTypesWindow`):
слева список типов участка, справа паспорт — **только для чтения** до кнопки **«Редактировать»** (при правке список
заперт; «Сохранить» — записать, «Отмена» — вернуть как было, Д1 25.09.2026) — название, класс, R, k, цвет, «статический по
умолчанию», место установки («везде» / «застройка» / «дорога») и его поля, шесть полей числа у объектов
защиты, бонусы места. Поля открыты **только при своём правиле места** (4-й элемент `FIELDS`): полосы, цели и бонусы —
у «застройки», **«Отступ от рек и болот»** и **«Дальность по дорогам от целей»** — у «дороги» (МОГ, план 13.3).
«Сохранить» проверяет паспорта (`validate`) и пишет справочник участка
`geo_cache/<участок>/типы_датчиков.json`; R и k номеров 1–4 уходят в задание — **только у
типов, чью форму открывали**. Группа **«Показывать данные на карте»** (29.09.2026; галка в заголовке — всё сразу)
кладёт на карту ячейки места типа и его места (`show_type_zone`), в заголовке — км² и число мест; внутри группы —
галки «разрешённая карта», «места (позиции)» и семь слоёв карты (Д3) с подсказками, что в слое
(`SensorTypesWindow.PART_TIPS`; «непроходимо (город)» переименовано в «непроходимо для БПЛА» — город там лишь 86 ячеек из 3 965).
**Слои — свои у каждого правила** (`PARTS` — словарь по правилу, виден блок правила в форме): у «застройки» — лес,
болота, неудобья, непроходимо, застройка, постройки ± полоса, полоса у дорог; у **«дороги»** — дороги, доезжает от
целей, реки, болота, запрет «реки и болота ± отступ», непроходимо; под ними — **векторные слои** (`VECTORS`): дороги
крупные, местные, лесные, реки, ручьи — линиями слоёв карты, контуры болот — из файла мест
(`ThreatMapView._draw_type_vectors`, перерисовка по кадру при остановке вида, независимо от галки «Слои»). Заголовок у
«дороги» — ещё «доезжает X % дорог, дальше всего D км» (`on_type_zone`). Под полем k — строка, с каким k
считают и откуда («одна на все типы» окна «Датчики» / своя, поле задания / из паспорта). У **порога прироста** и
**уровня защиты** цели — галка **«от k»**: стоит — поле только для чтения и пересчитывается при правке
«Кратности защиты цели» (порог 1 · 3 · 4 · 5 %, уровень 99 · 92 · 89.3 · 86.7 … %), в паспорт пишется 0; снята — своё число.

**Цвета.** Цвет типа — из его паспорта (`src/view_qt/tabs/threat_view.py` :: `type_color`): ключ палитры
`THREAT_COLORS` или «#rrggbb», выбранный в окне. Паспорта нет — прежний цвет номера:

| ключ | что красит |
|---|---|
| `sensor` | тип 1: кольцо зоны обзора (заливка 70) и центр, `z` = 20/21 |
| `sensor_t2`, `sensor_t3` | типы 2 и 3: синий и малиновый |
| `sensor_big` | большие: сине-фиолетовый, заливка **слабее** (30), `z` = 18/19 |
| `sensor_plain` | «Обычный» №5: зелёный `#10b981` (Д1) |
| `target_area` | район защиты цели: тёмно-зелёный `#15803d`, контур 2.2 и штриховка (Д5) |
| `bld_lo`, `bld_hi` · `flr_lo`, `flr_hi` | постройки по ячейкам: число (жёлтый → бурый) и этажность (голубой → синий) (Д2) |

Легенда собирается по типам задания с их названиями (`refresh_legend`).

**Почему у больших своя заливка и свой слой.** Радиус 15 км против 2 — круг в семь раз
шире; с обычной заливкой он закрыл бы полкарты, а нарисованный поверх малых — спрятал бы
их значки. Поэтому большие рисуются НИЖЕ малых и полупрозрачнее. Цвет холодный
сине-фиолетовый: далеко и от оранжевого малых, и от красного возвышенностей, и от
пурпура запретных зон.

Механика расстановки — [МЕТОДИЧКА_КАРТА_УГРОЗ §6.2а](../вкладка_3/МЕТОДИЧКА_КАРТА_УГРОЗ.md).

⚠️ 31.08.2026 цвет больших датчиков пробовали сменить на красный (`#e01b3c`) — **вернули

**ДВЕ РАМКИ, и путать их нельзя** (с 04.09.2026, план 8 задача 8.2):

| Рамка | Что означает | Когда видна | Элемент |
|---|---|---|---|
| **чёрная** штрих `[16, 8]`, alpha 210 | предел, за которым нет ни векторных данных, ни рельефа — дальше расчёт невозможен | всегда | `area_max_item` |
| **синяя** `THEME["accent"]`, толщина 3.0, штрих `[12, 6]` | РАЙОН МОДЕЛИРОВАНИЯ: где строится сетка | только когда район задан | `bbox_item` |

Синяя рисуется ярко (толщина **3.0** вместо 1.6, alpha **255** вместо 180) с 31.08.2026:
на плотной весовой карте тонкая полупрозрачная рамка читалась как случайная линия слоя.

**Ноль осей переносится галочкой «Отсчёт от угла района»** (блок ПОКАЗ, включается сама
при задании района). Ноль — в юго-западном углу района, и за его пределами подписи уходят
в минус; галочка снята — ноль в углу всей области, все координаты положительные.
⚠️ Сдвигаются ТОЛЬКО подписи (`ShiftedAxis`): данные, сетка, датчики и координаты по
клику живут в общем фрейме, иначе появилась бы вторая система отсчёта.

**Предел обзора — район, а не масштаб.** Камера не уходит за кадр ОБЛАСТИ и кадр района,
у каждого поле 4 % кадра с учётом формы окна (`_apply_view_limits`). Ограничения отдаления
(`maxXRange`/`maxYRange`) сняты: они мешали широкому экрану показать участок целиком.

**Пример.** Прежнее поле «район + 100 км» (`THREAT_VIEW_PAD_KM`, убрано 13.09.2026) на
области Донецка 95 × 75 км давало 100 км пустоты с каждой стороны, сейчас 3.8–4.3 км.

**Область и папка тайлов — первый блок окна «Исходные данные».** «Область…» выбирает файл
`область.txt` и перезапускает программу; «Папка тайлов…» и «Тайлы по умолчанию» меняют
корень подложки сразу. Окно «Исходные данные» доступно и без района — иначе с области без
района не уйти. Устройство — [план 10 §10.5](../планы/10_ПЛАН_ПРОЕКЦИЯ_И_ОСТАТКИ.md).

⚠️ **Отступ «вписать в окно» — доля кадра (3 %), а не километры.** Он был завязан на
`THREAT_VIEW_PAD_KM`, и когда тот вырос с 5 до 100 км, отступ стал 100/120 = **83 %
ширины**: вид отъезжал почти втрое, на небольшом экране карта превращалась в марку
посреди пустого поля. При запуске вписывается ВСЯ область (чтобы чёрная рамка была видна
целиком на любом экране), кнопка «Весь участок» — район.

**Строка координат под картой** (`lbl_coords`, план 8 задача 8.3): клик по карте — и
точка показана сразу в четырёх видах: градусы, градусы-минуты-секунды, радианы и
километры. Отдельным виджетом, а не текстом на сцене: на сцене строка ездила бы вместе с
картой и попадала в кадр поверх слоёв.

| Параметр | Смысл |
|---|---|
| `SPLASH_IMAGE` | путь к картинке; пустая строка или отсутствующий файл — заставки нет |
| `SPLASH_SECONDS` | сколько держать (0 — выключить совсем) |
| `SPLASH_FULLSCREEN` | во весь экран (иначе окно по размеру знака) |
| `SPLASH_EMBLEM_FRAC` | какую долю высоты экрана занимает эмблема |
| `SPLASH_MAX_PX` | высота эмблемы, если полноэкранный режим выключен |
| `SPLASH_PAD` | поле (рамка) вокруг эмблемы и текста |
| `SPLASH_TITLE` | название работы — крупно НАД эмблемой, переносится по словам |
| `SPLASH_EMBLEM_TEXT` | надпись ПОВЕРХ знака, на жёлтой ленте |
| `SPLASH_EMBLEM_TEXT_COLOR` / `_Y` / `_PT` | её цвет, положение по высоте знака (доля 0…1) и кегль |
| `SPLASH_AUTHORS_LABEL` / `SPLASH_AUTHORS` | «Разработали:» и список фамилий |

Пустая строка убирает свою надпись. Порядок сверху вниз: название → эмблема (с красной
надписью на ленте) → «Разработали:» → фамилии.

**Название и фамилии — ПОД/НАД знаком, на подложке цвета темы; на самой эмблеме только
короткая надпись отдела** — по геральдическому изображению длинный текст читался бы
плохо. Кегли считаются В ПИКСЕЛЯХ от высоты экрана: пункты зависят от системного DPI, и
на другой машине текст выехал бы за край.

**Почему заставка появляется до сборки вкладок.** Построение трёх вкладок занимает
секунды; если показывать эмблему после, пользователь всё это время смотрит в пустой
экран. Поэтому: показать → `app.processEvents()` (без него окно останется пустым
прямоугольником) → собрать интерфейс → досидеть остаток пяти секунд по таймеру.
`time.sleep` здесь недопустим — поток встанет, и Windows нарисует «программа не
отвечает».

⚠️ Для `.exe` файл нужно добавить в `datas` рецепта PyInstaller — иначе заставка молча
пропадёт, см. [СБОРКА_EXE.md](../сборка/СБОРКА_EXE.md).

## 10д. Мышь: двойной клик ставит точки, линейка — как в Google Earth

**Колесо** — масштаб ровно ×2 за щелчок (уровень тайлов, подложка пиксель в пиксель). **Ctrl + колесо** — плавно,
анимацией (×1.25 за щелчок, кадры по 16 мс, тачпад — пропорционально прокрутке), уровень тайлов заморожен; Ctrl
отпустили — вид той же анимацией встаёт на ближайший уровень. **Перетаскивание** — курсор «сжатая рука» (план
13.5.3, 13.5.6, 13.5.7; во время «Пуска» кнопки обстановки заблокированы без курсора ожидания — окнами пользоваться
можно). Разбор —
[код/ПОКАЗ_ГРАДАЦИЙ_И_СЛОЁВ](../код/ПОКАЗ_ГРАДАЦИЙ_И_СЛОЁВ.md) §3).

⚠️ **ТОЧКИ СТАВЯТСЯ ДВОЙНЫМ КЛИКОМ** (правило заказчика 21.09.2026): цель, ось сектора и
старт БПЛА. Одинарный щелчок только показывает координаты — случайное нажатие по карте
больше ничего не двигает. Правая кнопка в любом режиме — выход.

⚠️ **ПРИ ВЫБОРЕ ТОЧКИ ПРЯЧУТСЯ ВСЕ ОКНА**, кроме основного (`_hide_dialogs`), и
возвращаются после клика или выхода. Прячутся именно ВИДИМЫЕ — иначе вернулось бы то,
чего не открывали.

**Линейка «Расстояние»** живёт в `src/view_qt/maps/measure_tool.py` и работает одинарными кликами,
как в Google Earth:

| Действие | Что видно |
|---|---|
| ведём мышь после первой точки | полупрозрачная линия за курсором и километры у него |
| щёлкнули | отрезок закреплён: длина и время **посередине сегмента**, повёрнуты вдоль него |
| ведём дальше | сумма пути остаётся **за последней точкой**, как продолжение линии |

⚠️ **Время считается по скорости ВЫБРАННОГО ТИПА БПЛА** (формат «2 ч 35 мин»). Тип не
выбран — время не показывается вовсе: выдуманное число хуже пустого.

⚠️ **Подпись не встаёт вверх ногами:** если отрезок идёт влево, угол разворачивается на
180° (`_angle_deg`).

⚠️ **Отдельный поток линейке не нужен и невозможен:** рисование в Qt однопоточно, а
мешать расчётам она не может — тяжёлые этапы уже идут в фоновом потоке (`_run_async`).

## 11. Правило, которое нельзя нарушать

**Показ ≠ пересчёт.** Галка слоя и ползунок прозрачности меняют ТОЛЬКО видимость и
прозрачность. Пересчёт живёт в кнопках «Построить карту», «Добавить рельеф», «Расставить
датчики», «Пуск / Шаг / Пакетно»; «Применить» только принимает изменения.

Исключение сделано осознанно: «Зона пролёта», «Маршруты движения» и «Выборка» считаются
по включению галки — это ленивый расчёт, чтобы не заставлять жать лишнюю кнопку. Слой,
который сам не посчитается (тепловая карта маршрутов без маршрутов, приоритет высот без
добавленного рельефа), в панели **погашен** и подсказка говорит, что нажать.
