# Настройка интерфейса вкладки 3 — что и где менять руками

> **Кому это.** Здесь собрано всё, что можно поправить БЕЗ программирования: начальные
> значения полей, подписи слоёв и подсказки, цвета линий, толщина, штрих, порядок
> отрисовки, гашение подложки, легенда. Для каждой настройки — файл, имя и что именно
> изменится на карте.
>
> **Правило проекта:** параметры расчёта живут в `config.py`, а всё, что про ВИД карты,
> — вверху `view_qt/threat_view.py`. Не разносите значения по коду: они специально
> собраны в нескольких таблицах.

---

## 1. Начальные значения полей панели

**Файл:** `config.py`, класс `Params`.

Это то, что подставляется при запуске программы. В самом интерфейсе всё это меняется
мышкой, но стартовые значения задаются здесь.

| поле | что задаёт | сейчас |
|---|---|---|
| `threat_N` | сколько датчиков расставлять | 15 |
| `threat_R` | радиус обнаружения датчика, км | 2.0 |
| `threat_k` | сколько датчиков должны увидеть БПЛА, чтобы засчитать засечку | 1 |
| `threat_cand_step_km` | шаг сетки кандидатных позиций датчика, км | 3.0 |
| `threat_spend` | профиль расхода запаса хода | `"even"` (равномерно) |
| `threat_iter_mode` | приоритет по весу для итераций | `"max"` |
| `threat_iter_spread` | разброс маршрутов по карте | `"mix"` |
| `threat_iter_routes` | сколько маршрутов набирать | 150 |
| `threat_max_gap_km` | разрыв между весовыми секторами (мостик через пустоту) | 2.0 |
| `threat_corridor_slack_km` | насколько можно уйти вбок от ориентира | 1.0 |
| `threat_L_max` | запас хода, км (0 = считать автоматически) | авто |
| `map_layer3` | подложка при запуске | `"osm"` |

⚠️ **Шаг сетки и радиус связаны.** `threat_cand_step_km` — это шаг, с которым
расставлены КАНДИДАТНЫЕ позиции, из них жадный алгоритм выбирает лучшие. Если шаг
крупнее радиуса (сейчас 3 км против 2 км), датчик может не встать в лучшую точку — между
кандидатами остаются дыры шире зоны обзора. Мельче шаг — точнее расстановка, но перебор
дольше: 1.5 км → 1983 позиции, 3 км → 485, 6 км → 134.

## 2. Подписи слоёв, группы и подсказки

**Файл:** `view_qt/threat_view.py`, таблица `LAYER_GROUPS` в классе `ThreatMapView`.

Одна строка = один слой в панели «ПОКАЗ»:

```python
("chk_layers", "Векторные слои", True, "Реки, дороги, ЛЭП, железные дороги — …"),
#      │              │            │                      │
#      │              │            │                      └─ подсказка при наведении
#      │              │            └─ включён ли при запуске
#      │              └─ подпись в панели (её видит пользователь)
#      └─ ИМЯ ПЕРЕМЕННОЙ — не трогать, на него ссылается контроллер
```

* **менять подпись и подсказку** — свободно, это просто текст;
* **менять `True`/`False`** — включён ли слой при запуске;
* **переносить строку в другую группу** — можно, слой переедет в панели;
* ⚠️ **имя (`chk_...`) менять нельзя** — по нему контроллер узнаёт слой (`get_toggles`),
  и переименование сломает отрисовку.

Названия групп («местность», «весовая карта», …) — первый элемент каждой пары в
`LAYER_GROUPS`. У группы есть свой переключатель: он гасит всех её детей разом.

**Надписи режимов** (выпадающие списки) — в `config.py`:
`MODE_LABELS`, `THREAT_SPEND_LABELS`, `THREAT_ITER_MODE_LABELS`, `THREAT_ITER_SPREAD_LABELS`.
Слева ключ (его знает модель — не трогать), справа надпись (меняйте свободно).

## 3. Цвета и вид линий цифровой карты

**Файл:** `view_qt/threat_view.py`, таблица `LAYER_STYLE` (в самом верху файла).

```python
"road_major": dict(color="#9e4825", width=3.0, dash=None, z=-5.1,
                   casing="#ffffff", casing_w=5.0, alpha=250),
```

| поле | что делает |
|---|---|
| `color` | цвет линии, `"#rrggbb"` |
| `width` | толщина в пикселях |
| `dash` | штрих: `None` — сплошная, `[7, 4]` — 7 закрашено, 4 пусто |
| `z` | ПОРЯДОК отрисовки: меньше — ниже, больше — поверх остальных |
| `casing` | цвет обводки (`None` — без неё) |
| `casing_w` | ширина обводки, должна быть больше `width` |
| `alpha` | непрозрачность самой линии, 0…255 |

Легенда берёт цвета отсюда же — поправите цвет, поменяется и карта, и легенда.

### Порядок отрисовки (`z`) — снизу вверх

```
built_up (-5.9) → tree_row → stream → river → railway → pipeline → power
                → road_local → road_major → bridge (-5.0)
```

Логика: дороги наверху (по ним ориентируются), инфраструктура ниже, застройка в самом
низу. ⚠️ Раньше у всех слоёв стоял один `z = -5`, и порядок получался случайным — кто
нарисован последним, тот и сверху. Если задаёте свой `z`, держите шаг не меньше 0.1:
обводка слоя рисуется на `z − 0.04`.

### Три правила, которые легко нарушить

1. **Не гонитесь за максимальным контрастом.** Все фоны OSM светлые, поэтому «самый
   контрастный» цвет — чёрный. Сделав так, вы получите десяток одинаково чёрных линий:
   контраст к фону идеальный, а слои неразличимы между собой. Берите САМЫЙ СВЕТЛЫЙ тон,
   который ещё читается.
2. **Проверяйте на худшем фоне.** Карта OSM — это лес, поля, вода, дороги, застройка.
   Худший (самый тёмный) — лес. Если линия читается на нём, читается везде.
3. **Цвета мало — нужен ещё штрих или толщина.** Тонкие линии при отдалении сжимаются в
   пиксель, и соседние оттенки смешиваются. Поэтому ЛЭП — частые точки `[2,3]`,
   трубопровод — длинный пунктир `[9,5]`, лесополоса — короткий `[3,4]`, ж/д — «шпалы»
   (тёмный пунктир поверх белой обводки). Даже если цвета сошлись, штрих разведёт.

⚠️ **Слишком редкий штрих убивает линию.** `[1, 5]` закрашивает лишь шестую часть длины —
на общем виде такая линия вырождается в еле заметную пыль, и никакой цвет её не спасёт.
Держите закрашенную долю не ниже трети.

## 4. Цвета маршрутов, датчиков и зон

**Файл:** `view_qt/threat_view.py`, таблица `THREAT_COLORS`. Рядом с каждым цветом в
комментарии указано, где на карте он применяется.

| ключ | что красит |
|---|---|
| `route_all` | синие линии «возможные маршруты» |
| `route_iter` | накопленные итерационные маршруты |
| `route_gen` | обобщённая выборка (10 %) |
| `route_main` | текущий маршрут итерации (чёрный) |
| `envelope` | розовая заливка «все места пролёта» |
| `sensor` | датчик: кольцо зоны обзора и центр |
| `uav` | маркер летящего БПЛА |
| `crossing` | ромбы-развилки |
| `legend_*` | цвета в легенде |

Рядом же: `THREAT_URBAN_RGBA` (город) и `THREAT_WATER_RGBA` (вода) — цвета зон-исключений
в формате `(r, g, b, a)`.

Цвета рельефа — `RELIEF_*` там же: карта высот, укрытия, возвышенности, снятый коридор.

## 5. Подложка (карта-основа)

**Файл:** `view_qt/threat_view.py`, `ThreatMapView.BASEMAP_FADE = (0.20, 0.10)`.

Два числа: насколько **обесцветить** и насколько **осветлить** тайлы подложки.
`(0.0, 0.0)` — оставить как есть.

**Зачем.** OSM рисует СВОИ дороги, воду и лес, а мы кладём сверху свои — оранжевое на
оранжевом, синее на синем. Это главный источник каши на общем виде, и лечится он не
подбором палитры, а тем, что подложка уходит в фон.

⚠️ **Не перебарщивайте.** При `(0.62, 0.30)` карта выцветала почти в белый лист: лес,
поля и вода переставали различаться, и терялся контекст. Разумный предел — около 20 %.

⚠️ **Меняете гашение — пересчитайте палитру.** Контраст линий считался под ЭТОТ фон.
Сделаете подложку ярче — линии, подобранные под бледную, поплывут.

Гашение включено только для вкладки 3 (в `BasemapMixin` по умолчанию `(0.0, 0.0)`) —
у вкладки 2 поверх карты почти ничего не лежит, ей это не нужно.

## 6. Что меняется при отдалении

**Файл:** `view_qt/threat_view.py`, класс `ThreatMapView`.

| настройка | что делает | сейчас |
|---|---|---|
| `MARKER_SIZE` | базовый размер маркеров (мосты, развилки) | 11 и 7 px |
| `MARKER_MIN` | до какой доли они уменьшаются на общем виде | 0.45 |
| `CASING_MIN` | до какой доли худеет ОБВОДКА линий | 0.35 |
| `LINE_MIN` | до какой доли худеет сама линия | 0.75 |

**Почему обводка худеет сильнее линии.** Вблизи белый кант разделяет линии на
пересечениях — это его работа. Но на общем виде, где дороги идут густой сетью, канты
соседних дорог сливаются в сплошное белёсое пятно вокруг посёлков. Поэтому кант
ужимается втрое, а сама линия почти не меняется — иначе слой просто исчезнет.

Маркеры мельчают по той же причине: их сотни, и в полном размере они застилают карту.

## 7. Легенда

**Файл:** `view_qt/threat_view.py`.

| настройка | что делает |
|---|---|
| `LEGEND_PT` = 7.8 | кегль общей легенды (левый нижний угол) |
| `LEGEND_PT_MIN` = 4.8 | нижний предел (сейчас не используется — размер постоянный) |
| `RELIEF_LEGEND_PT` = 7.5 | кегль панели «приоритет по высоте» (правый верхний угол) |
| `RELIEF_LEGEND_PT_MIN` = 4.5 | до чего она мельчает при зуме |

**Разное поведение — намеренно.** Общая легенда длинная, и при зуме, ужимаясь, она
становилась нечитаемой ровно тогда, когда по ней и сверяют объекты. Поэтому её размер
ПОСТОЯННЫЙ. Панель «приоритет по высоте» — три цвета в три строки, её видно и мелкой,
поэтому она мельчает при приближении.

Сам текст легенды — метод `_legend_html`. Цвета он берёт из `LAYER_STYLE` и
`THREAT_COLORS`, так что правка цвета меняет карту и легенду разом.

По умолчанию легенда **скрыта** (`chk_legend` в `LAYER_GROUPS` со значением `False`).

## 8. Прозрачность по группам

**Файл:** `view_qt/threat_view.py`, таблица `OPACITY_TARGETS`.

Ползунок под группой гасит ВСЁ, что эта группа рисует. Таблица говорит, какие элементы
сцены относятся к какому слою:

```python
"chk_routes": ("route_area_img", "route_item"),   # заливка И синие линии
"chk_layers": ("*vectors", "bridge_scatter"),     # все линии карты и их обводки
```

Спецключ `"*vectors"` разворачивается в десяток векторных линий и их обводки — они живут
в словарях `_layer_items` / `_layer_casing`, а не отдельными полями.

⚠️ **Ползунок МАСШТАБИРУЕТ родную прозрачность, а не задаёт её.** У рельефа она 0.55, у
тепловой карты 0.62. Выставив 1.0 напрямую, вы сделали бы их непрозрачными и закрыли всё
под ними. При 100 % слой выглядит ровно так, как задуман.

⚠️ Если добавляете слою новый элемент на карте — впишите его сюда, иначе ползунок будет
гасить слой наполовину. Именно так и было: гасилась розовая зона пролёта, а синие линии
поверх неё оставались яркими.

## 9. Цветовая шкала (справа от карты)

**Файл:** `view_qt/threat_view.py`, таблица `SCALE_SPECS`.

Шкала одна на две тепловые карты — весовую и карту частоты пролёта. Обе рисуются
заливкой по всей области, и держать две шкалы негде: они займут правый край вдвое.
Показывается шкала **последнего включённого** слоя.

```python
"iter_heat": dict(item="iter_heat_img", chk="chk_iter_heat",
                  cmap=_iter_heat_cmap, label="частота пролёта (редко → часто)"),
```

`label` — подпись у шкалы, `cmap` — палитра (весовая карта — turbo, частота пролёта —
magma). Выключенный слой не забывается, а уходит в начало очереди: включите снова —
шкала опять станет его.

## 10. Окно «Векторные слои…»

Кнопка под группой «местность». Список рек, дорог, ЛЭП и прочего — что показывать по
отдельности.

* **не модальное** — с ним можно работать, глядя на карту;
* переключение действует **сразу**, ничего не пересчитывая: веса, маршруты и датчики
  остаются как были;
* выбор хранится в представлении, поэтому окно можно закрыть и открыть — набор останется;
* верхний переключатель — тот же, что чекбокс «Векторные слои» в панели.

**Чем отличается от «Выбрать цифровые карты…».** Там решается, какие слои НАКЛАДЫВАТЬ НА
СЕТКУ, то есть какие войдут в вес ячеек — смена набора требует пересборки карты и
сбрасывает маршруты. Здесь — только показ.

Класс окна — `VectorLayersDialog`, порядок слоёв в списке — `THREAT_LAYER_ORDER` из
`config.py`, подписи — `THREAT_LAYERS[...]["label"]` оттуда же.

## 11. Правило, которое нельзя нарушать

**Показ ≠ пересчёт.** Галка слоя и ползунок прозрачности меняют ТОЛЬКО видимость и
прозрачность. Пересчёт живёт в кнопках «Построить карту», «Добавить рельеф», «Расставить
датчики», «Пуск / Шаг / Пакетно» и «Применить».

Исключение сделано осознанно: «Зона пролёта», «Маршруты движения» и «Выборка» считаются
по включению галки — это ленивый расчёт, чтобы не заставлять жать лишнюю кнопку. Слой,
который сам не посчитается (тепловая карта маршрутов без маршрутов, приоритет высот без
добавленного рельефа), в панели **погашен** и подсказка говорит, что нажать.
