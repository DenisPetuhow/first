## Задача 13.6.5 — схемы состояний и правил

**13.6.5.1. Что требуется.** «Диаграммы состояний помогают описывать объекты, жизненный цикл которых зависит от
текущего состояния… Поидее это очень поможет для расстановки датчика, построения маршрута с учётом всех режимов,
правила для отдельного типа датчика».

**13.6.5.2. Как решать.** `архитектура/3_СОСТОЯНИЯ_И_ПРАВИЛА.md`:

* (а) **модель вкладки 3**: нет района → район → сетка → маршруты → датчики; что сбрасывает каждый переход назад
  (`clear_area`, `iter_reset`, `set_manual_mode`) и какие переходы запрещены — по коду;
* (б) **выборка маршрута со всеми режимами**: что переключают `on_iter_mode`, `on_iter_spread`, `on_iter_approach`,
  `on_iter_spend`, какие участки полёта проходит один маршрут (по `sample_one_route`, МОДЕЛИ_МАРШРУТОВ §4.5);
* (в) **правила места по типу датчика** — схема-решение: ячейка → запреты места (постройки, лес, неудобья) → правило
  типа (МОГ — доезд по дорогам; ПВН — у целей; большой — от справочника) → кандидат → жадный выбор; источники —
  `датчики/ТИП_*`, ОГРАНИЧЕНИЯ_ДАТЧИКОВ;
* (г) **жизнь датчика**: кандидат → поставлен расчётом / поставлен человеком (входные данные) → перенесён мышью →
  принят «Применить».

**13.6.5.3. Ловушки.** Состояние, которого нет в коде, на схеме — ложь: каждое — с полем или признаком, по которому
код его различает. Схема (б) самая большая — делить по режимам.
