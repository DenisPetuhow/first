# ПОСТАНОВКА ЗАДАЧИ: ВЕРБАЛЬНЫЙ И МАТЕМАТИЧЕСКИЙ ПОДХОДЫ
## Обобщение формулировок оптимизационных задач по сборникам 696–699

---

## 1. ДВУХУРОВНЕВАЯ СХЕМА ПОСТАНОВКИ

Во всех эталонных статьях постановка строится в два уровня:

**Уровень 1 — содержательная (вербальная) постановка.** Словесное описание объекта, условий, исходных данных, искомого и критерия. Открывается фразой-паттерном:
- «Задача <планирования/выбора/обоснования> … заключается в определении <оптимальных …> для обеспечения <цель> при ограничениях на <ресурс/время>» (696-16);
- «Постановка задачи заключается в оптимизации <управляемая переменная> с целью максимизации <показатель> за заданное время или (и) при заданном <ресурсе>» (697-7);
- «Содержательная формулировка задачи … состоит в следующем. Требуется найти такой …, который …» (699-87).

**Уровень 2 — формализованная (математическая) постановка.** Вводится связкой: «Формализованно задача может быть представлена записью (1)» (699-221) или «Формально указанная задача … может быть представлена в следующем виде» (698-295), после чего — запись в обозначениях с полной расшифровкой «где … – …».

Правило: сначала всегда вербальный уровень, затем математический; обозначения вводятся только на втором уровне и далее используются во всей статье без повторных определений.

## 2. ВЕРБАЛЬНАЯ ПОСТАНОВКА: КАНОНИЧЕСКИЕ ШАБЛОНЫ

### Шаблон В1 «Дано – Найти» (аналитические модели; эталон 696-16)
```
<Контекст: 1–2 предложения об объекте и условиях.>
Дано: <объект>, состоящий из m <элементов>, который должен за время T выполнить
<целевую функцию>. <Перечень известных величин с обозначениями и законами
распределения: «Известно, что … », «Также известны затраты …».>
Найти: <искомые переменные> для обеспечения заданного уровня d <свойства>
при ограничениях на <ресурс> v_доп.
```

### Шаблон В2 «Дано (множества параметров) – Найти (функции)» (имитационные модели; эталон 698-295)
```
Дано:
Str = {…} – множество параметров, характеризующих состав <объекта>, где …;
V1 = {…} – множество параметров, определяющих <надёжностные характеристики>, где …;
V2 = {…} – множество параметров, характеризующих <программу применения>, где …;
… (V3, V4, V5 — обеспеченность, логистика, вероятности источников);
Найти:
y1 = f1(V1,…,V5); y2 = f2(V1,…,V5); y3 = f3(V1,…,V5),            (1)
где y1 – <фактическое значение показателя 1>; …
```
Приём: исходные данные группируются в поименованные множества V_k по смысловым блокам — это делает постановку масштабируемой и читаемой.

### Шаблон В3 «Дано – Требуется – Ограничения» (алгоритмы; эталон 697-7)
```
Дано:
– количество имеющихся <объектов> n;
– количество <ресурсных элементов> m;
– затраты ресурсов Z = ⟨τt, τs, et, es⟩, где …;
– директивный ресурс времени τ_доп;
– допустимый энергоресурс e_доп.
Требуется: построить алгоритм α <…>, обеспечивающий <цель> :
        α* = arg max_{α∈Α_доп} s(α(n, m, Z)),                    (1)
где s – показатель результативности …
Ограничения:  e(α) ≤ e_доп,  t(α) ≤ τ_доп,
где e(α) – затраты …; t(α) – затраты … .
```

### Шаблон В4 «Пусть задан … Требуется найти …» (сигнальные/математические задачи; эталон 699-87)
```
Пусть задан <объект> в дискретной форме, представленный вектором X = (x1,…,xN)ᵀ, (1)
где N – …; xi – … <со статистическими свойствами: мат. ожидание, дисперсия>.
<Введение производных характеристик: R_k(X) — (2).>
<Введение показателей качества: F1(X) — (3), F2(X) — (4): «для практической оценки
… необходимо ввести количественные меры … предложены два ключевых показателя».>
Требуется найти такой вектор X*, который получен путём многократного применения
оператора преобразования Ψ(·), обеспечивающего минимум одновременно двум целевым
показателям (3) и (4), при соблюдении следующих ограничений: 1) …; 2) … .
```

### Шаблон В5 «Прямая и обратная постановки» (синтез структур; эталон 697-227)
```
В первой постановке при заданных <параметрах> и <числе элементов N_зад> ищется
оптимальная структура, при которой <показатель качества> будет минимальным.
Во второй постановке при заданных <параметрах> и требуемом <показателе качества>
ищется оптимальная структура, при которой необходимое <число элементов> будет
минимальным.
```
Приём: пара «прямая ↔ обратная задача» (максимум эффекта при заданном ресурсе ↔ минимум ресурса при заданном эффекте) — стандартный способ полного охвата прикладной проблемы.

### Шаблон В6 «Объект – Среда – Структура – Ограничения (нумерованные) – Допущения – Цель» (многокритериальный синтез структуры; эталон — статья-образец «Методика синтеза структуры беспилотной системы…», Витензон, Попов, Петухов)

Наиболее полный из проанализированных шаблонов; используется, когда синтезируемый объект — группа однотипных подвижных/сетевых элементов:

```
Пусть задано множество <элементов> M = {m1,…,mn}, где n – общее количество <элементов>.
Каждый <элемент> описывается набором параметров: ⟨p_i, v_i, …⟩, i = 1..n,   (1)
где p_i – <положение>; v_i – <скорость>; … .
<Для упрощения примем, что характеристики … унифицированы.>

Параметры окружающей среды Ω определяются областью выполнения задачи:
Ω: ⟨L, W, T_mission, μ_cov, k_com⟩,
где L – …; W – …; T_mission – …; μ_cov – <степень покрытия>; k_com – <связность>.

Структура <объекта> представляет собой сетевую организацию из n <элементов>,
формализуемую неориентированным графом G(H, C), где H – множество вершин,
C – множество рёбер (связей, удовлетворяющих условию ||p_i − p_j|| ≤ R).
<При необходимости анализа связности — матрица смежности A, лапласиан B = V − A,
алгебраическая связность Фидлера λ₂(B).>

Для обеспечения функциональности <объекта> необходимо выполнение следующих
ограничений:
1. <Структурное ограничение>: …
2. <Ограничение достаточности покрытия/охвата>: …
3. <Ограничение связности/коммуникации>: ∀i: deg(m_i) ≥ k_com.
4. <Пространственные ограничения>: — все <элементы> в рабочей области; —
   безопасное расстояние между элементами ≥ D; — расстояние между
   взаимодействующими элементами ≤ R.
5. <Временные и энергетические ограничения>: T ≤ T_mission; E_i < E_max.

Для практической реализации модели примем следующие допущения:
– <допущение 1 о среде>;
– <допущение 2 об отсутствии препятствий>;
– <допущение 3 о качестве связи>;
– <допущение 4 о характере расходования ресурса>.

Цель оптимизации: необходимо построить <объект>, в котором обеспечивается не
только <оптимальная конфигурация>, но и <оперативность/устойчивость> с
минимальными <затратами>. Переменная оптимизации — <структура>, представленная
вектором P = {p1,…,pn} ∈ R^(2n).
```

Ключевая особенность шаблона: ограничения задаются **нумерованным перечнем по физическому смыслу** (структурные → покрытие → связность → пространственные → временн\u00f3/энергетические), а не единой строкой — это повышает читаемость при большом числе разнородных ограничений (5 и более групп). Блок «Допущения» выносится отдельным абзацем **после** ограничений и **перед** формулировкой цели — это самостоятельный, обязательный для физически детализированных моделей элемент, отсутствующий в более простых шаблонах В1–В4.

### Шаблон В7 «Теоретико-множественная постановка через кортеж вложенных множеств» (эталон 699-19 «Теоретико-множественная модель оценивания устойчивости АС в дуэльной ситуации „объект – нарушитель“»)

Применяется, когда объект — разнородная система (сектора, узлы, сервисы, процессы), а не однородная группа элементов:

```
При разработке теоретико-множественной модели <объекта> принят ряд допущений.
<Допущение 1 об учитываемых/неучитываемых процессах.>
<Допущение 2 об ограничениях модели нарушителя/среды.>
<Допущение 3 о принятом подходе к моделированию динамики (напр. дискретно-событийном).>

Теоретико-множественная постановка задачи представлена в следующем виде.
Дано:
I. Модель Mst, описывающая структуру и функционирование <системы>:
   Mst = ⟨Cek, Arm, Cet, Lsv, Msr, Mirz⟩,
где Cek – множество <секторов/подсистем>, Cek = {cek1,…,cekn};
    состав каждого <сектора> задаётся функцией F: Cek → Arm × Cet × Lsv × …;
    Arm – множество <элементов типа 1>; Cet – множество <элементов типа 2>;
    Lsv – множество связей, Lsv ⊆ Arm × Cet; Msr – модель <сервисов/процессов>,
    Msr = ⟨Pr, Kpr, …⟩, где Pr – множество процессов, Kpr – коэффициенты
    критичности процессов; …
Найти: <искомую функцию/множество рациональных решений — см. шаблон Т3>.
```
Приём: объект раскладывается на именованные множества-компоненты (по одной букве-обозначению на смысловой блок), для каждого — своя внутренняя структура и своя функция/отношение связи с другими множествами. Это масштабируемый способ формализации, когда объект структурно неоднороден и не сводится к числовому вектору параметров.

## 3. МАТЕМАТИЧЕСКАЯ ПОСТАНОВКА: ТИПОВЫЕ ФОРМЫ ЗАПИСИ

### Т1. Скалярная оптимизация с ограничениями (базовая форма)
```
S* = arg extr_{S ∈ S_доп} W(S, U),
S_доп = { S : g_k(S) ≤ g_k^доп, k = 1..K },
```
где S — вариант решения (структура, алгоритм, вектор параметров); U — условия обстановки/среды; W — показатель эффективности; g_k — ресурсные и качественные ограничения.
Примеры реализации: 697-7 (α* = arg max s(α) при e(α) ≤ e_доп, t(α) ≤ τ_доп); 699-221 (S* = arg min C(S) | q(S, R) ∈ Q_тр — минимум стоимости создания и эксплуатации ОГ при выполнении требований потребителя к объёму и качеству услуг).

### Т2. Минимизация риска при двойном ограничении (риск-ориентированные модели; 698-245)
```
X* = arg min_{X_N} R(X_N)  при  R(X_N) ≤ R_max,  C(X_N) ≤ C_max,
R_yj = P_j · D_j · (1 − Σ_i E_ji · x_i),  x_i ∈ X_N,
```
где P_j — вероятность реализации j-го воздействия; D_j — ущерб; E_ji — вклад i-й меры в защищённость; (1 − ΣE_ji x_i) — остаточная уязвимость. Область допустимых решений иллюстрируется графиком «риск–затраты» с выделением допустимой области и оптимума.

### Т3. Поиск множества рациональных решений (699-25)
```
Ξ* = Argmax_{ξ ∈ Ξ_доп} F(ξ),   F(ξ) = w1·C(ξ) + w2·K(ξ),  w1 + w2 = 1,
Ξ_доп = { ξ : T_rw(ξ) ≤ T_др, T_rc(ξ) ≤ T_св, ∀t∈T: P_ex(·) ≥ P_гр },
```
Приёмы: (а) Argmax (с прописной) — когда ищется множество, а не единственная точка; (б) свёртка векторного критерия взвешенной суммой с нормировкой весов; (в) вероятностное ограничение «на всём интервале моделирования».

### Т4. Двухкритериальная задача через оператор преобразования (699-87)
```
X^(q+1) = Ψ(X^(q)) :  F1(Ψ(X^(q))) < F1(X^(q))  ∧  F2(Ψ(X^(q))) < F2(X^(q)),   (5)
```
при ограничениях сохранения инвариантов (дисперсии, энергии). Используется, когда решение строится итерационно и требуется одновременное улучшение нескольких показателей без свёртки.

### Т6. Многокритериальная оптимизация с явной весовой свёрткой по частным критериям (эталон — статья-образец «Методика синтеза структуры беспилотной системы…»)
```
Каждый частный критерий формализуется отдельной функцией:
F_1(P), F_2(P), …, F_k(P),                                        (n1)…(nk)
<для составных критериев — свёртка нижнего уровня:>
F_j(P) = Σ_l β_l · F_jl(P),   Σ_l β_l = 1,                          (m)
<далее — свёртка верхнего уровня, агрегирующая частные критерии в единый показатель:>
F(P) = Σ_j α_j · F_j(P),      Σ_j α_j = 1,                          (m+1)
P* = arg max_{P ∈ P°} F(P),                                         (m+2)
```
где P° — множество допустимых решений, удовлетворяющих техническим, пространственным и энергетическим ограничениям (шаблон В6).

Особенности приёма: (а) метод явно называется в тексте — «Применим метод взвешенной суммы, в котором агрегированная целевая функция определяется как …»; (б) свёртка двухуровневая — сначала объединяются однородные компоненты одного критерия (например, три составляющие результативности), затем разнородные критерии между собой; (в) для каждого веса в тексте явно указывается условие нормировки (сумма равна 1) и смысл — «весовые коэффициенты, определяющие приоритет каждого компонента»; (г) допустима запись как «arg max», так и (реже, при опечатке или альтернативной нотации) «agr max» — в собственном тексте предпочтителен нормативный вариант «arg max»/«arg min».

Ограничение метода (указывать при выборе): скалярная свёртка не гарантирует Парето-оптимальности при невыпуклой границе допустимых решений и чувствительна к выбору весов — при необходимости строгого обоснования весов уместна ссылка на методы их определения (экспертные, на основе ТЭЦП/квалиметрии — см. § 5 ниже).

### Т5. Условная оптимизация моментов/количества через анализ функции (696-16)
Последовательность: выражение показателя (1) → «Для определения оптимальных … найдём производные функции (1) по каждой переменной w_i» → уравнение ∂φ/∂w_i = 0, «решением которого является (2)» → частные случаи для типовых законов распределения → предельное количество из ресурсного ограничения (3): Σ c(w_i) ≤ T − θ_j → условие целесообразности очередного шага (4): w_i − w_{i−1} > c(w_i).

## 4. ЕДИНЫЙ ПОРЯДОК ВЫВОДА ОПТИМИЗАЦИОННОЙ ФОРМУЛИРОВКИ (обобщение)

Все проанализированные статьи сводимы к одной последовательности из шести шагов:

1. **Объект и управляемые переменные.** Определить, чем управляет исследователь: структура S, вектор параметров X, алгоритм α, моменты времени w_i. Формально: «вариант построения …, определяемый векторами …».
2. **Условия и неуправляемые факторы.** Среда U: законы распределения отказов F(τ), воздействия Y = {Y1, Y2, Y3}, требования потребителя Q_тр.
3. **Показатель эффективности W.** Ввести измеримую величину, связывающую переменные с целью (мат. ожидание выигрыша φ_n; стоимость C; риск R; вероятность P; пара показателей F1, F2). Каждый показатель — отдельной нумерованной формулой с обоснованием «данные показатели позволяют количественно оценить …».
4. **Критерий.** Выбрать один из трёх: (а) оптимальности — extr W; (б) пригодности — W ≥ W_тр (вероятностное ограничение P ≥ P_гр); (в) компромиссный — свёртка/Парето для векторного W. Явно указать направление: min затрат/риска/разрыва, max вероятности/результативности.
5. **Ограничения.** Ресурсные (время, память, энергия, стоимость: t ≤ τ_доп, v ≤ v_доп, C ≤ C_max), инвариантные (сохранение дисперсии/энергии), допустимостные (области определения). Записываются либо строкой «Ограничения: …», либо описанием множества S_доп; при большом числе разнородных ограничений (4–5 и более групп) — нумерованным перечнем по физическому смыслу (шаблон В6).
5а. **Допущения (для физически детализированных моделей).** Отдельный абзац после ограничений, перечисляющий упрощения, принятые для практической реализуемости модели («Для практической реализации модели примем следующие допущения: …»). Не путать с ограничениями: ограничение — требование к решению; допущение — упрощение самой модели среды/объекта, которое в общем случае не выполняется точно, но принимается ради разрешимости задачи. Явное перечисление допущений — признак добросовестной постановки и стандартный элемент, ожидаемый рецензентом.
6. **Каноническая запись + расшифровка.** Свести к форме Т1–Т4; после формулы — полная расшифровка «где … – …» столбиком; далее по тексту — фраза о методе решения: «Решение уравнения (2) позволяет определить … для любого вида распределения», «Для решения задачи используется численное вычисление градиента … методом конечных разностей».

Контроль корректности постановки: (а) каждая величина в формуле определена в «Дано» или в расшифровке; (б) критерий и ограничения не дублируют друг друга; (в) искомое из «Найти/Требуется» совпадает с аргументом arg extr; (г) размерности согласованы; (д) указано, чем гарантируется существование решения (неубывание функции, конечность множества, компактность области).

## 5. ТЭЦП КАК КАНОНИЧЕСКИЙ АППАРАТ ТРИАДЫ «РЕЗУЛЬТАТИВНОСТЬ – ОПЕРАТИВНОСТЬ – РЕСУРСОЁМКОСТЬ»

**Важное наблюдение для вашей диссертационной темы.** Триада критериев «результативность / оперативность / ресурсоёмкость», использованная в вашей статье о синтезе структуры БС, — не ситуативный выбор, а прямое применение признанного в корпусе формального аппарата: **теории эффективности целенаправленных процессов (ТЭЦП)**. Это подтверждается независимым появлением той же триады (под точными названиями) в статье 699-119 «Системный подход к выбору пункта размещения…», где она явно атрибутирована как аппарат ТЭЦП [со ссылкой на первоисточник] в сочетании с методами квалиметрии. Два независимых источника корпуса, использующие одну и ту же триаду, — основание закрепить её как стандартную для методик выбора/синтеза/размещения и явно ссылаться на ТЭЦП как на методологическую базу, а не изобретать критерии заново в каждой статье.

**Каноническая структура аппарата ТЭЦП:**

- **Вектор показателей эффективности (ВПЭ)** — верхнеуровневый формализованный вектор требований к объекту, включающий три компоненты:
  - **вектор параметров результативности (ВПР)** — степень достижения цели применения (в вашей статье — F_res: устойчивость связи + равномерность покрытия + степень покрытия области);
  - **вектор параметров оперативности (ВПО)** — временные затраты на достижение результата (в вашей статье — F_op: время реконфигурации относительно T_max);
  - **вектор параметров ресурсоёмкости (ВПРс)** — расходуемые ресурсы (трудовые, временные, энергетические; в вашей статье редуцирован до энергозатрат F_en). Примечание из 699-119: полный учёт ВПРс методологически сложен, поэтому на практике его часто редуцируют до одного доминирующего вида затрат (энергия, стоимость, время) — это допустимое и принятое в корпусе упрощение, если оговорено явно.
- Каждой компоненте ВПЭ задаётся **пороговое (требуемое) значение**; критерий пригодности решения — достижение всех порогов одновременно («примат эффективности»), критерий оптимальности — экстремум свёртки (см. шаблон Т6) при выполнении пороговых ограничений.
- При необходимости агрегировать разнородные факторы, не сводимые к ВПЭ напрямую (условия размещения, характеристики среды), используется **аппарат квалиметрии**: дерево показателей качества (ДПК) → нормализация частных показателей → интегральный показатель качества (ИПК).

**Рекомендация по использованию в постановках задачи:** при формулировке цели оптимизации методики/модели, где критерии естественно распадаются на «эффект / время / затраты», явно указывать в тексте связь с ТЭЦП (по образцу 699-119: «В рамках ТЭЦП …», «аппарат теории эффективности целенаправленных процессов [n]») — это усиливает методологическую обоснованность постановки и даёт формальную опору для последующей защиты выбора именно этой триады критериев, а не альтернативных наборов.

## 6. СЛОВАРЬ ФОРМУЛИРОВОК ДЛЯ ПОСТАНОВОК

- «Задача … заключается в определении оптимальных …»
- «Формализованно задача может быть представлена записью (1)»
- «Дано: … Найти: … Требуется: …»
- «Известно, что на … влияют …, которые обусловливают возможность … в момент времени τ, распределённый по закону F(τ)»
- «Требуется найти такой …, который обеспечивает … при соблюдении следующих ограничений»
- «в качестве обобщённого показателя качества системы может рассматриваться …»
- «по критерию минимума стоимости (максимума вероятности, достижения минимальной величины риска)»
- «при ограничениях на время завершения выполнения целевых задач (на объём … памяти, при допустимом энергоресурсе)»
- «решением которого является …»; «оптимальными … являются значения …»
- «Под … будем понимать величину …, где …»
- «Величина α_i есть вероятность того, что …»
- «Таким образом, … определение … проводится на основании выражения (2), а обоснованность … формируется на основе выражений (3) и (4)».
- «При разработке … модели принят ряд допущений»; «Для практической реализации модели примем следующие допущения: …»
- «Для обеспечения функциональности … необходимо выполнение следующих ограничений: 1. … 2. … 3. …»
- «Переменной оптимизации является …, представленная вектором …»
- «Применим метод взвешенной суммы, в котором агрегированная целевая функция определяется как …»
- «Множество допустимых решений … включает все конфигурации, удовлетворяющие … ограничениям»
- «В рамках ТЭЦП … рассматривается вектор параметров …» (см. раздел 5)
- «Теоретико-множественная постановка задачи представлена в следующем виде»
- «Состав … задаётся функцией F: … → …»; «Здесь … – множество …, характеризующих …»
