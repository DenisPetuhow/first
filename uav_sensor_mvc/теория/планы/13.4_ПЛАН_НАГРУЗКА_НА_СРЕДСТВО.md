## 1. Что требуется — словами заказчика (30.09.2026)

1. «Вводим новый показатель — **нагрузка на средство**: процент пролетевших БПЛА через это средство: если из 1000
   маршрутов пролетело 500 — 50 %».
2. «С учётом средств, что стоят у района защиты, **все равны**».
3. «По итогу моделирования или с учётом пройденных — в окне **Анализ** кнопка **Рассчитать нагрузку**».
4. «Новое окно с **выбором типа средства**: таблица — **номер по списку, нагрузка в процентах, количество маршрутов**,
   в порядке **убывания нагрузки**».
5. «**Общий режим** — все средства по убыванию, добавляется колонка **тип средства**».
6. «Сейчас с 1 по N средства нумеруются **вперемешку по порядку расстановки**: первым может быть №5 ПВН, потом №154
   МОГ и далее вниз» — номер в таблице тот же, что человек видит в списке средств.

## 2. Анализ: как устроено сейчас и что берём

| Что нужно | Что уже есть | Где |
|---|---|---|
| номер по списку | сквозной `n`: малые **по типам** в порядке номеров типов (1, 2, 3, 5…), внутри типа — в порядке выбора, первыми закреплённые (заданные человеком, ПВН этапа целей); затем большие (тип 4). ⚠️ Исправлено 30.09.2026 (журнал 355): было «в порядке расстановки, типы вперемешку» | `ThreatModel.sensors_table()` — его же видят таблица датчиков и заголовок «Датчик №n (тип t)» при правке |
| «маршрут прошёл через средство» | ближайшая точка маршрута не дальше радиуса средства — так считается засечка «Анализа» | `ThreatModel._detection` :: `seen_by` (маршрутов × датчиков) |
| радиус каждого средства | малые — `_sensor_radii()`; большие — `threat_R_big` (паспорт типа 4) | `threat_grid.py` |
| выборка | итерации, если их ≥ 5; иначе загруженная (галка); иначе «возможные маршруты» | `_sample_for_sensors()` — та же, по которой стоят средства и считается «Анализ» |
| окно «Анализ» | витрина HTML, текст собирает контроллер `_analysis_html` | `view_qt/analysis_window.py` :: `AnalysisDialog` |

**Решения (осторожные, записаны; ответ заказчика может их сменить — §4):**

* **Определение.** `L_j = M_j / M × 100 %`, где `M` — маршрутов в выборке, `M_j` — сколько из них хоть одной точкой
  прошли не дальше `R_j` от средства `j`. Каждый маршрут весит одинаково, средства равны: цели, приоритеты и
  кратность в нагрузку не входят (п. 2 заказчика).
* **Какие средства.** Все на карте: малые всех типов, в том числе ПВН этапа целей и заданные человеком, **и большие**
  (кольцо у объекта защиты — «средства у района защиты»). Номер — `n` из `sensors_table()`.
* **Какая выборка** — `_sample_for_sensors()`: после моделирования — пройденные итерации, до него — возможные
  маршруты. В окне пишется, по какой выборке и сколько маршрутов.
* **Снимок, а не живая таблица**: считается по кнопке, как «Анализ»; повторное нажатие — заново.
* **Порядок строк** по умолчанию: малые по убыванию нагрузки, затем большие по убыванию; при равной — номер по
  возрастанию (порядок повторяется до бита). Остальные порядки — список «Порядок» (§4).

**Свойства показателя** (пойдут в пособие и в проверки):
1. `0 ≤ L_j ≤ 100 %`; сумма по средствам **может быть больше 100 %** — один маршрут видят несколько средств.
2. **Тождество:** `Σ_j M_j = Σ_r h_r`, где `h_r` — сколько малых средств видят маршрут `r`; значит
   `Σ_малые L_j / 100 % = mean_hits` «Анализа» на той же выборке. По типу: объединение маршрутов его средств =
   `detect_frac` типа.
3. Нагрузка ≠ вклад в жадном: первое поставленное средство берёт наибольший **прирост**, а не наибольшую нагрузку —
   в тени соседей нагрузка велика, а вклад мал. Высокая нагрузка — «узкое место» (откажет — многие маршруты
   потеряют засечку); нулевая — средство без пролёта.

**Цена** (оценка по формуле, не замер): `seen_by` — маршрутов × точек × средств расстояний; 1000 маршрутов × 400 точек
× 40 средств = 1.6·10⁷ — доли секунды, память — куском на маршрут, как в `_detection`.

## 3. Задачи — что где делать

### 13.4.1. `model/sensor_load.py` — НОВЫЙ

* `seen_matrix(sample, pts, radii)` — (M, N) bool: маршрут `r` прошёл через средство `j` (как `seen_by`, но для любого
  списка точек и радиусов — и больших);
* `load_rows(seen, rows)` — по строкам `sensors_table`: `dict(n, type_id, routes=M_j, load_pct)`, отсортировано;
* `by_type(rows_out, type_id)` — строки одного типа в том же порядке.
Без Qt; комментарии по правилу (функция до 3 строк, «Вход:»/«Отдаёт:», единицы).

### 13.4.2. `ThreatModel.sensor_load()` — `model/threat_grid.py`

Собирает: выборку (`_sample_for_sensors`), `sensors_table()`, радиусы (малые — `_sensor_radii()`, большие —
`threat_R_big`), источник выборки (`sensor_source`). Отдаёт `dict(rows, n_routes, source, types={номер: название})`.
⚠️ Ничего не пишет в модель: показатель только читает (выключаемость в ноль — эталон тот же).

### 13.4.3. `view_qt/load_window.py` — НОВЫЙ, `SensorLoadDialog` (немодальное, по образцу `analysis_window.py`)

* сверху — выбор: «Все средства» (первая строка) и типы, которые есть на карте («№1 МОГ», «№2 ПВН», …);
* таблица (`QTableWidget`, только чтение, сортировка — уже готовым порядком):
  * по типу: **№ по списку · нагрузка, % · маршрутов**;
  * «Все средства»: **№ по списку · тип средства · нагрузка, % · маршрутов**;
* подпись над таблицей: выборка (итерации / возможные маршруты) и `M`; средств без пролёта — сколько;
* окно ничего не считает: данные — колбэком `data()`.

### 13.4.4. «Анализ моделирования» и контроллер

* `AnalysisDialog`: кнопка **«Рассчитать нагрузку»** над «Закрыть», колбэк `on_load`;
* `ThreatMapView._open_analysis_window` — передать колбэк; `_open_load_window` — открыть/обновить окно;
* `ThreatController.on_sensor_load()` → `model.sensor_load()`; нет средств или маршрутов — понятная строка в окне.

### 13.4.5. Проверки

* `metrics_check`: `0 ≤ L_j ≤ 100`; строк = малых + больших; номера = `sensors_table`; **Σ малые `M_j` = Σ `h_r`**
  (`mean_hits` × M) и объединение по типу = `detect_frac` × M — на одной выборке;
* `gui_check`: кнопка в «Анализе» открывает окно; «Все средства» — 4 колонки, по типу — 3; строки по убыванию;
  номер строки совпадает с `sensors_table`;
* `flow_check`: вызов `sensor_load()` не меняет датчики и показатели (снимок до/после);
* `reference_run` — сошёлся; `check_comments`, `check_names`, `docmap --check`.
