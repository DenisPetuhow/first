# Методичка · Загрузка цифровых карт и их отображение

Практическое руководство: где и как скачать цифровые карты для вкладки 3 «Карта
угроз», как подключить их в приложении, как проверить результат и как расширить
подход (например, на район вкладки 2). Со ссылками.

Связанные документы: механика весов — [`МЕТОДИЧКА_КАРТА_УГРОЗ.md`](МЕТОДИЧКА_КАРТА_УГРОЗ.md);
подсистема тайлов-подложки — [`МЕТОДИЧКА_КАРТА.md`](МЕТОДИЧКА_КАРТА.md).

---

## 0. Два разных понятия «карта» — важно не путать

В приложении есть **две независимые** «карты», и данные для них скачиваются
по-разному:

1. **Подложка (тайлы)** — картинка-фон (OSM/спутник). Выбирается в списке «КАРТА».
   Это растровые PNG-тайлы, они тянутся из интернета и кешируются автоматически —
   **отдельно скачивать не надо**. Только для оформления, в расчёте весов **не
   участвуют**. Подробнее — `МЕТОДИЧКА_КАРТА.md`.

2. **Цифровые слои (векторные объекты)** — реки, дороги, ж/д, ЛЭП, трубопроводы,
   лесополосы, застройка **с координатами и тегами**. Именно они накладываются на
   сетку 500 м и дают веса. Вот **их надо скачать** (это и есть «цифровые карты»
   в вашем смысле).

**Почему сейчас карта выглядит «странно» (не все дороги/объекты).** Пока реальные
векторные слои не скачаны, вкладка рисует **демо-СХЕМУ** — несколько условных
прямых линий (русло + пара дорог/ЛЭП), чтобы показать саму механику. Это не баг:
в панели «источник данных» так и написано `СХЕМА (демо, офлайн)`. Как только
подключите реальные данные (ниже) — появятся настоящие дороги/реки/объекты, и
источник сменится на `OSM …`.

## 1. Быстрый путь (рекомендуется): BBBike Extract → .osm.pbf

Один раз выгружаем небольшой кусок OSM ровно по нашему прямоугольнику.

**Шаг 1. Открыть BBBike Extract.**
🔗 https://extract.bbbike.org/

**Шаг 2. Задать прямоугольник участка.** Ввести координаты нашего bbox
(они уже зашиты в `config.THREAT_BBOX_LONLAT`):

| | Долгота (lon) | Широта (lat) |
|---|---|---|
| Ю-З угол (min) | **38.375** | **48.335** |
| С-В угол (max) | **39.654** | **49.016** |

На BBBike это поля *Left/Bottom/Right/Top* соответственно: Left=38.375,
Bottom=48.335, Right=39.654, Top=49.016. Можно и просто обвести прямоугольник
мышью по этим ориентирам (Рубежное — верх-лево, Молодогвардейск — низ-право).

**Шаг 3. Формат — Protocolbuffer (PBF).** В списке *Format* выбрать
`Protocolbuffer (PBF)` → это даст файл `.osm.pbf` (компактный, читается быстрее
всего). Указать e-mail, нажать *extract*. Через несколько минут придёт ссылка —
скачать архив, внутри `planet_*.osm.pbf`.

**Шаг 4. Положить файл в проект.** Создать папку `geo_cache/` внутри
`uav_sensor_mvc/` и положить туда файл, переименовав, например, в
`geo_cache/severodonetsk.osm.pbf`.
(Путь к кэшу можно переопределить переменной окружения `UAV_GEO_CACHE`.)

**Шаг 5. Установить геостек** (один раз; нужен только для обработки OSM):
```
pip install pyrosm geopandas shapely pyproj rasterio
```
На Windows `geopandas`/`rasterio` тянут библиотеку GDAL, которая через голый `pip`
иногда не собирается. Если ловите ошибки сборки — ставьте через conda:
```
conda install -c conda-forge geopandas rasterio pyrosm
```

**Шаг 6. Собрать слои** (превратить .osm.pbf в готовые слои приложения):
```
python tools/build_threat_grid.py geo_cache/severodonetsk.osm.pbf
```
Скрипт отфильтрует объекты по тегам (реки/дороги/ж-д/ЛЭП/трубопроводы/лесополосы/
застройка), переведёт их в км-фрейм участка и сохранит `geo_cache/threat_layers.npz`.

**Шаг 7. Подключить в приложении.** Есть два способа:
* автоматически — при следующем «Построить карту» приложение само найдёт
  `geo_cache/threat_layers.npz`; или
* через окно **«Выбрать цифровые карты…»** → *Загрузить файл* → указать
  `.npz` (готовые слои) **или сразу `.osm.pbf`** (приложение обработает его на
  месте тем же кодом, если установлен pyrosm).

Готово: «источник данных» станет `OSM (офлайн-кэш)` / `NPZ: …` / `OSM: …`, и на
карте появятся реальные дороги/реки/объекты.

## 2. Альтернатива: Geofabrik (весь регион) + локальная нарезка

Если планируете часто менять/расширять область или работать совсем без интернета —
удобнее скачать регион целиком и резать локально сколько угодно раз.

**Скачать регион:**
🔗 https://download.geofabrik.de/europe/ukraine.html — файл `ukraine-latest.osm.pbf`.

**Нарезать по bbox** (любым из двух):
* `osmium` (CLI, 🔗 https://osmcode.org/osmium-tool/):
  ```
  osmium extract -b 38.375,48.335,39.654,49.016 ukraine-latest.osm.pbf \
        -o geo_cache/severodonetsk.osm.pbf
  ```
* либо сразу отдать весь `ukraine-latest.osm.pbf` нашему скрипту — `pyrosm` сам
  прочитает только заданный `bounding_box` (медленнее, чем предварительная нарезка,
  но проще). Дальше как в разделе 1 с шага 6.

## 3. Быстрый разовый вариант без файлов: Overpass Turbo

Если нужен разовый экспорт нескольких слоёв «здесь и сейчас», без скачивания
регионов:

🔗 https://overpass-turbo.eu/ — вставить запрос по bbox, выполнить, *Export →
GeoJSON*. Пример (река + крупные дороги в нашем bbox):
```
[out:json][timeout:60];
(
  way["waterway"="river"](48.335,38.375,49.016,39.654);
  way["highway"~"motorway|trunk|primary|secondary"](48.335,38.375,49.016,39.654);
);
out geom;
```
(Overpass принимает bbox в порядке `south,west,north,east`.) Экспортированный
GeoJSON затем можно конвертировать в наш `.npz`/подать через geopandas — как
расширение (сейчас скрипт заточен под `.osm.pbf`; поддержку GeoJSON легко добавить
в `layers_from_osm`, если понадобится).

Официальный портал OSM (посмотреть объекты/теги глазами): 🔗 https://www.openstreetmap.org/ ·
справочник тегов: 🔗 https://wiki.openstreetmap.org/wiki/Map_features

## 4. Какие теги в какие слои идут

Единый список — в коде (`model.threat_grid.OSM_LAYER_FILTERS`), здесь для справки:

| Слой | OSM-тег(и) |
|---|---|
| Река | `waterway = river / canal / stream` |
| Дорога крупная | `highway = motorway / trunk / primary / secondary` |
| Дорога местная | `highway = tertiary / unclassified / residential` |
| Железная дорога | `railway = rail` |
| ЛЭП | `power = line` |
| Трубопровод | `man_made = pipeline` |
| Лесополоса | `natural = tree_row` |
| Застройка | `landuse = residential / industrial` |
| Мост | вычисляется как пересечение дороги/ж-д с рекой |

Чтобы добавить/убрать теги — правьте `OSM_LAYER_FILTERS` (один раз, в одном месте:
его используют и скрипт, и окно выбора карт).

## 5. Как это отображается и как проверить

После «Построить карту»:
* **источник данных** в панели: `OSM …` (не `СХЕМА`) — значит, данные реальные;
* **векторные слои** (чекбокс «векторные слои») — теперь настоящие дороги/реки, а
  не прямые демо-линии;
* **весовая карта (тепло)** — тепловой слой идёт вдоль реальных линий;
* окно **«Выбрать цифровые карты…»** позволяет включать/выключать отдельные слои и
  сразу видеть, как меняется карта весов (например, снять «застройку», чтобы убрать
  репеллер).

Проверка через показатели: в блоке «ВЕС КАРТЫ (по слоям)» суммы должны стать
заметно больше и разнообразнее, чем на демо-схеме.

Быстрая проверка без GUI, что слои прочитались:
```
python -c "from config import Params; from model.threat_grid import ThreatModel; \
m=ThreatModel(Params()); m.set_data_source('geo_cache/severodonetsk.osm.pbf'); \
m.build(); print(m.source); print({k:len(v) for k,v in m.layers.items()})"
```

## 6. Как расширить подход на вкладку 2 (район Курска) и другие области

Механика вкладки 3 полностью **переносима на любой участок**. Чтобы, например,
построить весовую карту угроз для района вкладки 2 (Курск):

1. **Bbox.** Задать прямоугольник области (для Курска — по рамке
   `geomap.OBLAST_BBOX`, например `34.05,50.90,38.45,52.35`). Аккуратный путь —
   не хардкодить, а вынести bbox в параметр (сейчас `config.THREAT_BBOX_LONLAT`
   один; для нескольких участков стоит сделать словарь `REGIONS = {"severodonetsk":
   (...), "kursk": (...)}` и выбирать активный — это небольшой рефакторинг).
2. **Данные.** Скачать `.osm.pbf` для нового bbox (раздел 1, те же шаги, свои
   координаты). Файлы разных участков держать раздельно, например
   `geo_cache/kursk.osm.pbf`.
3. **Слои.** `layers_from_osm(pbf, lon0, lat0, bbox)` уже принимает произвольные
   `lon0/lat0/bbox` — достаточно передать якорь и bbox нового участка.
4. **Отображение.** `ThreatMapView`/`ThreatModel` привязаны к своему bbox через
   конструктор — можно создать **второй экземпляр** вкладки угроз для Курска, ничего
   не меняя в коде отрисовки. Тайловая подложка уже общая (`basemap_mixin`) и
   принимает любой якорь.

То есть «весовая карта угроз для вкладки 2» = тот же `ThreatModel`/`ThreatMapView`
с курским bbox и курским `.osm.pbf`. Единственная доработка под мультирегион —
вынести bbox/якорь из констант в выбор региона (по желанию).

Для более богатой карты угроз можно позже добавить **растровые** слои местности
(рельеф/землепокрытие) — их источники:
* рельеф (ЦМР) Copernicus DEM GLO-30 / SRTM — 🔗 https://opentopography.org/;
* землепокрытие ESA WorldCover (вода/болота/застройка, 10 м) — 🔗 https://esa-worldcover.org/.
Они читаются `rasterio` и накладываются на ту же сетку (уклон, влажность — как
дополнительные веса/репеллеры). Это отдельный этап, в текущей версии не реализован.

## 7. Про виджет отображения (задокументировано на будущее)

Сейчас карта рисуется на **`pyqtgraph.PlotWidget`** (аппаратное ускорение, зум/пан
мышью, наложение растровых и векторных слоёв в одной сцене). Это осознанный выбор
на данном этапе, **оставляем его**. На случай, если позже понадобится сменить
виджет отображения, зафиксируем точки замены:

* **Что развязано.** Вся отрисовка сосредоточена во `view_qt/` (слой VIEW): тайловая
  подложка — `basemap_mixin.py`, карта угроз — `threat_view.py`. Модель
  (`model/threat_grid.py`) и контроллер (`controller_qt/threat_controller.py`)
  **не знают** про pyqtgraph — они оперируют массивами (км-координаты, веса) и
  вызывают методы `render_*`. Значит, сменить виджет = переписать только VIEW,
  сохранив те же методы (`render_threat/layers/sensors/entry_target`, `frame_bbox`,
  `get_toggles`, `set_metrics`).
* **Кандидаты на замену, если понадобится:**
  * чёткость тайлов на HiDPI — послойные `QGraphicsPixmapItem` вместо одного
    композитного растра (см. журнал, п. про размытие) — остаётся в pyqtgraph;
  * веб-виджет с настоящей slippy-map (Leaflet/MapLibre GL) в `QWebEngineView` —
    даёт «родные» тайлы и плавный зум, но усложняет наложение расчётных слоёв;
  * Matplotlib-канвас (как вкладка 1) — проще, но медленнее для интерактива.
* **Критерий выбора.** Пока приоритет — единая сцена «тайлы + векторы + тепло +
  датчики» с быстрым зумом; ему отвечает текущий pyqtgraph. Менять есть смысл
  только под конкретную новую задачу (например, онлайн-slippy-map).

## 8. Короткий чек-лист

1. BBBike (🔗 extract.bbbike.org) → bbox `38.375,48.335,39.654,49.016` → PBF →
   `geo_cache/severodonetsk.osm.pbf`.
2. `pip install pyrosm geopandas shapely pyproj rasterio`.
3. `python tools/build_threat_grid.py geo_cache/severodonetsk.osm.pbf`.
4. Приложение → вкладка «Карта угроз» → «Построить карту» (или «Выбрать цифровые
   карты…» → указать файл).
5. Убедиться: «источник данных: OSM …», на карте — реальные объекты.
