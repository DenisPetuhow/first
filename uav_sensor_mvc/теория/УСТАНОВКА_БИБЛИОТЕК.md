# Установка библиотек без интернета — из папки `offline_packages/`

> **Кому это.** Программу перенесли на другую машину, и при запуске расчёта появилась
> ошибка вида «Для чтения .osm.pbf нужен pyrosm/geopandas». Здесь — что ставить, чем и
> почему ошибка вообще возникла.

---

## 1. Сначала проверьте: а нужно ли ставить

⚠️ **Скорее всего — не нужно.** С 04.09.2026 программа считает карту по готовому кэшу
слоёв `.npz`, а он читается **одним numpy**. Геостек (`pyrosm`, `geopandas`, `shapely`,
`pyproj`) нужен ТОЛЬКО чтобы подготовить этот кэш из исходного `.osm.pbf` — один раз на
участок, командой `tools/build_threat_grid.py`.

Проверка одной командой:

```bash
UAV_SELFTEST=1 python main_qt.py
```

Самопроверка печатает, какие библиотеки есть, а каких нет, где лежат файлы участка и
строится ли карта — и всё это **не открывая окон**, поэтому работает даже там, где
интерфейс не поднимается. Обязательный минимум — `numpy`, `PyQt5`, `pyqtgraph`,
`matplotlib`, `pillow`; `rasterio` нужен для рельефа.

Если нужно проверить именно графику — `python check_env.py` (создаёт окно вкладки 3 в
режиме offscreen и рисует слои) и `python tools/gui_check.py`.

**Почему ошибка появилась.** С задачей 8.2 (свой район моделирования) программа
какое-то время читала исходный `.osm.pbf` напрямую — а для этого нужен `pyrosm`. На
машине, где его нет, построение падало, хотя раньше та же программа работала на одном
numpy. Исправлено: снова читается кэш `.npz` (ОГРАНИЧЕНИЯ 5.1м). Если кэш участка есть,
геостек не нужен вовсе.

**Кэш есть?** Загляните в папку участка: `geo_cache/<участок>/threat_layers_*.npz`.
Если файла нет — либо принесите его с машины, где он собран, либо ставьте геостек и
собирайте на месте (§4).

### Зачем вообще нужен `pyrosm` и что меняется без него

`.osm.pbf` — это **бинарный формат OpenStreetMap** (Protocol Buffers): не текст, а
упакованные таблицы узлов и ссылок между ними. Прочитать его «руками» нельзя — нужен
разборщик, и это `pyrosm` (он тянет за собой `geopandas`, `shapely`, `pyproj`). В файле
лежит ВСЁ, что есть в OSM на этот квадрат: дома, тропинки, скамейки, теги на трёх языках.

`.npz` — то, что от него остаётся после отбора: только наши слои (реки, дороги, ЛЭП,
застройка, пункты), уже пересчитанные в километры. Это обычные массивы numpy.

| | `.osm.pbf` | `.npz` |
|---|---|---|
| размер (область 291 × 250 км) | 17.1 МБ | **7.2 МБ** |
| чем читается | `pyrosm` + `geopandas` + `shapely` | **один numpy** |
| время чтения | **4.3 с** | **0.03 с** |
| что внутри | все объекты OSM, сырые теги, координаты в градусах | 13 804 массива: наши слои в километрах |

**Без `pyrosm` программа работает полностью** — на готовом `.npz`. Не получится ровно
двух вещей: **подготовить новый участок** из свежего экстракта (`build_threat_grid.py`) и
выбрать в окне «Цифровые карты» источником сам файл `.osm.pbf`. То есть геостек — это
инструмент подготовки данных, а не работы с ними.

Поэтому и правильный порядок такой: `.osm.pbf` разбирают **один раз на участок** на
машине, где геостек стоит, а дальше носят с собой лёгкий `.npz`.

## 2. Что лежит в `offline_packages/`

36 файлов, 169 МБ — все зависимости проекта под **Python 3.14, Windows 64-бит**:

| Группа | Пакеты |
|---|---|
| ядро | `numpy`, `matplotlib`, `pillow`, `packaging`, `six`, `setuptools` |
| интерфейс | `PyQt5`, `PyQt5_Qt5`, `pyqt5_sip`, `pyqtgraph` |
| рельеф | `rasterio`, `affine`, `attrs`, `certifi`, `click`, `cligj` |
| геостек (только для подготовки кэша) | `pyrosm`, `geopandas`, `shapely`, `pyproj`, `pyogrio`, `pandas`, `protobuf`, `python_rapidjson`, `cykhash` |
| прочее | `python_docx`, `lxml`, `tzdata`, `python_dateutil`, `contourpy`, `cycler`, `fonttools`, `kiwisolver`, `pyparsing`, `typing_extensions`, `colorama` |

⚠️ **Файлы `.whl` — под конкретную версию Python.** Имя вида
`numpy-2.5.1-cp314-cp314-win_amd64.whl` означает: CPython **3.14**, Windows 64-бит. На
Python 3.11 или 3.12 они не встанут — pip скажет «not a supported wheel on this
platform». Версию смотреть командой `python -V`.

## 3. Как поставить

**Обычная установка** (всё, что нужно программе):

```powershell
python -m pip install --no-index --find-links offline_packages ^
    numpy PyQt5 pyqtgraph matplotlib pillow rasterio
```

Ключи: `--no-index` — не ходить в интернет вовсе, `--find-links` — искать пакеты в этой
папке. Если запускаете не из корня проекта, укажите полный путь к `offline_packages`.

**Геостек** (нужен, только если собираете кэш слоёв сами):

```powershell
python -m pip install --no-index --find-links offline_packages ^
    pyrosm geopandas shapely pyproj
```

**Проверка после установки:**

```bash
UAV_SELFTEST=1 python main_qt.py     # библиотеки, файлы участка, построение карты
python tools/flow_check.py --quick   # порядок работы модели
python tools/gui_check.py            # интерфейс: рамки, оси, слои
```

## 4. ⚠️ Если геостек не ставится: `cykhash`

`pyrosm` зависит от `cykhash`, а он лежит в папке **исходником**
(`cykhash-2.0.1.tar.gz`), а не готовым `.whl`. Разница принципиальная: `.whl` просто
распаковывается, а `.tar.gz` **собирается на месте** — и для этого нужен компилятор C++
(Visual Studio Build Tools). Без него установка обрывается ошибкой вида «Microsoft Visual
C++ 14.0 or greater is required».

Три выхода, по возрастанию мороки:

1. **Не ставить геостек вовсе** — принести готовый `threat_layers_*.npz` с машины, где
   он уже собран (файл небольшой: 6.9 МБ на область 291 × 250 км). Программа с ним
   работает полностью, §1;
2. **скачать готовое колесо** `cykhash` под свою версию Python с машины с интернетом
   (`pip download cykhash`) и положить в `offline_packages`;
3. **поставить Build Tools** и собрать из исходника — дольше всего и нужно только если
   первые два пути закрыты.

## 5. Как пополнить папку

С машины, где есть интернет, тем же Python той же версии:

```powershell
python -m pip download -d offline_packages <имя пакета>
```

⚠️ `pip download` тянет то, что подходит **текущей** машине. Если у заказчика другая
версия Python или другая разрядность, добавьте явные ключи:

```powershell
python -m pip download -d offline_packages --only-binary=:all: ^
    --python-version 314 --platform win_amd64 <имя пакета>
```

Именно `--only-binary=:all:` заставляет pip брать готовые колёса и ругаться там, где
готового нет, — вместо того чтобы молча положить исходник, который потом не соберётся
(как получилось с `cykhash`).
