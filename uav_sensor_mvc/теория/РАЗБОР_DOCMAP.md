# Разбор `tools/переносимое/docmap.py` — построчно, для чтения человеком

Скрипт обслуживает **саму документацию**: делает оглавления с номерами строк, ищет битые
ссылки и следит за структурой папок. Здесь разобрано, что делает каждый кусок кода и
почему он написан именно так. Читать вместе с открытым файлом `tools/переносимое/docmap.py`.

> **Зачем вообще.** Документация проекта — около 160 тысяч токенов. Открывать методичку
> на 1300 строк ради одного вопроса нельзя, поэтому у каждого большого документа в начале
> лежит оглавление с номерами строк: посмотрел — открыл нужные 50 строк. Номера строк
> сдвигаются при каждой правке, поэтому их **пересчитывает машина**, а не человек.

---

## Как запускать

```bash
python tools/переносимое/docmap.py             # пересобрать оглавления и напечатать отчёт
python tools/переносимое/docmap.py --check     # НИЧЕГО не менять, только проверить
python tools/переносимое/docmap.py файл.md     # работать с одним файлом
```

Скрипт **ничего не запускает сам**: ни по расписанию, ни при сохранении файла. Его
вызывают руками — после правки документов и в конце проверки на достоверность.

Режим `--check` возвращает **код 1**, если что-то не в порядке, и **0**, если всё чисто.
Это нужно, чтобы проверку можно было встроить в другие сценарии.

---

## Блок 1. Шапка и настройка вывода

Сразу после импортов стоит такая пара строк:

```python
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```

**Что это.** `sys.stdout` — поток вывода в консоль. `reconfigure` переключает его на
кодировку UTF-8. Проверка `hasattr` означает «если у объекта есть такой метод» — на очень
старых версиях Python его нет, и без проверки скрипт упал бы при запуске.

**Зачем.** Консоль Windows по умолчанию работает в кодировке cp1251 или cp866, где нет
символов вроде `─` и части русских букв в UTF-8-представлении. Без этой строки скрипт
падал с ошибкой `UnicodeEncodeError` **при первой же попытке напечатать заголовок отчёта**.
`errors="replace"` — страховка: если терминал совсем не умеет какой-то символ, он будет
заменён на вопросительный знак, но программа не упадёт.

## Блок 2. Настройки — всё, что можно захотеть поменять

```python
BEGIN = "<!-- ОГЛАВЛЕНИЕ · сгенерировано tools/переносимое/docmap.py — руками не править -->"
END = "<!-- /ОГЛАВЛЕНИЕ -->"

MIN_LINES = 300
MAX_LINES = 1500
```

**`BEGIN` и `END`** — две строки-маркера. В markdown запись `<!-- … -->` это комментарий:
при просмотре документа он не виден, а скрипту служит меткой. Всё, что между маркерами, —
территория скрипта, он её переписывает целиком. Остальной текст файла не трогается
никогда.

**`MIN_LINES = 300`** — порог, ниже которого оглавление не делается: в коротком файле
оно занимает больше места, чем экономит.

**`MAX_LINES = 1500`** — порог, выше которого скрипт скажет «файл пора делить на части».
Сам он ничего не делит — только предупреждает.

```python
SKIP_DIRS = {".git", ".claude", "tile_cache", "geo_cache", ...}
SKIP = {"CLAUDE.md", "README.md", "теория/README.md", ...}
```

**`SKIP_DIRS`** — папки, куда не заходить: служебные каталоги, кэши тайлов и карт, папка
с фотографиями. Фигурные скобки означают **множество** — набор значений без порядка, в
котором быстро проверяется «есть ли элемент внутри».

**`SKIP`** — файлы-указатели: `CLAUDE.md` и все `README.md`. У них структура не как у
методички (сплошные таблицы, а не разделы), машинное оглавление им не нужно.

## Блок 3. Сбор списка документов — `walk_md`

```python
def walk_md():
    out = []
    for root, dirs, files in os.walk(ROOT):
        dirs[:] = [d for d in dirs if d not in SKIP_DIRS]
        for f in files:
            if f.endswith(".md"):
                out.append(norm(os.path.relpath(os.path.join(root, f), ROOT)))
    return sorted(out)
```

**Что делает.** Обходит все папки проекта и собирает пути ко всем файлам с расширением
`.md`. Возвращает отсортированный список — дальше по нему работают все проверки.

**Разбор непонятных мест:**

* `os.walk(ROOT)` — обход дерева папок. На каждом шаге отдаёт тройку: текущая папка
  (`root`), список подпапок в ней (`dirs`), список файлов (`files`).
* `dirs[:] = [...]` — **важный трюк**. Запись `dirs[:] =` меняет список *на месте*, а не
  создаёт новый. `os.walk` смотрит на этот список после каждого шага и решает, куда идти
  дальше. Выбросили оттуда `.git` — и обход туда не пойдёт вовсе. Если написать просто
  `dirs = [...]`, получится новый список, а `os.walk` продолжит обходить всё подряд.
* `[d for d in dirs if d not in SKIP_DIRS]` — это **списковое включение**, короткая запись
  цикла. Читается так: «взять каждый `d` из `dirs`, оставить те, которых нет в списке
  исключений». То же самое можно написать циклом на четыре строки.
* `os.path.relpath(…, ROOT)` — превратить полный путь в путь относительно корня проекта,
  чтобы в отчёте было `теория/ОГРАНИЧЕНИЯ.md`, а не длинный путь от диска `C:`.
* `norm(...)` — своя маленькая функция, заменяющая обратные слэши Windows на прямые. Иначе
  один и тот же файл выглядел бы то так, то этак.

## Блок 4. Построение оглавления — `build_toc`

Самая содержательная функция. На вход — **текст файла без старого оглавления** и
**позиция вставки**. На выходе — список строк готового блока.

### Шаг 1. Найти заголовки

```python
items, fenced = [], False
for i, s in enumerate(lines, 1):
    if s.lstrip().startswith("```"):
        fenced = not fenced
        continue
    if fenced:
        continue
    m = re.match(r"^(#{2,3})\s+(.+?)\s*$", s)
    if m:
        title = re.sub(r"[*`]|⚠️|✅|📌", "", m.group(2)).strip()
        items.append((len(m.group(1)), i, title))
```

**Что происходит.** Идём по строкам сверху вниз и собираем заголовки.

* `enumerate(lines, 1)` — перебор с нумерацией, начиная с единицы. То есть `i` — это
  номер строки в файле в человеческом счёте (первая строка = 1, а не 0).
* `fenced` — флаг «мы сейчас внутри блока кода». Строка с тремя обратными кавычками
  переключает его: `fenced = not fenced` означает «поменять на противоположное».
  Пока флаг поднят, строки пропускаются командой `continue`.
  **Зачем:** в методичках есть примеры markdown-разметки, и в них встречаются строки,
  начинающиеся с `##`. Без этого флага примеры попали бы в оглавление как настоящие
  разделы.
* `re.match(r"^(#{2,3})\s+(.+?)\s*$", s)` — регулярное выражение, шаблон поиска. По частям:
  `^` начало строки, `(#{2,3})` от двух до трёх решёток подряд (это и есть уровень
  заголовка), `\s+` хотя бы один пробел, `(.+?)` любой текст (это название), `\s*$` возможные
  пробелы до конца строки. Круглые скобки создают «группы» — куски, которые потом можно
  достать отдельно: `m.group(1)` даст решётки, `m.group(2)` — название.
* `re.sub(r"[*`]|⚠️|✅|📌", "", …)` — вычистить из названия звёздочки, обратные кавычки и
  значки, заменив их на пустоту. В оглавлении нужен чистый текст.
* `items.append((len(m.group(1)), i, title))` — запомнить тройку: **уровень** (число решёток —
  2 или 3), **номер строки**, **название**.

### Шаг 2. Посчитать сдвиг — здесь был баг

```python
shift = 4 + len(items) + 1 + 1
```

**Суть проблемы.** Заголовки нашли в тексте **без** блока оглавления. Но читатель
откроет файл **с** блоком — и всё, что ниже места вставки, окажется ниже на высоту
этого блока. Если сдвиг не учесть, оглавление врёт.

**Из чего складывается высота блока:**

| Слагаемое | Что это |
|---|---|
| `4` | строка-маркер `BEGIN` плюс три строки шапки («Оглавление — номер строки · раздел…») |
| `len(items)` | по одной строке на каждый заголовок |
| `+1` | строка-маркер `END` |
| `+1` | пустая строка, которая ставится после блока |

Отсюда и разная величина ошибки в разных файлах: при 32 заголовках сдвиг 38 строк, при
14 заголовках — 20, при 38 — 44. Ровно эти числа и наблюдались, пока баг жил.

### Шаг 3. Собрать строки блока

```python
for lvl, ln, title in items:
    out.append("> %s`%4d` %s" % ("  " if lvl == 3 else "",
                                 ln + shift if ln > pos else ln, title))
```

**Разбор записи.** Строка `"> %s`%4d` %s"` — шаблон, где `%s` означает «сюда подставить
текст», а `%4d` — «сюда подставить целое число, выровняв по ширине в 4 знака» (чтобы
столбик номеров был ровным). После `%` в скобках идут три значения по порядку:

1. `"  " if lvl == 3 else ""` — это **тернарный оператор**, короткое «если-иначе».
   Читается: «два пробела, если уровень равен трём, иначе ничего». Так подразделы
   печатаются с отступом и видна вложенность.
2. `ln + shift if ln > pos else ln` — тот же приём: «номер плюс сдвиг, если заголовок ниже
   места вставки, иначе номер как есть». Проверка `ln > pos` нужна на случай, если в файле
   окажется заголовок третьего уровня выше первого раздела — он не сдвинется.
3. `title` — название раздела.

Символ `>` в начале — markdown-цитата: блок оглавления отображается серой врезкой и
визуально отделён от текста.

## Блок 5. Вставка в файл — `apply_toc`

Функция делает три вещи по очереди.

### Найти и вырезать старый блок

```python
try:
    a, b = lines.index(BEGIN), lines.index(END)
    had = lines[a:b + 1]
    tail = b + 2 if b + 1 < len(lines) and not lines[b + 1].strip() else b + 1
    clean = lines[:a] + lines[tail:]
except ValueError:
    had, clean = None, lines
```

* `lines.index(BEGIN)` — найти номер строки с маркером. Если маркера нет, Python выбросит
  ошибку `ValueError`, её ловит `except`: значит, оглавления в файле ещё не было.
* `lines[a:b + 1]` — **срез списка**, кусок от строки `a` до строки `b` включительно
  (`+1` потому, что правая граница среза не включается). Это старое оглавление, его
  запоминаем для сравнения.
* `tail` — вычисляем, откуда продолжается текст: если сразу за маркером `END` идёт пустая
  строка, её тоже надо выбросить, иначе пустые строки будут накапливаться при каждом
  запуске.
* `clean = lines[:a] + lines[tail:]` — склеиваем текст до блока и текст после блока.
  Получается файл без оглавления — именно по нему считаются номера строк.

### Определить место вставки

```python
pos = next((i for i, s in enumerate(clean) if s.startswith("## ")), None)
```

Ищем первый заголовок второго уровня. `next(…, None)` берёт первый подходящий элемент,
а если ничего не нашлось — возвращает `None` вместо ошибки. Тогда функция сообщит «нет
разделов» и файл не тронет.

Блок встаёт **перед первым разделом**: вводная часть документа остаётся сверху, оглавление
идёт следом.

### Решить, что делать

```python
if had == toc:
    return "актуально"
if check_only:
    return "УСТАРЕЛО" if had is not None else "НЕТ ОГЛАВЛЕНИЯ"
io.open(path, "w", encoding="utf-8").write(
    "\n".join(clean[:pos] + toc + [""] + clean[pos:]))
```

* Сравниваем старое оглавление с новым. Совпали — ничего не делаем. **Из-за этого
  сравнения скрипт идемпотентен:** второй запуск подряд не меняет ни одного файла.
* В режиме `--check` файл не переписывается, возвращается только диагноз.
* Иначе собираем файл заново: текст до места вставки, блок, пустая строка, остаток.
  `"\n".join(...)` склеивает список строк обратно в текст, вставляя между ними переводы
  строки.

## Блок 6. Три проверки

### `verify_toc` — сверка номеров строк

**Это проверка результата, а не намерения.** Разница принципиальная и стоила мне бага.

Функция открывает **уже готовый файл** и делает два независимых прохода:

1. читает строки самого оглавления и достаёт из них пары «название → обещанный номер»;
2. отдельно ищет по файлу настоящие заголовки и запоминает, на каких строках они лежат.

Потом сравнивает. Если раздел обещан на строке 16, а лежит на 54 — это попадает в отчёт.

**Почему прежняя проверка баг не видела.** Она сравнивала блок в файле с тем, что
сгенерировал бы генератор. То есть подтверждала, что генератор согласен сам с собой.
Систематическая ошибка так не ловится: она одинаково искажает и то, что проверяют, и то,
чем проверяют. Проверять надо результат — открыть файл так, как его откроет читатель.

### `check_links` — битые ссылки

Проходит по всем документам, находит markdown-ссылки (подпись в квадратных скобках, путь в круглых) и проверяет, есть ли
файл по этому пути. Ссылки бывают относительные, поэтому путь считается от папки, где
лежит сам документ.

Пропускаются два вида целей:

* внешние адреса (начинаются с `http` или `mailto:`);
* всё, где внутри «пути» есть **запятая**. Это отсев ложных срабатываний: в методичке по
  загрузке карт есть примеры запросов вида `way["waterway"="river"](48.335,38.375,…)`, и
  разбор ссылок принимает квадратные скобки с круглыми за markdown-ссылку.

### `check_structure` — папки и размеры

Две проверки:

* документы группируются по папкам, и в каждой папке должен быть `README.md` — иначе
  папка выпадает из навигации;
* каждый файл проверяется на превышение `MAX_LINES`. Скрипт не делит файлы сам, только
  сообщает: «пора делить на части».

## Блок 7. Запуск — `main`

```python
args = [a for a in sys.argv[1:] if not a.startswith("--")]
check = "--check" in sys.argv
```

`sys.argv` — список аргументов командной строки; нулевой элемент это имя самого скрипта,
поэтому берём срез `[1:]`. Всё, что начинается с двух дефисов, считается флагом, остальное —
именем файла.

Дальше выбирается, с чем работать: если указан файл — только с ним, иначе со всеми
документами длиннее `MIN_LINES`.

Затем печатаются четыре раздела отчёта: **оглавления**, **сверка номеров строк**,
**ссылки**, **структура**. В самом конце:

```python
if stale or bad or problems or wrong:
    ...
    return 1
return 0
```

Если хоть в одной проверке что-то нашлось — код возврата 1. Проверки при этом не
прерывают друг друга: отчёт печатается полностью, чтобы за один прогон было видно всё.

## Что менять, если понадобится

| Хочу | Где править |
|---|---|
| оглавления в файлах покороче/подлиннее | `MIN_LINES` (сейчас 300) |
| другой порог «пора делить файл» | `MAX_LINES` (сейчас 1500) |
| включить в оглавление заголовки 4-го уровня | шаблон `#{2,3}` в `build_toc` → `#{2,4}` |
| не делать оглавление какому-то файлу | добавить его в `SKIP` |
| не проверять какую-то папку | добавить её в `SKIP_DIRS` |

⚠️ **Оглавления руками не править.** Следующий запуск скрипта перезапишет блок целиком.
Если номера в оглавлении выглядят неверными — не исправляйте их, а запустите
`python tools/переносимое/docmap.py`: либо всё встанет на место, либо проверка покажет настоящую
причину.

## История бага — как это выглядело

| | |
|---|---|
| **Симптом** | в плане рельефа раздел «Состав работы» значился на строке **16**, а лежал на **54**; «Что вскрылось при реализации» — **26** против **64** |
| **Масштаб** | все 13 файлов с оглавлениями; сдвиг **38** строк в плане рельефа, **20** в ОГРАНИЧЕНИЯХ, **44** в карте угроз |
| **Причина** | номера считались по тексту без блока, а читатель видит файл с блоком |
| **Почему не поймала проверка** | `--check` сверял блок с тем, что сгенерировал бы генератор, — то есть с самим собой |
| **Кто нашёл** | заказчик, открыв документ по указанному номеру строки |
| **Исправление** | прибавлять высоту блока (`shift`) + новая проверка `verify_toc` по готовому файлу |
| **Результат** | расхождений было **84** в трёх проверенных файлах, стало **0** во всех 31 |

Эта же новая проверка сразу нашла вторую поломку — задвоенный заголовок
`## 3. Этапы реализации` в `ЖУРНАЛ_1.md`, оставшийся от деления журнала на части.

**Общий вывод** записан в [переносимые правила](переносимое/README.md):
автоматизировать стоит то, что зависит от **расположения** текста (номера строк, списки
разделов), и нельзя — то, что зависит от **смысла** (актуальны ли утверждения). А любая
такая автоматика обязана проверять свой результат, а не своё намерение.
