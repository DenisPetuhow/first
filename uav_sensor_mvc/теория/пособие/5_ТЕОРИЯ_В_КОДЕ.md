# 5. ТЕОРИЯ В КОДЕ — какие разделы математики и информатики здесь работают

> **Что это.** Перечень тем, на которых стоит программа, с указанием, ГДЕ каждая живёт в
> коде и ЗАЧЕМ понадобилась. Это оглавление, а не учебник: у каждой темы — одна-две фразы
> сути и ссылка на разбор.
>
> **Зачем.** Пособие объясняет постановку задачи, методички — как устроен текущий код.
> Между ними был пробел: «какая вообще математика тут используется» — вопрос, который
> возникает и при объяснении работы, и при написании статьи. Список заведён 05.09.2026 по
> заданию заказчика и **будет дополняться**: сейчас в нём то, что уже применено.
>
> ⚠️ **Пометка «применено» обязательна.** Тема, которая «пригодилась бы», и тема, которая
> реально работает в коде, — разные вещи; путать их нельзя, иначе документ начнёт обещать
> несуществующее (та же ловушка, что с заделами: [ОГРАНИЧЕНИЯ §7](../ОГРАНИЧЕНИЯ.md)).

## 1. Дискретная оптимизация

| Тема | Где применено | Суть в одной фразе |
|---|---|---|
| **Субмодулярная максимизация при мощностном ограничении** ✅ | `model/optimization.py` :: `CoverageCache.greedy` | покрытие — функция с убывающей отдачей, и для неё жадный выбор даёт не хуже (1 − 1/e) ≈ 63 % от оптимума |
| **Задача о покрытии множества (set cover) с кратностью k** ✅ | там же: `n_vec`, `cur_min = min(n_vec, k)` | каждый маршрут нужно увидеть не один раз, а k; после k-го засечения дальнейший прирост нулевой — отсюда «насыщение» |
| **Лексикографический критерий** ✅ | `greedy`: основной → вторичный → третичный ключи | когда основной прирост у всех нулевой, решение принимает следующий ключ; без этого `argmax` брал первого по порядку сетки |
| **Матроид разбиения** ✅ | `_place_multi_type`: свой N у каждого типа | «не больше N₁ датчиков типа 1, не больше N₂ типа 2…» — это ограничение матроида разбиения, при нём у жадного алгоритма гарантия 1/2, а не (1 − 1/e) |
| **Задача о назначениях (венгерский алгоритм)** ✅ | `model/optimization.py` (свой, без scipy) | сопоставить датчики двух расстановок, чтобы номера не «прыгали» между итерациями |
| Приближение с ограничением связности | — | не применено; понадобится, если появится требование «датчики должны видеть друг друга» |

**Разбор:** [1_ТЕОРИЯ §4](1_ТЕОРИЯ_ОПТИМИЗАЦИИ.md) свойства функции покрытия ·
[§6](1_ТЕОРИЯ_ОПТИМИЗАЦИИ.md) цепочка «функция → алгоритм → гарантия».

## 2. Теория вероятностей и статистика

| Тема | Где применено | Суть |
|---|---|---|
| **Метод Монте-Карло** ✅ | `threat_routes.py` :: `sample_one_route`, `iter_batch` | маршрут не один, а выборка: случайные точки входа, случайные отклонения, случайный выбор среди почти равных вариантов |
| **Выборочное среднее и разброс** ✅ | `tools/reference_run.py`, `reference_cases.py` | эталон хранит норму И допуск, снятый по нескольким прогонам: без допуска стохастика неотличима от поломки |
| **Оценка по выборке (SAA, sample average approximation)** ✅ | расстановка по накопленным пролётам | вместо неизвестного распределения маршрутов оптимизируем среднее по конечной выборке |
| Риск-меры (CVaR и подобные) | — | не применено: сейчас максимизируется среднее покрытие, а не «худший случай» |

**Разбор:** [1_ТЕОРИЯ §7](1_ТЕОРИЯ_ОПТИМИЗАЦИИ.md).

## 3. Графы и поиск пути

| Тема | Где применено | Суть |
|---|---|---|
| **Алгоритм Дейкстры по стоимости** ✅ | `threat_routes.py` :: `_dijkstra_cost` | цена шага зависит от привлекательности местности — маршрут «тянется» по коридорам |
| **Поле расстояний (расстояние до цели)** ✅ | `_dijkstra_dist` | геометрическое поле, по которому проверяется запас хода `L_max` |
| **Связные компоненты (8-связность)** ✅ | `threat_grid.py` :: `_label8` | разметка коридоров: сколько их и какой самый большой — структурный показатель эталона |
| **Обход в ширину по достижимости** ✅ | `flight_envelope` | зона пролёта: куда БПЛА вообще способен долететь вход → место → цель |
| A*, эвристики | — | не применено: сетка мелкая, Дейкстры хватает |

## 4. Вычислительная геометрия

| Тема | Где применено | Суть |
|---|---|---|
| **Отсечение линии прямоугольником (клиппинг)** ✅ | `threat_grid.py` :: `_clip_parts`, `_edge_point` | линия рвётся по рамке района, на границе ставится точка ПЕРЕСЕЧЕНИЯ — иначе обрубок уходил за рамку на длину сегмента (замер: до 11.7 км) |
| **Точка в многоугольнике** ✅ | запретные зоны, `passable_mask` | попадает ли ячейка в нарисованную человеком зону |
| **Дуги окружности и радиус разворота** ✅ | `model/trajectories.py` :: `turn_radius_km`, `make_arc_by_angle` | физика полёта: R_min = v² / (g·tg θ); ⚠️ ловушка единиц — часть функций в радианах, часть в градусах |
| **Морфологическое замыкание** ✅ | `threat_grid.py` :: `THREAT_PLACE_CLOSE_KM` | «залечивает» дырки внутри пятна населённого пункта: парки и площади не размечены как застройка и рвали бы контур |
| **Проекция и локальный км-фрейм** ✅ | `model/geo_frame.py` :: `lonlat_to_km`, `km_to_lonlat` | всё считается в километрах от юго-западного угла участка; градусы — только на входе и выходе |

## 5. Обработка растров и больших данных

| Тема | Где применено | Суть |
|---|---|---|
| **Отображение файла в память (`numpy.memmap`)** ✅ | `view_qt/map_image.py` :: `read_detail_window` | карта 237 млн точек не помещается в память целиком (950 МБ в Qt), поэтому читается только видимый кусок — 0.003…0.37 с |
| **Прореживание с шагом (subsampling)** ✅ | там же: `step` | шаг округляется ВНИЗ, в сторону детали: лучше отдать чуть больше точек, чем показать грубее экрана |
| **Ленивое декодирование JPEG (`draft`)** ✅ | `load_image_rgba` | Pillow умеет декодировать сразу в 1/2, 1/4, 1/8 — без этого большой файл читается втрое дольше |
| **Выборка растра высот по координате** ✅ | `load_dem_grid`, `_sample_geotiff` | GeoTIFF → значение высоты в центре каждой ячейки сетки |
| **Кэширование по ключу** ✅ | `_read_key`, `_layers_cache`, `layers_cache_path` | чтение `.osm.pbf` (4.3 с) и высот (6.0 с) не повторяется на каждое построение |

## 6. Векторные вычисления (numpy)

| Приём | Где применено | Зачем |
|---|---|---|
| **Векторизация вместо циклов** ✅ | `CoverageCache.add_trajectory`: `traj[:, None, :] - cand[None, :, :]` | расстояния «все точки × все кандидаты» одной операцией; цикл на Python здесь был бы в сотни раз медленнее |
| **Битовые маски участков и popcount** ✅ | `_mask`, `_popcount` | «какие участки маршрута закрыты» хранится в одном 32-битном числе на маршрут, объединение — побитовое ИЛИ |
| **Булевы маски вместо ветвлений** ✅ | `passable_mask`, `water_mask`, `keep = cells_w != 0.0` | отбор ячеек и кандидатов без единого `if` по элементам |
| **`np.split` по разрывам индексов** ✅ | `_clip_parts` | разбить линию на непрерывные куски внутри рамки |

## 7. Архитектура и инженерия

| Тема | Где применено | Суть |
|---|---|---|
| **MVC** ✅ | `model/`, `view_qt/`, `controller_qt/` | модель не знает о Qt и остаётся проверяемой без экрана — на этом стоят все скрипты `tools/*_check.py` |
| **Сигналы и слоты, обратные вызовы** ✅ | `set_callbacks`, `sigPositionChangeFinished` | представление не вызывает модель напрямую: оно сообщает о событии, решает контроллер |
| **Готовый интерактивный примитив вместо своего** ✅ | `pg.TargetItem` для перетаскивания датчика | у сцены есть сигнал клика, но нет «нажал — веду — отпустил»; библиотечный маркер решает это сам |
| **Снимок состояния (undo одного шага)** ✅ | `_snapshot_before_iter` / `on_clear_iter` | вернуться к состоянию до моделирования, не пересчитывая всё заново |
| **Инварианты вместо значений в проверках** ✅ | `tools/metrics_check.py` | «сумма по типам равна числу датчиков» верно на любом участке, а «кратность 7.2» — только на этом |
| **Регрессионный эталон** ✅ | `tools/reference_run.py`, `reference_cases.py` | правка сверяется с записанными числами; допуск отделяет стохастику от поломки |
