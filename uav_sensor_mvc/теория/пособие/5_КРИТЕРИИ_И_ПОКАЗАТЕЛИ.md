## 1. Три слова — коротко

| | **Критерий** | **Ограничение** | **Показатель** |
|---|---|---|---|
| что это | по чему **выбираем** место датчика | что **нельзя** нарушить при выборе | чем **оцениваем** результат после |
| участвует в оптимизации | да — входит в целевую функцию | да — сужает допустимые решения | **нет** — считается после расстановки |
| пример | кратность k с насыщением | разнос, карта места, квота N | доля маршрутов, засечённых ≥ 1 раз; % не выполнивших k |

⚠️ **Кратность — критерий, а не показатель** (заказчик 24.09.2026). Критерий «кратность k» определяет,
куда встанет датчик. Показатель к нему — **доля маршрутов, засечённых ≥ k раз**, или обратная — **%
маршрутов, не выполнивших критерий k**: по ним видно, насколько оптимизация справилась.

⚠️ **Ловушка — подмена критерия показателем** ([1 §2.1](1_ТЕОРИЯ_ОПТИМИЗАЦИИ.md)): если максимизировать
«среднюю кратность», все датчики сядут в одну точку. Поэтому в критерии — насыщение `min(n, k)`.

## 2. Критерии — что оптимизирует программа

| Критерий | Где работает | Формула (по маршрутам выборки) | Код | Статус |
|---|---|---|---|---|
| **кратность по району моделирования** k | основной ключ жадного; общий проход | a₁ · min(n, k) / k | `CoverageCache.greedy`, `joint_greedy` | ✅ |
| **равномерность** — покрытые сегменты пути | основной ключ, второе слагаемое | a₂ · (покрытых сегментов) / L_seg | там же | ✅ |
| доля пути в зоне | вторичный ключ — когда основной насыщен | Σ доли точек маршрута в радиусе | `_cov` | ✅ |
| резерв — сколько маршрутов кандидат накрывает | третичный ключ | Σ `_hit` по маршрутам | `covsum` | ✅ |
| **кратность защиты цели** | основной ключ этапа целей — по **подлёту** к цели | min(n, k_цели) / k_цели | `target_stage.stage` (`tgt_k`) | ✅ 1 по умолчанию, правится в окне |
| **приоритет цели** | доля бюджета целей: сколько ПВН цели положено; излишек тех, кому нужно меньше, — остальным | nᵢ = min(потребность, max(наименьшее, λ·pᵢ)), Σ = бюджет | `target_stage.allot` | ✅ 30.09.2026 (было: вес маршрутов в общем жадном, 24.09) |
| бонус места (высота крыши, размер пункта) | модульное слагаемое к основному ключу ПВН | β_h · ранг_этажей + β_c · ранг_пункта | `sensor_zones.bonus_vector` | ✅ 0.1 / 0 |

**Ключи — лексикографика, а не сумма**: вторичный смотрится, только когда основной у всех нулевой.
Разбор — [код/1.КАК_КОД_РЕШАЕТ_ЗАДАЧУ §5](../код/1.КАК_КОД_РЕШАЕТ_ЗАДАЧУ.md).

**Правило выбора типа на шаге общего прохода** — «по наибольшему приросту» (`gain`, ✅ решение заказчика
24.09.2026, В13.22): не отдельный критерий, а способ свести критерии нескольких типов в один выбор.

## 3. Ограничения — чего нельзя нарушить

| Ограничение | Смысл | Статус |
|---|---|---|
| квота N у каждого типа | матроид разбиения — гарантия 1/2 | ✅ |
| разнос | внутри типа 1.6·R (ослабляется до 0.75·R), между типами 0.8·(R₁ + R₂) | ✅ |
| карта места типа | ПВН — застройка ∪ постройки ± 0.5 км, без леса и неудобий, без воды | ✅ |
| зона пролёта | кандидаты — только там, куда БПЛА долетает | ✅ |
| **число ПВН у цели** | доля по приоритету (строка выше) до **потребности**: до **уровня защиты**, а недостижим — пока до потолка кривой цели ≥ k **порогов прироста** (оба от k: 99 · 92 · 89.3 · 86.7 … % и 1 · 3 · 4 … %); бюджет — **потолок** 50 / 70 % N; меньше max(k, 3) не ставить | ✅ 30.09.2026 ([датчики/ЗАЩИТА_ОБЪЕКТОВ](../датчики/ЗАЩИТА_ОБЪЕКТОВ.md)) |
| **отступ от цели** | не ближе R/2 | ✅ 24.09.2026 (план 13.1, Д9) |

### 4.2. По объекту защиты (✅ план 13.1, Д9–Д10: отчёт расстановки и «Анализ» — «Защита объекта»)

⚠️ **«Засечено» по всему маршруту для цели пусто**: МОГ видят маршрут за 25–35 км до цели, и во всех
вариантах замера 24.09.2026 оно — 100 %. Показатель цели считается по **подлёту** — точкам маршрутов к
этой цели внутри её зоны.

| Показатель | Что значит | Замер 24.09.2026 (одна цель, МОГ 10 + ПВН 20, стоп 1 %) |
|---|---|---|
| **подлёт засечён ≥ 1 / ≥ 2 раз** | всеми датчиками и одними ПВН | всеми 100 / 92.8 %, ПВН 99.6 / 67.6 % |
| **% подлёта, не выполнившего кратность защиты цели** | 1 − подлёт ≥ k_цели | по ПВН 0.4 % при k_цели 1 |
| **рубеж обнаружения** | расстояние от цели до первой засечки: медиана и худшие 10 % маршрутов | 30.5 и 4.1 км |
| у целей X из N | сколько ПВН ушло к целям | 7 из 20 |
| **почему кратность мала** | недостижимо (мест < k в радиусе R или мешает разнос) · не хватает ПВН | кратность 2: недостижимо 0.4 % |
| **сколько ПВН добавить** | до 90 / 95 % подлёта с кратностью защиты | кратность 2: 12 → 81.6 %, 20 → 89.6 %, 30 → 94.0 % |

### 4.4. Время подлёта (✅ 06.10.2026, журнал 365: строка «Анализа»)

**Время подлёта** маршрута `r` — его длина, делённая на крейсерскую скорость типа БПЛА:

```
t_r = L_r / v,   L_r = Σ_i ‖p_{i+1} − p_i‖
```

По выборке показываются минимум, медиана и максимум. Пример: маршрут 145 км при 180 км/ч — 48 мин. Показатель, а не критерий: расстановка его не видит; скорость задаёт и радиус разворота `R_min = v² / (g·tg φ)`, поэтому от ТТХ зависят и форма маршрута, и время.

### 4.3. По каждому средству — нагрузка (✅ план 13.4, 30.09.2026: «Анализ» → «Рассчитать нагрузку»)

**Нагрузка на средство** `j` — доля маршрутов выборки, прошедших через его зону:

```
L_j = M_j / M × 100 %,   M_j = |{ r : min по точкам r ‖r − s_j‖ ≤ R_j }|
```

`M` — все маршруты единой выборки (все цели вместе; по одной цели — маршруты к ней), `R_j` — радиус средства. Маршруты весят поровну, средства равны:
малые, ПВН у района защиты и большие. Пример: из 1 000 маршрутов через средство прошло 500 — нагрузка 50 %.

| Свойство | Что значит |
|---|---|
| `0 ≤ L_j ≤ 100 %`, **сумма может быть больше 100 %** | один маршрут видят несколько средств |
| `Σ_малые L_j / 100 % = средняя кратность` | тождество: `Σ_j M_j = Σ_r h_r` — одни и те же пары «маршрут × средство», сосчитанные по строкам и по столбцам |
| объединение маршрутов средств типа / `M` = засечка типа | та же матрица, другой разрез |
| `L_j = 0` | средство без пролёта («простаивающие» 4.1) |
| по цели: `Σ_целей M_j(ц) = M_j`, `Σ_целей M(ц) = M` | маршрут идёт к одной цели — выборка делится без остатка; `L_j(ц)` — доля от маршрутов к цели `ц` |

⚠️ **Нагрузка — показатель, а не критерий, и не вклад.** Жадный ставит средство по наибольшему **приросту**
(новые маршруты, недобор кратности), а не по нагрузке: средство в тени соседей может нести большую нагрузку при
малом вкладе. Высокая нагрузка — **узкое место**: откажет — многие маршруты потеряют засечку; низкая — средство
стоит на редком пути. Как считается в коде — [код/НАГРУЗКА_НА_СРЕДСТВО](../код/НАГРУЗКА_НА_СРЕДСТВО.md).

## 5. 📌 Блок выходных данных для сравнения расчётов (задел)

Чтобы сравнивать расчёты и варианты программы между собой, каждый раз выводить **один и тот же набор**:

| Группа | Что |
|---|---|
| **условия** | участок, число маршрутов, зерно, типы (N · R · k), цели (число, приоритеты), правило очереди |
| **по району** | засечено; по типам — засечка ≥ k и % не выполнивших k; не хуже X %; простаивающие |
| **по каждой цели** | ПВН у цели; подлёт ≥ 1 / ≥ k_цели; % не выполнивших; рубеж (медиана, худшие 10 %) |
| **цена** | время расстановки, пик памяти |

⚠️ Условия — рядом с числами, всегда: без них число нельзя ни повторить, ни опровергнуть
([10_ПРОВЕРКИ_И_ПРОГОНЫ](../переносимое/10_ПРОВЕРКИ_И_ПРОГОНЫ.md)). Образец такой таблицы — замеры
[плана 13.1 §Д9.4](../история/архив/13.1_ПЛАН_ДОРАБОТКА_ДАТЧИКОВ.md).
