## 1. Термины

| Термин | Что это | Откуда число |
|---|---|---|
| **зона цели** | массив застройки и построек, где стоит цель, ± R, ∩ карта места ПВН; цель в лесу — район, нарисованный человеком | [ТИП_ПВН §5](ТИП_ПВН.md) |
| **вместимость** | сколько мест встаёт в зону плотной укладкой с разносом 1.6 R | `capacity` |
| **подлёт** | куски маршрутов к ЭТОЙ цели внутри её зоны | `approach` |
| **кратность защиты k** | сколько ПВН должны видеть подлёт; паспорт, «Кратность защиты цели» | `tgt_k`, по умолчанию 1 |
| **уровень защиты** | доля подлёта, засечённого ≥ k раз, при которой цель защищена | от k: 99 · 92 · 89.3 · 86.7 … %, либо своё |
| **порог прироста** | меньше него прирост доли уже «не стоит ПВН» | от k: 1 · 3 · 4 · 5 … %, либо своё |
| **кривая цели** | доля подлёта ≥ k после 1, 2, 3 … ПВН, если ставить у этой цели одной | жадный цели до вместимости |
| ⭐ **потребность** | сколько ПВН цели нужно: до уровня; уровень недостижим — до насыщения (§3) | по кривой, `need` |
| ⭐ **доля** | сколько ПВН цели положено из бюджета — по приоритету, не больше потребности | `allot`, §4 |
| ⭐ **минимум** | первая очередь цели — не больше её доли и наименьшего max(k, 3) | §4 |
| **бюджет целей** | сколько ПВН типа можно отдать целям: потолок 50 % N (одна цель) / 70 % N (все), но не меньше наименьших | `tgt_cap_one`, `tgt_cap_all` |

## 2. Как было и что не так (разбор поручения заказчика 30.09.2026)

**Как было (план 13.1, §Д9.7, 24.09.2026).** (1) минимум **min(3, вместимость)** у каждой цели — по убыванию
приоритета, пока хватает N; (2) сверх минимумов — **один общий жадный** по подлётам всех целей, маршрут весит
p_цели / (Σp · подлётов цели); (3) цель выбывает, набрав уровень, или весь этап стоит, когда **ни один ПВН** не даёт
прироста ≥ порога. ✅ Проверено по коду — так и было: «сначала по 3 у всех, потом по приоритету» — верно.

**Что не так — три находки (замер: `arh`, три цели по 150 маршрутов, ПВН 20 × 0.5 км, зерно 1000; скрипты
`alloc_capture.py`, `alloc_run.py` в scratchpad сессии):**

1. **приоритет почти не влиял на число.** Он входил лишь весом в общий жадный: при k 2 приоритеты 90/5/5 дали
   **8 / 3 / 3**, а равные — 6 / 4 / 4; при k 1 и 90/5/5 — 4 / 3 / 3, как при равных;
2. **минимум — константа 3.** При нехватке он раздавался целиком старшим: 5 ПВН на три цели (k 1) — **3 / 2 / 0**,
   третья цель без защиты;
3. ⚠️ **цель бросалась ниже уровня.** Стоп «ни один ПВН не даёт ≥ порога» проверял **один** ПВН, а при k ≥ 2
   прирост неровный: первый ПВН пары прироста доли ≥ 2 не даёт, при k 3 первые три дают 0 · 0 · 6 %. Снимок 6
   (29.09.2026): Мирный — 10 ПВН, подлёт ≥ 2 **81.6 %** при уровне 92 %, стоп «прирост < 3 %», а 4 ПВН потолка ушли в
   общий проход; площадке — 3 (места кончились). Это и есть «у первой 10, у второй 3, критерий не добран, а
   расстановка пошла дальше».

## 3. Потребность — по кривой цели

Каждая цель сначала считается **одна**: её жадный ставит ПВН до вместимости, по ходу пишется кривая — доля подлёта ≥ k
после каждого ПВН. Потребность:

* **уровень достижим** — сколько ПВН до него (первая точка кривой ≥ уровня);
* **недостижим** даже на всех местах зоны — **до насыщения**: пока до потолка кривой (доли при всех местах) остаётся не
  меньше **k порогов**; дальше ПВН почти ничего не добавляют.

⚠️ **Почему остаток до потолка, а не прирост шага.** Прирост шага при k ≥ 2 неровный, и стоп по нему обрывает цель
на подъёме. Кривые целей (замер выше, доля подлёта ≥ k после 1, 2, 3 … ПВН):

| Цель | k 1 | k 2 | k 3 |
|---|---|---|---|
| Мирный (мест 142, вместимость 40) | 49 · 76 · 86 · **96** · 96 · 98 … | 0 · 25 · 33 · 45 · 57 · 65 · 69 · 72 · 76 · 79 · 81 · 83 · 84 · **86** … **91** на 18 | 0 · 0 · 6 · 7 · 17 · 25 … **69** на 27 |
| площадка (мест 52) | 93 · **100** | 0 · 30 · 41 · 52 · 57 · 60 · **63** … 67 | 0 · 0 · 19 · 19 · 20 · 28 … 45 |

Пример: Мирный при k 2 и уровне 95 % — уровень недостижим (потолок 91 %), порог 3 %: потребность — пока остаток ≥ 6 %,
то есть до 86 % на **14 ПВН**. Стоп по шагу давал 9 ПВН и 76 %, по одному ПВН при k 3 — ноль.

## 4. Доля и минимум — бюджет по приоритету

**Бюджет целей** B = min(N, max(потолок, Σ наименьших)); потолок — 50 % N при одной цели, 70 % N при нескольких.

**Доля** цели — «деление водой»: nᵢ = λ·pᵢ, но не больше потребности и не меньше наименьшего max(k, `tgt_min`); λ
подбирается так, чтобы Σ nᵢ = B; округление — по наибольшей дробной части, при равных — старшей. Смысл:

* приоритет задаёт **число**, а не только порядок: 0.5 / 0.3 / 0.2 → 7 / 4 / 3 из 14;
* цели, которой нужно меньше её доли, даётся её потребность, **излишек идёт остальным по приоритету** — старшей
  больше всех. Поэтому «3 3 3 → 10 3 3» не выходит, если младшим нужно больше 3: старшая берёт сверх своей доли только
  то, что младшим не нужно. А при 90/5/5 старшей и положено почти всё: **8 / 3 / 3** из 14 — младшим только наименьшее;
* хватает всем (Σ потребностей ≤ B) — каждой её потребность, остаток бюджета — в общий проход.

**Не хватает на наименьшее всем** (Σ max(k, 3) > B): сперва **по k каждой** — старшим первыми, меньше k засечки ≥ k
не даст; остаток — снова по приоритету до наименьшего. 5 ПВН на три цели при k 1 — **3 / 1 / 1** (было 3 / 2 / 0).

**Минимум** — первая очередь цели: min(доля, наименьшее). Это «минимум, рассчитанный из числа ПВН, мест и приоритета»:
при избытке — max(k, 3), при нехватке — меньше, по приоритету.

| Потребности, приоритеты, бюджет | Доли | Пояснение |
|---|---|---|
| 14 / 3, поровну, 14, k 2 | **11 / 3** | случай снимка 6: площадке нужно 3 — Мирному остальное до потолка, в общий проход не уходит ни один |
| 20 / 20 / 20, поровну, 14 | 5 / 5 / 4 | поровну, лишняя единица — по дробной части |
| 12 / 8 / 8, 90 / 5 / 5, 14, k 2 | 8 / 3 / 3 | младшим — наименьшее, остальное старшей |
| 14 / 7 / 5, 0.5 / 0.3 / 0.2, 14, k 2 | 7 / 4 / 3 | λ·p |
| 4 / 2 / 2, 0.5 / 0.3 / 0.2, 5, k 1 | 3 / 1 / 1 | нехватка: по k каждой, остаток старшей |

(Таблица — проверка `flow_check` 4м.)

## 4а. Подробно на примерах (заказчик 02.10.2026: «не совсем понятно — поясни с примерами»)

Числа — кривые целей из замера §2 (`arh`, ПВН × 0.5 км). Код этих шагов с комментариями —
[код/РАСПРЕДЕЛЕНИЕ_ПВН_ПО_ЦЕЛЯМ](../код/РАСПРЕДЕЛЕНИЕ_ПВН_ПО_ЦЕЛЯМ.md).

### Пример 1. «Цель добирает, пока до максимума кривой остаётся не меньше k порогов»

**Кривая** — доля подлёта, засечённая ≥ k раз, после 1, 2, 3 … ПВН, если ставить у цели одной до заполнения её зоны.
**Максимум кривой** (потолок) — доля, когда заняты все места зоны: больше у этой цели не набрать ничем.
**Остаток** — потолок минус то, что уже набрано: сколько ещё в принципе можно добрать.
**k порогов** — порог прироста × кратность: k 1 — 1 %, k 2 — 2 · 3 = 6 %, k 3 — 3 · 4 = 12 %.

Мирный, кратность 2, уровень 95 % — на кривой его нет (потолок 91 %), значит, считаем по остатку:

| ПВН у цели | 9 | 10 | 11 | 12 | 13 | **14** | 15 | 16 | 18 |
|---|---|---|---|---|---|---|---|---|---|
| доля подлёта ≥ 2, % | 76 | 79 | 81 | 83 | 84 | **86** | 87 | 89 | 91 |
| до потолка 91 % осталось, % | 15 | 12 | 10 | 8 | 7 | **5** | 4 | 2 | 0 |
| ≥ 6 % (k порогов)? | да | да | да | да | да | **нет — стоп** | | | |

Потребность — **14**: следующие ПВН вместе дали бы только 5 % — меньше двух порогов. Если бы уровень был 85 %, правило
остатка не понадобилось бы: на кривой 85 % набирается на 14-м ПВН — потребность = 14 по уровню.

**Почему не «один ПВН дал меньше порога — стоп».** При кратности 2 первый ПВН пары прироста доли ≥ 2 не даёт (подлёт
видит один ПВН), прирост скачет: 0 → 25 → 8 → 12 %. При кратности 3 первые три ПВН: 0 · 0 · 6 % — правило шага
остановило бы цель на нуле. Остаток до потолка от неровности шага не зависит.

| Цель | k | Порог | Кривая (начало … конец) | Потребность |
|---|---|---|---|---|
| Мирный | 1 | 1 % | 49 · 76 · 86 · **96** … 100 | **4** — уровень 95 % набран на 4-м |
| Мирный | 2 | 3 % | 0 · 25 · 33 … 86 … 91 | **14** — остаток < 6 % |
| Мирный | 3 | 4 % | 0 · 0 · 6 · 7 · 17 … 58 … 69 | **15** — остаток < 12 % на 58 % |
| площадка | 2 | 3 % | 0 · 30 · 41 … 63 … 67 | **7** — остаток < 6 % |

### Пример 2. «Доля — не больше потребности цели»

Доля по приоритету считается так, будто ПВН нужны всем без конца: λ·приоритет. Но цели, которой нужно меньше, давать
больше её потребности бессмысленно — лишние ПВН ничего ей не добавят. Поэтому доля = min(потребность, λ·приоритет), а λ
подбирается так, чтобы розданное в сумме было ровно бюджетом.

Снимок 6: бюджет 14, приоритеты поровну, потребности 14 (Мирный) и 3 (площадка, мест с подлётом мало):

| Шаг | Мирный | площадка | Σ |
|---|---|---|---|
| поровну, λ·0.5 при λ = 14 | 7 | 7 | 14 |
| площадке нужно только 3 — её доля 3 | 7 | **3** | 10 — 4 ПВН свободны |
| λ растёт, пока Σ = 14: λ = 22 → Мирному min(14, 11) | **11** | 3 | 14 |

Итог **11 + 3**: излишек площадки (4 ПВН) ушёл Мирному, а не в общий проход. Если бы Мирному тоже хватало меньше бюджета
(потребности 10 и 3, Σ 13 ≤ 14), каждой досталась бы её потребность, а 1 ПВН — в общий проход.

### Пример 3. Минимум: был константой 3 — теперь расчётом и с остановкой при нехватке

**Наименьшее** = max(k, `tgt_min` = 3), но не больше потребности: меньше k засечки ≥ k не даёт вовсе. **Минимум** —
первая очередь цели = min(доля, наименьшее).

(а) ПВН хватает: минимумы 3 · 3 · 3 ставятся первыми, остальное — по доле. Минимум не «константа»: если доля меньше 3
(см. (б)), минимум меньше.

(б) **Не хватает**: 5 ПВН на три цели (приоритеты 0.5 · 0.3 · 0.2, k 1, потребности 4 · 2 · 2):

| Шаг | Мирный | площадка | третья | Осталось |
|---|---|---|---|---|
| наименьшее min(потребность, 3) | 3 | 2 | 2 | Σ 7 > 5 — всем не хватает |
| сперва по k = 1 каждой, старшим первыми | 1 | 1 | 1 | 2 |
| остаток «водой» по приоритету (λ = 5: 2.5 · 1.5 · 1) | 2.5 → **3** | 1.5 → **1** | 1 | 0 |
| **итог** | **3** | **1** | **1** | подлёт 86 · 93 · 81 % |

Было «3 старшей, 2 следующей, 0 последней» (3 · 2 · 0) — третья цель оставалась без защиты.

(в) **Совсем мало**: 2 ПВН на три цели при k 2 — по k = 2 получает только старшая (2 · 0 · 0), у остальных в отчёте
«ПВН не хватило». Это и есть «остановиться, когда не хватит»: ставить им по одному ПВН нельзя — при k 2 один ПВН
защиты не даёт.

## 5. Порядок постановки

Места у целей могут быть общими (зоны рядом), поэтому ставится по очереди и **поверх уже стоящих**: жадный цели
считает засечки ПВН соседних целей и держит от них разнос 1.6 R.

1. **минимум у всех** — по убыванию приоритета: младшим достаются их места до того, как старшая займёт всё вокруг;
2. **до доли** — у старшей, пока не наберёт уровень или долю, потом у следующей;
3. **остаток бюджета** (цель набрала уровень раньше доли благодаря соседям, остаток от округления) — целям ниже
   уровня, старшим первыми: уровень достижим — до уровня, недостижим — до насыщения.

На каждом шаге цель останавливается, как только **набрала уровень**. Остальное из квоты типа идёт в общий проход
закреплёнными позициями (как и прежде).

## 6. Отчёт: почему остановились

У каждой цели в отчёте и в «Анализе»: поставлено, **нужно** (потребность), **доля по приоритету**, минимум, подлёт ≥ k и
причина:

| Причина | Когда | Что делать |
|---|---|---|
| «уровень X %» | цель защищена | — |
| «мест с подлётом нет» | свободных мест, видящих незасечённый подлёт, не осталось | расширить зону — «Изменить цели» → район |
| «насыщение: максимум X %» | уровень недостижим даже на всех местах; добрано до насыщения | снизить уровень или кратность защиты; «Анализ» скажет, чего не хватает |
| «доля N, потолок B» / «доля N, квота N» | бюджет кончился раньше уровня: цель получила свою долю | поднять приоритет цели, потолок целей или N типа |
| «ПВН не хватило» | при нехватке этой цели не досталось даже k | добавить ПВН |

## 8. Где в коде и ловушки

`src/model/placement/target_stage.py`: `need` (потребность по кривой) · `least` (наименьшее) · `allot` + `_water` (доли) · `_fill`
(жадный цели поверх стоящих, кривая) · `stage` (порядок §5, отчёт §6). Отчёт — `src/controller_qt/threat_controller.py`
(строка «у целей» и раздел «Защита объекта» в «Анализе»). Разбор кода — [код/ЦЕЛИ_И_РОЗЫГРЫШ §11](../код/ЦЕЛИ_И_РОЗЫГРЫШ.md).

1. ⚠️ **потребность — по кривой ОДНОЙ цели**, а ставится поверх соседей: соседние ПВН могут дать уровень раньше —
   тогда цель останавливается раньше доли, а остаток уходит по шагу 3;
2. ⚠️ порог — только для насыщения, когда уровень недостижим; при достижимом уровне цель не бросается ниже него,
   пока есть её доля (иначе — снова снимок 6);
3. ⚠️ **потолок целей остаётся** (решение В13.30: min(насыщение, потолок)) — без него при k 2 цели забрали бы все ПВН
   типа; поднять — «Потолок на все цели» в окне типа;
4. ⚠️ `tgt_min` («Меньше не ставить у цели») — нижняя граница, **не минимум**: минимум — доля по приоритету;
5. числа потребности и доли — по выборке: другая выборка — другие кривые (показатель, а не обещание).
