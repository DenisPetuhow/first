## 1. Что оптимизируется

**F(S)** — польза набора датчиков S по выборке маршрутов, **основной критерий**, среднее по маршрутам:

```
F(S) = среднее по маршрутам [ a1 · min(n, k) / k  +  a2 · (покрытых сегментов) / L_seg ]
```

`n` — сколько датчиков засекли маршрут, `k` — кратность, `L_seg` — сегментов в маршруте.
Насыщение `min(n, k)` делает F **субмодулярной**: каждый следующий датчик на том же маршруте даёт
не больше предыдущего. Ещё F **монотонна**: лишний датчик пользы не отнимает. На этих двух
свойствах держатся все гарантии ниже.

## 2. Гарантии жадного — теоремы

| Ограничение | Гарантия жадного | У нас |
|---|---|---|
| не больше N датчиков (кардинальность) | **1 − 1/e ≈ 63 %** от оптимума (Немхаузер, Уолси, Фишер, 1978) | один малый тип |
| **матроид разбиения**: у каждого типа своя квота N_t | **1/2** (Фишер, Немхаузер, Уолси, 1978) | общий проход по типам (13.6) |
| модульный бонус места | гарантия та же: сумма субмодулярной и модульной — субмодулярна | бонус ПВН (13.7) |
| **разнос** (запрет пар ближе d) | ⚠️ **не матроид** — гарантия строго не доказана | внутри типа и между типами |

**Матроид разбиения** — это «множество кандидатов разбито на части (типы), из каждой части берём не
больше своей квоты». Общий проход ровно такой: каждый шаг — пара «тип + место», квоты N_t не
превышаются. Отсюда 1/2 там, где при очереди «сначала тип 1, потом тип 2» не было никакой.

⚠️ **Разнос ломает строгость.** Запрет «не ближе d» — ограничение другого рода; писать «1/2» без
оговорки нельзя ([ОГРАНИЧЕНИЯ 1.14](../правила/ОГРАНИЧЕНИЯ.md)). Поэтому теорема — ориентир, а
**число** даёт граница Минью (§3), которая считается на самой задаче.

## 3. Граница Минью — что это

Для монотонной субмодулярной F и **любого** набора S:

```
OPT ≤ F(S) + сумма N наибольших приростов Δ(c | S) по кандидатам c
```

Смысл: оптимальный набор из N датчиков не может дать больше, чем «уже набранное» плюс N самых
выгодных добавок к нему — субмодулярность запрещает добавкам расти. Верхняя граница есть на
каждом шаге жадного; берём **наименьшую** из них.

## 4. Как это реализовано

`CoverageCache.greedy` (один тип) и `joint_greedy` (несколько):

1. на каждом шаге приросты `primary` уже посчитаны для выбора — отдельного прохода не нужно;
2. `note_bound`: N наибольших приростов (`optimization.top_sum` — одна на оба прохода и на `top_gain`) + F
   текущего набора → граница шага;
   `ub = min(ub, …)`; ещё раз — после последнего шага;
3. ⚠️ приросты берутся **по всем кандидатам, и закрытым разносом тоже**: такая граница верна для
   задачи без разноса, а значит — и для нашей, более тесной;
4. ⚠️ **доля — по своему вкладу:** `(F − F₀) / (граница − F₀)`, где F₀ — польза до прохода: покрытие
   чужих датчиков (`placed`, путь одного типа). Иначе отношение завышалось бы за счёт того, что уже стояло.
   ⚠️ Закреплённые человеком и ПВН этапа целей ставятся уже в проходе, после F₀: в общем проходе F₀ = 0, и доля — от
   всего F набора (проверено по коду 18.10.2026; В16.01.12 — заказчик: «от всего результата»). ✅ С 20.10.2026
   запоминается и вторая база FA — F сразу после закреплённых: от неё считается «прирост жадного» (§5);
5. при общем покрытии — **одна граница на весь проход**: `OPT ≤ F(S) + Σ по типам (N_t лучших)`.
   Граница «по типу» там неверна: чужие датчики после последнего хода типа подняли бы F выше неё.
   ✅ С 18.10.2026 она же — строка **«в целом»** в «Анализе» (`joint_greedy.whole_bound`, `ThreatModel.gap_whole`); при
   своей кратности «в целом» — суммой F и границ типов. При средствах разного масштаба F — вариант H (16.1): формула
   границы та же, приросты — `_two_gain` ([код/СТЕПЕНЬ_ПОКРЫТИЯ_В_КОДЕ §2, §4](../код/СТЕПЕНЬ_ПОКРЫТИЯ_В_КОДЕ.md));
6. бонус места в границу не входит — оценка остаётся про засечку.

Результат — `last_bound = (F, F₀, граница, доля)`, модель — `gap_bounds`, `metrics()["gap"]`, отчёт —
«тип N · не хуже X % от лучшего на тех же местах». **Выбор жадного граница не меняет ни на бит.**

## 5. ⭐ Что значит «не хуже X %» — и почему нужны две величины

**Замер 24.09.2026** (план 13 §13.8.4; 250 маршрутов, больших 0):

| Обстановка | не хуже |
|---|---|
| МОГ как в эталоне (20 × 2 км, k 3) | **84.8 %** |
| ПВН один (20 × 0.5 км, k 4) | **54.4 %** |
| МОГ 10 + ПВН 20 | 67.0 / 69.6 % |

⚠️ **X % — доказанный минимум, а не потеря.** На пяти малых задачах перебором (12 кандидатов, 2–3
датчика) жадный **совпал с оптимумом**, а граница была выше него на 9–16 %. Настоящий зазор обычно
много меньше, чем «100 − X».

⚠️ **«На тех же местах» ≠ «вообще».** Граница считается по кандидатам ЭТОГО типа. У ПВН кандидаты —
только карта места (застройка), поэтому число значит «не хуже X % от лучшей расстановки **в
застройке**». Лучшая расстановка без запрета мест может быть выше — разница и есть **цена запрета**:

```
доля_на_местах = F / граница(кандидаты карты места)          — сейчас в отчёте, с подписью
доля_вообще    = F / граница(все кандидаты зоны пролёта)      — ✅ 25.09.2026, «Анализ» (Д4)
цена запрета   ≈ доля_на_местах − доля_вообще
```

✅ **Обе величины — с 25.09.2026** ([план 13.1, Д4](../история/архив/13.1_ПЛАН_ДОРАБОТКА_ДАТЧИКОВ.md)): отчёт расстановки — «на
разрешённых местах», окно «Анализ» — раздел «Зазор до оптимума» с обеими (`ThreatModel.gap_all`). Граница «вообще»:
`UB + max(0, лучшие приросты по сетке типа без карты − на карте)` на итоговом наборе. Замер `arh` (МОГ 10 + ПВН 20):
ПВН 45.4 → 42.2 % (своя k), 79.2 → 75.3 % (одна k) — цена запрета 3–4 пункта. Кэш без карты — 17 682 кандидата,
7.6 с, 40 МБ: поэтому только по запросу. У типа «везде» (МОГ) величина одна.

✅ **«В целом» — с 18.10.2026** (план 16.01, 16.1, В16.01.3): первая строка раздела — граница всего набора; «от лучшего
вообще» — с прибавками всех типов с картой места. Замер `out_test/plan16/m16_1/h_measure.py` (МОГ 10 + ПВН 20 + пост 2 × 25 км, H, три зерна,
150 маршрутов): в целом 90.9 · 90.8 · 90.7 %, от лучшего вообще 83.3 · 83.2 · 80.5 %. Расчёт по шагам —
[код/СТЕПЕНЬ_ПОКРЫТИЯ_В_КОДЕ §4](../код/СТЕПЕНЬ_ПОКРЫТИЯ_В_КОДЕ.md).

**Что такое «лучшее», прибавки и потолок — по шагам, с примером** — §5а.

**Две строки в «Анализе»** (заказчик 20.10.2026: «добавь от прироста — то, что доставил жадный»):

| Строка | Формула | Что значит |
|---|---|---|
| «в целом: не хуже X %» | (F − F₀) / (граница − F₀), F₀ = 0 | весь набор — закреплённые человеком, ПВН у целей и жадный — от лучшего набора той же численности |
| «прирост жадного: не хуже Y %» | (F − FA) / (граница − FA), FA — F сразу после закреплённых | только то, что добавил жадный, — от лучшего возможного добавления к уже стоящим |

**Закреплённые** — то, что стоит до хода жадного: датчики, поставленные человеком (до итераций — все заданные, при
итерациях — статические), и ПВН этапа целей у объектов защиты. Нет их — FA = F₀, числа совпадают, вторая строка не
выводится. Замер (`out_test/plan16/m16_1/gain_measure.py`; МОГ 18, ПВН 10, 40 маршрутов, зерно 1000): у района —
цель по умолчанию (Мирный), 4 ПВН у неё дают FA = 0.289 из F = 0.839, граница 0.979 → «в целом» 85.7 %, «прирост
жадного» (0.839 − 0.289) / (0.979 − 0.289) = **79.7 %**; три цели (7 ПВН у целей) — 84.1 % и 78.1 %.

## 5а. ⭐ «Не хуже X %» по шагам: что такое лучшее, прибавки, потолок (вопросы заказчика 20.10.2026)

**1. Что такое «лучшее» и где оно стоит.** «Лучшее» (OPT) — расстановка с наибольшим F среди всех, где средств
каждого типа столько же (например, 18 МОГ и 10 ПВН) и каждое стоит на одном из **разрешённых мест** — тех же
кандидатов, из которых выбирал жадный (сетка мест, карта места типа). Это **не** места, которые выбрал жадный:
лучший набор может стоять в совсем других клетках. «На тех же местах» значит «из того же списка возможных мест».

**2. Почему его нельзя найти перебором.** На `arh` у МОГ 2 416 возможных мест, ставим 18: вариантов
C(2 416, 18) ≈ 1.2·10⁴⁵ (46 цифр); у ПВН 1 407 мест, ставим 10 — ≈ 8·10²⁴; вместе — их произведение. Миллиард
вариантов в секунду перебирал бы 10⁴⁵ дольше, чем существует Вселенная. Поэтому лучшее не считается — считается
**потолок**: число, про которое доказано, что лучшее не больше его.

**3. Прибавка места — за счёт чего.** Берём готовую расстановку жадного и мысленно ставим в место c **ещё одно**
средство, ничего не убирая. На сколько вырастет F — это прибавка Δ(c): новые засечки (маршрутам, которым не хватало
до k засечек) плюс новые участки маршрутов под наблюдением. Место, где всё уже накрыто, даёт 0; место среди
маршрутов, которых никто не видит, — много.

**4. Потолок = F + N самых больших прибавок.** Прибавки считаются у **всех** возможных мест типа — и уже занятых (у
них 0), и закрытых разносом. Из них берутся N наибольших (N — сколько средств типа ставим: 18 для МОГ) и
складываются с F. Это мысленный опыт: на карту ничего не ставится, «ещё пару средств» никто не добавляет.

**Почему лучшее не выше потолка.** Лучший набор — это N мест. Добавим все его N средств к нашему готовому набору:
получится не меньше, чем лучший набор сам по себе (больше средств — не хуже). А добавленные по одному, они дают не
больше своих прибавок Δ(c), посчитанных для нашего набора: по мере роста набора прибавки только падают (убывающая
отдача — новое средство частью видит уже накрытое). Значит, OPT ≤ F + Δ(его N мест) ≤ F + N наибольших Δ = потолок.

**Пример по шагам** — 6 маршрутов, 3 места, ставим N = 2; F — сколько маршрутов засечено (k = 1):

| Место | засекает маршруты |
|---|---|
| P1 | 1, 2, 3, 4 |
| P2 | 1, 2, 5 |
| P3 | 3, 4, 6 |

1. Жадный: шаг 1 — P1 (4 новых маршрута); шаг 2 — у P2 новый 1 (маршрут 5), у P3 — 1 (маршрут 6), берёт P2. Итог
   F = 5 (маршруты 1–5).
2. Прибавки к готовому {P1, P2}: P1 — 0 (уже стоит), P2 — 0, P3 — 1 (маршрут 6).
3. Потолок = 5 + (1 + 0) = 6 — две наибольшие прибавки: 1 и 0.
4. «Не хуже» = 5 / 6 = **83 %**.
5. Проверка перебором: лучшее — {P2, P3}, F = 6 — **другие места**, чем у жадного (P1 в нём нет). Здесь потолок
   совпал с лучшим, и 83 % — настоящая доля.

**«Прирост жадного» на том же примере.** Пусть P1 поставил человек (закреплён), жадный добавляет одно: P2 → F = 5,
FA = 4 (засекает один P1).
* «в целом» = 5 / 6 = 83 %;
* «прирост жадного» = (5 − 4) / (6 − 4) = **50 %** — жадный добавил 1 маршрут из 2, которые добавил бы лучший набор.
* ⚠️ Потолок — от лучшего набора **вообще**, где P1 может и не стоять ({P2, P3} = 6). При закреплённом P1 больше 5 не
  набрать ничем, и настоящая доля прироста — 100 %. «Прирост жадного» — тоже доказанный минимум, а при закреплённых
  он бывает заметно строже настоящего.

**На карте** (`arh`, МОГ 18 + ПВН 10, 40 маршрутов, зерно 1000; `out_test/plan16/m16_1/gain_measure.py`): F = 0.839
(доля от 1 — кратность и степень покрытия в среднем по маршрутам), 4 ПВН у Мирного дают FA = 0.289, потолок 0.979 —
лучшее не выше 0.979.
* «в целом» = 0.839 / 0.979 = **85.7 %**;
* «прирост жадного» = (0.839 − 0.289) / (0.979 − 0.289) = 0.550 / 0.690 = **79.7 %**.

**Как читать.**
* X % — нижняя граница, «хуже не бывает»; настоящая доля обычно ближе к 100 % (§5: на малых задачах перебором жадный
  совпадал с лучшим, потолок был выше на 9–16 %).
* Потолок далёк от лучшего, когда много мест с крупными прибавками **перекрывают друг друга**: в сумму идут все N, а
  лучший набор разом взять их не может. Поэтому у ПВН — много похожих мест в одной застройке — X % ниже, чем у МОГ
  (замер §5: 54 % против 85 %).

## 6. Очередь типов — «осталось / доступно»

Коротко — [README §4](README.md). Здесь — почему это не ломает гарантию: правило очереди выбирает
только, **чей** кандидат ставится на шаге; квоты соблюдаются, значит, набор остаётся независимым в
матроиде разбиения. Гарантия 1/2 доказана для правила «наибольший прирост» (`gain`); `tight`,
`round`, `types` — эвристики без гарантии, граница Минью считается для любого.

| `add_trajectory` — временно | ~48 байт на «точка × кандидат» целиком: разность, её копия в `norm`, квадраты — до 619 МБ | кусками по 2¹⁹ пар, √(dx² + dy²) на месте — **13 МБ** |
| `greedy` / `joint_greedy` — копии кэша | `H` int64 + `M` uint32 + `Fc` float64 — 20 байт на пару | в хранимом виде — 9 байт |
| шаг жадного — приросты | 6–7 матриц float64 / int64 разом; второй ключ — на каждом шаге | на месте, ~24 байта на пару; второй ключ — только после насыщения |
