# МЕТОДИЧКА — ВВОД И ВЫВОД ДАННЫХ ЧЕРЕЗ ФАЙЛЫ

> **Что здесь.** Как программа обменивается данными с человеком и с другими программами
> через файлы: какие папки, какие форматы, по каким правилам читается и пишется. По этим
> правилам сделаны ДАТЧИКИ (§3) и МАРШРУТЫ ПРОЛЁТА (§5, задача 8.6, готово 06.09.2026) —
> формат у обоих общий, отличается только содержание строк.
>
> **Зачем отдельный документ.** Форматов будет несколько, и каждый следующий соблазнительно
> сделать «как удобнее сейчас». Через полгода это оборачивается тремя разными способами
> писать координаты и тремя разборщиками. Здесь записаны общие правила — новый формат
> заводится по ним, а не заново.

---

## 1. Папки: что читаем и что пишем — врозь

```
датчики/
├── загрузка/      ← сюда кладут файлы, которые программа ЧИТАЕТ
└── выгрузка/      ← сюда программа ПИШЕТ по кнопке «В файл…»
```

| Правило | Почему так |
|---|---|
| папка **своя**, а не корень программы | выгрузки терялись среди исходников; теперь всё в одном месте |
| две подпапки, а не одна | входные файлы человек готовит сам, выходные создаёт программа; в общей папке они путаются |
| папки создаются **сами** при первом обращении | требовать от человека создать папку — лишний шаг, а забытая папка ломала бы кнопку |
| путь считается от **корня программы**, а не от текущей директории | иначе файлы разбредаются по диску в зависимости от того, откуда запустили |
| в git **не попадают** (`.gitignore`) | это рабочие данные конкретного расчёта, а не код |

**Имя файла по умолчанию — дата и время:** `2026_09_05_09_15_sensor.txt`.
Год первым, разделитель `_`: такие имена сортируются по алфавиту в том же порядке, что и
по времени, и в папке выгрузки сразу виден порядок работ. Двоеточие времени Windows в
имени файла не допускает, потому и подчёркивания.

⚠️ **Память последней папки здесь НЕ применяется.** Обычно программа запоминает, где
человек был в прошлый раз, но для этих кнопок правило другое (заказчик 05.09.2026):
диалог всегда открывается в своей папке. Иначе один поход в чужую папку уводил бы туда
все следующие выгрузки, и файлы снова расползались бы.

**Где в коде:** `view_qt/input_window.py` :: `sensors_dir(kind)`, `default_file_name(when)`,
константы `SENSORS_DIR`, `DIR_LOAD`, `DIR_SAVE`.

## 2. Общие правила формата — на все файлы программы

Эти семь правил делают файл читаемым обратно и переносимым. Новый формат заводится по ним.

| № | Правило | Зачем |
|---|---|---|
| 1 | всё, что начинается с `#` — **комментарий** | шапку можно дополнять, не ломая чтение |
| 2 | первая строка — **опознавательная**: `# UAV-SENSORS v1` | по ней видно, что файл наш и какой версии |
| 3 | колонки разделены **пробелами**, число пробелов не важно | файлы правят руками в блокноте, ровнять по столбцам никто не станет |
| 4 | координаты — **только градусы** (lon, lat) | не зависят ни от якоря, ни от района: файл переносится между участками. Километры программа считает сама |
| 5 | кодировка **UTF-8 без BOM**, перевод строки любой | блокнот Windows пишет UTF-8 с BOM: при чтении первую строку чистим от `﻿`, иначе она не опознаётся |
| 6 | **одна плохая строка не роняет чтение** | отчёт «принято 18, отброшено 2 (строки 7, 12)» полезнее, чем отказ читать весь файл |
| 7 | то, что программа записала, она **обязана прочитать сама** без правки руками | иначе выгрузка бесполезна как вход |

⚠️ **Числа в шапке — справочные.** Программа их показывает, но параметры расчёта берёт
из своих полей: файл описывает ПОЗИЦИИ, а не настройки. Иначе загрузка чужого файла молча
меняла бы радиусы и кратности, и человек считал бы не то, что видит в окне.

## 3. Файл датчиков (формат `UAV-SENSORS v1`)

```
# UAV-SENSORS v1
# дата: 2026-09-05 09:15
#
# типы датчиков:
#   тип  класс    N   R, км   кратность k
#     1  малый    20    2.0        3
#     2  малый     0    3.0        3
#     3  малый     0    5.0        3
#     4  большой   3   15.0        3
#
#  N  тип  режим           lon          lat
#--- ---- -------------- ----------- -----------
    1    1  динамический    40.881100    62.793400
    2    1  статический     40.512000    62.802000
    3    4  статический     40.330000    62.760000
```

| Колонка | Что значит |
|---|---|
| `N` | номер по порядку — **при чтении необязателен** |
| `тип` | 1–3 малые, 4 большие |
| `режим` | `статический` / `динамический`; принимаются также `стат`/`дин`, `static`/`dynamic`, `s`/`d` |
| `lon`, `lat` | градусы, точка или запятая как разделитель дробной части |

**Опора разбора — слово режима**, а не номер колонки: тип стоит перед ним, координаты —
сразу после. Поэтому читается и файл, выгруженный программой (с номерами), и строка из
трёх полей, набранная руками: `2 s 40.5 62.8`.

**Что проверяется при чтении:** тип из списка существующих; координаты — числа и в
земном диапазоне (±180, ±90). Не прошло — строка в отчёт «отброшено», остальные читаются.

**Датчик вне района — законно.** Человек мог задать позиции заранее, до выбора района.
Окно показывает, сколько таких (`manual_outside_area`), но не «чинит» их подтягиванием.

**Где в коде:** `view_qt/input_window.py` :: `write_sensors_file`, `read_sensors_file`,
`parse_mode`, `mode_word`. Читает и пишет одно и то же место — иначе форматы разъезжаются.

## 4. Куда попадают прочитанные датчики

Прочитанная строка — это **условие моделирования**, а не результат расчёта:

```
файл → read_sensors_file → (тип, режим, lon, lat)
     → ThreatModel.add_manual_lonlat(...)          # градусы → километры фрейма
     → manual_sensors[]                            # живут рядом с запретными зонами
```

Список `manual_sensors` переживает пересборку карты и смену района: он задан человеком и
от местности не зависит. Убирается только явно — кнопкой «Очистить датчики», «Сбросом»
или из таблицы окна.

Что с ними делает расстановка — [МЕТОДИЧКА_ДАТЧИКИ_РЕЖИМЫ §1–2](вкладка_3/МЕТОДИЧКА_ДАТЧИКИ_РЕЖИМЫ.md).

## 5. Файл маршрутов пролёта (формат `UAV-ROUTES v1`) ✅ СДЕЛАНО 06.09.2026

Выгрузка и загрузка накопленной выборки пролётов (задача 8.6). Те же семь правил §2;
отличие от датчиков только в содержании.

**Что хранится:** каждый маршрут — это ломаная из точек (lon, lat). Маршрутов сотни,
точек в каждом — десятки.

⚠️ **ФОРМАТ ТОЧЕК ПЕРЕСМОТРЕН 06.09.2026** (заказчик: первая версия — строка на точку —
«очень длинно»: 150 маршрутов × ~60 точек = **9 000 строк**). Стало: **строка на
МАРШРУТ**, все его точки — через `" | "`, каждая `N - lon lat`:

```
# UAV-ROUTES v1
# дата: 2026-09-05 10:20
# маршрутов: 150   точек всего: 8 430
#
# R 1  длина 141.8 км
1 - 40.881100 62.793400 | 2 - 40.872000 62.788100 | 3 - 40.860000 62.781000 | …
# R 2  длина 147.3 км
1 - …
```

Те же 150 маршрутов — **150 строк** вместо 9 000. Номер точки и дефис — необязательны
при чтении (в скобках в `_POINT_RE`): строку можно набрать рукой просто парой чисел
через пробел, как и в файле датчиков. ⚠️ Одна плохая точка внутри строки не роняет ни
строку, ни маршрут целиком — она просто выпадает, остальные разбираются.

**Как решены открытые вопросы** (были записаны заранее, чтобы не решать дважды):

| Вопрос | Решение |
|---|---|
| хранить ли высоту точки | нет: модель плоская, высоты берутся из рельефа по координате |
| хранить ли время/скорость | нет: скорость постоянная и лежит в параметрах |
| что делать при загрузке в ДРУГОЙ район | принимается и показывается, как датчики: координаты самодостаточны, участок и якорь НЕ проверяются (`check_compatible`) |
| нужен ли отдельный модуль | да, `model/flight_log.py` — новый механизм, а не часть окна |

**Папки — по тому же правилу:** `маршруты/загрузка` и `маршруты/выгрузка`, имя по дате и
времени: `2026_09_05_10_20_routes.txt`.

**Куда попадают загруженные маршруты:** ОТДЕЛЬНОЕ поле `ThreatModel.loaded_routes` —
⚠️ НЕ смешивается с `iter_routes` (счётчик итераций и вся статистика иначе соврут).
Как и `manual_sensors`, это ВХОДНЫЕ ДАННЫЕ: переживает пересборку карты, смену цели и
входа, убирается только новой загрузкой или кнопкой «Сброс». Чекбокс «Загруженная
выборка» (панель, группа «пролёт БПЛА») включает показ жёлтым пунктиром и разрешает
`_sample_for_sensors()` брать эти маршруты источником для расстановки, но ТОЛЬКО пока
своих итерационных маршрутов накоплено меньше 5 — как только их станет ≥5, приоритет
безусловно переходит к своей выборке (заказчик: «с пуском итераций он уже не работает»).

Выгрузка активна, только когда пакет пройден целиком (`ThreatModel.iterations_complete()`
— `len(iter_routes) >= p.threat_iter_routes`); иначе кнопка сообщает «нет данных», а не
пишет неполный файл.

**Кнопка «Удалить выборку»** (заказчик 06.09.2026) — рядом с «Выгрузить»/«Загрузить»,
убирает ТОЛЬКО `loaded_routes` и гасит галку показа. Отличие от «Сброса»: датчики, цель
и зоны не трогает — нужна ровно затем, чтобы вернуть расстановку к расчёту «по зоне
пролёта» (или по своим итерациям, если они уже идут), не откатывая всё остальное.

**Заголовок после расстановки называет источник.** Если датчики посчитаны ПО
ЗАГРУЖЕННОЙ истории — заголовок так и говорит: «Датчиков N (расстановка по ЗАГРУЖЕННОЙ
истории маршрутов)», а не молчит, будто расстановка обычная. Модель хранит это в поле
`ThreatModel.sensor_source` (`iter` / `loaded` / `zone` / `weight` / `manual`),
выставляется в `place_sensors()` сразу после `_sample_for_sensors()`.

**Окно «Посмотреть маршруты»** (кнопка сверху справа в окне «Исходные данные», заказчик
06.09.2026) — список маршрутов ДВУХ источников (свои пройденные / загруженная история),
таблица всех точек выбранного, подсветка на карте толстой белой линией (`Показать на
карте`) и снятие подсветки (`Сбросить`). ⚠️ **Список ДИНАМИЧЕСКИЙ**: обновляется сам
после каждого пройденного маршрута (Пуск/Шаг/Пакетно), после загрузки/удаления истории,
«Очистить» и «Сброс» — не только при повторном открытии окна. Выбор при этом СОХРАНЯЕТСЯ:
если смотрели не последний маршрут — выбор остаётся; если смотрели последний — выбор
следует за новым последним, чтобы видеть свежее.

**Где в коде:** `model/flight_log.py` :: `save_flights`, `load_flights`,
`check_compatible`, `routes_dir`, `default_file_name` · `model/threat_grid.py` ::
`load_routes_lonlat`, `clear_loaded_routes`, `loaded_routes_lonlat`, `iterations_complete`,
`_sample_for_sensors`, `sensor_source` · `view_qt/threat_view.py` :: кнопки
`btn_flights_save`/`btn_flights_load`/`btn_flights_clear`, слои `route_loaded_item`
(жёлтый пунктир) и `route_preview_item` (белая подсветка), чекбокс `chk_loaded_routes`,
`refresh_route_viewer` · `view_qt/route_viewer.py` :: `RouteViewerDialog` (новый файл —
правило «новый механизм — свой модуль») · `controller_qt/threat_controller.py` ::
`on_flights_save`, `on_flights_load`, `on_flights_clear`, `on_route_preview`,
`_routes_data_for_viewer`.

## 6. Задел: своя карта по клику мыши (задача 8.5)

## 7. Чем проверяется ввод-вывод

`python tools/gui_check.py` — раздел окна «Исходные данные» (датчики):

| Проверка | Что подтверждает |
|---|---|
| запись → чтение того же файла | координаты, типы и режимы совпали до знака |
| строка без номера, по-английски (`2 s 40.5 62.8`) | разбор опирается на слово режима, а не на колонки |
| строка «мусор в строке» | отброшена одна, остальные приняты, чтение не упало |
| папки `загрузка` и `выгрузка` | создаются сами, диалоги открываются в них |
| имя файла | `2026_09_05_09_15_sensor.txt` при заданных дате и времени |

Раздел «7. ИСТОРИЯ ПОЛЁТОВ» того же скрипта — маршруты (задача 8.6):

| Проверка | Что подтверждает |
|---|---|
| пакет не завершён → «Выгрузить» не пишет файл | нет полутени данных вместо предупреждения |
| выгрузка → чтение модулем `flight_log` | маршрутов и точек ровно столько же, шапка опознана |
| файл — строка на маршрут, а не на точку | число строк-точек равно числу маршрутов, точки разделены `|` |
| загрузка кнопкой → `model.loaded_routes` | попадает в ОТДЕЛЬНОЕ поле, `iter_routes` не тронут |
| координаты до и после круга «выгрузка → загрузка» | совпали с точностью формата (< 1 м) |
| источник для расстановки ДО итераций (галка включена) | `_sample_for_sensors()` возвращает `loaded_routes`, `sensor_source == "loaded"` |
| после накопления ≥5 своих итераций | источник переключается на `iter_routes` безусловно |
| окно «Посмотреть маршруты»: списки, таблица, подсветка/сброс на карте | оба источника показывают свои точки; подсветка видна и снимается |
| динамическое обновление: новый маршрут добавлен без переоткрытия окна | список растёт сам; выбор НЕ последнего маршрута не сбивается, выбор последнего — следует за новым |
| «Удалить выборку» | `loaded_routes` очищается, галка гаснет, свои итерации и датчики не тронуты |
| файл не в формате `UAV-ROUTES` | `check_compatible` возвращает причину, а не падает |
| кнопка «Сброс» | `loaded_routes` очищается, галка гаснет |
