# Предел вида: почему рамка липла к краю окна

> **Правился:** 12.09.2026 — разбор заведён по правке задачи 10.8 (замечание заказчика
> «чёрная граница перекрылась, это уже 2 раз»).

> **Что это.** Разбор одного механизма: как у вкладки 3 задаётся предел перемещения
> камеры и почему он **дважды** обрезал чёрную рамку области. Случай учебный: ошибка
> пряталась не в формуле, а в том, **от какой рамки** считали.

---

## 1. Три величины, которые легко спутать

На карте живут три разных прямоугольника, и путаница между ними и есть причина:

| Прямоугольник | Что означает | Где задан | Размер на `arh` |
|---|---|---|---|
| **область показа** | докуда есть данные и тайлы; по ней нарисована **ЧЁРНАЯ рамка** | `THREAT_AREAS[...]["bbox"]` | 302.25 × 249.59 км |
| **район расчёта** | где считается сетка 500 м; **СИНЯЯ рамка** | `["work"]`, либо мышью | 120.3 × 73.0 км |
| **кадр** | что реально видно в окне | `vb.viewRange()` | зависит от формы окна |

⚠️ **Кадр — не то же самое, что данные.** Оси заблокированы по масштабу
(`setAspectLocked(True)`): километр по X и километр по Y занимают на экране одинаково,
иначе карта была бы растянута. Поэтому на широком окне кадр **шире** области: лишнее по
бокам — неизбежная плата за неискажённую карту.

---

## 2. Как ошибка выглядела

Вписывание при запуске просит отступ 3 % кадра:

```python
def frame_bbox(self, whole_area=False):
    kx0, kx1, ky0, ky1 = self.area_max_km if whole_area else self.bbox_km
    self.pi.setRange(xRange=(kx0, kx1), yRange=(ky0, ky1), padding=self.VIEW_FIT_PAD)
```

А предел перемещения ставился так (было):

```python
self._set_view_limits(self.bbox_km, THREAT_VIEW_PAD_KM)   # РАЙОН ± 100 км
```

Вписываем **область**, а предел считаем по **району**. Пока район сидел посередине
области, поля хватало. На `arh` он смещён к востоку:

```
область   X 0.00 ............................................ 302.25
район     X          101.24 ........... 221.53
предел    X    1.24 ................................ 321.53      ← слева 1.24, а надо 0
```

**Слева не хватило 1.24 км** — и чёрная рамка оказалась ровно за пределом вида, вплотную
к краю окна. Справа запас 19.28 км, поэтому симптом был **только слева**.

---

## 3. Вторая половина — та, из-за которой «2 раз»

Первая ошибка объясняет левый край, но не всё. Замер на `pg.PlotWidget` показал:

```
окно 1560×960, предел «район ± 100»:
   вид X   1.2 .. 317.1 (316 км)   Y  26.2 .. 223.4 (197 км)
   отступы: слева −1.24  справа +14.86  снизу −26.16  сверху −26.16
```

Область высотой **249.6 км показывалась как 197** — срезано по 26 км сверху и снизу,
хотя предел по Y был с запасом (−14.85 … 258.13). Почему?

**Потому что предел по X душит кадр целиком.** Кадру нужно 320 км по ширине, предел даёт
316; из-за блокировки масштаба высота кадра равна ширине, делённой на соотношение окна:
316 / 1.62 = 195 км. Область по высоте не влезает — обрезается.

⚠️ **Это ровно та болезнь, которую уже лечили.** В шапке `_set_view_limits` записано,
что `maxXRange`/`maxYRange` убрали, потому что «широкий экран упирался в предел по одной
оси и подрезал участок по другой». Границы прямоугольника делают **то же самое** —
вылечили половину, симптом вернулся с другой стороны. Отсюда и «уже 2 раз».

---

## 4. Как сделано теперь

Ключевая мысль: **предел должен вмещать КАДР, а не данные.** Сколько нужно кадру —
считается по форме окна:

```python
def _fit_frame(self, box, aspect):
    # Кадр, в который вписывается рамка при заблокированном масштабе осей.
    # Принимает: рамку (x0,x1,y0,y1) км и соотношение сторон окна. Отдаёт: рамку кадра.
    x0, x1, y0, y1 = box
    k = 1.0 + 2.0 * self.VIEW_LIMIT_PAD          # рамка плюс поле с двух сторон
    fw, fh = (x1 - x0) * k, (y1 - y0) * k        # кадр без учёта формы окна, км
    if fw / fh < aspect:                         # окно шире рамки — кадр растёт по X
        fw = fh * aspect
    else:                                        # окно уже рамки — кадр растёт по Y
        fh = fw / aspect
    cx, cy = (x0 + x1) * 0.5, (y0 + y1) * 0.5    # центр рамки: кадр строим вокруг него
    return (cx - fw * 0.5, cx + fw * 0.5, cy - fh * 0.5, cy + fh * 0.5)
```

Сам предел — **объединение** трёх рамок, и область входит всегда:

```python
asp = self._view_aspect()
parts = [self._fit_frame(self.area_max_km, asp),                 # кадр под область
         _pad_box(self.bbox_km, km=THREAT_VIEW_PAD_KM)]          # район + простор
if extra_km:                                 # своя карта может торчать за область
    parts.append(self._fit_frame(extra_km, asp))
self._set_view_limits((min(p[0] for p in parts), max(p[1] for p in parts),
                       min(p[2] for p in parts), max(p[3] for p in parts)),
                      0.0, min_ref=self.area_max_km)   # приближение — от области
```

**Почему `min_ref`.** Предел ПРИБЛИЖЕНИЯ (`minXRange`) считался как «размер границ / 60».
Границы теперь растут вместе с окном — значит на широком мониторе зум молча слабел бы.
Поэтому приближение считается от области, а границы — от кадра: две разные величины, и
смешивать их нельзя.

## 5. Где предел ставится — четыре места, и все через одну дверь

| Когда | Точка вызова |
|---|---|
| при создании вкладки | `__init__` (форма окна ещё неизвестна — предел черновой) |
| ⚠️ при первом показе | `showEvent`, **до** `frame_bbox`: иначе вписываем в черновой предел |
| при смене формы окна | `resizeEvent` |
| при смене района мышью | `set_area_rect` |
| при загрузке своей карты | `_apply_map_image`, `_apply_map_vector` |

⚠️ **Именно рассеянность вызовов и породила ошибку.** Прежде предел ставили три места, и
каждое считало своё объединение — область не входила ни в одно. Теперь считает **один**
метод `_apply_view_limits`, а места вызова только сообщают ему повод.

## 7. Что из этого стоит запомнить

1. **«Отступ есть» и «отступ видно» — разные утверждения.** Отступ задавался верно
   (3 % кадра), а виден не был: его съедал предел. Проверять надо конечный результат
   (`viewRange`), а не входное число;
2. **при блокировке масштаба осей любой предел по одной оси действует на обе** — это и
   есть ловушка, на которой обожглись дважды;
3. **симптом «только слева» означает асимметрию**, а асимметрия бывает там, где предмет
   смещён внутри другого. Это и подсказало, где искать.
