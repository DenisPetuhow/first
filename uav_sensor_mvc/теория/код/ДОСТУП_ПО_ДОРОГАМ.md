## 0. Коротко — путь от паспорта до места

```
паспорт МОГ: zone = «дорога», wet_buf_km = 0.5, drive_km = 0
  → ThreatGrid.allowed_mask(spec)          ключ кэша: правило, отступ, дальность, ЦЕЛИ, разрыв, R
    → sensor_zones.allowed_parts(…, targets)   развилка по правилу: «застройка» — ПВН, «дорога» — сюда
      → road_access.access_parts            дороги → истоки у целей → Дейкстра → запрет → итог
  → ThreatGrid.type_candidates(spec, карта)  «дорога» → road_access.place_nodes (блоками), крыш нет
  → _place_multi_type                        общий проход по типам — как у ПВН, без изменений
```

| Шаг | Функция | Что делает | Замер `arh` |
|---|---|---|---|
| 1 | `road_cells` | ячейки с линией слоёв `DRIVE_LAYERS` (крупные, местные, лесные) | 8 596 ячеек |
| 2 | `sources` | ближайшая к каждой цели ячейка дороги | 0.21 км от цели |
| 3 | `road_distance` | Дейкстра: км по дорогам от истоков | 97.0 % дорог доезжает, дальше всего 181.9 км |
| 4 | `access_parts` | запрет «реки ∪ болота ± отступ», итог `result` | запрет 8 861, разрешено 6 333 ячеек |
| 5 | `place_nodes` | одно место на блок s × s ячеек | 2 365 мест (шаг 1 км) |

Вся карта — **0.23 с**; считается раз на сетку и набор целей (кэш `ThreatGrid._allowed`).

## 1. Дороги — растр слоёв, а не вектор

`grid._present[name]` — булев растр «линия слоя проходит через ячейку»; его кладёт сборка карты
(`_rasterize_polylines` → `acc > 0`). Берём готовое, потому что вся модель мест работает по ячейкам 0.5 км, и карта
ПВН — тоже.

```python
DRIVE_LAYERS = ("road_major", "road_local", "track")   # по чему едет МОГ: дороги и лесные (В13.3.1)
RIVER_LAYERS = ("river",)                               # у чего стоять нельзя: реки и каналы, без ручьёв (В13.3.2)
```

⚠️ **Железная дорога — не дорога**: МОГ по рельсам не едет. **Ручьи — не реки**: заказчик сказал «реки»; ручьи
добавили бы к запрету 11.6 % сетки (12 951 против 8 861 ячейки), а общий запрет воды (русло ± 250 м,
`_places_filter`) их и так держит.

## 2. Дейкстра по ячейкам — 8 соседей без запрета «среза угла»

```python
_STEPS = tuple((dy, dx, math.hypot(dy, dx)) for dy in (-1, 0, 1) for dx in (-1, 0, 1) if dy or dx)
...
while heap:                                      # ближайшая ещё не закрытая ячейка
    d, y, x = heapq.heappop(heap)
    if d > best[y][x]:                           # устаревшая запись очереди
        continue
    for dy, dx, k in _STEPS:                     # 8 соседей
        ...
            nd = d + k * h                       # км до соседа: h по стороне, h·√2 по диагонали
```

* **Почему heapq, а не numpy.** Дейкстра последовательна по сути; на 8 596 ячейках дорог она занимает сотые доли
  секунды. Растр переводится в списки (`tolist`) — индекс списка в цикле Python быстрее индекса numpy.
* ⚠️ **Почему без запрета «среза угла»** (диагональ только при соседе по стороне). Растеризация кладёт точки линии
  шагом 0.4·h по **серединам** отрезков, и дорога, срезающая угол ячейки, попадает в две диагональные ячейки без
  общей стороны. С запретом от цели доезжало **37.0 %** ячеек дорог, без него — **97.0 %**; кусков сети при 8 соседях
  37, крупнейший — 8 336 ячеек. Разрывы давал растр, а не OSM.
* **Цена** — две параллельные дороги в диагональных ячейках сливаются в одну сеть. На сетке 0.5 км это не лечится;
  точнее — граф по вектору (задел плана 13.3 §6).
* **Предел `drive_km`** не встроен в саму Дейкстру: она считает всё, а `access_parts` режет `dist <= lim`. Так карта
  «км по дорогам» (`dist`) одна на любой предел, и её можно показать целиком.

## 3. Запрет: стоять нельзя, ехать можно

```python
ban = _dilate(river | wet, nb)                   # реки и болота ± отступ — стоять нельзя
...
return dict(..., result=reach & ~ban & seen, ...)
```

`ban` вычитается **из итога**, а не из графа: Дейкстра ездит по всем ячейкам дорог, включая мост через реку и гать
через болото. Выкинь полосу из графа — каждая река делила бы сеть надвое, и за рекой мест не было бы вовсе (проверка
`flow_check` 4п: «мост проезжаем, стоять у реки ± 0.5 км нельзя»).

* **Отступ в ячейках** — `round(wet_buf_km / h)`: 0.5 км = одна ячейка, квадратное кольцо (`_dilate`). Место в центре
  соседней ячейки оказывается в 0.5–0.7 км от линии реки.
* **Болота — только слой `wetland`.** В старом файле мест болота лежали в `rough` вместе с кустарником и песками; МОГ
  кустарник не мешает, поэтому без слоя `wetland` болот у МОГ просто нет (у `arh` слой есть — 1 484 ячейки).
* **`seen`** — проходимое для БПЛА ± R, как у ПВН: место, откуда не видно ни одного маршрута, бесполезно.

## 4. Места блоками, а не узлами решётки

```python
s = max(1, int(round(float(step_km) / grid.h)))  # сторона блока, ячеек
by, bx = iy // s, ix // s                        # блок ячейки
far = (iy - by * s - off) ** 2 + (ix - bx * s - off) ** 2   # удаление от центра блока
order = np.lexsort((far, key))                   # по блоку, внутри — от центра
first = np.r_[True, key[order][1:] != key[order][:-1]]      # первая в блоке — ближайшая к центру
```

⚠️ **Почему не `type_nodes`, как у ПВН.** Узлы решётки шагом 1 км (R/2 при R = 2 км) попадают в каждую четвёртую
ячейку; дорога шириной в одну ячейку может пройти между рядами узлов целиком и не дать ни одного места. Блок
гарантирует: есть в блоке разрешённая ячейка — есть и место. `lexsort` устойчив, поэтому при равном удалении
побеждает первая по порядку ячейка — выбор повторяется до бита.

**Крыш у МОГ нет** — `roof` = все False, и общий запрет воды режет все места (у ПВН крыша у реки его обходит).

## 5. Где легко сломать

1. **Ключ кэша карты** (`ThreatGrid.allowed_mask`) обязан включать **цели** (`_access_targets`): карта МОГ от них
   зависит. У прочих правил цели в ключ не идут — иначе перенос цели зря пересчитывал бы карту ПВН.
2. **`min_small_radius`** берёт шаг общей сетки только от типов «везде». МОГ «дорога» в нём не участвует; когда
   ограничены все типы, шаг — по R типа 1 (без этого ПВН 0.5 км вчетверо мельчил сетку, которой никто не пользуется).
3. **Справочник участка сильнее встроенного.** У `arh` МОГ записан «везде» (правка заказчика 28.09.2026) — там
   правило не действует, пока заказчик не выберет «дорога» в окне типа (В13.3.5). Проверки `flow_check` и
   `gui_check` берут встроенный справочник, `reference_run` — справочник участка.
4. **Окно типа**: поля и галки слоёв живут **по своему правилу** (4-й элемент `FIELDS`, словарь `PARTS`); ключи
   `wetland` и `nopass` есть у обоих правил — у каждого своя галка (`_parts_by`).
