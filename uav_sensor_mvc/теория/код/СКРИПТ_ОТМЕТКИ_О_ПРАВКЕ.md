## 1. Какую ошибку он ловит и почему её не ловят остальные

Семь прежних проверок сверяют **содержание**: имена функций, значения чисел, ссылки,
противоречия между документами. Все они бессильны против документа, который **весь
правильный, кроме одного утверждения**.

Живой пример, стоивший половины рабочего дня 11.09.2026. Раздел §5.3 методички маршрутов
назывался «Weighted maximum coverage (вкладка 3)» и начинался словами «единица покрытия —
не точка маршрута, а КЛЕТКА весовой карты». В нём:

* все **имена** живые — `CoverageCache`, `greedy_weighted`, `threat_cand_step_km`;
* все **числа** верные;
* все **ссылки** целы;
* другие документы ему **не противоречат**.

И при этом он врал о главном: так работает **запасной** путь расстановки, который
включается, только если маршрутов меньше пяти. Основной путь — по маршрутам. Найти это
можно было единственным способом — открыть код и прочитать развилку.

**Общий признак таких ошибок:** документ описывает состояние, которое когда-то было
верным. Значит ловить надо не содержание, а **разрыв во времени** — «код ушёл вперёд
документа». Два способа это заметить:

| Способ | Что сравнивает | Чем плох в одиночку |
|---|---|---|
| `codemap.py --stale` (шаг 0) | дату документа из git против дат правок КОДА, который он упоминает | видит только связку «документ ↔ код»; правку документа без правки кода не замечает |
| **`check_dates.py` (шаг 8)** | **отметку в шапке документа против даты его коммита** | видит только «документ ↔ он сам» |

Вместе они закрывают обе стороны.

## 2. Главная идея: отметка не заменяет git, а спорит с ним

Наивная мысль — «поставим дату в шапку, чтобы не лазить в git» — **неверна**. Дата в
шапке проставляется руками, значит врать она будет чаще, чем git, а не реже.

Ценность в другом: **git не врёт никогда, шапка врёт от невнимательности — и расхождение
между ними и есть сигнал.**

```
шапка = git   → правку записали. Порядок
шапка < git   → ⚠️ файл правили ПОЗЖЕ, чем отметили: что изменилось — не записано
шапка > git   → файл ещё не закоммичен (правка в работе) — это норма, не ошибка
```

Отсюда и направление сравнения в коде: в расхождения попадает **только** случай
`шапка < git`.

## 3. Как устроен разбор — по шагам

### 3.1. Поиск корня проекта

```python
def _find_root(markers=("CLAUDE.md", "config.py")):
    d = os.path.dirname(os.path.abspath(__file__))
    while True:
        if any(os.path.exists(os.path.join(d, m)) for m in markers):
            return d
        up = os.path.dirname(d)
        if up == d:          # дошли до корня диска
            return os.path.abspath(".")
        d = up
```

Приём общий для всех скриптов папки `переносимое/` и заведён **после двух одинаковых
поломок**: раньше корень считался как «`dirname` N раз», и при переносе папки счётчик
врал **молча** — скрипт запускался и проверял не те файлы (однажды «нашёл 0 файлов вместо
37»). Поиск по маркеру вверх от себя не зависит от глубины вложения.

⚠️ Ловушка, ради которой стоит `if up == d`: на Windows `os.path.dirname("C:\\")`
возвращает `"C:\\"` — без этой проверки цикл вечный.

### 3.2. Чтение отметки — регулярным выражением и только из шапки

```python
MARK_RE = re.compile(r">\s*\*\*Правился:\*\*\s*(\d{2}\.\d{2}\.\d{4})")
...
m = MARK_RE.search(text[:2000])          # отметка живёт в шапке, не глубже
```

Два решения в двух строках:

* **`\d{2}\.\d{2}\.\d{4}`** — формат даты жёсткий, один на весь проект. Свободный формат
  («11 сентября», `2026-09-11`) пришлось бы разбирать, а разбор дат — это
  `dateutil` в зависимостях ради одной строки;
* **`text[:2000]`** — ищем только в начале файла. Иначе фраза «Правился» в теле
  документа (например, в цитате из другого файла) сойдёт за отметку. Ограничение
  дешевле и надёжнее, чем «искать до первого `##`».

### 3.3. Дата последнего коммита — через `git log`

```python
out = subprocess.run(
    ["git", "log", "-1", "--format=%ad", "--date=format:%d.%m.%Y", "--", rel],
    cwd=ROOT, capture_output=True, text=True, encoding="utf-8")
return (out.stdout or "").strip()
```

Разбор по частям:

| Кусок | Зачем |
|---|---|
| `-1` | нужен только последний коммит файла |
| `--format=%ad` | дата автора (`%ad`), а не коммита (`%cd`): при `rebase` вторая меняется, первая нет |
| `--date=format:%d.%m.%Y` | **git сам форматирует дату** в наш формат — не надо парсить его вывод |
| `--` перед путём | отделяет путь от имён веток. Без него файл с именем как у ветки уводит git не туда |
| список аргументов, не строка | без оболочки: пробелы и кириллица в пути не требуют кавычек |
| `encoding="utf-8"` | иначе на Windows вывод придёт в `cp1251` и кириллица в путях побьётся |
| `(out.stdout or "")` | у нового файла, которого ещё нет в истории, вывод пустой — не `None`, но подстраховка дешёвая |

⚠️ **Ошибки git не проверяются намеренно.** Если репозитория нет вовсе, `git log` вернёт
пустоту, и скрипт просто не сможет сравнить даты — но отработает и проверит остальное.
Падать здесь нечем: отсутствие git не делает документацию неверной.

### 3.4. Сравнение дат без разбора дат

```python
def _key(d):
    p = d.split(".")
    return (p[2], p[1], p[0]) if len(p) == 3 else ("", "", "")
```

Дата `ДД.ММ.ГГГГ` превращается в кортеж `("ГГГГ", "ММ", "ДД")`. Кортежи строк сравниваются
поэлементно, а внутри каждого элемента — посимвольно; поскольку все части
**фиксированной ширины с ведущими нулями**, лексикографический порядок совпадает с
хронологическим.

**Почему не `datetime.strptime`.** Он бы бросил исключение на кривой дате, и проверку
пришлось бы оборачивать в `try`. Здесь же кривая дата просто не совпадёт с
`MARK_RE` и до сравнения не дойдёт.

⚠️ Приём работает **только** при ведущих нулях: `9.9.2026` сломает порядок. Поэтому в
регулярном выражении стоит `\d{2}`, а не `\d{1,2}` — формат навязывается на входе.

### 3.5. Обход документов и что из него исключено

```python
SKIP_DIRS = {"карта_кода", "журнал", "архив"}
...
for dp, dn, fn in os.walk(os.path.join(ROOT, "теория")):
    dn[:] = [d for d in dn if d not in SKIP_DIRS]
```

⚠️ **Ключевая деталь: `dn[:] = [...]`, а не `dn = [...]`.** `os.walk` читает список
подпапок **по ссылке** и по нему решает, куда идти дальше. Присваивание `dn = ...`
создаёт новое имя и на обход не влияет — папка всё равно будет пройдена. Срезовое
присваивание меняет тот самый список. Эта ошибка тихая: скрипт работает, просто проверяет
лишнее.

Почему исключены именно эти три папки:

| Папка | Почему не проверяется |
|---|---|
| `карта_кода/` | **сгенерировано**: дата означала бы «когда запускали скрипт», а не «когда менялось содержание». Здесь отметку не ставят вовсе — пересборка её затрёт |
| `журнал/` | журнал сам себе хроника — требовать от него вторую отметку бессмысленно |
| `архив/` | закрытые документы не правятся по определению, отставать им не от чего |

⚠️ **Исключение из ПРОВЕРКИ, а не запрет на отметку.** В `архив/` и `журнал/` отметки
проставились при заведении и лежат там безвредно — просто скрипт их не сверяет. Запрет
жёсткий только для `карта_кода/`: там любая ручная строка исчезнет при пересборке.

## 4. Вторая работа скрипта: генерация `ЖУРНАЛ_ПАПКИ.md`

### 4.1. Почему НЕ руками — разбор отвергнутого варианта

Задумывался рукописный мини-журнал в каждой папке: дата, файл, что сделано. **Отвергнуто
12.09.2026 при реализации**, и причина видна именно из кода: черновик скрипта, который
заводил такие файлы, **засеивал их из `git log`**. То есть данные уже были в git, а
файл оказывался их рукописной копией.

**Копия, которую обновляют руками, устаревает первой.** В тот же день на этом обожглись
трижды:

| Что соврало | Как именно |
|---|---|
| указатель журнала | обещал 245 пунктов и неверную длину части 5 |
| план 7, задача З6 | числил открытым пункт, сделанный восемью днями раньше ДРУГИМ планом |
| §5.3 методички маршрутов | описывала запасной путь расстановки как основной |

Восемь рукописных журналов добавили бы восемь мест, способных соврать, не добавив ничего
к тому, что уже есть в git и в отметках.

**Решение: генерировать**, как оглавления и карту кода. В шапке — пометка «сгенерировано,
руками не править».

### 4.2. Что попадает в файл

Две таблицы, из двух разных источников:

1. **отметки в документах** — из шапок (`MARK_RE`), отсортированы по дате убыванием:

   ```python
   marks.sort(key=lambda t: _key(t[1]), reverse=True)
   ```

   тот же ключ, что и в сравнении, — свежее сверху;

2. **последние правки по git** — `git log --name-only` по папке. Вывод чередует строки
   «дата⇥сообщение» и имена файлов, поэтому разбирается по признаку табуляции:

   ```python
   for line in (out.stdout or "").split("\n"):
       if "\t" in line:
           date, subj = line.split("\t", 1)       # заголовок коммита
       elif line.strip().endswith(".md"):
           ...                                     # файл этого коммита
   ```

   ⚠️ `split("\t", 1)` с ограничением: сообщение коммита само может содержать табуляцию,
   и без лимита оно обрезалось бы.

   ⚠️ Пара `(дата, файл)` кладётся в `seen`: один файл может встретиться в нескольких
   коммитах одного дня, и без этого таблица дублировалась бы.

### 4.3. Замер: сколько это стоит

Прогон 12.09.2026 на 56 документах: **8 мини-журналов пересобрано, расхождений 0**,
время — доли секунды. Дорогая часть — вызовы `git log` (по одному на документ плюс по
одному на папку), то есть ~64 запуска процесса. При росте документации втрое это станет
заметно; тогда стоит брать одну общую историю за один вызов и раскладывать её в памяти.

## 5. Ловушки, известные заранее

* ⚠️ **Отметка «первая, содержание не сверялось».** При заведении она проставлена в 68
  документов **датой из git**, а не сегодняшней. Это честно: содержание мы не сверяли, и
  отметка лишь заводит точку отсчёта. Ставить сегодняшнюю было бы враньём — документ
  выглядел бы свежепроверенным;
* ⚠️ **Скрипт не проверяет, ПРАВДА ли написанное в отметке.** Он сверяет только даты.
  Текст «§5.3 переписан» может оказаться выдумкой — это ловит пятый шаг сверки, глазами;
* ⚠️ **Незакоммиченные файлы дают `шапка > git`** — и это норма, не ошибка. Поэтому в
  расхождения берётся только строгое `шапка < git`;
* ⚠️ **`--write-logs` перезаписывает файл целиком.** Всё, что дописали руками, пропадёт
  при следующей пересборке — на то и пометка в шапке.

## 6. Как запускать

### 6.1. Откуда и чем

**Запускать из корня проекта** — той папки, где лежат `CLAUDE.md` и `config.py`. Путь к
скрипту пишется от неё:

```bash
python tools/переносимое/check_dates.py
```

⚠️ **Не предварять командой `cd "путь" &&`** — разрешения на команды сверяются с началом
строки, и такая приставка сбрасывает их: запрос на подтверждение всплывает на ровном
месте (замер: из 757 команд сессии 656 шли с `cd`, и список разрешений покрывал 24 %
вызовов). Рабочая папка и так корень проекта.

⚠️ **Кириллица в пути к скрипту — это нормально.** Папка называется `переносимое`, и
Python открывает её без оговорок. Но если вывод в консоли Windows покажется «кракозябрами»
(консоль по умолчанию `cp1251`), запускать так:

```bash
# PowerShell: попросить Python выводить в UTF-8
$env:PYTHONIOENCODING='utf-8'; python tools/переносимое/check_dates.py
```

⚠️ **Git должен быть доступен** — скрипт вызывает `git log`. Если репозитория нет, даты
из git будут пустыми, и сравнение просто не состоится: скрипт отработает и проверит
остальное, но «шапка отстала» показать не сможет.

### 6.2. Три команды и когда какая

| Команда | Когда запускать | Что делает |
|---|---|---|
| `check_dates.py` | **после правки документов**, вместе с остальными семью проверками | отчёт; **код возврата 1**, если есть расхождения |
| `check_dates.py --list` | когда надо увидеть картину целиком | то же плюс построчно: у каждого документа отметка и дата git |
| `check_dates.py --write-logs` | **после коммита** правок в документы | пересобирает `ЖУРНАЛ_ПАПКИ.md` во всех живых папках |

⚠️ **`--write-logs` запускать ПОСЛЕ коммита, а не до.** Он берёт даты из `git log`, а
незакоммиченная правка в историю ещё не попала — в журнале папки её просто не будет.

## 7. Как читать вывод

Скрипт печатает **только расхождения**, и каждая строка означает своё действие.

### 7.1. Всё в порядке

```
проверено документов: 58; расхождений: 0
```

Ничего делать не надо. ⚠️ **Смотреть на код возврата, а не на глаз:** проверка считается
пройденной, когда `EXIT=0`. Отчёт читают глазами и видят то, что ждут увидеть — на этом
уже обожглись 11.09.2026 с `docmap --check`.

```bash
python tools/переносимое/check_dates.py; echo "EXIT=$?"     # bash
python tools/переносимое/check_dates.py; "EXIT=$LASTEXITCODE"   # PowerShell
```

### 7.2. «НЕТ ОТМЕТКИ "Правился"»

```
НЕТ ОТМЕТКИ «Правился» (2):
    теория/планы/10_ПЛАН_ПРОЕКЦИЯ_И_ОСТАТКИ.md
    теория/планы/9_ПЛАН_ОРГАНИЗАЦИЯ_ПРОЕКТА.md
```

**Что значит:** у документа нет строки-отметки в шапке. Обычно это **новый файл**, который
только что завели.

**Что делать:** дописать сразу после заголовка первого уровня:

```markdown
# Название документа

> **Правился:** 12.09.2026 — что именно изменено, одной фразой.
```

⚠️ Формат даты **строго `ДД.ММ.ГГГГ` с ведущими нулями**: `09.09.2026`, а не `9.9.2026`.
Иначе отметка не распознается вовсе и документ снова попадёт в этот список (почему именно
так — §3.4).

### 7.3. «ШАПКА ОТСТАЛА ОТ GIT» — главная находка

```
ШАПКА ОТСТАЛА ОТ GIT (1) — файл правили, а что изменилось, не записали:
    теория/МЕТОДИЧКА_МОДЕЛИ_МАРШРУТОВ.md          шапка 02.09.2026 < git 11.09.2026
```

**Что значит:** файл коммитили **11 сентября**, а в шапке стоит **2 сентября**. Значит
правку внесли, а что изменилось — не записали. Ровно ради этого скрипт и написан.

**Что делать:** ⚠️ **дописать отметку, а НЕ подогнать дату.** Открыть, посмотреть
`git log -p` по файлу, понять, что менялось, и записать это словами:

```markdown
> **Правился:** 11.09.2026 — §5.3 переписан: основной путь расстановки — маршруты,
> по клеткам веса считает только запасной.
```

Если просто поставить свежую дату, проверка замолчит, а знание потеряется — это худший
исход из возможных.

### 7.4. «ПАПКА БЕЗ ЖУРНАЛ_ПАПКИ.md»

```
ПАПКА БЕЗ ЖУРНАЛ_ПАПКИ.md (8):
    теория
    теория/карты
```

**Что значит:** в папке есть документы, а сгенерированного мини-журнала нет.

**Что делать:** `python tools/переносимое/check_dates.py --write-logs`. Руками такой файл
не создавать — он сгенерированный.

### 7.5. «ФАЙЛ НЕ УПОМЯНУТ В МИНИ-ЖУРНАЛЕ ПАПКИ»

```
ФАЙЛ НЕ УПОМЯНУТ В МИНИ-ЖУРНАЛЕ ПАПКИ (1):
    теория/карты/МЕТОДИЧКА_НОВАЯ.md          -> теория/карты/ЖУРНАЛ_ПАПКИ.md
```

**Что значит:** документ есть, а в журнале папки его нет — журнал устарел.

**Что делать:** тот же `--write-logs`. Если после пересборки строка осталась — файл ещё
не закоммичен, и в `git log` его нет (см. ловушку в §6.2).

### 7.6. Вывод `--list`

```
  теория/карты/МЕТОДИЧКА_КАРТА.md            шапка 04.09.2026   git 04.09.2026
  теория/карты/МЕТОДИЧКА_ЗАГРУЗКА_КАРТ.md    шапка 10.09.2026   git 10.09.2026
```

Две даты рядом. Читается так:

| Что видно | Как понимать |
|---|---|
| **шапка = git** | правку записали, порядок |
| **шапка < git** | ⚠️ правили позже, чем отметили — попадёт в расхождения |
| **шапка > git** | файл ещё не закоммичен, правка в работе. **Это норма**, не ошибка |
| **git пустой (`—`)** | файла нет в истории вовсе: новый, либо забыли `git add` |

## 7а. Сквозной разбор кода: `main()` и генератор

Выше разобраны приёмы по отдельности. Здесь — **как это собрано вместе**: два цикла,
которые и составляют весь скрипт.

### 7а.1. `main()` — один проход, три списка

Проверка устроена как **один обход документов**, по ходу которого набираются три разных
списка находок. Не три прохода — потому что самая дорогая операция здесь вызов `git log`,
и делать её трижды по одному файлу незачем.

```python
def main():
    if "--write-logs" in sys.argv:
        write_folder_logs()
    show = "--list" in sys.argv
    no_mark, stale, no_log = [], [], []
    folder_logs = {}
```

**Почему `--write-logs` идёт ПЕРВЫМ, до проверки.** Если сначала проверить, а потом
пересобрать, отчёт покажет «папка без журнала» для папки, которую эта же команда только
что и создала. Порядок «сперва пересобрать, потом проверить» даёт честный итог за один
запуск.

`folder_logs` — **кэш прочитанных мини-журналов**. В папке `вкладка_3` девять документов;
без кэша её журнал читался бы с диска девять раз.

```python
    for rel in docs():
        path = os.path.join(ROOT, rel)
        text = io.open(path, encoding="utf-8").read()
        m = MARK_RE.search(text[:2000])
        gd = git_date(rel)
        if not m:
            no_mark.append(rel)
            continue
```

⚠️ **`io.open(..., encoding="utf-8")`, а не просто `open`.** На Windows `open` берёт
кодировку системы (`cp1251`), и любой документ с «⚠️» или «→» упал бы на
`UnicodeDecodeError`. Явная кодировка — правило для всех скриптов этой папки.

⚠️ **`continue` после `no_mark`.** Нет отметки — сравнивать не с чем, и остальные проверки
для этого файла бессмысленны. Без `continue` ниже пришлось бы каждый раз проверять `m` на
`None`.

```python
        mark = m.group(1)
        if show:
            print("  %-58s шапка %s   git %s" % (rel, mark, gd or "—"))
        if gd and _key(mark) < _key(gd):
            stale.append((rel, mark, gd))
```

Здесь три решения в трёх строках:

| Строка | Решение | Почему так |
|---|---|---|
| `%-58s` | ширина колонки фиксирована | иначе даты «пляшут» и таблицу не прочитать глазами |
| `gd or "—"` | пустая дата показывается прочерком | пустая строка выглядела бы как обрыв вывода |
| `if gd and …` | без даты git сравнение **пропускается** | у нового файла истории нет, и «отставания» быть не может |

⚠️ **Сравнение строго одностороннее — `<`, а не `!=`.** Случай «шапка новее git» (правка
ещё не закоммичена) — это норма работы, а не ошибка. Поставь здесь `!=` — и проверка
ругалась бы на каждый файл, который прямо сейчас редактируют.

```python
        folder = os.path.dirname(rel)
        if os.path.basename(folder) in NO_FOLDER_LOG:
            continue
        if folder not in folder_logs:
            lp = os.path.join(ROOT, folder, FOLDER_LOG)
            folder_logs[folder] = (io.open(lp, encoding="utf-8").read()
                                   if os.path.exists(lp) else None)
```

**`None` как «журнала нет» против пустой строки.** Значение `None` в кэше означает именно
отсутствие файла, а `""` означало бы «файл есть, но пустой». Различие нужно ниже: из
`None` собирается список «папка без журнала», а пустой журнал — это уже «файл не упомянут».

```python
        name = os.path.basename(rel)
        if name not in log:
            no_log.append((rel, folder))
```

⚠️ **Проверка `name not in log` — намеренно грубая: подстрокой, а не разбором таблицы.**
Мини-журнал сгенерирован нами же, его формат известен, и разбирать markdown ради одного
вопроса «упомянут ли файл» — работа, которая сломается при первой же смене формата.
Плата за грубость: файл `КАРТА.md` считается упомянутым, если в журнале есть
`МЕТОДИЧКА_КАРТА.md`. Ложно-отрицательное срабатывание, и оно безопаснее ложной тревоги —
скрипт промолчит там, где мог бы зря поднять шум.

### 7а.2. Печать: сначала копим, потом выводим

```python
    print()
    if no_mark:
        print("НЕТ ОТМЕТКИ «Правился» (%d):" % len(no_mark))
        for r in no_mark:
            print("   ", r)
```

Находки **не печатаются по ходу цикла**, а копятся в списках и выводятся в конце —
группами. Печать по ходу перемешала бы три вида находок в одну ленту, и глазами её не
разобрать. Плюс заголовок группы несёт число: `(2)` сразу говорит про объём.

```python
    total = len(no_mark) + len(stale) + len(missing_logs) + len(no_log)
    print("\nпроверено документов: %d; расхождений: %d" % (len(docs()), total))
    return 1 if total else 0
```

⚠️ **Возврат кода, а не `sys.exit` внутри.** `main()` возвращает число, а выход делает
обёртка `sys.exit(main())` в конце файла. Так функцию можно вызвать из другого скрипта и
получить число, а не остановку процесса.

⚠️ **Печатается ВСЕГДА, даже когда всё хорошо.** Молчание при успехе выглядит как «скрипт
не запустился». Строка «расхождений: 0» — доказательство, что проверка правда прошла.

### 7а.3. Генератор: почему таблицы собираются списком строк

```python
        body = [GEN_HEAD, "", "# Журнал папки — `%s`" % (base or "теория"), "", ...]
        for name, d, note in marks:
            body.append("| `%s` | %s | %s |" % (name, d, note or "—"))
        ...
        io.open(...).write("\n".join(body))
```

Текст собирается **списком строк и склеивается один раз**, а не наращивается через
`body += "..."`. Причина не в скорости (файлы крошечные), а в читаемости: в списке видно
построчную структуру будущего markdown, и строку таблицы нельзя случайно «слепить» с
соседней, забыв `\n`.

```python
        body.append("| %s | `%s` | %s |" % (d, f, s.replace("|", "/")[:100]))
```

⚠️ **`s.replace("|", "/")` — обязательная защита.** `s` это сообщение коммита, то есть
**чужой текст**, попадающий в ячейку markdown-таблицы. Один символ `|` в сообщении разорвёт
строку на лишние колонки, и таблица поедет. Обрезка `[:100]` — по той же причине: длинное
сообщение растягивает колонку так, что таблицу не прочитать.

```python
        note = text[m.end():].split("\n")[0].strip(" —") if m else ""
```

Берётся хвост строки **после** совпадения с датой — то есть человеческое пояснение из
отметки. `m.end()` даёт позицию сразу за датой; `split("\n")[0]` обрезает по концу строки;
`strip(" —")` убирает тире-разделитель, чтобы в таблице не было `— — текст`.

```python
        marks.sort(key=lambda t: _key(t[1]), reverse=True)
```

Тот же ключ сравнения, что и в проверке (§3.4). **Один ключ на два применения** — если
формат даты когда-нибудь сменится, править придётся одно место, а не два.

### 7а.4. Разбор вывода `git log --name-only`

Самый неочевидный кусок. `git log --name-only` выдаёт **чередование**: строка заголовка
коммита, затем имена изменённых файлов, потом следующий коммит:

```
10.09.2026→Итог плана 8, журнал разделён на часть 6
теория/журнал/ЖУРНАЛ_5.md
теория/планы/8_ПЛАН_КАРТА_И_ИНТЕРФЕЙС.md

06.09.2026→Датчики: режимы по фазам
теория/карты/README.md
```

Разбирается по признаку табуляции — её даёт наш же формат `%ad\t%s`:

```python
    for line in (out.stdout or "").split("\n"):
        if "\t" in line:
            date, subj = line.split("\t", 1)     # заголовок коммита
        elif line.strip().endswith(".md"):
            name = os.path.basename(line.strip())
            if name == FOLDER_LOG or (date, name) in seen:
                continue
            seen.add((date, name))
            rows.append((date, name, subj))
```

| Приём | Зачем |
|---|---|
| `\t` как признак | в именах файлов табуляции не бывает, а в нашем формате она ровно одна |
| `split("\t", 1)` **с лимитом** | сообщение коммита само может содержать табуляцию; без лимита оно бы обрезалось |
| `date`, `subj` живут **между витками** | имена файлов идут ПОСЛЕ своего заголовка, и переменные хранят «текущий коммит» |
| `name == FOLDER_LOG` | журнал папки не должен упоминать сам себя — иначе каждая пересборка добавляет строку о пересборке |
| `seen` из пар `(дата, файл)` | один файл может попасть в несколько коммитов одного дня |

⚠️ **Пустая строка между коммитами не мешает:** она не содержит табуляции и не
оканчивается на `.md`, поэтому не попадает ни в одну ветку `if`. Это не случайность, а
причина, по которой условия написаны через «что строка из себя представляет», а не через
счётчик строк.
