## 1. Зачем: область была константой кода

До 13.09.2026 область задавалась **правкой `config.py`**: `THREAT_AREA = "arh"` и запись в
словаре `THREAT_AREAS`. Сменить область — найти строку, поправить, перезапустить. В
собранной программе — никак.

**Пример.** Чтобы открыть Донецк, надо было менять `"arh"` на `"severodonetsk"` в строке 192
`config.py`. Заказчик же завёл третью область (Marshut) и сказал, что их будет больше.

## 3. Кто за что отвечает

| Где | Отвечает за |
|---|---|
| `geo_cache/<область>/область.txt` | **описание области**: `область` (обязательно), `район`, `название`, `исходник`, `слои`, `рельеф`, `вход`, `цель` |
| `area_file.py` :: `parse_area_text` | текст файла → запись того же вида, что `config.THREAT_AREAS[...]`; все проверки |
| `area_file.py` :: `read_area_folder` | папка **или сам файл** → запись; нет файла — подсказка, в каких вложенных папках он есть |
| `area_file.py` :: `active_area` | какая область активна: выбранная → файл области по умолчанию → реестр |
| `area_file.py` :: `saved_choice`, `apply_saved_choice` | память выбора (`ui_state.json`, раздел «область») → переменные окружения |
| `area_file.py` :: `format_area_text` | запись области в текст — так файлы заводятся из реестра |
| `main_qt.py`, начало файла | `apply_saved_choice()` **до** `from config import …` |
| `config.py` :: `_AREA` | запись области из `active_area`; из неё — `THREAT_BBOX_LONLAT`, `THREAT_WORK_LONLAT`, имена файлов |
| `config.py` :: `THREAT_AREA_SOURCE`, `THREAT_AREA_ERROR`, `THREAT_AREA_LABEL`, `THREAT_TILE_AREA` | откуда взята область, почему выбранная не открылась, подпись, имя папки тайлов |
| `view_qt/input_window.py` :: `_build_area`, `set_area_info` | блок «Область и папка тайлов» в окне «Исходные данные» — только кнопки и подпись |
| `view_qt/threat_view.py` :: `_area_info_text`, `_pick_tile_root` | текст подписи; обработка «Папка тайлов…» |
| `view_qt/threat_view.py` :: `set_area_ready` (`keep`), `set_busy` | «Исходные данные» доступны и без района |
| `view_qt/area_choice.py` :: `choose_area`, `restart_program` | выбор файла → проверка → подтверждение → память → перезапуск |
| `view_qt/area_choice.py` :: `choose_tile_root` | новый корень тайлов → окружение → память → сброс тайлов |
| `view_qt/geomap.py` :: `cache_root`, `clear_tile_memory` | корень тайлов читается при каждом обращении; память тайлов сбрасывается |
| `tools/area_check.py` | проверка всего механизма без окна |

⚠️ **Окно ничего не решает.** `input_window` только сообщает «нажали кнопку» колбэками
`on_pick_area`, `on_pick_tiles`; действие выполняет `area_choice`, а подпись готовит
`threat_view`. Так же устроены все колбэки этого окна.

## 4. Порядок при запуске

```
main_qt.py
  │  area_file.apply_saved_choice()      ui_state.json → UAV_AREA_DIR, UAV_TILE_CACHE
  ▼
from config import …                     ← ⚠️ ТОЛЬКО ПОСЛЕ этого
  config.py
    active_area(THREAT_AREAS, "arh")
      1) UAV_AREA_DIR задан?      → область.txt из этой папки (или сам файл)
      2) geo_cache/arh/область.txt? → он
      3) иначе                    → запись реестра THREAT_AREAS["arh"]
    THREAT_BBOX_LONLAT, THREAT_WORK_LONLAT, THREAT_LAYERS_FILE, … — из записи
  ▼
model/threat_grid.py, view_qt/threat_view.py  — импортируют эти константы по имени
```

**Как это в коде:**

```python
# main_qt.py — ДО `from config import …`
import area_file
area_file.apply_saved_choice()           # память окна -> переменные окружения

# config.py
import area_file as _area_file
THREAT_AREA, _AREA, THREAT_AREA_SOURCE = _area_file.active_area(THREAT_AREAS, THREAT_AREA)
THREAT_AREA_ERROR = _area_file.LAST_ERROR    # почему выбранная папка не открылась; "" — открылась
```

⚠️ **Почему `apply_saved_choice` не перебивает уже заданную переменную.** Явный запуск
(`UAV_AREA_DIR=… python main_qt.py`, проверки) важнее памяти окна — иначе переменную
окружения нельзя было бы использовать для проверки конкретной области.

## 5. Почему разбор файла — в корне проекта, а не в `model/`

Файл читает `config.py`. А пакет `model` при импорте тянет `threat_grid`, который сам
импортирует `config`:

```
config → model/__init__ → model/threat_grid → config      ← круг: config ещё не дочитан
```

Поэтому `area_file.py` лежит **в корне** и зависит только от стандартной библиотеки.
Корень кэша `geo_cache/` он тоже вычисляет сам (`geo_cache_root`) — тем же правилом, что
`model.threat_grid.geo_cache_root`, но без импорта модели.

---

## 6. ⭐ Почему смена области — перезапуск

Модель и вид берут константы области **по имени при импорте**:

```python
# model/threat_grid.py — строка импорта
from config import (THREAT_BBOX_LONLAT, THREAT_WORK_LONLAT, THREAT_LAYERS_FILE, THREAT_AREA_DIR, …)
```

Такой импорт копирует **значение** в пространство имён модуля. Поменяй потом
`config.THREAT_BBOX_LONLAT` — у `threat_grid` останется старое. Мест, где область прочитана
так, около тридцати: модель, вид, контроллер.

**Какие были варианты:**

| Вариант | Цена | Решение |
|---|---|---|
| **перезапуск программы** | несколько секунд заставки; несохранённый расчёт пропадает (об этом спрашивается) | ✅ **выбрано заказчиком** — расчёт и эталон не трогаются |
| смена на лету: область — аргументом во всех ~30 местах, пересборка вкладки 3 | большая переделка модели и вида | ❌ отклонено: риск для эталона, выигрыш — несколько секунд |
| `importlib.reload` модулей | ничего не переделывать | ❌ ненадёжно: объекты, созданные до перезагрузки, живут со старыми значениями |

```python
# view_qt/area_choice.py
os.environ[af.ENV_AREA] = folder                  # новый экземпляр наследует окружение
if not restart_program():                         # перезапуск не удался
    QtWidgets.QMessageBox.information(parent, "Сменить область",
        "Выбор сохранён. Закройте программу и откройте снова — область сменится.")
```

⚠️ **Переменную окружения ставить ДО перезапуска, а не только память.** Новый процесс
наследует окружение старого, где `UAV_AREA_DIR` уже задан прежней областью. А
`apply_saved_choice` заданную переменную не перебивает (§4) — и программа открылась бы на
старой области, хотя в памяти записана новая.

**Пример.** `restart_program` в собранной программе: `sys.executable` — сам `.exe`, и имя
скрипта ему не передаётся; из исходников — `python main_qt.py` с тем же путём.

## 7. Почему папка тайлов — сразу, без перезапуска

С тайлами другой расклад: `geomap.cache_root()` читает `UAV_TILE_CACHE` **при каждом
обращении**, константы нет. Значит, достаточно сменить переменную и забыть загруженное:

```python
os.environ[af.ENV_TILES] = root
gm.clear_tile_memory()          # ⚠️ ключ памяти — (участок, слой, z, x, y), КОРНЯ в нём нет
tiles.clear()                   # снять со сцены картинки прежнего корня
view._refresh_basemap(force=True)
```

⚠️ **Без `clear_tile_memory` смена не видна.** Ключ декодированного тайла в памяти не
содержит корня: тот же `(z, x, y)` отдался бы из памяти старой картинкой, хотя папка уже
другая.

**Пример.** Уровни z8–z10 области `arh` в памяти: до 512 тайлов. Выбрали другую папку — без
сброса все они показывались бы из прежнего кэша, пока не вытеснятся.

## 8. Выбирается файл, а не папка

Первая версия кнопки открывала окно «Выбор папки». Заказчик в тот же вечер: «пишет нет
подходящего файла `область.txt`, хотя он есть».

**Причина.** Окно «Выбор папки» Windows **не показывает файлы** («Нет элементов,
удовлетворяющих условиям поиска»). Не видя `область.txt`, человек выбирал папку уровнем
выше — `geo_cache/`, где файла действительно нет.

**Решение — два слоя.** Кнопка выбирает **сам файл** (`getOpenFileName`); а если в функцию
всё же пришла папка без файла, сообщение перечисляет вложенные папки, где он есть:

```python
subs = sorted(d for d in os.listdir(folder)
              if os.path.isfile(os.path.join(folder, d, AREA_FILE_NAME)))
hint = "; он есть во вложенных папках: %s — выберите одну из них" % ", ".join(subs)
```

## 9. Проверки файла — что не принимается и почему

| Что | Почему не молча |
|---|---|
| нет `область` | без рамки области нет ни предела вида, ни якоря километров |
| район выходит за область | расчёт вне области идёт без слоёв и рельефа — ошибка незаметна на карте |
| **незнакомый ключ** | опечатка «раион» иначе тихо открыла бы область без района |
| порядок чисел перепутан | `lon_min > lon_max` даёт отрицательную ширину — сетка из нуля ячеек |

**Удобства, а не строгости:** десятичная запятая через `;` (`37,95; 61,71; …`); BOM Блокнота
(`utf-8-sig`); не заданные `исходник`, `слои`, `рельеф` ищутся по расширению в папке; `вход`
по умолчанию — у восточного края, `цель` — центр района.

⚠️ **Папка внутри `geo_cache/` записывается ИМЕНЕМ, снаружи — полным путём.** Тогда
`area_cache_dir` для `arh` даёт тот же путь, что и раньше из реестра, а `os.path.join(root,
полный_путь)` для внешней папки возвращает сам полный путь. Тайлы же ищутся всегда по
**имени** папки (`THREAT_TILE_AREA`): полный путь внутри `tile_cache/` не имеет смысла.

## 10. ⚠️ Проверочные скрипты память окна не читают

`apply_saved_choice` вызывается только в `main_qt.py`. `reference_run`, `flow_check`,
`gui_check` импортируют `config` без неё и всегда открывают область по умолчанию.

**Пример, от чего это защищает.** Открыли в программе Marshut и закрыли. Если бы проверки
читали память, `reference_run` молча считал бы Marshut, у которой нет эталона, и печатал
«эталона нет» — а правка модели осталась бы непроверенной.

## 11. Где ломается легко

* ⚠️ **новый импорт `config` раньше `apply_saved_choice`** в `main_qt.py` — область молча
  останется по умолчанию. Строка вызова — самая первая после `import sys`;
* ⚠️ **константа области, прочитанная не из `_AREA`**, — например, прямое обращение к
  `THREAT_AREAS[THREAT_AREA]`: для области из файла такой записи в реестре нет;
* ⚠️ **`THREAT_AREA_DIR` как имя папки тайлов** — у области вне `geo_cache/` это полный путь;
  для тайлов — только `THREAT_TILE_AREA`;
* файл `arh` обязан совпадать с реестром по рамке, району, файлам, входу и цели — иначе
  эталон поедет. Это ловит `area_check` раздел 2.
