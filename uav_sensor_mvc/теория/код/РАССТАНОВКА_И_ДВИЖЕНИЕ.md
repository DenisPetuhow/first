## 1. Три источника выборки — и приоритет между ними

Прежде чем разбирать расстановку, надо понять, **по чему** она считается. Источников три,
и порядок строгий (`threat_grid.py` :: `_sample_for_sensors`):

```python
if len(self.iter_routes) >= 5:                            # 1) идут итерации — их маршруты
    return self.iter_routes
if self.show_loaded_routes and len(self.loaded_routes) >= 5:   # 2) загруженная история
    return self.loaded_routes
return self.routes                                        # 3) «все возможные пути»
```

⚠️ **Итерации всегда в приоритете.** Как только накопится ≥ 5 своих маршрутов, чекбокс
«показать загруженную выборку» на расстановку влиять перестаёт. Это не оплошность, а
решение: свои свежие данные достовернее принесённых из файла.

⚠️ **Порог именно 5, а не 1.** По одному-двум маршрутам покрытие вырождается: датчик
встаёт ровно на единственную линию, и любая следующая итерация всё ломает.

| Источник | Когда работает | Что показывает |
|---|---|---|
| `iter_routes` | идёт моделирование | что реально «налетали» |
| `loaded_routes` | загружена история и включён чекбокс | сравнение расстановок на одних данных |
| `routes` | **до моделирования** | все возможные пути (§4) |

## 2. Модель движения: как рождается один маршрут

`threat_routes.py` :: `sample_one_route` → `_walk_field`.

### 2.1. Розыгрыш точки входа

```python
live = [i for i, e in enumerate(ents) if e["reachable"]]   # недостижимые в розыгрыш не идут
avail = [i for i in live if i not in recent[-cool:]]       # пауза повтора: cool = 2
if not avail:
    avail = live                                # точек меньше паузы — пауза снимается
pick = avail[int(rng.integers(len(avail)))]     # РАВНОМЕРНО между оставшимися
```

⚠️ **Розыгрыш равномерный, хотя точки отбирались по весу.** Вес участвует при **отборе**
самих пяти точек, а при выборе старта — нет: при неизвестном нарушителе делать одну точку
втрое вероятнее другой оснований нет (решение заказчика).

⚠️ **Пауза повтора нужна из-за природы случайности.** Равномерный розыгрыш сам по себе
даёт серии — «выпало трижды подряд», — и на коротких прогонах часть точек не отрабатывала
вовсе. Точка, из которой только что стартовали, не берётся следующие **два** раза.

⚠️ **История лежит в контексте `ctx`, а не в функции.** Поэтому правило работает и в
`plan_routes`, и в итерациях: они делят один контекст.

### 2.2. Шаг блуждания — три множителя

```python
prog = dfield[cur] - dj                              # насколько сосед ближе к цели
corr = _mode_corridor_pref(wnorm[vy, vx], wmode)     # привлекательность клетки по весу
s = float(np.exp(prog / tau)) * corr * hf            # оценка = прогресс × вес × курс
if vy * nx + vx in visited:
    s *= 0.12                                        # петля: гасим, но НЕ запрещаем
```

| Множитель | Что выражает | Без него |
|---|---|---|
| `exp(prog / tau)` | стремление к цели | бродит и не долетает |
| `corr` | местность (река, дорога — ориентиры) | летит напрямик, коридоры ни при чём |
| `hf` | удержание курса: 14.0 прямо, 2.5 доворот, 0.5 на пределе | зигзаг, физика нарушена |

⚠️ **`tau` — «температура», и она убывает сама.** Запас хода на исходе → `tau` мал → `exp`
резко выделяет соседа с максимальным прогрессом. То есть случайность гаснет по мере
расхода топлива **без отдельного правила**: в начале маршрут волен петлять, в конце идёт
к цели.

⚠️ **Повторный заход штрафуется, а не запрещается.** Запрет загонял бы в тупик: иногда
единственный выход — вернуться на клетку назад.

### 2.3. Физика движения — жёсткие пределы

Поверх вероятностей стоят запреты, которые не обходятся никаким весом:

* **поворот за шаг** ≤ `TURN_MAX_DEG` = 45°. Было «малый вес вместо запрета» — и набегало:
  **88 % маршрутов** имели поворот круче 90°. Стало 0.7–2 %;
* **окно разворота** `TURN_WINDOW_KM` = 3 км, ≤ 90°: четыре шага по 45° складывались в
  разворот на 180°, формально не нарушая радиуса. Было у 84 % маршрутов, стало у 19–23 %;
* ⚠️ **окно — правило МЯГКОЕ**, снимается, если иначе прохода нет. Жёстким быть не может:
  маршрут, отвернувший вбок при большом запасе, обязан когда-то повернуть к цели, и запрет
  оставлял его в тупике — при `L` = 150 км доходило **10 маршрутов из 150**.

### 2.4. Выбор соседа — «метод рулетки»

```python
sc = np.asarray(score, float)
j = int(np.searchsorted(np.cumsum(sc), rng.random() * sc.sum()))
```

`cumsum` даёт нарастающие границы секторов, `searchsorted` находит сектор, куда попала
случайная точка. ⚠️ То же распределение, что у `rng.choice(p=…)`, но **без нормировки и
без аллокаций** на каждом шаге — а шагов миллионы.

## 3. Жадный алгоритм: как из маршрутов получаются позиции

`optimization.py` :: `CoverageCache.greedy`.

### 3.1. Почему вообще жадный

Задача — **максимизация покрытия** при ограничении на число датчиков. Полный перебор
невозможен (NP-трудная), но у функции покрытия есть свойство, которое всё решает:
**субмодулярность** — каждый следующий датчик приносит не больше предыдущего на том же
месте («убывающая отдача»).

Для таких функций доказано (Nemhauser, Wolsey, Fisher, 1978): жадный выбор даёт **не хуже
(1 − 1/e) ≈ 63 %** от недостижимого оптимума. Это **гарантия с доказательством**, а не
«обычно неплохо».

### 3.2. Где в коде видно субмодулярность

```python
new_min = np.minimum(n_vec[:, None] + H, k)        # ← НАСЫЩЕНИЕ: после k-й засечки прироста нет
gain_n  = (new_min - cur_min[:, None]) / k         # прирост кратности
new_pop = _popcount(mask_vec[:, None] | M)         # сегментов пути накрыто
gain_m  = (new_pop - cur_pop[:, None]) / Lseg      # прирост ДОЛИ ДЛИНЫ маршрута
primary = (a1 * gain_n + a2 * gain_m).mean(axis=0) # усреднение ПО МАРШРУТАМ
```

| Строка | Что в ней важно |
|---|---|
| `np.minimum(…, k)` | **то самое насыщение**: из него и растёт гарантия. Убрать — гарантии нет |
| `_popcount(… \| M)` | маршрут нарезан на `L_seg` сегментов и хранится **битовой маской**: «накрыть ещё кусок» — это `OR`, а `popcount` считает результат |
| `.mean(axis=0)` | усреднение **по маршрутам**, не по клеткам. Вот где видно: единица покрытия — **маршрут** |
| `[:, None] + H` | прирост считается для ВСЕХ кандидатов сразу, матрицей; цикл был бы в сотни раз медленнее |

### 3.3. Три ключа — лексикографика, а не сумма

```python
if   primary.max()   > 1e-9:   score = primary     # 1) кратность + доля длины
elif secondary.max() > 1e-12:  score = secondary   # 2) прирост покрытой доли
else:                          score = covsum      # 3) ⚠️ резерв кратности
c = int(np.argmax(np.where(avail, score, -np.inf)))
```

⚠️ **Складывать ключи нельзя.** Вторичный смотрится, только когда основной у всех нулевой;
в сумме слабый вторичный перебивал бы настоящий прирост.

⚠️ **Без третьего ключа датчики уходили в угол карты.** При насыщении `score` обнулялся у
всех кандидатов, и `argmax` брал **первого по порядку массива** — позицию без единого
пролёта. Замер на реальных данных: **4 из 12** датчиков не ловили ничего. `covsum`
(«сколько маршрутов кандидат вообще накрывает») даёт осмысленный резервный порядок.

### 3.4. Принудительные позиции: порядок операций

```python
for aidx in (anchors or []):      # СНАЧАЛА поставить все
    take(int(aidx))
for aidx in (anchors or []):      # ПОТОМ исключить соседей
    exclude_near(int(aidx), max(anchor_sep, min_sep))
```

⚠️ **Два цикла, а не один — и это исправление бага.** Раньше шло одним циклом, и позиция,
попавшая в зону разноса предыдущей, **молча терялась**: `avail` к её очереди уже был снят.
Для двух якорей у входа и цели это не замечали (они далеко друг от друга), но заданную
человеком позицию ронять нельзя: поставил два датчика рядом — программа обязана оставить
оба.

⚠️ **Разнос применяется только к тому, что алгоритм выбирает САМ.** Заданное человеком —
входные данные, их не «разносят».

⚠️ **`anchors` — один механизм, два разных смысла.** Якорь (позиция, которую алгоритм
назначает себе сам; отключены 29.08.2026) и условия моделирования (позиции человека).
Разница принципиальна для гарантии: первое — самоограничение алгоритма, второе —
сокращение задачи. Разбор — [СЕКТОР_И_НАЗНАЧЕНИЯ](СЕКТОР_И_НАЗНАЧЕНИЯ.md).

## 4. Расчёт позиций ДО моделирования

**Частый вопрос:** «почему датчики уже стоят, хотя моделирование не запускали?»

### 4.1. Что происходит

```python
if len(self.iter_routes) < 5 and len(self.routes) < 5:
    self.plan_routes()                       # маршрутов нет — построить «все возможные»
sample = self._sample_for_sensors()
if sample and len(sample) >= 5:
    self.sensors = self._place_by_routes(self.candidates, sample)   # ОСНОВНОЙ путь
else:
    self.sensor_source = "weight"
    self.sensors = self._place_by_weight(self.candidates)           # запасной
```

⚠️ **До моделирования работает ТОТ ЖЕ основной путь.** Разница только в источнике выборки:
вместо накопленных пролётов берутся «все возможные пути» — 250 представительных маршрутов
от `plan_routes`. Механизм расстановки не меняется.

### 4.2. Чем «возможные маршруты» отличаются от итерационных

| | «возможные» (до моделирования) | итерационные |
|---|---|---|
| сколько | 250 | 150 (по умолчанию) |
| задача выборки | лечь по области **максимально широко** | показать, как летают **на самом деле** |
| разброс | веер (`mix`): через разные VIA-точки | по заданным режимам панели |
| отбор | жадный по покрытию области | все накопленные |

⚠️ **Приоритет по весу берётся ИЗ ПАНЕЛИ** (`THREAT_ROUTE_MODE_SRC = "panel"`). Раньше был
`mix`, а он разыгрывает режим **каждому маршруту** — то есть **треть линий** строилась в
режиме «приоритет минимального веса», целенаправленно уходя с тяжёлых коридоров, и выбор
в панели на картину не влиял вовсе.

### 4.3. Запасной путь — по клеткам веса

`_place_by_weight` → `greedy_weighted`. Включается, **только если маршрутов меньше пяти** —
например, запас хода не позволяет долететь.

```python
g_mult   = wpos * lt_k / k - wneg * lt_1     # кратность до k, минус штраф за репеллеры
g_spread = wpos * lt_1 - wneg * lt_1         # охват НОВЫХ клеток
gcell    = a1 * g_mult + a2 * g_spread
gain     = cov_f @ gcell                     # прирост по всем кандидатам — одним умножением
```

⚠️ **Это `T` = 1:** вместо выборки из сотен маршрутов подаётся **одна** статичная
«псевдотраектория» — вся весовая карта. Вес известен заранее и не меняется, цикл
накопления не нужен.

⚠️ **Замер, объясняющий приоритет:** частота пролёта под датчиком выше средней в **2.0**
раза, вес — лишь в **1.3**. Поэтому по маршрутам, а не по весу.

### 4.4. Расстановка пересчитывается по ходу

`THREAT_SENSOR_REFRESH_EVERY` = **5**: каждые пять накопленных маршрутов позиции считаются
заново. Видно, как расстановка сходится — сдвиг между обновлениями падает с ≈ 5 км до нуля
к 30-й итерации.

⚠️ Раньше пересчёт был только в конце прогона, и датчики казались неподвижными.
